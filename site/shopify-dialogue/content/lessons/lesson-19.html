十二、Product Structured Data

这一块是 Shopify Theme SEO 非常重要的知识。

你经常会看到：

html
<script type="application/ld+json">

  ...
}
</script>

这叫：

它不是给用户看的，而是给搜索引擎理解页面数据的。

例如 Product：

json

  "@context": "https://schema.org",
  "@type": "Product",
  "name": "Nike Air Max",

    "https://example.com/image.jpg"

  "description": "Running shoes",
  "sku": "AIR-001"
}

还可以描述：

文本
Product

├── image
├── description
├── sku

    ├── price
    ├── currency
    └── availability

十三、为什么 Structured Data 很重要？

假设普通 HTML：

html

<p>$129.99</p>

人类很容易理解：

文本

但 Structured Data 可以更加明确地告诉机器：

json
{
  "@type": "Product",
  "name": "Nike Air Max",
  "offers": {
    "@type": "Offer",
    "price": "129.99"
  }
}

也就是：

文本
HTML
↓
给人看

JSON-LD
↓
给机器理解

{{ canonical_url }} 不是你在 Shopify 后台某个地方配置的变量。

它是 Shopify Theme 里的一个 Liquid 全局对象，Shopify 会根据当前页面自动计算它的 canonical URL。

你要做的是：在 Theme 的 <head> 里使用它。

通常位置：

文本
layout/
└── theme.liquid

找到：

liquid
<head>

然后加入：

liquid
<link rel="canonical" href="{{ canonical_url }}">

例如：

liquid
<head>
  <meta charset="utf-8">

  <title>{{ page_title }}</title>

  {% if page_description %}
    <meta
      name="description"
      content="{{ page_description | escape }}"
    >
  {% endif %}

  <link
    rel="canonical"
    href="{{ canonical_url }}"
  >

  {{ content_for_header }}
</head>

它是怎么工作的？

假设当前访问：

文本
/products/nike-air-max

那么：

liquid
{{ canonical_url }}

Shopify 会渲染成类似：

html
<link
  rel="canonical"
  href="https://example.com/products/nike-air-max"
>

如果当前是：

文本
/collections/shoes

就会对应当前 Collection 的 canonical URL。

所以你可以把它理解成：

文本
{{ canonical_url }}
        ↓
Shopify 根据当前页面自动计算
        ↓
当前页面的标准 URL

一个很容易踩的坑

不要自己写死：

liquid
<link
  rel="canonical"
  href="https://example.com/products/xxx"
>

因为 theme.liquid 会被很多页面共用。

正确思路是：

liquid
<link rel="canonical" href="{{ canonical_url }}">

让 Shopify 根据当前页面动态生成。

还有一个细节很重要：

如果你使用的是 Shopify 的主流 Online Store 2.0 Theme，你的 Theme 可能本来就已经有这行代码了。

所以你现在可以打开：

→ Online Store
→ Themes
→ Edit code
→ layout
→ theme.liquid

然后搜索：

文本
canonical

否则一个页面可能出现两个 canonical。

  <meta charset="utf-8">

  <title>{{ page_title }}</title>

  <link
    rel="canonical"
    href="{{ canonical_url }}"
  >

  {{ content_for_header }}

</head>

它一般放在 <head> 里面。

2. 它到底是什么？

你可以把：

liquid
{{ content_for_header }}

理解成一个：

Shopify 平台预留的动态注入点。

它不是一个普通变量，比如：

liquid
{{ product.title }}

这种变量是：

文本
Product
 ↓
title
 ↓
字符串

而：

liquid
{{ content_for_header }}

更像：

文本
Shopify Platform
       │
       ├── Shopify 自己需要的内容
       ├── App 需要注入的内容
       ├── Tracking / Analytics 相关内容
       ├── 某些平台功能
       └── 其他运行时内容
              │
              ▼
      content_for_header
              │
              ▼
         <head>

所以它是 Shopify Theme 和 Shopify 平台之间非常重要的一个连接点。

3. 为什么 Shopify 要这样设计？

假设你的 Theme 是：

文本
theme.liquid

但是你的店铺安装了很多东西：

文本
Shopify
├── Shopify 本身
├── Review App
├── Analytics
├── Marketing App
├── Search App
├── Subscription App
└── 其他 App

这些东西可能都需要往页面里注入一些：

html
<script>
<link>
<meta>
...

如果 Shopify 要求你手动写：

liquid
<script>Shopify stuff...</script>

那 Theme 开发会非常麻烦。

所以 Shopify 提供：

liquid
{{ content_for_header }}

作为平台注入点。

4. 一个非常重要的区别

你可能会看到：

liquid
{{ content_for_header }}

然后产生疑问：

“它到底输出什么 HTML？”

这里要注意：

你不应该依赖它当前具体输出什么。

因为它是 Shopify 动态生成的内容。

也就是说，不要写这种逻辑：

liquid
{{ content_for_header }}

{% if content_for_header contains 'xxx' %}
...
{% endif %}

也不要去修改它输出的内容。

你应该把它当成：

文本
Shopify reserved area

5. 为什么不能删？

这个非常重要。

如果你把：

liquid
{{ content_for_header }}

删掉：

liquid
<head>

  <title>{{ page_title }}</title>

  <!-- 没有 content_for_header -->

</head>

你的 Theme 可能出现各种问题。

因为 Shopify / App 依赖的某些内容可能无法正常注入。

所以正常 Theme 应该保留：

liquid
{{ content_for_header }}

Shopify 的 Theme 检查要求也涉及 content_for_header 的存在。官方文档明确说明它必须出现在 theme.liquid 的 <head> 中。 Shopify

canonical_url

9. content_for_header 和 content_for_layout

顺便给你讲一个经常一起出现的东西：

liquid
{{ content_for_header }}

和：

这两个名字非常容易混。

content_for_header

位置：

  {{ content_for_header }}

        ↓

        ↓

10. 所以一个 Shopify Theme 的骨架

你现在应该开始能看懂：

liquid
<!doctype html>

<html>
<head>

  <meta charset="utf-8">

  <meta
    name="viewport"
    content="width=device-width, initial-scale=1"
  >

  <title>
    {{ page_title }}
  </title>

  {% if page_description %}
    <meta
      name="description"
      content="{{ page_description | escape }}"
    >
  {% endif %}

  <link
    rel="canonical"
    href="{{ canonical_url }}"
  >

  {{ content_for_header }}

</head>

<body>

  {% sections 'header-group' %}

  <main>
    {{ content_for_layout }}
  </main>

  {% sections 'footer-group' %}

</body>
</html>

你现在看到这份代码，实际上已经把我们前面学的很多东西串起来了：

文本
theme.liquid
│
├── SEO
│   ├── page_title
│   ├── page_description
│   └── canonical_url
│
├── Shopify Platform
│   └── content_for_header
│
├── Header
│
├── 当前页面
│   └── content_for_layout
│
└── Footer

这就是 Shopify Theme 的“总入口”。
