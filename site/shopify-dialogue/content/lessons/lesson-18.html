一、先理解 Pagination：分页

假设你的 Collection 有：

文本
500 个商品

我们不可能一次全部渲染。

所以：

liquid
{% paginate collection.products by 24 %}

  {% for product in collection.products %}
    {% render 'product-card', product: product %}
  {% endfor %}

{% endpaginate %}

意思就是：

文本

      ↓
每页 24 个
      ↓
Page 1 → 1~24
Page 2 → 25~48
Page 3 → 49~72
...

Shopify 当前对 Collection 商品使用 paginate 时，每页最多可以展示 50 个商品。Shopify

三、最简单的 Pagination

你可以直接：

七、Sort 怎么实现？

八、用户改变 Sort 后怎么办？

例如：

文本
当前：

/collections/shoes?page=2

用户选择：

文本
Price Low → High

我们需要变成：

文本
/collections/shoes?page=2&sort_by=price-ascending

一个非常简单的实现：

js
const sortSelect = document.querySelector('#SortBy');

sortSelect.addEventListener('change', (event) => {

  const url = new URL(window.location.href);

  url.searchParams.set(
    'sort_by',
    event.target.value
  );

  window.location.href = url.toString();

});

这里最重要的是：

js
const url = new URL(window.location.href);

而不是自己重新拼：

js
'/collections/shoes?sort_by=' + ...

因为当前 URL 可能已经有：

文本
filter
page
其他参数

我们应该：

文本
读取当前 URL
        ↓
只修改 sort_by
        ↓
保留其他参数

九、但这里还有一个非常重要的问题：切换 Sort 时 page 要不要保留？

假设：

文本
当前：

Page 5

然后用户选择：

文本
Price Low → High

如果继续：

文本
page=5

可能会产生很奇怪的体验。

因为：

文本
默认排序
Page 5

和：

文本

Page 5

是完全不同的数据集合。

通常我们希望：

文本

        ↓
回到 Page 1

所以：

js
const url = new URL(window.location.href);

url.searchParams.set(
  'sort_by',
  event.target.value
);

url.searchParams.delete('page');

window.location.href = url.toString();

这就是一个很典型的 URL State 管理。

十二、现在加入 Section Rendering

如果我们使用：

js
window.location.href = url

那么页面会完整刷新。

但 Shopify 还有更高级的方式：

文本
Section Rendering API

我们上一课已经提过。

Shopify 官方明确支持使用 Section Rendering API，通过 AJAX 请求 Section HTML，从而更新页面局部内容而不重新加载整个页面。它也可以用于 Collection 的分页。ShopifyShopify

十三、假设我们的 Collection Section

文本
sections/
└── main-collection-product-grid.liquid

里面：

liquid
{% paginate collection.products by 24 %}

  <div
    class="collection-grid"
    data-section-id="{{ section.id }}"
  >

    {% for product in collection.products %}
      {% render 'product-card', product: product %}
    {% endfor %}

  </div>

  <div class="collection-pagination">
    {{ paginate | default_pagination }}
  </div>

{% endpaginate %}

注意：

liquid
{{ section.id }}

非常重要。

因为 JSON Template 中的 Section ID 可能是动态生成的。Shopify 官方也建议通过 section.id 或实际 DOM wrapper 获取，而不是假设固定文件名就是 Section ID。ShopifyShopify

十四、然后 JS 可以请求第二页

例如：

js
const url = new URL(window.location.href);

url.searchParams.set('page', '2');

const sectionId =
  document.querySelector('[data-section-id]').dataset.sectionId;

const response = await fetch(
  `${url.pathname}?${url.searchParams.toString()}&sections=${sectionId}`
);

const data = await response.json();

Shopify：

文本
Browser
   ↓
/collections/shoes?page=2
&sort_by=price-ascending
&sections=xxxxx
   ↓
Shopify
   ↓
Liquid
   ↓
只渲染这个 Section
   ↓
返回 HTML

Section Rendering API 会返回指定 Section 的 HTML；请求 URL 上的 page、sort_by 等参数也会参与 Section 的 Liquid 渲染。Shopify

十五、然后替换 DOM

比如：

js
const html =
  data[sectionId];

const parser =
  new DOMParser();

const doc =
  parser.parseFromString(
    html,
    'text/html'
  );

const newSection =
  doc.querySelector(
    `[data-section-id="${sectionId}"]`
  );

const currentSection =
  document.querySelector(
    `[data-section-id="${sectionId}"]`
  );

currentSection.replaceWith(
  newSection
);

       ↓

       ↓
