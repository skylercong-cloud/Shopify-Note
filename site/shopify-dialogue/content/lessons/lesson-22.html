上一课我们建立了：

文本
Product
   │
   └── Variant
          │
          └── Inventory

这一课把 Collection 放进整个数据模型。

最重要的一句话：

Collection 不是 Product 的父级目录，而是一个“产品集合”。

一个 Product 可以进入多个 Collection。

一、Collection 到底是什么？

例如你的店铺有：

文本
1000 个 Product

你可能希望建立：

文本
Running Shoes
Nike
Men's Shoes
Best Sellers
Summer Sale
New Arrivals

这些都是 Collection。

可以理解成：

文本
                         Products
                            │
       ┌────────────────────┼────────────────────┐
       ▼                    ▼                    ▼
Running Shoes              Nike             New Arrivals
       │                    │                    │
       ├── Product A        ├── Product A        ├── Product C
       ├── Product B        ├── Product D        ├── Product E
       └── Product C        └── Product F        └── Product A

注意：

文本
Product A

同时存在于：

文本
Running Shoes
Nike
New Arrivals

所以这是典型的：

Product ↔ Collection 多对多关系

二、Collection 和 Product 的关系

数据库思维可以粗略理解：

文本
Product
   ↕
Collection

而不是：

文本
Collection
   │
   ├── Product
   ├── Product
   └── Product

后者容易让你误以为：

一个 Product 只能属于一个 Collection。

实际上不是。

三、Shopify 有两种核心 Collection

你需要记住：

文本
Collection
├── Manual Collection
└── Smart Collection

也可以理解成：

文本
手动 Collection
自动 Collection

四、Manual Collection

Manual Collection：

商家自己决定哪些 Product 加进去。

例如：

文本
New Arrivals

管理员选择：

文本
Product A
Product B
Product C
Product D

那么：

文本
New Arrivals
├── A
├── B
├── C
└── D

你可以把它理解成：

文本
Merchant
   ↓
手动选择 Product
   ↓
Collection

五、Manual Collection 适合什么？

非常适合：

精选商品

文本
Featured Products

首页推荐

文本
Homepage Picks

节日专题

文本
Black Friday

编辑精选

文本
Editor's Choice

营销活动

文本
Summer Sale

例如市场团队说：

“我们挑 30 个商品作为首页精选。”

那就非常适合 Manual Collection。

六、Smart Collection

Smart Collection 的思路完全不同。

它不是：

文本
Merchant
 ↓
一个个选择 Product

而是：

文本
定义条件
 ↓
Shopify 自动判断
 ↓
符合条件的 Product
 ↓
进入 Collection

例如：

文本
Collection:
Nike Shoes

条件：

文本
Vendor = Nike
AND
Product Type = Shoes

那么：

文本
Product A
Vendor = Nike
Type = Shoes
      ↓
      ✓

Product B
Vendor = Adidas
Type = Shoes
      ↓
      ✗

Product C
Vendor = Nike
Type = Bag
      ↓
      ✗

最终：

文本
Nike Shoes
└── Product A

七、Smart Collection 的核心思想

可以把它理解成：

文本
Product Data
      │
      ▼
   Conditions
      │
      ▼
 Shopify evaluates
      │
      ▼
Matching Products
      │
      ▼
   Collection

所以：

Smart Collection 本质上是一个基于 Product 数据的动态集合。

八、什么数据可以成为条件？

常见的商品属性包括：

文本
Vendor
Product Type
Tag
Price
...

例如：

文本
Vendor = Nike

或者：

文本
Product Type = Shoes

或者：

文本
Tag = sale

这样你就可以构造：

文本
Nike Shoes
文本
Vendor = Nike
AND
Product Type = Shoes

九、这和我们之前学的 Filter 有什么区别？

这是一个非常重要的区别。

Collection

决定：

哪些 Product 属于这个集合。

例如：

文本
Nike Shoes

Filter

决定：

用户在这个 Collection 中进一步筛选什么。

例如：

文本
Nike Shoes
│
├── Color
│   ├── Black
│   └── White
│
├── Size
│   ├── 8
│   └── 9
│
└── Price
    ├── <$50
    └── $50-$100

所以：

文本
Collection
    ↓
定义商品范围

Filter
    ↓
用户进一步缩小范围

假设店铺有：

十一、Collection 在 Liquid 中是什么？

你之前已经使用过：

liquid
{{ collection.title }}

Collection 对象有很多属性。

例如：

liquid
{{ collection.id }}

{{ collection.handle }}

{{ collection.description }}

{{ collection.url }}

还有：

liquid

以及：

十二、Collection URL

Collection 最常见的 URL：

文本
/collections/shoes

其中：

文本
collections

是 Shopify 的 Collection 路径。

而：

文本
shoes

通常就是：

liquid
collection.handle

所以：

文本
Title:
Running Shoes

Handle:
running-shoes

URL：

文本
/collections/running-shoes

十三、Handle 是什么？

Handle 是 Shopify 用来表示资源 URL 的一个字符串。

例如：

文本
Title:
Running Shoes

Handle:
running-shoes

URL：

文本
/collections/running-shoes

Product 也是一样：

文本
Title:
Nike Air Max

Handle:
nike-air-max

URL：

文本
/products/nike-air-max

所以：

文本
Title
 ↓
Handle
 ↓
URL

十四、Handle 不是 ID

这一点要记住。

例如：

文本
Collection ID:
gid://shopify/Collection/123456

Handle:
running-shoes

两者用途不同。

ID

用于：

文本
API
Database relationship
GraphQL

Handle

主要用于：

文本
URL

所以不要混淆：

文本
ID ≠ Handle

十五、Collection 和 Sort

上一阶段我们已经讲过：

现在从数据模型角度重新理解：

例如：

其中：

文本

特别值得记。

十六、Manual Sort

如果 Collection 使用：

文本

可以理解为：

商家人工决定商品在 Collection 中的顺序。

例如：

文本

2. Product C
3. Product F

5. Product D

这对于：

文本
Featured

Homepage
Campaign

非常有用。

十七、为什么不能把 Metafield 直接当 Collection Sort？

这是我们上一阶段讨论过的问题。

例如你定义：

文本
custom.rating

数据：

文本
Product A → 4.9
Product B → 4.5
Product C → 4.8

你可能自然想：

文本
/collections/shoes?sort_by=rating

但 Shopify 原生 Collection sort 并不是任意 Metafield Sort。

原生排序是有限的：

文本
manual
best-selling
title
price
created
...

所以：

文本
Metafield
   ≠
Native Collection Sort

这也是为什么如果你要做：

文本
Rating
Recommendation Score
Margin
Priority
AI Score

这种复杂排序，往往需要：

文本
App / Backend

参与。

十八、Collection 与 SEO

现在再把第 19 课连接回来。

例如：

文本
/collections/running-shoes

它是一个非常重要的 SEO 页面。

所以 Collection 通常需要：

文本
Collection
│
├── title
├── description
├── products
├── image

Theme：

liquid

  {{ collection.title }}
</h1>

{% if collection.description != blank %}

    {{ collection.description }}
  </div>

然后：

文本
canonical
title
description

一起组成 Collection SEO。

十九、Collection 数据模型和 Theme 页面模型

现在可以把：

文本
Collection

和 Theme：

文本

联系起来。

请求：

文本

大致：

文本

   │
   ▼
Shopify
   │
   ▼
Collection
   │
   ▼

   │
   ▼

   │

所以：

这和 React 非常像：

文本

 ↓

 ↓

只是 Shopify 是：

Liquid

二十、一个非常重要的架构区分

以后你学习 Shopify App 时一定会遇到这个问题：

“Collection 是不是 Theme 的东西？”

不是。

Collection 属于：

文本
Shopify Commerce Data

Theme 只是：

文本
读取 Collection
 ↓
展示 Collection

所以：

文本
Shopify Platform
│
├── Product
├── Variant
├── Collection
├── Customer
├── Order
├── Inventory
└── ...
        │
        ▼
      Theme
        │
        ▼
      UI

这就是我们从 Theme 转向 Data Model 后最重要的思维变化。
