这一课是 Shopify 数据模型里非常核心的一课。

你前面已经学了：

文本
Product
   ↓
Variant
   ↓
InventoryItem
   ↓
InventoryLevel
   ↓
Location

现在把「购买流程」接起来：

文本
Product
   ↓
Variant
   ↓
Cart
   ↓
Checkout
   ↓
Order
   ↓
Fulfillment

这条链你以后做 Shopify Theme、App、ERP、订单同步，都会反复遇到。

一、先把 4 个概念分清楚

最容易混淆的是：

文本
Cart
Checkout
Order
Fulfillment

它们分别代表：

对象 核心含义
Cart 用户准备买什么
Checkout 用户正在完成购买
Order 购买已经形成的订单
Fulfillment 订单怎么发货/履约

可以先记成：

文本
Cart
= 想买

Checkout
= 正在买

Order
= 买成功了

Fulfillment
= 怎么发出去

Shopify 官方对购物旅程的定义也是类似的：Cart 保存买家准备购买的商品，Checkout 用于最终确认并完成交易。Shopify

二、Cart：购物车

假设用户进入：

文本
Nike Air Max
Black / 9
$129

点击：

文本
Add to Cart

这时候发生的不是：

文本
创建 Order

而是：

文本
创建/修改 Cart

例如：

文本
Cart
├── Nike Air Max / Black / 9 × 1
├── T-Shirt / White / M × 2
└── Socks × 1

Shopify 的 Cart 本质上就是：

一个买家准备购买的商品集合，以及当前购物过程中的相关信息。

Storefront API 当前的 Cart 模型还包含 buyer identity、cost、preferences 等信息。ShopifyShopify

三、Cart 里面最重要的是 Line

你之前已经接触过这个概念：

文本
Cart
  ↓
Cart Lines

例如：

文本
Cart
│
├── Line 1
│     └── Variant A × 1
│
├── Line 2
│     └── Variant B × 2
│
└── Line 3
      └── Variant C × 1

在 Theme Liquid 中：

liquid
{% for item in cart.items %}
  {{ item.product.title }}
  {{ item.quantity }}
{% endfor %}

这里的：

liquid
cart.items

实际上就是购物车里的 line items。

Shopify 当前 Theme 文档也明确把 line item 定义为购物车中的一条商品记录，其中记录了加入购物车的 Variant 和数量。Shopify

四、为什么 Cart Line ≠ Variant？

这个非常重要。

例如：

文本
Variant
Nike Air Max / Black / 9

用户可能加入：

文本
Line 1
Nike Air Max / Black / 9
quantity = 1

另外又加入了一条带有不同自定义属性的同一 Variant：

文本
Line 2
Nike Air Max / Black / 9
quantity = 1
properties:
  gift = "yes"

所以：

文本
Variant

是商品规格。

而：

文本
Cart Line

是：

这个 Variant 以某种购买上下文进入当前 Cart 的一条记录。

这也是为什么以后做 Cart Drawer 时，不应该简单地认为：

文本
Variant ID = Cart Line ID

它们是不同层次的数据。

五、Cart 的典型结构

可以把它理解成：

文本
Cart
│
├── id
│
├── lines
│    ├── line 1
│    │     ├── merchandise → Variant
│    │     └── quantity
│    │
│    ├── line 2
│    │     ├── merchandise → Variant
│    │     └── quantity
│    │
│    └── line 3
│
├── buyerIdentity
│
├── cost
│
└── checkoutUrl

其中：

lines

买了什么。

quantity

买多少。

buyerIdentity

谁在买/买家上下文。

cost

购物车当前估算金额。

checkoutUrl

准备进入 Shopify Checkout 的地址。

当前 Storefront API 文档明确支持从 Cart 获取 checkoutUrl，然后把买家导向 Shopify Web Checkout。Shopify

六、Theme 里的 Cart

如果你做 Shopify Theme：

文本
templates/cart.json

通常对应：

文本
/cart

页面。

Theme 里可以直接使用：

liquid
{{ cart.item_count }}

以及：

liquid
{% for item in cart.items %}

  {{ item.product.title }}

  {{ item.variant.title }}

  {{ item.quantity }}

{% endfor %}

Shopify 官方 Theme 文档当前仍然以 cart Liquid 对象作为 /cart 页面的核心数据来源。Shopify

七、Cart Drawer 又是什么？

你之前已经学过 Cart Drawer。

现在从数据模型角度看就很清楚了：

文本
Cart
│
└── Cart Drawer
       ↑
       │
    Theme UI

Cart Drawer 不是 Shopify 的一个独立业务对象。

它只是：

Theme 用来展示 Cart 的一种 UI。

例如：

文本
Shopify Cart
      ↓
cart.items
      ↓
Theme
      ↓
Cart Drawer

所以：

文本
Cart Drawer ≠ Cart

这一点一定要记住。

八、Ajax Cart API 在这里干什么？

如果是 Shopify Theme：

文本
Browser
   ↓
JavaScript
   ↓
Ajax Cart API
   ↓
Shopify Cart

例如添加商品：

js
const response = await fetch(
  window.Shopify.routes.root + 'cart/add.js',
  {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json'
    },
    body: JSON.stringify({
      items: [
        {
          id: variantId,
          quantity: 1
        }
      ]
    })
  }
);

这里：

文本
id

是 Variant ID。

然后：

文本
Variant
↓
Cart Line
↓
Cart

Shopify 当前文档明确说明 Ajax API 是面向 Shopify-hosted Theme 的轻量 API，可用于添加商品到 Cart、更新购物车等。Shopify

九、Checkout 到底是什么？

这是非常容易误解的地方。

很多前端开发者第一反应是：

Checkout 不就是 Cart 页面吗？

不是。

可以这样理解：

文本
Cart
↓
"我要买这些东西"

然后：

文本
Checkout
↓
"我要正式完成这笔购买"

Checkout 会涉及：

文本
商品
+
数量
+
价格
+
折扣
+
税
+
运费
+
收货地址
+
联系方式
+
支付

所以：

文本
Cart

更偏向：

购物篮。

而：

文本
Checkout

更偏向：

交易确认流程。

整个过程：

文本

      ↓
Add to Cart
      ↓
Cart
      ↓
Checkout
      ↓
Payment
      ↓
Order

例如：

文本
Nike Air Max
$129
    ↓
Add to Cart
    ↓
Cart
Subtotal: $129
    ↓
Checkout
    ↓
Shipping
$10
    ↓
Tax
$11
    ↓
Total
$150
    ↓
Payment
    ↓

这里你会发现一个重要区别：

文本
Cart total

并不一定等于：

文本
最终 Order total

因为 Checkout 阶段可能涉及：

文本
Shipping
Tax
Discount
Market pricing
Payment

Shopify 当前 Cart 文档也明确指出 Cart 的 cost 是估算值，最终结算金额可能在 Checkout 中变化。Shopify

十一、现在的 Shopify 不应该再用旧 Checkout API 思维

这个对你以后开发 App 非常重要。

以前 Shopify 有：

文本
Checkout API

例如：

文本
checkoutCreate

但 Shopify 已经推进到：

文本
Storefront Cart API

当前官方文档说明：

  • Checkout APIs 在 Storefront API 中已经弃用
  • 2025-04 起 Checkout APIs sunset
  • 推荐迁移到 Storefront Cart API
  • Native Mobile 可以考虑 Checkout Kit。ShopifyShopify

所以你现在学习 Shopify，应该建立这个新模型：

文本
旧：

Product
 ↓
Checkout API
 ↓
Checkout


现在：

Product
 ↓
Cart API
 ↓
Cart
 ↓
checkoutUrl
 ↓
Shopify Checkout

这个变化非常重要。

十二、为什么 Shopify 不让你自己实现 Checkout？

因为 Checkout 涉及非常复杂的商业基础设施：

文本
Payment
Tax
Shipping
Discount
Fraud
Inventory
Address
Currency
Market
Order
Compliance

Shopify 的思路是：

文本
你负责：

Storefront
Cart UI
商品展示
购物体验

Shopify 负责：

Checkout
Payment
Order
Commerce infrastructure

所以通常：

文本
Cart
↓
checkoutUrl
↓
Shopify Checkout

而不是：

文本
Cart
↓
自己写一个支付页面
↓
自己创建订单

十三、Checkout 完成以后才产生 Order

这是整个数据模型最关键的一条：

文本
Cart
   ↓
Checkout
   ↓
Purchase completed
   ↓
Order

所以：

Cart 不是 Order。

例如：

文本
用户把 iPhone 放进购物车

并不意味着：

文本
产生订单

用户可能：

文本
加入购物车
↓
关闭浏览器

此时没有完成购买。

十四、Order 是什么？

Shopify 官方当前把 Order 定义为：

Customer 向商店购买一个或多个商品的请求。

并且 Order 是整个购买生命周期的重要中心对象，连接：

文本
Customer
Product
Payment
Fulfillment
Returns
Refunds

Shopify

所以：

文本
Order
│
├── Customer
│
├── Line Items
│      ├── Product
│      └── Variant
│
├── Payment
│
├── Shipping Address
│
├── Transactions
│
├── Fulfillment
│
└── Refund
