Largest Contentful Paint

简单理解：

例如 Product 页面：

三、Shopify Theme 中最常见的 LCP 问题

最典型：

文本
Product Hero Image

比如：

liquid
{{ product.featured_image
  | image_url: width: 1200
  | image_tag
}}

如果你错误地给首屏主图：

html

就可能产生问题。

为什么？

因为：

文本

=
告诉浏览器
“这张图晚一点加载也可以”

但首屏最大的图片恰恰是：

文本

所以一般应该：

文本

    ↓

Below the fold
    ↓
Lazy loading

四、Lazy Loading

例如 Product Gallery：

    media
    | image_url: width: 1000

{% endfor %}

如果有：

文本

没必要全部立即加载。

可以：

文本

↓
优先加载

第二张以后
↓
lazy loading

这会减少页面初始网络压力。

五、但是第一张图片不能简单全部 lazy

这是 Shopify Theme 开发非常常见的性能细节。

比如：

文本

│
├── Hero Image ← LCP
│
├── Thumbnail
├── Thumbnail
├── Thumbnail
└── Thumbnail

应该考虑：

文本

→ eager / browser priority

其他图片
→ lazy

所以：

liquid
{% for media in product.media %}

  {% if forloop.first %}

    {{
      media
      | image_url: width: 1200
      | image_tag:
        loading: 'eager',
        fetchpriority: 'high',
        alt: media.alt
    }}

  {% else %}

    {{
      media
      | image_url: width: 1000
      | image_tag:
        loading: 'lazy',
        alt: media.alt
    }}

  {% endif %}

{% endfor %}

这里的思想非常重要：

文本

性能优化 =
知道什么应该优先
知道什么可以延迟

十一、JavaScript 不要阻塞首屏

例如：

html
<script src="{{ 'app.js' | asset_url }}"></script>

如果脚本很大，并且阻塞 HTML 解析，就会影响页面加载。

通常更合理的是：

html
<script
  src="{{ 'app.js' | asset_url }}"
  defer
></script>

defer 的基本含义：

文本
HTML parsing
      │
      ├──────────────┐
      │              │
      ▼              ▼
继续解析 HTML      下载 JS
      │              │
      └──────┬───────┘
             ▼
          执行 JS

而不是：

文本
HTML
 ↓
遇到 JS
 ↓
暂停 HTML
 ↓
下载 JS
 ↓
执行
 ↓
继续 HTML

十二、但不要“所有 JS 都 defer”

又是一个很重要的思维。

例如某些必须在非常早期执行的代码：

文本

可能有特殊要求。

所以性能优化不是：

文本
全部 defer

而是：

文本
分析脚本用途
 ↓
是否阻塞首屏？
 ↓
是否必须立即执行？
 ↓
是否可以延迟？

    defer

{% endif %}

不过现代 Theme 开发也可以进一步采用模块化/按需加载，而不是大量模板条件判断。

核心思想只有一个：

用户不需要的 JS，不要让用户下载。

十四、CSS 也一样

例如你有：

现代 HTTP/2/HTTP/3 下，请求成本已经和过去不同。

所以真正目标不是：

而是：

发送给浏览器的资源应该尽量与当前页面需求匹配。

十五、CLS

第二个 Core Web Vital：

Cumulative Layout Shift

简单理解：

页面加载过程中，内容突然乱跳。

比如：

文本
开始：

┌──────────────┐
│ Product      │
│ Image        │
└──────────────┘

      ↓

图片加载完成

┌──────────────┐
│              │
│ Product      │
│ Image        │
└──────────────┘

页面下面的内容突然往下移动。

这就是 Layout Shift。

十六、图片是 CLS 的常见来源

例如：

html
<img src="product.jpg">

浏览器一开始不知道：

文本
图片最终多高？

于是：

文本

图片加载后：

文本
高度 = 600px

整个页面：

文本
↓
↓
↓

发生移动。

所以应该让浏览器提前知道尺寸。

例如：

html
<img
  src="product.jpg"
  width="800"
  height="800"
>

或者通过正确的 CSS aspect ratio。

Shopify 的 image_tag 会根据图片信息生成相关尺寸属性，这也是为什么通常应该优先使用 Shopify 的 Image Liquid filters，而不是自己手写原始 URL。
