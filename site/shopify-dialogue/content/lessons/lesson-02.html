我们一层一层拆。

1. Shopify 最底层：Platform

你可以把 Shopify 理解成一个已经帮你实现了大量电商基础设施的后端平台。

例如一家卖鞋子的 Shopify 商店：

文本
Shopify
│
├── Product
│    ├── Shoes A
│    ├── Shoes B
│    └── Shoes C
│
├── Customer
│    ├── Tom
│    ├── Jack
│    └── Alice
│
├── Order
│    ├── #1001
│    ├── #1002
│    └── #1003
│
├── Inventory
│
├── Discount
│
├── Shipping
│
├── Payment
│
└── Checkout

这部分不是你自己开发的。

这就是 Shopify 最大的价值。

如果你以前做传统电商：

文本
你自己
│
├── Node.js
├── MySQL
├── Redis
├── Payment
├── Order
├── Product
├── User
├── Inventory
└── Admin

Shopify 相当于：

这些基础设施已经有人帮你做好了。

你的公司只需要在它上面开发自己的业务。

2. Shopify Admin

然后是你以后工作中会经常看到的：

Shopify Admin

也就是商家后台。

例如：

文本
Shopify Admin
│
├── Products
├── Orders
├── Customers
├── Content
├── Analytics
├── Discounts
├── Marketing
├── Settings
└── Apps

商家可以在这里：

文本
创建商品
     ↓
上传商品图片
     ↓
设置价格
     ↓
设置库存
     ↓
设置商品描述

然后这些数据就存在 Shopify 平台里面。

例如：

文本
Product
{
    title: "Nike Air Max",
    price: 129.99,
    inventory: 100,
    ...
}

Theme 并不是 Product 数据的来源。

Theme 只是：

把 Shopify 里的数据展示出来。

这个区别非常重要。

3. Storefront

接下来是消费者看到的网站。

例如：

文本
https://example.com

这就是：

Storefront

也就是：

商店前台。

例如：

文本
Home
│
├── Banner
├── Featured Products
├── Collections
├── Reviews
└── Footer

用户进入：

文本
/products/nike-air-max

看到：

文本
┌────────────────────────────┐
│           Header           │
├────────────────────────────┤
│                            │
│    Product Image           │
│                            │
│    Nike Air Max            │

│                            │

│                            │
├────────────────────────────┤
│           Footer           │
└────────────────────────────┘

这个页面就是 Theme 在负责。

4. Theme 在整个系统中的位置

现在把它放进整个架构：

文本
Shopify Platform
       │
       │ Product data
       │ Collection data
       │ Page data
       ▼
     Theme
       │
       ├── Liquid
       ├── HTML
       ├── CSS
       └── JavaScript
       │
       ▼
   Storefront
       │
       ▼
     用户

所以：

Theme 本质上是 Shopify Storefront 的“UI 层”。

这句话建议你记住。

5. 那 Shopify App 是什么？

这里是第二个非常重要的概念。

很多新人会把：

文本
Theme
App

混在一起。

其实完全不是一回事。

Theme

主要解决：

“网站长什么样、用户怎么操作。”

例如：

  • Header
  • Banner
  • Product Card
  • Product Page
  • Cart
  • Search
  • Footer

App

主要解决：

“Shopify 原本没有的业务能力怎么办？”

例如你的公司想开发：

自动评论系统

文本
Shopify
    ↓
你的 Review App
    ↓
客户下单
    ↓
自动发送邮件
    ↓
邀请客户评论
    ↓
评论保存
    ↓
Storefront 显示

或者：

ERP 同步

文本
Shopify
    ↓
Your App
    ↓
ERP
    ↓
库存同步

或者：

AI 商品描述

文本
Shopify Admin
      ↓
你的 App
      ↓
AI
      ↓
生成商品描述
      ↓
写回 Shopify

这些就不是 Theme 的职责了。

6. Theme 和 App 的关系

你可以把它想成：

文本
                Shopify
                   │
        ┌──────────┴──────────┐
        │                     │
       Theme                 App
        │                     │
       UI                  Business Logic
        │                     │
    Storefront              API
        │                  Database
        │                  Webhook
        │                  OAuth
        ▼                     ▼
      用户                   商家

当然实际情况比这个复杂，但作为第一阶段的心智模型，这个非常好用。

7. 这里出现一个关键问题

假设产品页有一个按钮：

文本
[ Add to Cart ]

这个按钮到底是谁负责？

答案：

主要是 Theme + Shopify 的 Cart 能力。

例如 Theme 中：

文本

      ↓
Add to Cart
      ↓
Cart
      ↓
Checkout
      ↓
Payment

你通常不需要自己写：

文本

购物车数据库
支付系统

因为 Shopify 已经提供了。

8. 那 API 又在哪里？

现在我们引入第三个核心概念：

API

如果：

文本
Theme

是 Shopify Storefront 的 UI 层，

那么：

文本
API

就是你和 Shopify 平台进行程序化交互的通道。

例如：

文本
你的程序
   │
   │ API
   ▼
Shopify

你可以通过 API：

文本
查询商品
创建/修改商品
查询订单
查询客户
修改某些数据

等等。

9. Shopify API 不是只有一个

这也是以后非常容易混乱的地方。

先建立一个概念：

文本
Shopify APIs
│
├── Admin API
│
└── Storefront API

Admin API

主要面向：

商家 / 后台 / App

例如：

文本
Your App
    │
    │ Admin API
    ▼
Shopify Admin Data

你的 App 可能需要：

文本
获取商品
获取订单
修改商品
获取客户
创建 metafield

这时候通常考虑 Admin API。

10. Storefront API

而 Storefront API 更偏向：

消费者前台

例如你不想使用 Shopify Theme，而是自己做一个：

文本
Next.js

网站：

文本
Next.js
   │
   │ Storefront API
   ▼
Shopify

然后：

文本
Next.js
   ↓
获取商品
   ↓
显示商品
   ↓
加入购物车
   ↓
Checkout

这就是：

Headless Commerce

11. 什么叫 Headless？

这个概念你作为前端工程师一定会喜欢。

传统 Shopify：

文本
Shopify
   │
   ├── 数据
   ├── 电商逻辑
   └── Theme
          │
          ▼
      Storefront

而 Headless：

文本
Shopify
   │
   ├── Product
   ├── Customer
   ├── Order
   ├── Cart
   └── Checkout
          │
          │ API
          ▼
       Next.js
          │
          ▼
       Browser

也就是说：

Shopify 负责 Commerce，你负责 Frontend。

这就是 Headless。

14. Shopify 数据流

现在我们再深入一层。

这是非常重要的一张图。

假设运营人员在 Shopify Admin 创建商品：

文本
Shopify Admin
      │
      │ 创建 Product
      ▼
Shopify Platform
      │
      │ 保存 Product
      ▼
Product Data
      │
      │
      ▼
Theme
      │
      │ Liquid
      ▼
HTML
      │
      ▼
Browser

例如：

Admin：

文本
Product Title:
Nike Air Max

Price:
$129

Theme：

liquid
<h1>{{ product.title }}</h1>

<span>
  {{ product.price }}
</span>

最终浏览器：

html
<h1>Nike Air Max</h1>

<span>$129</span>

所以你以后看到：

liquid
{{ product.title }}

不要把它理解成：

“Liquid 有一个 product 变量。”

更准确的思考方式是：

Shopify 把当前商品的数据注入到 Theme 渲染上下文中，Liquid 用模板语法读取这些数据。

这就是 Shopify Theme 的核心。

15. 那 JavaScript 在哪里？

你可能会问：

“如果 Liquid 是服务端模板，那前端交互怎么办？”

答案：

JavaScript。

例如：

文本

        ↓
JavaScript
        ↓
Shopify Cart API
        ↓
Cart 更新
        ↓
页面更新

所以现代 Shopify Theme 实际上经常是：

文本
Liquid
+
HTML
+
CSS
+
JavaScript

并不是：

文本
只有 Liquid

这一点非常重要。

18. 再往后还有 Metafield

假设 Shopify 默认 Product 没有你想要的字段：

文本

├── Title

├── Description
└── ???

100% Cotton

USA

Machine Wash

这时候就可能使用：

可以暂时理解成：

所以：

       ├── country

这个以后也是 Shopify 开发非常重要的一部分。

19. 再往上还有 Metaobjects

如果 Metafield 是：

给某个对象增加自定义字段

那么 Metaobject 可以理解成：

让你创建一种自己的数据结构。

例如：

文本
Brand
│
├── Name
├── Logo
├── Description
└── Website

或者：

文本
FAQ
│
├── Question
└── Answer

这样你就开始发现：

Shopify 本身其实已经逐渐变成一个：

Commerce Platform + CMS + APIs + Extensibility Platform

而不只是“建个网店的网站”。

21. 一个非常重要的“职责划分表”

以后遇到需求，你可以先问自己：

文本

组合使用。
