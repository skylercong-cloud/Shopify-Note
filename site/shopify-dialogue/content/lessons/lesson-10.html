六、特别注意：Cart Line ≠ Variant

这里是 Shopify Theme 开发最容易混淆的地方之一。

假设：

文本
Product
└── T-Shirt

Variant
└── Black / M

Cart
└── Line Item
    ├── Variant: Black / M
    └── Quantity: 2

所以：

文本
Product
   ↓
Variant
   ↓
Cart Line

一个 Variant 在购物车中并不一定简单等于一个 Line。

例如同一个 Variant 如果具有不同的：

  • properties
  • selling plan
  • price 情况

可能形成不同的 line item。Shopify 官方文档也明确说明，相同商品在这些条件不同的情况下可能拆成不同 line items。Shopify

所以以后做 Cart Drawer：

不要简单地把 variant_id 当成整个 Cart Line 的唯一业务概念。

八、update.js

这个和 change.js 有一个非常重要的区别。

update.js 更适合：

一次批量更新多个购物车项目，或者同时更新 note / attributes / discount 等购物车信息。

例如：

js

  123456: 2,
  789012: 1
};

const response = await fetch(
  window.Shopify.routes.root + 'cart/update.js',
  {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json'
    },
    body: JSON.stringify({
      updates
    })
  }
);

const cart = await response.json();

也就是：

文本
Variant/Line Key A → 2
Variant/Line Key B → 1

一次提交。

Shopify 当前文档说明，updates 可以使用 line item's variant_id 或 key 作为 key；也可以使用数组按购物车 line 顺序更新。Shopify

ChatGPT 讲解09-19 21:03

这两个问题都问到了非常关键的地方。尤其第 2 个问题，实际上已经开始进入「Shopify 促销系统 / Functions / App」的范畴了。

1. Section Rendering 会不会导致整个页面刷新？

不会。恰恰相反，它就是为了避免整个页面刷新。

你可以把它理解成：

文本
传统页面刷新：

浏览器
  ↓
请求整个页面
  ↓
Shopify Server
  ↓
Liquid 渲染整个页面
  ↓
返回完整 HTML
  ↓
浏览器重新加载整个页面

而 Section Rendering 是：

文本
浏览器
  ↓
Ajax 请求
  ↓
Shopify Server
  ↓
只渲染指定 Section
  ↓
返回 Section HTML
  ↓
JavaScript 找到对应 DOM
  ↓
替换这一小块 DOM

官方文档明确说明，Section Rendering 可以通过 AJAX 请求指定 Sections，然后动态替换指定元素，而不会重新加载整个页面。ShopifyShopify

例如：

js
const response = await fetch(
  '/?sections=cart-drawer,cart-icon-bubble'
);

const sections = await response.json();

返回：

js
{
  "cart-drawer": "<div>...</div>",
  "cart-icon-bubble": "<div>...</div>"
}

然后：

js
document.querySelector('#CartDrawer').innerHTML =
  sections['cart-drawer'];

整个页面：

文本
Header       ← 不动
Product      ← 不动
Banner       ← 不动
Cart Drawer  ← 更新
Footer       ← 不动

所以你可以把它理解成：

Shopify Server 重新执行 Liquid，但是浏览器只替换你请求的那几个 Section，并不会刷新整个页面。

这其实是 Shopify Theme 很有意思的地方。

2. 活动页想让某个产品卖 $19.99，怎么办？

这个问题非常好，因为这里必须区分：

“前端显示一个价格”

和

“真正让客户以这个价格结账”

这是完全不同的两件事。

先看最重要的结论

假设 Shopify 后台：

文本
Product
└── T-Shirt
    └── Variant
        原价：$29.99

你的活动页想：

文本
活动价：$19.99

你不能简单地这样：

js
fetch('/cart/add.js', {
  body: JSON.stringify({
    items: [
      {
        id: variantId,
        quantity: 1,
        price: 1999
      }
    ]
  })
});

因为 Shopify Ajax Cart API 的 add.js 核心参数是 Variant ID 和 quantity；它并没有给 Theme 前端一个“任意指定售价”的 price 参数。官方文档列出的添加参数包括 variant、quantity，以及 line item properties 等。Shopify

而且这是必须限制的。

否则任何用户打开 DevTools：

js
price: 0.01

然后：

文本
$29.99
   ↓
$0.01

那整个电商系统就失控了。

所以：

不能相信浏览器传过来的“我要以多少钱购买”。

这就要看你的业务需求。

文本

这种情况下，真正进入 Cart 的就是一个价格为 $19.99 的 Variant。

这在业务规则比较简单的时候很好理解。

方案 D：Shopify Functions

这就是你这个问题真正值得重点学习的地方。

如果你的需求是：

“这个活动页上的某个商品，满足某种活动条件后，在 Cart 中变成特殊价格。”

那么你可能会进入：

Shopify Functions / Cart Transform / Discount Functions

这个层面。

当前 Shopify 的 Cart Transform API 可以通过 Function 修改购物车商品的价格和展示方式；官方文档明确把“promotion / special offer / price changes”列为相关使用场景。ShopifyShopify

最关键的一句话

你问的这个问题，本质上是在问：

“Shopify 的价格到底由谁决定？”

答案不是：

文本
浏览器 JS

文本
                Shopify
                   │

        └──────────┬──────────┘
                   ↓
                  Cart
                   ↓
               Final Price
                   ↓
                Checkout

浏览器可以展示价格、发起加购请求、携带活动上下文，但不能被当成可信的“最终价格来源”。
