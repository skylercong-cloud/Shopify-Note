这一课非常适合你，因为它会把你熟悉的前端概念：

URL

1. 先看完整流程

用户在搜索框输入：

文本
shirt

点击搜索后：

文本
/search?q=shirt
        ↓
Shopify
        ↓
Search Template
        ↓
search 对象
        ↓
search.results
        ↓
搜索结果
        ↓
Product Card

所以最核心的一句话：

Shopify Search 页面，本质上就是 Shopify 根据 URL 中的搜索关键词生成 search 对象，然后 Theme 把搜索结果渲染出来。

2. Search URL

Shopify 默认搜索 URL：

文本
/search?q=shirt

这里：

文本
search

是搜索页面。

而：

文本
q=shirt

是搜索关键词。

你作为 React 开发者，可以把它理解成：

js
const params = new URLSearchParams(
  window.location.search
);

const query = params.get('q');

得到：

文本
shirt

Shopify 则会把这个搜索请求转换成：

liquid
search.terms

3. Search 对象

进入：

文本
/search?q=shirt

Liquid 中就可以访问：

liquid
{{ search.terms }}

结果：

文本
shirt

然后：

liquid
{{ search.results_count }}

可以得到搜索结果数量。

还有：

liquid
search.performed

它可以帮助判断用户是否真的执行了搜索。

4. 第一个搜索页面

我们先写一个最基础版本：

liquid
<h1>
  Search
</h1>

{% if search.performed %}

  <p>
    Results for:
    "{{ search.terms }}"
  </p>

  {% if search.results_count > 0 %}

    <div class="search-results">

      {% for result in search.results %}

        <div class="search-result">

          <a href="{{ result.url }}">
            {{ result.title }}
          </a>

        </div>

      {% endfor %}

    </div>

  {% else %}

    <p>
      No results found.
    </p>

  {% endif %}

{% endif %}

5. search.results 是什么？

这里非常重要。

不要一看到：

liquid
search.results

就认为它一定是 Product。

它是：

Shopify 搜索返回的结果集合。

结果可能包含不同类型的资源。

例如：

文本
search.results
│
├── Product
├── Page
├── Article
└── Collection

具体搜索结果类型和可搜索内容会受到 Shopify 搜索配置、资源状态等影响。

所以你要建立这个概念：

文本
Search
   ↓
Results
   ↓
不同资源

6. 这和 Collection 有什么区别？

这是一个非常重要的区别。

Collection

文本
Collection
   ↓
明确的一组 Product

例如：

文本
Shoes
├── Nike
├── Adidas
└── New Balance

Search

文本
Search
   ↓
用户输入关键词
   ↓
Shopify 搜索
   ↓
返回匹配结果

例如：

文本
shirt
   ↓
T-Shirt
Shirt Jacket
Dress Shirt
Shirt Accessories
...

所以：

Collection 是“预先定义的一组商品”，Search 是“根据用户查询动态产生的结果”。

7. Search Result Card

实际项目中我们也不会把所有 HTML 都写在 Search Template。

例如：

文本
snippets/
├── product-card.liquid
└── search-result-card.liquid

Search：

liquid
{% for result in search.results %}

  {% render 'search-result-card',
    result: result
  %}

{% endfor %}

这样结构就非常清晰：

文本
Search Page
    ↓
Search Results
    ↓
Search Result Card

8. 如果结果是 Product

我们可以判断：

liquid
{% for result in search.results %}

  {% if result.object_type == 'product' %}

    {% render 'product-card',
      product: result
    %}

  {% endif %}

{% endfor %}

于是：

文本
Search
 ↓
Product Result
 ↓
Product Card

这样就可以复用我们上一课写的 Product Card。

9. Search Form

现在问题来了：

用户怎么输入搜索关键词？

Theme 通常会有 Search Form。

最简单可以理解成：

html
<form action="/search" method="get">

  <input
    type="search"
    name="q"
    placeholder="Search products"
  >

  <button type="submit">
    Search
  </button>

</form>

用户输入：

文本
shirt

提交之后：

文本
/search?q=shirt

Shopify 接下来处理搜索。

10. 这里你应该看到一个非常典型的 Web 模式

文本
Form
 ↓
GET
 ↓
URL Query
 ↓
Shopify
 ↓
Liquid

和普通 Web 开发完全一样。

React/Next.js 里：

文本
/search?q=shirt
        ↓
searchParams.q

Shopify Theme：

文本
/search?q=shirt
        ↓
search.terms

这个对应关系非常值得记。

11. Search Pagination

假设：

文本
搜索结果
100 个

当然不能一次全部渲染。

所以和 Collection 一样：

liquid
{% paginate search.results by 24 %}

  {% for result in search.results %}

    {% render 'search-result-card',
      result: result
    %}

  {% endfor %}

  {{ paginate | default_pagination }}

{% endpaginate %}

于是：

文本
/search?q=shirt

第一页。

第二页：

文本
/search?q=shirt&page=2

12. Search 和 Collection 的共同结构

现在把两个页面放在一起：

文本
Collection
   ↓
collection.products
   ↓
Pagination
   ↓
Product Card

Search：

文本
Search
   ↓
search.results
   ↓
Pagination
   ↓
Search Result Card

所以：

Collection 和 Search 的 Theme 开发模式非常相似。

13. 但是 Search 更复杂

因为：

文本
collection.products

基本就是 Product。

而：

文本
search.results

可能是不同资源类型。

所以实际项目通常会：

文本
search.results
      │
      ├── Product
      │     ↓
      │  Product Card
      │
      ├── Page
      │     ↓
      │  Page Card
      │
      └── Article
            ↓
        Article Card

这就是 Search 和 Collection 一个非常核心的区别。

14. Search Template

Theme 中通常有：

文本
templates/
└── search.json

它负责搜索页面的 Section 组合。

比如：

json
{
  "sections": {
    "main": {
      "type": "main-search"
    }
  },
  "order": [
    "main"
  ]
}

于是：

文本
/search?q=shirt
       ↓
search.json
       ↓
main-search.liquid
       ↓
search
       ↓
search.results

和 Collection 完全可以类比：

文本
Collection
 ↓
collection.json
 ↓
main-collection

Search：

文本
Search
 ↓
search.json
 ↓
main-search

16. Search Input 和 Predictive Search

这里开始进入下一阶段。

普通 Search：

文本
用户输入
   ↓
点击 Search
   ↓
/search?q=shirt
   ↓
完整页面加载

Predictive Search：

文本
用户输入：

s
 ↓
sh
 ↓
shi
 ↓
shir
 ↓
shirt

每输入一次
      ↓
请求 Shopify
      ↓
返回预测结果
      ↓
更新下拉框

例如：

文本
┌───────────────────────────┐
│ shirt                     │
├───────────────────────────┤
│ Products                  │
│                           │
│ 👕 Classic T-Shirt  $29   │
│ 👕 Oversized Shirt $39    │
│                           │
│ Collections               │
│                           │
│ Shirts                    │
│                           │
│ Search for "shirt" →      │
└───────────────────────────┘

这个就是我们下一课要学的：

Predictive Search

17. 为什么 Predictive Search 对你很重要？

因为它第一次真正把 Shopify Theme 里的：

文本
Liquid
+
JavaScript
+
Shopify API

组合起来。

传统 Search：

文本
HTML Form
 ↓
GET /search
 ↓
Shopify
 ↓
Liquid

Predictive Search：

文本
JavaScript
 ↓
请求 Shopify
 ↓
JSON
 ↓
JavaScript
 ↓
DOM

这就更接近你熟悉的 React 前端开发。

18. 你现在应该掌握的核心知识

这一课先记住下面这张表：

概念 作用
/search Search 页面
q 搜索关键词 URL 参数
search 当前搜索对象
search.terms 搜索关键词
search.results 搜索结果
search.results_count 结果数量
search.performed 是否执行过搜索
search.json Search Template
paginate 搜索结果分页
