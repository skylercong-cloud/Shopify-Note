这一课非常重要，因为你以后做 Shopify App、ERP、仓储系统、订单系统、跨境电商库存同步，都会遇到它。

你先记住一条核心关系：

文本
Product
   ↓
Variant
   ↓
InventoryItem
   ↓
InventoryLevel
   ↓
Location

但这里有一个容易误解的地方：

库存数量并不是直接挂在 Variant 上的。

Shopify 把「商品规格」和「库存管理」拆成了不同的数据对象。

一、先建立整体模型

假设我们卖：

文本
Nike Air Max

有两个 Variant：

文本
Black / 9
Black / 10

其中：

文本
Black / 9

是一个真正可以购买的具体 SKU。

现在公司有三个仓库：

文本
San Jose Warehouse
Los Angeles Warehouse
New York Warehouse

库存可能是：

文本
Nike Air Max
└── Black / 9
      │
      ↓
   InventoryItem
      │
      ├── San Jose      → 20
      ├── Los Angeles   → 15
      └── New York      → 8

这里：

  • Variant：卖的是什么规格
  • InventoryItem：这个 Variant 对应的库存管理对象
  • Location：库存在哪里
  • InventoryLevel：这个库存商品在这个地点有多少库存

Shopify 官方当前的 GraphQL Admin API 也是这样建模的：InventoryItem 连接一个 Variant 与它在不同 Location 的库存，而 InventoryLevel 连接一个 InventoryItem 和一个 Location。ShopifyShopify

二、Variant 和 InventoryItem 为什么要分开？

这是理解 Shopify 数据模型的关键。

你可能会想：

文本
Variant
  id
  sku
  price
  inventory

为什么不直接这样？

因为：

Variant 描述的是「卖什么」，InventoryItem 描述的是「怎么管理这个东西的库存」。

例如：

文本
Variant
----------------
Black / 9
SKU: NK-001-BK-9
Price: $129

对应：

文本
InventoryItem
----------------
SKU: NK-001-BK-9
tracked: true
shipping information
customs information
inventory history
...

而 InventoryItem 还可以继续关联多个库存地点。

官方当前定义中，InventoryItem 是一个 Variant 的库存信息，并且可以通过 inventoryLevels 查看这个商品在不同 Location 的库存。Shopify

三、InventoryLevel 才是真正的「地点库存」

这个概念一定要理解。

假设：

文本
InventoryItem
    =
Nike Air Max Black / 9

它有：

文本
Location A
San Jose

和：

文本
Location B
Los Angeles

那么实际上存在：

文本
InventoryLevel #1
InventoryItem + San Jose
available = 20

InventoryLevel #2
InventoryItem + Los Angeles
available = 15

所以可以把 InventoryLevel 理解成：

某个库存商品，在某个地点的库存记录。

官方文档也是这么定义的：一个 InventoryLevel 将一个 InventoryItem 与一个 Location 连接起来，并记录该地点的各种库存状态。Shopify

四、Location 是什么？

Location 不只是「仓库」。

它可以代表：

文本
Warehouse
Retail Store
Popup Store
Fulfillment Center
Dropshipper

也就是说，它代表一个 Shopify 中进行库存管理/履约的地点。

例如：

文本
Locations
├── San Jose Warehouse
├── Los Angeles Warehouse
├── New York Store
└── Shopify Fulfillment Network

官方当前文档也明确把 Location 描述为可以存储和履行库存的实体，例如仓库、零售店、popup、dropshipper 等。Shopify

五、所以四个对象到底是什么关系？

我们把它画完整：

文本
Product
│
├── Variant A
│      │
│      └── InventoryItem A
│             │
│             ├── InventoryLevel
│             │       └── San Jose
│             │              available: 20
│             │
│             ├── InventoryLevel
│             │       └── Los Angeles
│             │              available: 15
│             │
│             └── InventoryLevel
│                     └── New York
│                            available: 8
│
└── Variant B
       │
       └── InventoryItem B
              │
              ├── San Jose
              ├── Los Angeles
              └── New York

所以：

文本
Product
   1
   │
   └── N Variants
             │
             └── 1 InventoryItem
                       │
                       └── N InventoryLevels
                                  │
                                  └── 1 Location

你是前端开发，所以可以直接用数据库思维理解。

假设自己设计数据库：

文本
products
---------
id
title

----------------
id

然后：

文本

---------------
id

sku

再：

文本

---------
id

最后：

文本

文本

                                  │

这个模型就非常接近 Shopify 的思维。

七、为什么一个 Variant 可以有多个库存？

这就是 Shopify 多仓库能力的基础。

例如：

文本
Variant:
Nike Air Max / Black / 9

库存：

Location Available
San Jose 20
Los Angeles 15
New York 8

那么这个 Variant 并不是：

文本
inventory = 43

这么简单。

Shopify 更关心：

文本
San Jose → 20
Los Angeles → 15
New York → 8

因为订单履约时必须知道：

这件商品到底从哪个 Location 发货？

Location 不只是库存数字的容器，它还参与订单履约能力和在线订单配置。Shopify

八、一个特别容易踩坑的地方：available ≠ on_hand

现在进入稍微高级一点的部分。

现代 Shopify Inventory 不只有一个简单的：

文本
quantity

而是存在多个库存状态。

当前 Admin GraphQL API 的 InventoryLevel.quantities 可以查询例如：

文本
available
incoming
committed
on_hand
reserved
damaged
quality_control
safety_stock

具体可用的状态取决于 Shopify 当前 API 版本和场景。Shopify

例如：

文本
San Jose Warehouse

on_hand       = 100
committed     = 20
reserved      = 10
available     = 70

你可以先用非常简单的方式理解：

文本
on_hand
↓
物理上手里的库存

committed
↓
已经被订单等流程占用的库存

available
↓
当前可供销售/分配的库存

所以：

文本
on_hand ≠ available

这也是为什么我们之前说：

liquid
variant.available

不能理解成：

文本
库存数量 = X

它更接近：

这个 Variant 当前是否可购买/可售。

九、为什么 variant.available 不等于库存？

例如：

文本
Variant
Black / 9

Inventory:
San Jose = 0
Los Angeles = 0
New York = 5

如果这个商品可以从 New York 发货：

文本
variant.available
=
true

但你不能从：

liquid
{{ variant.available }}

得到：

文本
5

因为：

文本
available

是一个布尔状态，而不是库存数量。

真正详细的库存数据属于 Inventory 模型。

十、Theme 和 Inventory 的职责边界

这也是 Theme 学习中非常重要的一条。

Theme

主要负责：

文本
显示
↓
商品
Variant
价格
库存可售状态

例如：

liquid
{% if product.selected_or_first_available_variant.available %}
  <button>Add to cart</button>
{% else %}
  <button disabled>
    Sold out
  </button>
{% endif %}

Theme 的职责主要是：

把 Shopify 的库存/可售状态展示给消费者。

App / Admin API

如果你要：

文本
查询仓库库存
修改库存
同步 ERP
同步 WMS
库存预警
批量调整库存
库存同步

那就属于：

文本
Shopify App
      ↓
Admin GraphQL API
      ↓
Inventory

而不是 Theme。

例如：

文本
ERP
 ↓
App
 ↓
Shopify Admin API
 ↓
InventoryItem
 ↓
InventoryLevel
 ↓
Location

十二、GraphQL 里大概是什么感觉？

例如我们想查询某个 InventoryLevel：

graphql
query {
  inventoryLevel(id: "...") {
    id

    quantities(names: [
      "available",
      "on_hand",
      "committed"
    ]) {
      name
      quantity
    }

    item {
      id
      sku
    }

    location {
      id
      name
    }
  }
}

结果概念上类似：

json
{
  "inventoryLevel": {
    "id": "...",
    "quantities": [
      {
        "name": "available",
        "quantity": 70
      },
      {
        "name": "on_hand",
        "quantity": 100
      },
      {
        "name": "committed",
        "quantity": 20
      }
    ],
    "item": {
      "id": "...",
      "sku": "NK-001-BK-9"
    },
    "location": {
      "id": "...",
      "name": "San Jose Warehouse"
    }
  }
}

这正是 Shopify 当前 Admin GraphQL API 的数据关系：InventoryLevel → InventoryItem + Location + quantities。Shopify

十三、从 React 开发者角度类比

你可以把它想象成：

js
const product = {
  title: 'Nike Air Max',

  variants: [
    {
      id: 'variant-1',
      title: 'Black / 9',
      price: 129,

      inventoryItem: {
        id: 'inventory-item-1',

        levels: [
          {
            location: 'San Jose',
            available: 20
          },
          {
            location: 'Los Angeles',
            available: 15
          },
          {
            location: 'New York',
            available: 8
          }
        ]
      }
    }
  ]
};

然后：

js
const variant = product.variants[0];

const available =
  variant.inventoryItem.levels
    .reduce(
      (total, level) => total + level.available,
      0
    );

但注意：

这只是帮助理解数据关系的伪代码，不代表 Shopify Theme 中可以直接这么访问。

因为 Theme Liquid、Storefront 数据和 Admin GraphQL 数据是不同层次。
