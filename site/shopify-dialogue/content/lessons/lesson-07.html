好，我们按计划继续。前面你刚好把 Product → Variant → Cart → Checkout 这条链路问透了，所以现在进入下一课非常合适。

这一课我们暂时不急着做完整 Cart Drawer，先把商品详情页最核心的一段彻底搞明白：

用户选择 Color / Size → 找到对应 Variant → 更新价格/图片/库存 → 拿到 Variant ID → 为加购做准备。

这其实是 Shopify Theme 前端开发里非常核心的一块。

三、第一步：Liquid 把 Variants 输出给前端

商品页面里，我们可以先把所有 Variant 输出出来。

例如：

liquid
<script type="application/json" id="ProductJSON">
  {{ product.variants | json }}
</script>

假设 Shopify 商品有：

文本
Black / S
Black / M
Black / L
White / S
White / M
White / L

浏览器拿到的 JSON 可以理解成：

json
[
  {
    "id": 101,
    "title": "Black / S",
    "options": ["Black", "S"],
    "available": true,
    "price": 2999
  },
  {
    "id": 102,
    "title": "Black / M",
    "options": ["Black", "M"],
    "available": true,
    "price": 2999
  }
]

这里我继续用简化后的结构帮助你理解。

真正开发时，你应该以 Shopify 实际返回的数据结构为准。

四、第二步：渲染 Option Selector

Liquid 可以根据：

liquid
product.options_with_values

生成选择器。

例如：

liquid
{% for option in product.options_with_values %}

  <div class="product-option">
    <p>{{ option.name }}</p>

    {% for value in option.values %}
      <button
        type="button"
        data-option-value="{{ value }}"
      >
        {{ value }}
      </button>
    {% endfor %}

  </div>

{% endfor %}

最终可能生成：

文本
Color

[ Black ] [ White ]


Size

[ S ] [ M ] [ L ]

这里非常值得你注意：

Liquid 负责“生成选择器”

而：

JavaScript 负责“用户选择之后发生什么”。

这就是我们之前反复强调的：

文本
Liquid
=
Server-side rendering

JavaScript
=
Browser interaction

六、第四步：根据选择寻找 Variant

假设：

javascript
variants = [
  {
    id: 101,
    options: ['Black', 'S']
  },
  {
    id: 102,
    options: ['Black', 'M']
  },
  {
    id: 103,
    options: ['Black', 'L']
  },
  {
    id: 104,
    options: ['White', 'S']
  },
  {
    id: 105,
    options: ['White', 'M']
  }
];

用户选择：

文本
Black
M

我们需要找到：

文本
['Black', 'M']

对应的 Variant：

文本
id = 102

JS 可以这样理解：

javascript
const selected = ['Black', 'M'];

const variant = variants.find(variant => {
  return variant.options.every(
    (value, index) => value === selected[index]
  );
});

然后：

javascript
console.log(variant.id);

得到：

文本
102

七、这一步是整个 Variant Selector 的灵魂

你一定要理解：

文本
用户选择

Color = Black
Size = M

        ↓

['Black', 'M']

        ↓

遍历 product.variants

        ↓

找到

Black / M

        ↓

Variant ID = 102

所以：

Variant Selector 本质上就是一个“根据用户选择找到 Variant”的匹配系统。

这才开始有意思。

假设找到：

  id: 102,
  price: 2999,
  available: true,
  featured_image: ...

① 更新价格

文本

$29.99

如果用户选择：

文本

文本

JS：

javascript
priceElement.textContent = formatMoney(
  variant.price
);

九、② 更新库存状态

比如：

javascript
variant.available

如果：

javascript
variant.available === true

显示：

文本

如果：

javascript

显示：

所以：

   │

十三、为什么我们不能只用 product.selected_or_first_available_variant？

这是 Shopify Liquid 里面一个很容易遇到的概念。

你可能看到：

liquid
{{ product.selected_or_first_available_variant.id }}

它非常有用。

它可以帮助你获取：

当前选中的 Variant，或者默认第一个可购买 Variant。

例如：

liquid
<input
  type="hidden"
  name="id"
  value="{{ product.selected_or_first_available_variant.id }}"
>

这对于 Product Form 特别有用。

但是注意：

用户在浏览器里改变 Color / Size 后，Liquid 不会重新执行。

因为 Liquid 是服务器端渲染。

所以：

文本
第一次打开页面
       ↓
Liquid
       ↓
HTML

之后用户：

文本
Black → White

浏览器里发生的事情需要：

文本
JavaScript

来处理。

这就是为什么 Variant Selector 通常是：

文本
Liquid + JavaScript

而不是只用 Liquid。

十四、这里你应该再次建立 Shopify 的“两个世界”

这是 Shopify Theme 开发最重要的思维之一。

页面第一次打开

 ↓
Liquid
 ↓
HTML
 ↓
Browser

Liquid 可以：

文本
product
product.variants
product.options
product.featured_image

用户操作以后

文本
Browser
 ↓
JavaScript
 ↓
DOM
 ↓
Shopify API

比如：

文本

       ↓
JavaScript
       ↓
找到 Variant
       ↓
更新价格
       ↓
用户点击 Add to Cart
       ↓
Cart API

所以：

Liquid 负责把 Shopify 数据带到浏览器，JavaScript 负责用户交互。
