一、先理解 Predictive Search 是什么

普通搜索是：

文本
用户输入 shirt
       ↓
点击搜索
       ↓
/search?q=shirt
       ↓
完整搜索页面

Predictive Search 是：

文本
用户输入 s
       ↓
立即请求
       ↓
显示预测结果

用户输入 sh
       ↓
再次请求
       ↓
更新预测结果

用户输入 shi
       ↓
再次请求
       ↓
更新预测结果

最终：

文本
┌──────────────────────────────┐
│ shi                          │
├──────────────────────────────┤
│ Products                     │
│                              │
│ 👕 Classic T-Shirt     $29   │
│ 👕 Oversized Shirt     $39   │
│ 👕 Shirt Jacket        $59   │
│                              │
│ Collections                  │
│                              │
│ Shirts                       │
│                              │

这就是 Predictive Search。

四、Predictive Search 的核心 API

Shopify 提供 Predictive Search API。

我们先记住它的基本请求思想：

文本
/search/suggest.json?q=shirt

你可以把它理解成：

文本
/search

是完整搜索页面。

而：

文本
/search/suggest.json

是：

给 JavaScript 使用的预测搜索接口。

五、最简单的 fetch

JavaScript：

js
const query = 'shirt';

const response = await fetch(
  `/search/suggest.json?q=${encodeURIComponent(query)}`
);

const data = await response.json();

console.log(data);

这里你应该注意：

js
encodeURIComponent(query)

不要直接把用户输入拼接进 URL。

例如用户输入：

文本
red shirt & shoes

需要正确编码。

六、URL 构造

实际 Theme 中更推荐考虑 Shopify 的 locale 路径。

我们之前已经讲过：

js
window.Shopify.routes.root

所以可以构造：

js
const url =
  `${window.Shopify.routes.root}search/suggest.json?q=${encodeURIComponent(query)}`;

例如：

文本
window.Shopify.routes.root
        ↓
/
        ↓
/search/suggest.json?q=shirt

如果商店存在语言路径，则根路径也可以随商店环境变化。

十、什么是 Debounce？

假设用户输入：

文本
s

等待。

又输入：

文本
sh

重新等待。

又输入：

文本
shi

重新等待。

只有用户停止输入一小段时间：

文本
shi
   ↓
300ms 没有继续输入
   ↓
发送请求

React 里你肯定见过类似：

js
setTimeout
clearTimeout

十一、自己实现一个 debounce

js
let timer;

input.addEventListener('input', () => {

  clearTimeout(timer);

  timer = setTimeout(() => {

    search(input.value.trim());

  }, 300);

});

然后：

js
async function search(query) {

  if (!query) {
    results.innerHTML = '';
    return;
  }

  const url =
    `${window.Shopify.routes.root}search/suggest.json?q=${encodeURIComponent(query)}`;

  const response = await fetch(url);

  const data = await response.json();

  console.log(data);
}

现在：

文本
输入
 ↓
clearTimeout
 ↓
等待 300ms
 ↓
search()

十三、但不要马上大量使用 innerHTML

为什么？

因为你需要考虑：

  • HTML 转义
  • 用户输入
  • 数据来源
  • XSS
  • DOM 性能
  • 可维护性

对于 Shopify 返回的数据，官方提供的预测搜索响应结构和 Theme API 用法应以当前 Shopify 文档为准；生产项目里不要把任意未处理字符串直接拼进 HTML。

你可以先把：

理解成：

 ↓

而不是急着写复杂 DOM。

二十、AbortController

前端常见解决方法：

js
let controller = null;

async function search(query) {

  if (controller) {
    controller.abort();
  }

  controller = new AbortController();

  const url =
    `${window.Shopify.routes.root}search/suggest.json?q=${encodeURIComponent(query)}`;

  const response = await fetch(url, {
    signal: controller.signal
  });

  const data = await response.json();

  return data;
}

流程：

文本
用户输入 shirt
      ↓
Request A

用户马上输入 shoes
      ↓
Abort Request A
      ↓
Request B
      ↓
显示 shoes

这就是你作为前端开发者非常应该掌握的生产级思维。

二十三、今天最重要的 8 个知识点

记住这几个：

文本
① Predictive Search ≠ Full Search

② Predictive Search 主要是异步请求

③ /search/suggest.json 是预测搜索接口

④ JavaScript 负责请求和 UI 更新

⑤ Debounce 减少请求

⑥ AbortController 处理请求竞态

⑦ search.results 和预测搜索结果都不是简单等同于 Product

⑧ Search UI = Input + API + Rendering + Keyboard Interaction
