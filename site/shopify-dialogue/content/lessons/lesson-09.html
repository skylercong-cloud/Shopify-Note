三、Cart Item 和 Product 不一样

这里特别容易搞混。

你之前学的是：

文本

Variant

现在又出现：

三者关系：

文本

   ↓

   ↓
Cart Line Item

例如：

文本

所以在 Cart 里：

liquid

得到 Product。

而：

liquid

得到当前购买的 Variant。

七、数量 + / - 的真正流程

例如：

文本

八、/cart/change.js

它的用途就是：

修改 Cart 中某个商品的数量。

概念：

javascript
fetch('/cart/change.js', {
  method: 'POST',
  ...
});

请求数据：

javascript
{
  line: 1,
  quantity: 2
}

意思：

文本
Cart 的第 1 个 Line
数量修改为 2

不过真实开发时你需要非常注意：

不要简单把 line 当成一个永久稳定的商品 ID。

Cart 的顺序、内容会变化，所以实现时应该根据 Shopify 当前 Cart 数据和主题架构来正确维护 line/item 标识。

九、例如点击 +

javascript
async function changeQuantity(line, quantity) {

  const response = await fetch('/cart/change.js', {
    method: 'POST',

    headers: {
      'Content-Type': 'application/json'
    },

    body: JSON.stringify({
      line,
      quantity
    })
  });

  const cart = await response.json();

  console.log(cart);
}

调用：

javascript
changeQuantity(1, 2);

意思：

文本
第 1 个 Line
数量变成 2

十、删除商品其实也是 Change API

也就是说：

二十一、一个非常重要的工程问题：Loading

真实项目里，用户点击：

文本
+

到 Shopify 返回结果之间存在网络延迟。

所以不要让用户：

文本
+ + + + + +

疯狂点击。

通常需要：

文本
点击 +
 ↓
Button disabled
 ↓
Loading
 ↓
API
 ↓
更新 UI
 ↓
恢复

例如：

javascript
button.disabled = true;

try {
  await changeQuantity(line, quantity);
} finally {
  button.disabled = false;
}

这就是普通前端工程经验，在 Shopify Theme 里同样适用。

二十二、Error 也要处理

比如：

就一定成功。

至少应该：

javascript

  // 显示错误

文本

这也是 Shopify Theme 和普通前端工程一样需要考虑的地方。
