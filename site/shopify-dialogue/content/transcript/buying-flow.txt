作为前端开发，你可以先这样理解：

| Shopify | 类比前端 |

| Product | 商品模型 |
| Variant | 真正可购买的 SKU |
| Cart | 前端购物车状态 + Shopify 服务端购物车 |
| Checkout | 订单结算流程 |
| Order | 最终生成的订单 |
| Cart Drawer | Shopping Cart Modal / Drawer |

最重要的一条：

```text

   ↓
```

# 二、什么是「加入购物车」？

最简单理解：

> **Add to Cart = 把某个 Variant 放进当前 Cart。**

比如用户在商品页：

```text
Classic T-Shirt

Color:
○ Black
● White

Size:
○ S
● M
○ L

$29.99

[ Add to Cart ]
[ Buy It Now ]
```

用户选择：

```text
White
M
```

前端首先需要找到：

```text
White / M
↓
Variant ID
↓
123456789
```

然后调用 Shopify 的 Cart API。

概念上类似：

```javascript
fetch('/cart/add.js', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    items: [
      {
        id: 123456789,
        quantity: 1
      }
    ]
  })
})
```

这里最关键的是：

```javascript
id: 123456789
```

这个不是 Product ID。

而是：

> **Variant ID**

这也是为什么我们前面一直强调：

```text
Product ≠ Variant
```

真正加入购物车的是 **Variant**。

# 五、Shopify Cart Drawer 的完整流程

这是你以后写 Shopify Theme 时非常重要的一条链路。

```text
用户点击 Add to Cart
        ↓
获取 Variant ID
        ↓
JavaScript
        ↓
POST /cart/add.js
        ↓
Shopify Cart
        ↓
返回 Cart 数据
        ↓
更新 Cart Drawer
        ↓
Drawer 打开
```

例如：

```javascript
async function addToCart(variantId) {
  const response = await fetch('/cart/add.js', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json'
    },
    body: JSON.stringify({
      items: [
        {
          id: variantId,
          quantity: 1
        }
      ]
    })
  });

  const data = await response.json();

  console.log(data);

  openCartDrawer();
}
```

你可以把它理解成：

```text
React：

setCart(...)
setCartDrawerOpen(true)

Shopify：

fetch('/cart/add.js')
       ↓
Shopify Cart
       ↓
更新 DOM
       ↓
打开 Drawer
```

# 七、Buy It Now / 立即购买

立即购买的核心思想是：

```text
选择 Variant
      ↓
Buy It Now
      ↓
Checkout
```

也就是：

```text
Product
   ↓
Variant
   ↓
Checkout
```

而不是：

```text
Product
   ↓
Variant
   ↓
Cart
   ↓
Checkout
```

所以从用户体验上：

```text
Add to Cart

商品
 ↓
购物车
 ↓
继续购物
 ↓
Checkout
```

而：

```text
Buy It Now

商品
 ↓
Checkout
```

# 八、为什么 Shopify 有时候“立即购买”看起来又不一样？

这里需要注意一个非常重要的 Shopify 概念：

> **动态结账按钮 / Dynamic Checkout Button**

例如商品页可能出现：

```text
[ Add to Cart ]

[ Buy it now ]
```

这个按钮并不一定是你自己写：

```html
<button>
  Buy it now
</button>
```

Shopify Theme 可以使用 Shopify 提供的动态结账按钮机制。

它会根据：

- 商品
- 商店配置
- 支付方式
- 用户环境
- 可用的 accelerated checkout

决定具体显示什么。

例如可能出现：

```text
Buy it now
```

或者：

```text
Shop Pay
```

以及其他支持的 accelerated checkout 方式。

所以你以后开发 Shopify 商品页时，要区分：

```text
普通 Add to Cart
```

和：

```text
Dynamic / Accelerated Checkout
```

这两个概念。

```text

```

```text

$5
```



# 十五、一个很重要的坑：不要自己实现 Checkout

作为 Shopify 新手，这一点你一定要记住：

> **Theme 开发时，一般不要自己从零开发支付页面。**

也就是说，不要想着：

```text
React / Liquid

自己做：
姓名
地址
信用卡
CVV
支付
```

然后自己：

```text
POST payment
```

这不是 Shopify Theme 正常的开发方式。

通常是：

```text
Theme
 ↓
Cart
 ↓
Shopify Checkout
 ↓
Payment
 ↓
Order
```

Checkout 是 Shopify Commerce 核心能力的一部分。

如果业务需要定制 Checkout，现在 Shopify 主要通过：

```text
Checkout Extensibility
```

等扩展机制进行，而不是随便修改一个 checkout HTML 页面。

## 1. 加购：除了 Ajax API，Shopify 确实提供现成的 Product Form

**是的。**

Shopify Theme 官方就提供了：

```liquid
{% form 'product', product %}
  ...
  <input type="submit" value="Add to cart">
{% endform %}
```

这个 `product` form 是 Shopify 推荐的商品加购基础方式，它里面可以放：

- Variant selector
- Quantity
- Line item properties
- Add to Cart
- Accelerated checkout button

官方文档也明确把 Product Form 定义为商品 Variant 加入购物车的主要方式。 [product](https://shopify.dev/docs/storefronts/themes/architecture/templates/product/overview?utm_source=chatgpt.com)

例如：

```liquid
{% form 'product', product %}

  <select name="id">
    {% for variant in product.variants %}
      <option value="{{ variant.id }}">
        {{ variant.title }}
      </option>
    {% endfor %}
  </select>

  <input
    type="number"
    name="quantity"
    value="1"
  >

  <button type="submit">
    Add to Cart
  </button>

{% endform %}
```

这里你可以注意：

```html
<select name="id">
```

选择的是：

> **Variant ID**

提交这个 Form，就可以完成商品加入 Cart。

### 那 Ajax API 是干嘛的？

如果你希望：

```text
点击 Add to Cart
       ↓
页面不刷新
       ↓
购物车数量更新
       ↓
Cart Drawer 打开
```

那么通常会使用 Ajax Cart API。

例如：

```javascript
fetch('/cart/add.js', {
  method: 'POST',
  ...
})
```

Shopify 官方 Ajax Cart API 就是专门提供：

- add
- change
- update
- clear

等 Cart 操作的。 [About the Shopify Ajax API](https://shopify.dev/docs/api/ajax?utm_source=chatgpt.com) [Cart API reference](https://shopify.dev/docs/api/ajax/reference/cart?utm_source=chatgpt.com)

所以可以这样理解：

```text
                 加购
                  │
        ┌─────────┴─────────┐
        ↓                   ↓
 Product Form           Ajax Cart API
        │                   │
   Shopify标准方式       自定义交互
        │                   │
   页面可能跳转          无刷新体验
```

### 对你来说非常重要

你以后写 Theme，不是：

> “Shopify 没有加购功能，我自己开发一个。”

而是：

> **Shopify 已经提供 Cart 能力，我决定采用 Form 还是 Ajax API，以及怎么做 UI。**

# 2. Cart Drawer：这个就和你想象的不太一样

这里是最容易产生误解的地方。

## Shopify Theme 并不是给你一个“所有主题通用的 Cart Drawer UI”

也就是说，并不存在一个简单的：

```liquid
<ShopifyCartDrawer />
```

然后 Shopify 自动给你一个漂亮的购物车弹窗。

**传统 Liquid Theme 开发里，Cart Drawer 通常是 Theme 自己实现的 UI。**

比如 Dawn 这样的 Shopify Theme，本身就有自己的 Cart Drawer、Cart Items、Cart Footer 等 Theme 代码。

Shopify 官方的 Theme 架构也明确说明：

> Theme 的功能可以通过 Liquid、CSS、JavaScript、sections、snippets 等实现。 [Theme architecture](https://shopify.dev/docs/storefronts/themes/architecture?utm_source=chatgpt.com)

所以你通常会看到类似：

```text
sections/
    cart-drawer.liquid

snippets/
    cart-drawer-item.liquid

assets/
    cart-drawer.js
```

然后：

```text
Cart Drawer
      │
      ├── HTML/Liquid
      ├── CSS
      └── JavaScript
```

---

# 3. 那 Cart Drawer 的数据是不是也要自己获取？

**对。**

但不是说 Shopify 没有能力。

而是：

> **Shopify 提供 Cart 数据 API，你的 Theme 决定怎么把这些数据展示成 Drawer。**

比如：

```text
点击 Add to Cart
        ↓
POST /cart/add.js
        ↓
Shopify Cart 更新
        ↓
返回数据
        ↓
更新 Cart Drawer
```

你可以自己：

```javascript
fetch('/cart.js')
```

查询 Cart。

也可以：

```javascript
fetch('/cart/change.js')
```

修改某个 Cart Item 数量。

或者：

```javascript
fetch('/cart/update.js')
```

更新 Cart。

这些都是 Shopify Ajax Cart API 提供的。 [Cart API reference](https://shopify.dev/docs/api/ajax/reference/cart?utm_source=chatgpt.com)

---

# 4. 但是 Shopify 现在还有一个很重要的能力：Section Rendering

这对 Theme 开发非常重要。

假设：

```text
Cart Drawer
```

里面有：

```text
商品
数量
Subtotal
Cart 数量 Bubble
Checkout 按钮
```

你不一定要：

```javascript
fetch('/cart.js')
        ↓
拿 JSON
        ↓
自己拼 HTML
        ↓
innerHTML = ...
```

Shopify 的 Ajax Cart API 支持请求相关 Sections 的渲染结果。官方文档明确支持在 Cart API 请求中传 `sections` 参数。 [Cart API reference](https://shopify.dev/docs/api/ajax/reference/cart?utm_source=chatgpt.com)

例如概念上：

```javascript
fetch('/cart/add.js', {
  method: 'POST',
  body: ...
})
```

同时请求：

```text
cart-drawer
cart-icon-bubble
cart-footer
```

然后 Shopify 帮你根据 Liquid：

```text
cart-drawer.liquid
cart-icon-bubble.liquid
cart-footer.liquid
```

重新渲染 HTML。

于是变成：

```text
JavaScript
     ↓
Cart API
     ↓
Shopify
     ↓
Liquid Section Render
     ↓
HTML
     ↓
替换页面 DOM
```

这个模式对于 Shopify Theme 非常重要。

---

# 5. 所以 Cart Drawer 到底谁负责？

可以这样记：

| 部分 | 谁负责 |
|---|---|
| Cart 数据 | Shopify |
| Add / Change / Update | Shopify Cart API |
| Cart Drawer UI | **Theme 开发者** |
| Drawer 样式 | **Theme 开发者** |
| Drawer 打开/关闭 | **Theme JS** |
| Cart HTML | Liquid / Section |
| Cart 数据刷新 | Ajax Cart API |
| 局部 HTML 更新 | Section Rendering API |

所以：

> **Shopify 提供购物车“大脑”，Theme 开发者负责购物车“脸和交互”。**

# 6. 不过现在 Shopify 也有一个新的例外

目前 Shopify 还提供了 **Storefront Web Components**，其中有 `shopify-cart` component，可以提供 mini shopping cart 能力，并支持通过组件方法添加商品、展示 Cart，以及进行样式定制。 [shopify-cart](https://shopify.dev/docs/api/storefront-web-components/components/shopify-cart?utm_source=chatgpt.com) [Common patterns](https://shopify.dev/docs/api/storefront-web-components/common-patterns?utm_source=chatgpt.com)

但是你现在是在学习：

> **传统 Shopify Liquid Theme 开发**

所以现阶段我建议你先把它理解成：

```text
传统 Theme：

Shopify Cart API
       +
Liquid
       +
JavaScript
       +
CSS
       ↓
自己实现 Cart Drawer
```

这个才是你以后实际维护 Theme 时最常遇到的模式。

# 7. 第三个问题：Checkout

你这个理解也是：

> **基本正确。**

而且这里 Shopify 和普通电商系统最大的区别之一就在这里。

你一般**不需要自己开发支付结算系统**。

正常 Shopify Theme：

```text
Cart
 ↓
Checkout
 ↓
Payment
 ↓
Order
```

Shopify 已经提供 Checkout。

你的 Theme 一般只需要让用户进入：

```text
Checkout
```

例如 Cart 页面可以通过 Shopify 提供的 Cart Form：

```liquid
<form
  action="{{ routes.cart_url }}"
  method="post"
>
```

然后：

```html
<input
  type="submit"
  name="checkout"
  value="Checkout"
>
```

Shopify 官方 Cart Template 文档就是这么描述从 Cart 进入 Checkout 的。 [cart](https://shopify.dev/docs/storefronts/themes/architecture/templates/cart?utm_source=chatgpt.com)

---

# 8. 所以你不需要自己做这些

一般情况下你不需要自己开发：

```text
❌ Checkout 页面
❌ 信用卡支付系统
❌ 支付状态处理
❌ 订单创建逻辑
❌ 支付成功后的 Order 创建
```

Shopify 帮你处理：

```text
Checkout
   ↓
Customer Information
   ↓
Shipping
   ↓
Payment
   ↓
Order
```

# 9. 那 Buy It Now 呢？

这个也很有意思。

Shopify 有：

> **Accelerated Checkout**

商品页面可以使用：

```liquid
{{ form | payment_button }}
```

Shopify 会根据商店和用户环境提供相应的 accelerated checkout 按钮。官方文档现在仍然把它作为 Product Form 的一部分。 [Liquid filters: payment_button](https://shopify.dev/docs/api/liquid/filters/payment_button?utm_source=chatgpt.com) [Accelerated checkout](https://shopify.dev/docs/storefronts/themes/pricing-payments/accelerated-checkout?utm_source=chatgpt.com)

所以你看到：

```text
[ Add to Cart ]

[ Buy it now ]
```

第二个按钮很多时候不是你自己写：

```javascript
fetch('/checkout')
```

而是 Shopify 提供的 accelerated checkout 机制。

# 10. 所以你可以建立一个非常重要的认知

Shopify Theme 开发不是：

```text
我要做一个电商网站
↓
所有功能自己写
```

而是：

```text
                Shopify
                   │
        ┌──────────┼──────────┐
        ↓          ↓          ↓
      Cart       Checkout    Order
        │          │          │
      API       Shopify      Shopify
        │       Checkout     Backend
        │
        ↓
      Theme
        │
   ┌────┼─────┐
   ↓    ↓     ↓
 Liquid CSS   JS
   │    │     │
   └────┼─────┘
        ↓
       UI
```

**Shopify 管“电商能力”，Theme 管“店铺体验”。**

```text
提供 Cart 数据 + API + Section Rendering
```

```text
通常自己实现 Drawer UI
```

> **Cart Drawer 通常是 Theme 开发者自己写。**

```text
Checkout
```
