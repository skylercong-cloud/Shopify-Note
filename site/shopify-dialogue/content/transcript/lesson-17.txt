# 一、什么是 Storefront Filtering？

Shopify 官方现在推荐使用 **Storefront filtering** 来实现 Collection 和 Search 页面筛选。 [Storefront filtering](https://shopify.dev/docs/storefronts/themes/navigation-search/filtering/storefront-filtering?utm_source=chatgpt.com) [Filtering](https://shopify.dev/docs/storefronts/themes/navigation-search/filtering?utm_source=chatgpt.com)

例如一个鞋子 Collection：

```text
Shoes
│
├── Availability
│   ├── In stock
│   └── Out of stock
│
├── Color
│   ├── Black
│   ├── White
│   └── Red
│
├── Size
│   ├── S
│   ├── M
│   └── L
│
├── Price
│   ├── $0 - $50
│   └── $50 - $100
│
└── Brand
    ├── Nike
    └── Adidas
```

用户选择：

```text
Color = Black
Size = M
```

Shopify 会根据这些条件返回符合条件的商品。

---

# 二、Shopify Filtering 和普通 JS Filter 的区别

这个概念一定要理解。

你可能会想到：

```js
products.filter(product => ...)
```

但是 Shopify Collection Filtering **不是这么工作的**。

因为：

```text
Shopify 上可能有 10000 个商品
```

你不可能先把 10000 个商品全部传到浏览器：

```js
const products = [...]
```

然后：

```js
products.filter(...)
```

这会非常浪费。

Shopify 的方式是：

```text
Browser
   ↓
发送筛选条件
   ↓
Shopify Server
   ↓
筛选商品
   ↓
Liquid
   ↓
返回符合条件的 HTML
```

也就是说：

> **筛选主要发生在 Shopify 服务端，而不是浏览器端。**

这也是为什么 Shopify Theme 可以保持比较好的性能。

官方也推荐让 Liquid 服务端渲染商品网格，再使用 Section Rendering API 做筛选/排序后的局部更新。 [Render essential content in Liquid and HTML, not JavaScript](https://shopify.dev/docs/storefronts/themes/best-practices/performance/render-essential-content-server-side?utm_source=chatgpt.com)

# 三、核心对象：`collection.filters`

这是这一课最重要的 Liquid 对象。

例如：

```liquid
{% for filter in collection.filters %}

  <h3>{{ filter.label }}</h3>

{% endfor %}
```

假设 Shopify 后台配置了：

```text
Availability
Color
Size
Price
Brand
```

那么：

```liquid
collection.filters
```

就代表这些筛选器。

官方的 Theme Filtering 实现就是通过 `filter` 对象配合 `collection` 或 `search` 对象完成的。 [Support storefront filtering](https://shopify.dev/docs/storefronts/themes/navigation-search/filtering/storefront-filtering/support-storefront-filtering?utm_source=chatgpt.com)

# 四、最基本的 Filter UI

我们先写一个简单版本：

```liquid
{% for filter in collection.filters %}

  <div class="filter-group">

    <h3>
      {{ filter.label }}
    </h3>

    {% for value in filter.values %}

      <label>
        <input
          type="checkbox"
          name="{{ value.param_name }}"
          value="{{ value.value }}"
        >

        {{ value.label }}

      </label>

    {% endfor %}

  </div>

{% endfor %}
```

你可以把它理解成 React：

```jsx
collection.filters.map(filter => (
  <FilterGroup filter={filter} />
))
```

而：

```liquid
{% for value in filter.values %}
```

类似：

```jsx
filter.values.map(value => ...)
```

# 五、Filter 真正厉害的地方：URL

假设用户选择：

```text
Color = Red
```

URL 会出现类似：

```text
/collections/shoes?filter.v.option.color=red
```

如果再选择：

```text
Size = L
```

可能变成：

```text
/collections/shoes
?filter.v.option.color=red
&filter.v.option.size=L
```

Shopify 官方规定了 Storefront Filtering 的 URL 参数结构。 [Storefront filtering](https://shopify.dev/docs/storefronts/themes/navigation-search/filtering/storefront-filtering?utm_source=chatgpt.com)

这意味着：

```text
Filter
 ↓
URL
 ↓
Shopify
 ↓
Collection
```

而不是：

```text
Filter
 ↓
React state
 ↓
本地 products.filter()
```

# 六、为什么 Shopify 要把 Filter 放进 URL？

这是一个非常重要的电商设计。

比如用户筛选：

```text
Color = Black
Size = M
```

URL：

```text
/collections/shoes
?filter.v.option.color=black
&filter.v.option.size=M
```

那么用户可以：

### 1. 刷新页面

筛选状态还在。

### 2. 分享链接

把 URL 发给别人：

```text
https://store.com/collections/shoes?filter...
```

别人打开也是相同筛选结果。

### 3. 浏览器后退

```text
All Shoes
   ↓
Black
   ↓
Black + M
   ↓
Back
```

URL 状态可以恢复。

### 4. SEO / 可访问性

页面状态不是完全依赖 JS 内存。

所以 Shopify Filtering 的一个核心思想就是：

> **URL 是筛选状态的一部分。**

# 七、AND 和 OR

这里特别容易搞混。

Shopify Storefront Filtering 的规则是：

> 不同 Filter 之间通常是 AND，同一个 Filter 的多个值通常是 OR。 [Storefront filtering](https://shopify.dev/docs/storefronts/themes/navigation-search/filtering/storefront-filtering?utm_source=chatgpt.com)

例如：

```text
Color = Black
Size = M
```

相当于：

```text
Color = Black
AND
Size = M
```

商品必须同时满足。

---

但是：

```text
Color = Black
Color = White
```

相当于：

```text
Color = Black
OR
Color = White
```

所以：

```text
不同 filter
     ↓
    AND

同一个 filter 多个 value
     ↓
    OR
```

这是电商筛选非常常见的设计。

# 十一、Active Filters

现在考虑一个实际问题。

用户选择：

```text
Color = Black
Size = M
```

页面最好显示：

```text
Active filters:

[ Black × ] [ M × ]

Clear all
```

这样用户知道当前到底筛选了什么。

在 Liquid 中，你可以围绕 Filter 的 active values 来构建这个 UI。

概念上：

```liquid
{% for filter in collection.filters %}

  {% for value in filter.active_values %}

    <a href="{{ value.url_to_remove }}">
      {{ value.label }} ×
    </a>

  {% endfor %}

{% endfor %}
```

这里的核心思想是：

```text
用户选中的 Filter
        ↓
active_values
        ↓
生成 remove URL
        ↓
点击后取消这个条件
```

这比自己手工拼 URL 安全很多。

# 十八、为什么不是 React 全量接管？

这是 Shopify Theme 和传统 React SPA 一个很重要的区别。

传统 React：

```text
Browser
 ↓
React
 ↓
API
 ↓
JSON
 ↓
React state
 ↓
React DOM
```

Shopify Theme：

```text
Browser
 ↓
Shopify
 ↓
Liquid
 ↓
HTML
 ↓

```

加入 AJAX 后：

```text

 ↓

 ↓
Shopify
 ↓

 ↓

```

所以 Shopify 官方也推荐：

> 核心商品内容应该优先由 Liquid/HTML 服务端渲染，而不是完全依赖 JavaScript 在客户端生成。 [Render essential content in Liquid and HTML, not JavaScript](https://shopify.dev/docs/storefronts/themes/best-practices/performance/render-essential-content-server-side?utm_source=chatgpt.com)

# 12. 最重要的一个区别

你现在已经可以把 Shopify 的：

```text
Filter
Sort
```

彻底分开了。

### Filter

回答：

> **哪些商品应该出现？**

例如：

```text
Color = Black
Material = Leather
Origin = China
Price = $50~$100
```

---

### Sort

回答：

> **出现的这些商品按照什么顺序排列？**

例如：

```text
Newest
Price
Best Selling
Featured
```

---

### 最终可以组合：

```text
/collections/shoes
    ?
    filter.v.option.color=Black
    &
    filter.p.m.custom.material=Leather
    &
    sort_by=created-descending
```

逻辑就是：

```text
1000 个商品
     ↓
Color = Black
     ↓
300 个
     ↓
Material = Leather
     ↓
80 个
     ↓
Newest
     ↓
按照 created_at DESC 排列
```

**所以“上架时间”这个需求你完全不用自己造字段，Shopify 原生已经给你了。**  [collection](https://shopify.dev/docs/storefronts/themes/architecture/templates/collection?utm_source=chatgpt.com) [Liquid objects: collection](https://shopify.dev/docs/api/liquid/objects/collection?utm_source=chatgpt.com)

而你真正需要记住的是：

> **Filter 的自定义能力很强，可以基于 Metafield / Metaobject 等数据；Sort 的原生能力相对固定。想做任意自定义动态排序，就不能简单把 Metafield 当成 `sort_by` 使用。**

另外，Shopify 当前 Storefront API 的 Collection 排序枚举也仍然是固定的一组键（如 `BEST_SELLING`、`CREATED`、`PRICE`、`TITLE`、`MANUAL` 等），这也说明了“任意 Metafield Sort”不是标准 Collection Sort 能力。 [ProductCollectionSortKeys - Storefront API](https://shopify.dev/docs/api/storefront/latest/enums/ProductCollectionSortKeys?utm_source=chatgpt.com)

如果继续我们的课程，**第 18 课就正好可以把 `Filter + Sort + Pagination + URL` 四个东西串起来**，到时候你会真正理解一个 Shopify Collection 页是怎么工作的。

# 但有几种实现方式

## 方案 1：最推荐——建立一个 Collection

如果这批产品本身具有明确的业务意义，比如：

```text
限时促销商品
新品
夏季商品
跑鞋
Top Picks
```

最自然的 Shopify 建模方式就是：

```text
Products
   ↓
Collection
   ↓
Collection Products
   ↓
sort_by
```

例如创建：

```text
Summer Sale
```

把这 50 个商品放进去。

你的普通页面：

```text
/pages/summer-sale
```

实际上只是**展示这个 Collection 的商品**。

然后你就可以使用：

```text
created-descending
price-ascending
price-descending
best-selling
manual
```

等原生排序。

这通常是 Shopify 思维里最合理的做法。

---

# 方案 2：普通页面 + Collection

你甚至不一定要让用户访问：

```text
/collections/summer-sale
```

你可以自己做：

```text
/pages/summer-sale
```

然后这个 Page Template 里面展示某个 Collection。

比如：

```text
pages/summer-sale
        ↓
找到 summer-sale collection
        ↓
collection.products
        ↓
按照 Collection Sort
        ↓
Product Card
```

概念上：

```liquid
{% assign products_collection = collections['summer-sale'] %}

{% for product in products_collection.products %}
  {% render 'product-card', product: product %}
{% endfor %}
```

这样你的页面虽然是：

```text
/pages/summer-sale
```

但商品数据来源还是：

```text
Collection
```

# 方案 3：如果这批产品是动态的

这个就更有意思。

比如你说：

> 我有一个首页模块，想展示“最新上架的 12 个商品”。

这时候你甚至不需要自己创建一个 Collection。

Shopify Theme 本身有一些产品来源可以使用，比如通过 **Collection** 作为商品来源，让 Theme Editor 让商家选择一个 Collection，然后：

```liquid
{% assign products = section.settings.collection.products %}
```

但是这里有一个限制：

**如果你只是拿到一个 Liquid Product 数组，不能把 Shopify Collection 的 `sort_by` 机制直接套在这个数组上。**

也就是说，不是：

```liquid
{% assign products = section.settings.collection.products %}

{% assign products = products | sort: 'price' %}
```

然后期待它等价于 Shopify：

```text
price-ascending
```

这两个东西不是一回事。

# 4. 一个很典型的例子

假设你做首页：

```text
Home
│
├── Hero
│
├── Featured Products
│
├── New Arrivals
│
└── Best Sellers
```

你希望：

### New Arrivals

```text
最新上架
```

### Best Sellers

```text
销量最高
```

### Featured Products

```text
人工推荐
```

最 Shopify 的设计通常是：

```text
Collections
│
├── Featured
│   └── manual
│
├── New Arrivals
│   └── created-descending
│
└── Best Sellers
    └── best-selling
```

然后首页 Section：

```text
Featured Products
      ↓
Featured Collection

New Arrivals
      ↓
New Arrivals Collection

Best Sellers
      ↓
Best Sellers Collection
```

---

# 5. 这其实是 Shopify 一个非常重要的设计思想

你可能会觉得：

> “我只是想在一个页面上展示几个 Product，为什么非要 Collection？”

因为 Shopify 把 **Collection 当成商品集合的核心查询/组织单位之一**。

所以：

```text
Product
   ↓
Collection
   ↓
Filter / Sort / Pagination
```

是一条非常成熟的路径。

而不是：

```text
Product
   ↓
随便拿一个数组
   ↓
自己实现所有电商查询逻辑
```

---

# 6. 如果我就是不想用 Collection 呢？

那就分情况。

### 如果只是简单排序

例如你已经有：

```liquid
{% assign products = ... %}
```

某些 Liquid 数组可以使用 `sort` 等 Liquid filter 做基础排序。

例如概念上：

```liquid
{% assign sorted_products = products | sort: 'title' %}
```

但是注意：

> 这和 Shopify Collection 的 `sort_by=price-ascending`、`best-selling`、`created-descending` 不是一个能力。

尤其是：

```text
Best Selling
```

这种需要 Shopify 后端销售数据参与的排序，不能简单理解成：

```liquid
products | sort: 'sales'
```

因为你根本没有一个普通 Product 属性：

```text
product.sales
```

---

# 7. 所以你的问题可以总结成一张表

| 场景 | 推荐方案 |
|---|---|
| Collection 页面排序 | `collection.sort_options` |
| 普通页面展示一组有明确业务意义的商品 | 建 Collection |
| 首页“新品” | Collection + `created-descending` |
| 首页“热卖” | Collection + `best-selling` |
| 首页“精选” | Collection + `manual` |
| 普通页面展示某 Collection | 可以 |
| 任意 Liquid Product 数组使用 Collection `sort_by` | ❌ |
| 自己对数组按简单字段排序 | 部分可以用 Liquid `sort` |
| 按 Shopify 销量等后端数据动态排序 | 不能靠普通 Liquid `sort` |

# 8. 还有一个非常重要的架构问题

假设你的需求是：

> “我做一个 Landing Page，里面有 20 个指定商品，并且用户可以选择价格低到高 / 高到低 / 最新。”

我不会首先想到：

```text
Landing Page
    ↓
20 个 Product
    ↓
自己实现 Sort
```

我会优先考虑：

```text
Landing Page
       ↓
指定 Collection
       ↓
20 个 Product
       ↓
Shopify 原生 Sort
```

甚至可以让 Theme Editor 配置：

```text
Product Source:
[ Summer Sale ▼ ]

Sort:
[ Price: Low to High ▼ ]

Products per page:
[ 20 ]
```

这样你的 Section 就非常灵活。

---

## 但有一个边界值得你记住

如果你的需求变成：

> “这个页面里的产品来自 5 个不同 Collection，我把它们合并，然后按照 Shopify 的 Best Selling 重新排序。”

这时候就不是简单的 Collection Sort 了。

因为你实际上是在做：

```text
Collection A
      +
Collection B
      +
Collection C
      ↓
   合并 Product
      ↓
  全局排序
```

这时就需要进一步考虑 **Storefront API / App / 后端查询** 等方案，而不是简单依赖 Liquid 的 Collection Sort。

---

所以你刚才这个问题其实非常好，因为它揭示了一个很重要的 Shopify 数据模型：

```text
                Product
                   │
          ┌────────┴────────┐
          ↓                 ↓
     Collection         Metafield
          │
          ↓
   Query / Filter / Sort
          │
          ↓
        Theme
```

**Collection 不只是“给商品分组的文件夹”，在 Shopify 里它还是 Storefront 商品查询和排序的重要载体。**

这也是为什么我们后面学 **Collection → Product → Variant → Metafield** 时，数据模型一定要连起来理解。

## ChatGPT · 2026-09-19 Sat 23:06

对，**如果你说的是 Shopify 原生 Collection 的 `sort_by`，还是不能直接按“评分”排序。**

比如你有：

```text
Product A → rating = 4.9
Product B → rating = 4.7
Product C → rating = 4.5
```

你想让用户选择：

```text
Sort by:
- Rating: High → Low
```

不能直接写成：

```text
/collections/shoes?sort_by=rating-descending
```

因为 Shopify 原生 Collection Sort 并没有这个排序键。

### 但“评分排序”并不是做不到

只是要换实现方式。

如果评分来自某个 Review App，例如：

```text
Product
└── rating = 4.9
```

你可以：

**方案 A：App / 后端计算排序**

```text
Review 数据
   ↓
计算 rating / score
   ↓
你的 App / 后端
   ↓
得到排序后的 Product
   ↓
展示
```

**方案 B：把评分转化成推荐顺序**

例如：

```text
评分 + 销量 + 评论数
        ↓
recommendation_score
        ↓
计算商品排名
        ↓
维护 Collection 的 manual 顺序
```

然后前台：

```text
Sort by:
Featured
```

实际上对应：

```text
manual
```

这样 Shopify 原生 Collection 仍然可以负责分页、展示等。

---

所以你可以记住一个非常重要的边界：

```text
Shopify 原生 Collection Sort
│
├── Price              ✅
├── Created / Newest   ✅
├── Best Selling       ✅
├── Title              ✅
└── Manual             ✅
```

而：

```text
自定义字段
│
├── Rating             ❌ 不能直接作为 sort_by
├── Review Count       ❌
├── Profit Margin      ❌
├── Custom Score       ❌
└── Recommendation    ❌
```

**不是这些数据不能存在 Shopify 里，而是 Shopify 原生 Collection Sort 没有提供“任意字段排序”的接口。**

如果你以后做一个类似美柚这种自己的电商/内容产品，这个区别也很重要：**“数据能不能存” 和 “Shopify Storefront 能不能直接拿这个字段做服务端排序”是两回事。**
