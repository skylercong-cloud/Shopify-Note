## 我的提问 · 2026-09-19 Sat 22:04

Shopify app和function有什么区别

## ChatGPT · 2026-09-19 Sat 22:04

可以把它先记成一句话：

> **Shopify App = 一个完整的“应用/业务系统”**
>
> **Shopify Function = Shopify 运行在特定业务节点上的“后端扩展函数”**

两者不是完全平级的东西，**Function 通常是 App 的一个组成部分**。

### 先用你熟悉的前端思维理解

如果你做 React/Next.js：

```text
Shopify App
│
├── Admin UI
├── React / Next.js
├── 数据库
├── Shopify Admin API
├── Webhook
├── OAuth
├── 后端服务
│
└── Shopify Function
      └── 专门执行某个 Shopify 业务逻辑
```

所以：

**App 更像一个完整项目，Function 更像这个项目里的一个特殊后端能力。**

---

## 1. Shopify App 是什么？

App 的核心作用是：

> **给 Shopify 商家增加新的业务能力。**

例如你做一个“营销活动管理 App”：

```text
商家进入 App
      ↓
创建活动
      ↓
选择商品
      ↓
设置活动时间
      ↓
设置折扣规则
      ↓
保存到数据库
      ↓
调用 Shopify API
      ↓
创建/配置 Discount
```

你的 App 可以包含：

- React / Next.js 管理后台
- 数据库
- Shopify Admin API
- GraphQL
- Webhook
- OAuth
- App Bridge
- Polaris
- Shopify Function
- 第三方 API
- ERP / CRM / 物流系统

所以 App 的能力范围非常大。

---

# 2. Shopify Function 是什么？

Function 更专注：

> **在 Shopify 的特定业务流程中执行自定义逻辑。**

比如：

```text
用户购物车
    ↓
Shopify
    ↓
Discount Function
    ↓
判断：
这个商品是不是活动商品？
活动有没有过期？
用户是否符合条件？
    ↓
计算折扣
    ↓
Shopify Checkout
```

Function 不是让你做一个完整后台。

它更像：

```js
function calculateDiscount(input) {
    // Shopify 把业务数据给你

    if (满足活动条件) {
        return {
            discount: ...
        };
    }

    return {};
}
```

也就是说：

**Shopify 在某个业务节点调用你的 Function。**

---

# 3. 两者最重要的区别

| | Shopify App | Shopify Function |
|---|---|---|
| 定位 | 完整应用 | 业务逻辑扩展 |
| 主要面向 | 商家/后台/外部系统 | Shopify 业务运行时 |
| 是否有 UI | 可以有 | 通常没有 |
| 是否有数据库 | 可以有 | Function 本身不是数据库 |
| 是否可以调用外部系统 | App 可以 | Function 有严格限制 |
| Admin API | 可以使用 | 不是它的主要能力 |
| Webhook | 可以 | 不是主要用途 |
| OAuth | 可以 | 不负责 |
| React/Next.js | 可以 | 通常不是核心 |
| 执行方式 | App 自己运行 | Shopify 在特定时机调用 |
| 典型用途 | 商家后台、ERP、营销系统 | 折扣、配送、支付、购物车等业务逻辑 |

假设：

```text

活动价格：$19.99
```

App 可以让商家看到：

```text
┌─────────────────────────┐
│ Summer Sale             │
│                         │
│ 活动名称：Summer Sale   │
│ 开始时间：9/1           │
│ 结束时间：9/30          │
│                         │
│ 商品：                  │
│ ☑ T-Shirt               │
│ ☑ Hoodie                │

│                         │
│ [保存活动]              │
└─────────────────────────┘
```

这就是 **App**。

---

### Function 负责什么？

当用户真正购物：

```text
用户加入 T-Shirt
        ↓
Cart
        ↓
Shopify Discount Function
        ↓
判断 T-Shirt 是否符合活动
        ↓
计算折扣
        ↓
$29.99 → $19.99
        ↓
Checkout
```

这就是 **Function**。

# 5. 所以它们经常一起出现

一个完整的营销 App 可能是：

```text
                 Shopify App
                     │
        ┌────────────┼────────────┐
        ↓            ↓            ↓
     Admin UI      Database    Shopify API
        │            │            │
        └────────────┼────────────┘
                     ↓
              创建活动配置
                     │
                     ↓
              Discount Function
                     │
                     ↓
              Shopify Cart
                     │
                     ↓
                 Checkout
```

这才是比较完整的架构。

# 6. 一个特别重要的概念

你可以这样理解：

### App 是“我要做什么”

例如：

> 我要做一个营销活动管理系统。

### Function 是“Shopify 在某个业务节点帮我执行什么规则”

例如：

> 当用户结账时，如果这个商品属于活动商品，就给它计算折扣。

```text
├── metafields
│
└── metaobjects
```

---

# 三、然后重点搞懂 Variant

这是 Shopify 最重要的概念之一。

```text
Product
   │
   ├── Option: Color
   │       ├── Black
   │       └── White
   │
   ├── Option: Size
   │       ├── S
   │       ├── M
   │       └── L
   │
   └── Variants
          ├── Black / S
          ├── Black / M
          ├── Black / L
          ├── White / S
          ├── White / M
          └── White / L
```

然后我们继续往下：

```text
Variant
   ↓
Inventory Item
   ↓
Inventory Level
   ↓
Location
```

这时候你就真正理解 Shopify 库存了。

---

# 四、然后是 Collection

理解：

```text
Product
   ↓
Collection
```

但是 Collection 不是 Product 的父级。

更准确地说：

```text
             Product A
              ↙     ↘
             ↓       ↓
        Collection A  Collection B
```

一个 Product 可以属于多个 Collection。

然后继续理解：

```text
Collection
 ↓
Products
 ↓
Product Grid
 ↓
Filter
 ↓
Pagination
```

这就刚好和 Theme 第 13～18 课连接起来。

---

# 五、然后进入 Customer

```text
Customer
│
├── name
├── email
├── phone
├── addresses
│
├── orders
│
└── metafields
```

然后我们会讨论：

```text
Customer
   ↓
Cart
   ↓
Checkout
   ↓
Order
```

这里会开始真正理解 Shopify 的购买生命周期。

---

# 六、Order 是第二个重点

我们会重点搞清：

```text
Order
│
├── Customer
│
├── Line Items
│
├── Shipping Address
│
├── Billing Address
│
├── Transactions
│
├── Fulfillment
│
└── Metafields
```

尤其是：

> **Order ≠ Cart**

```text
用户准备买
    ↓
Cart
    ↓
Checkout
    ↓
支付
    ↓
Order
```

这条链你一定要形成肌肉记忆。

---

# 七、Inventory

然后我们会专门花一课讲：

```text
Product
   ↓
Variant
   ↓
Inventory Item
   ↓
Inventory Level
   ↓
Location
```

例如：

```text
T-Shirt
   ↓
Black / M
   ↓
Inventory Item #123
   ↓
     ┌──────────────┐
     ↓              ↓
California       New York
   20               8
```

这样你以后看到：

> “这个商品还有多少库存？”

就不会简单理解成：

```text
variant.inventory_quantity
```

而是能理解 Shopify 背后的库存模型。

---

# 八、Metafield + Metaobject

这个我们会继续深入。

### Metafield

```text
Product
   │
   ├── title
   ├── price
   ├── variants
   │
   └── metafields
          ├── material
          ├── size_guide
          ├── care_instruction
          └── custom_badge
```

---

### Metaobject

如果业务复杂，就会变成：

```text
Product
   ↓
Metafield
   ↓
Metaobject Reference
   ↓
Size Guide
```

例如：

```text
Size Guide
├── title
├── description
├── image
└── size_chart
```

这部分以后会直接连接到：

**Theme + App + Function**

---

# 九、最后我们建立完整 Shopify 数据关系图

学完这条线之后，你应该能看到这样的结构：

```text
                         Shopify
                            │
       ┌────────────────────┼────────────────────┐
       ↓                    ↓                    ↓
    Product              Customer             Collection
       │                    │                    │
       ↓                    ↓                    ↓
    Variant              Cart / Order       Products
       │
       ↓
 Inventory Item
       │
       ↓
 Inventory Level
       │
       ↓
    Location


Product
   │
   ├── Metafield
   │      ↓
   │   Metaobject
   │
   └── Media


Customer
   ↓
Order
   ├── Line Items
   ├── Transaction
   └── Fulfillment
```

这张图以后会成为我们整个 Shopify 学习的**核心地图**。

# 十、两条线最终会合并

真正的 Shopify Theme 开发不是单纯写 Liquid。

最终是：

```text
              Shopify Data Model
                     │
                     ↓
        ┌────────────────────────┐
        │                        │
        ↓                        ↓
      Liquid                   JavaScript
        │                        │
        ↓                        ↓
      HTML                    Browser
        │                        │
        └───────────┬────────────┘
                    ↓
               Storefront
```

例如一个商品页：

```text
Product
   │
   ├── Variant
   ├── Media
   ├── Metafield
   └── Collection
         ↓
      Liquid
         ↓
    Product Page
         ↓
       JavaScript
         ↓
 Variant Selection
         ↓
       Cart API
         ↓
        Cart
```

这时候你就不再是：

> “我会一点 Shopify Liquid。”

而是开始进入：

> **“我理解 Shopify Storefront 的完整运行方式。”**
