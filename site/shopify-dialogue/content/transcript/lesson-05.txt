# 第 5 课：Shopify Theme 开发模式与项目结构

## 一、先回答一个最现实的问题

作为前端工程师，你打开一个 Shopify 项目，可能看到：

```text
assets/
config/
layout/
locales/
sections/
snippets/
templates/
```

你可能会想：

> “这跟我以前的 React 项目差别也太大了。”

确实。

React 项目可能是：

```text
src/
├── components/
├── pages/
├── hooks/
├── services/
├── utils/
└── App.tsx
```

Shopify Theme 则是：

```text
theme/
├── assets/
├── config/
├── layout/
├── locales/
├── sections/
├── snippets/
└── templates/
```

**不要试图把 Shopify 硬套成 React 项目。**

你需要理解 Shopify 自己的组织方式。

先记住这张：

```text
Theme

│   ├── index.json
│   ├── product.json
│   ├── collection.json
│   ├── cart.json
│   └── page.json

├── sections/
│   ├── header.liquid

│

│   ├── theme.css
│   ├── theme.js
│   └── ...

    ├── en.default.json
    └── ...
```

先不要背。

我们一个一个理解。

# 三、layout：整个网站的外壳

我们之前已经讲过：

```text
layout/theme.liquid
```

它类似：

```text
App Shell
```

例如：

```liquid
<!doctype html>
<html>
<head>
  {{ content_for_header }}
</head>

<body>
  {% section 'header' %}

  {{ content_for_layout }}

  {% section 'footer' %}
</body>
</html>
```

整体关系：

```text
theme.liquid
│
├── Header
│
├── 当前页面
│
└── Footer
```

所以你以后想修改：

> 全站 `<head>`、全站 Header、Footer、全局脚本

通常第一时间想到：

```text
layout/
```

---

# 四、templates：决定“这是什么页面”

比如：

```text
/products/t-shirt
```

这是：

```text
Product Page
```

所以对应：

```text
templates/product.json
```

而：

```text
/collections/shoes
```

对应：

```text
templates/collection.json
```

首页：

```text
/
```

对应：

```text
templates/index.json
```

所以：

```text
URL
 ↓
页面类型
 ↓
Template
```

你可以建立这个映射：

```text
首页
 ↓
index

商品详情
 ↓
product

商品集合
 ↓
collection

购物车
 ↓
cart

普通页面
 ↓
page
```

---

# 五、JSON Template 是什么？

现代 Shopify Theme 中你会大量看到：

```text
product.json
```

例如：

```json
{
  "sections": {
    "main": {
      "type": "main-product"
    },
    "recommendations": {
      "type": "related-products"
    }
  },

  "order": [
    "main",
    "recommendations"
  ]
}
```

它表达的是：

> **这个页面由哪些 Section 组成，以及顺序是什么。**

例如：

```text
product.json
       │
       ├── main-product
       │
       ├── product-description
       │
       └── related-products
```

这非常像一个：

> **页面配置文件。**

---

# 六、所以 Template 和 Section 是什么关系？

这是非常重要的一层。

```text
Template
   │
   ├── Section
   ├── Section
   └── Section
```

比如 Product Page：

```text
Product Template
│
├── Main Product
├── Product Description
├── Reviews
└── Related Products
```

所以：

> **Template 决定页面由哪些模块组成。**

而：

> **Section 负责具体模块怎么渲染。**

---

# 七、Section 才是真正干活的地方

比如：

```text
sections/main-product.liquid
```

里面可能有：

```liquid
<h1>{{ product.title }}</h1>

<div class="product-price">
  {{ product.selected_or_first_available_variant.price | money }}
</div>

{% render 'product-form', product: product %}
```

所以：

```text
product.json
      ↓
main-product
      ↓
Liquid
      ↓
HTML
```

---

# 八、Section = “可配置组件”

假设：

```text
sections/image-banner.liquid
```

定义：

```liquid
{% schema %}
{
  "name": "Image Banner",
  "settings": [
    {
      "type": "text",
      "id": "heading",
      "label": "Heading"
    },
    {
      "type": "image_picker",
      "id": "image",
      "label": "Image"
    }
  ]
}
{% endschema %}
```

那么商家进入 Theme Editor：

```text
Image Banner

Heading
[ Summer Sale ]

Image
[ banner.jpg ]
```

然后：

```liquid
{{ section.settings.heading }}
```

读取：

```text
Summer Sale
```

---

# 九、这里有一个很重要的开发思想

普通 React：

```text
开发者
 ↓
Component
 ↓
Props
```

Shopify：

```text
开发者
 ↓
Section
 ↓
Schema
 ↓
Theme Editor
 ↓
商家配置
 ↓
section.settings
```

所以 Shopify Theme 开发时，你经常不是简单地：

> “把 UI 写出来。”

而是在思考：

> “这个 UI 哪些东西应该让运营人员自己配置？”

例如：

```text
标题 → text
图片 → image_picker
颜色 → color
商品 → product
商品集合 → collection
链接 → url
```

---

# 十、Snippet：解决重复代码

假设你在很多地方都需要：

```text
商品图片
商品标题
价格
```

你可以创建：

```text
snippets/product-card.liquid
```

然后：

```liquid
{% render 'product-card', product: product %}
```

这和 React：

```jsx
<ProductCard product={product} />
```

非常类似。

所以：

```text
Section
=
页面级、可配置组件

Snippet
=
小型复用组件
```

# 十一、一个实际例子：商品卡片

假设 Collection 页面有：

```text
┌──────────────┐
│    Image     │
│              │
│ Nike Shoes   │
│ $99.00       │
└──────────────┘
```

你可能有：

```text
sections/main-collection.liquid
```

里面循环商品：

```liquid
{% for product in collection.products %}

  {% render 'product-card', product: product %}

{% endfor %}
```

然后：

```text
snippets/product-card.liquid
```

负责：

```liquid
<article class="product-card">

  <img src="{{ product.featured_image | image_url }}">

  <h3>
    {{ product.title }}
  </h3>

  <span>
    {{ product.price | money }}
  </span>

</article>
```

最终：

```text
Collection Section
        ↓
for products
        ↓
Product Card Snippet
        ↓
HTML
```

这就是 Shopify Theme 中非常典型的开发模式。

# 十三、config：Theme 的全局配置

例如：

```text

```

这里可以定义：

```text
Theme Settings
```

例如：


# 十四、config 和 Section Schema 有什么区别？

这个很容易混。

### Section Schema

控制：

> **某一个 Section**

例如：

```text
Hero Banner
├── Title
├── Image
└── Button
```

---

### Theme Settings

控制：

> **整个 Theme**

例如：

```text
Theme Settings
├── Logo
├── Colors
├── Typography
└── Social Media
```

所以：

```text
Section Schema
   ↓
局部配置

Theme Settings
   ↓
全局配置
```

# 十五、locales：国际化

跨境电商一定会遇到：

```text
English
French
German
Spanish
Japanese
Chinese
...
```

Theme 里面：

```text
locales/
├── en.default.json
├── fr.json
├── de.json
└── ...
```

例如：

```json
{
  "products": {
    "add_to_cart": "Add to cart"
  }
}
```

Liquid：

```liquid
{{ 'products.add_to_cart' | t }}
```

这样就能实现多语言。

所以：

```text
locales
 ↓
i18n
```

作为跨境电商前端，这部分你后面会经常遇到。

# 十七、现在进入 Shopify 开发最重要的一个选择

你以后会遇到两种完全不同的开发方式。

## 模式 A：Theme Development

```text
Shopify
 ↓
Theme
 ↓
Liquid
 ↓

```

适合：

- 普通 Shopify 商店
- 商品详情页

- Collection
- Cart

这是你**现在应该优先学习的方向**。

# 十九、Theme / App / Headless 怎么选择？

这一张表你以后工作中会非常有用：

| 需求 | 优先考虑 |
|---|---|

| 做商品卡片 | Snippet |

# 🎯 第 5 课核心知识点

今天你不需要记所有文件。

先把下面这句话记住：

> **Template 决定页面结构，Section 负责页面模块，Snippet 负责代码复用，Liquid 负责 Shopify 数据渲染，JavaScript 负责浏览器交互。**

再加上：

> **Schema 决定商家在 Theme Editor 里能配置什么。**

以及：

> **Metafield / Metaobject 负责扩展 Shopify 的数据模型。**

这几个概念一旦真正掌握，你就已经开始从“前端开发工程师”转换成“Shopify Theme 开发工程师”了。
