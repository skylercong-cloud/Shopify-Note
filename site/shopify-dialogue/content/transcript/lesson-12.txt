# 第 12 课：Metafield + Shopify Functions —— 让活动规则“配置化”

上一课我们有一个活动：


# 一、先建立一个完整的数据模型

我们设计一个活动：

```text
活动名称：
Summer Sale

活动时间：
2026-09-01
~
2026-09-30

活动商品：
T-Shirt

活动价格：
$19.99
```

我们可以把它抽象成：

```js
{
  "campaign": "summer_sale",
  "startsAt": "2026-09-01T00:00:00Z",
  "endsAt": "2026-09-30T23:59:59Z",
  "targetVariantIds": [
    "gid://shopify/ProductVariant/123"
  ],
  "price": "19.99"
}
```

注意：

**这不是让浏览器传给 Shopify 的数据。**

而是：

> **商家/你的 App 配置在 Shopify 后台的数据。**

# 二、为什么要放 Metafield？

假设你直接写死：

```js
if (variantId === '123') {
  price = 19.99;
}
```

那以后活动改商品怎么办？

改价格怎么办？

改日期怎么办？

你只能：

```text
修改代码
↓
重新部署 Function
```

这显然不适合运营。

```text
Shopify Admin
      ↓
活动配置
      ↓
Metafield
      ↓
Function
```

运营人员可以修改：

```text
活动价格：19.99
```

Function 不需要重新部署。

# 三、一个非常重要的概念

这里其实有两种 Metafield：

### 普通业务数据

例如：

```text
Product
└── custom.material
```

这是我们之前学习的：

```liquid
{{ product.metafields.custom.material.value }}
```

---

### Function Configuration

例如：

```text
Discount
└── function-configuration
```

它不是简单拿来给 Theme 显示的。

它的目的主要是：

> **给 Function 提供运行时配置。**

Shopify 官方的 Discount Function 示例就是从 discount metafield 中读取 JSON 配置，例如目标 SKU 和折扣百分比。 [Discount Function API](https://shopify.dev/docs/api/functions/2026-01/discount?utm_source=chatgpt.com)

---

# 四、为什么配置通常是 JSON？

比如：

```json
{
  "percentage": 20,
  "skus": [
    "TSHIRT-BLACK",
    "TSHIRT-WHITE"
  ]
}
```

Function 读取：

```graphql
discount {
  metafield(
    namespace: "$app",
    key: "function-configuration"
  ) {
    jsonValue
  }
}
```

然后 Function：

```js
const configuration =
  input.discount?.metafield?.jsonValue ?? {};
```

得到：

```js
{
  percentage: 20,
  skus: [
    "TSHIRT-BLACK",
    "TSHIRT-WHITE"
  ]
}
```

官方文档现在也推荐复杂 Function 配置使用 JSON metafield，因为活动规则经常是嵌套结构。 [Metafields for input queries](https://shopify.dev/docs/apps/build/functions/input-queries/metafields-for-input-queries?utm_source=chatgpt.com)

# 五、这样 Function 就变成“通用引擎”

这是今天最重要的思想。

不要：

```text
Function
↓
写死 Summer Sale
```

而应该：

```text
Function
↓
读取 Configuration
↓
执行通用规则
```

比如：

```json
{
  "percentage": 20,
  "targetVariantIds": [
    "gid://shopify/ProductVariant/123",
    "gid://shopify/ProductVariant/456"
  ]
}
```

Function：

```text
读取配置
   ↓
遍历 Cart Lines
   ↓
Variant 是否匹配？
   ↓
是
   ↓
20% Discount
```

这样同一个 Function 可以服务：

```text
Summer Sale
Black Friday
Christmas Sale
VIP Sale
Flash Sale
```

只需要不同的配置。

# 六、把它类比成 React

你作为前端开发，可以这样理解：

传统写法：

```js
function Product({ product }) {
  if (product.id === 123) {
    return <SalePrice />;
  }

  return <NormalPrice />;
}
```

这是：

> **业务规则硬编码。**

配置化：

```js
const config = {
  saleProductIds: [123, 456],
  discount: 20
};
```

然后：

```js
function Product({ product, config }) {
  if (config.saleProductIds.includes(product.id)) {
    return <SalePrice />;
  }

  return <NormalPrice />;
}
```

这就是：

> **业务逻辑 + 配置分离。**

Shopify Functions 也是同样的思想。

# 七、现在我们把活动完整设计出来

```json
{
  "campaign": "summer_sale",

  "startsAt": "2026-09-01T00:00:00Z",

  "endsAt": "2026-09-30T23:59:59Z",

  "targetVariantIds": [
    "gid://shopify/ProductVariant/123"
  ],

  "discountType": "fixed_price",

  "price": "19.99"

```

注意这里我故意设计成：

```text
discountType = fixed_price
```

而不是：

```text
percentage = 20
```

因为我们的业务需求是：

```text
正常：
$29.99

活动：
$19.99
```

而不是：

```text
打八折
```

# 八、但 Discount Function 的思路更适合“计算折扣”

这时候出现一个非常重要的设计问题。

原价：

```text
$29.99
```

活动价：

```text
$19.99
```

实际上等价于：

```text
Discount
=
$29.99 - $19.99

=
$10.00
```

所以 Function 可以计算：

```text
discountAmount = originalPrice - campaignPrice
```

例如：

```js
const originalPrice = 29.99;
const campaignPrice = 19.99;

const discount = originalPrice - campaignPrice;
// 10.00
```

然后给 Cart Line：

```text
-$10
```

这样最终：

```text
$29.99
- $10.00
──────────
$19.99
```

# 九、Function 真正看到什么？

我们可以让 input query 请求：

```graphql
query Input {
  cart {
    lines {
      id
      quantity

      merchandise {
        __typename

        ... on ProductVariant {
          id
          product {
            id
          }
        }
      }

      cost {
        amountPerQuantity {
          amount
        }
      }
    }
  }

  discount {
    metafield(
      namespace: "$app",
      key: "function-configuration"
    ) {
      jsonValue
    }
  }
}
```

于是 Function 拿到：

```js
{
  cart: {
    lines: [
      {
        id: "gid://shopify/CartLine/1",

        quantity: 1,

        merchandise: {
          id: "gid://shopify/ProductVariant/123"
        },

        cost: {
          amountPerQuantity: {
            amount: "29.99"
          }
        }
      }
    ]
  },

  discount: {
    metafield: {
      jsonValue: {
        campaign: "summer_sale",
        price: "19.99",
        targetVariantIds: [
          "gid://shopify/ProductVariant/123"
        ]
      }
    }
  }
}
```

这正是 Shopify 官方 Discount Function 当前支持的模式：Input Query 可以同时读取 Cart Lines 和 discount 上的 metafield 配置。 [Discount Function API](https://shopify.dev/docs/api/functions/2026-01/discount?utm_source=chatgpt.com) [Discount Function API](https://shopify.dev/docs/api/functions/unstable/discount?contentToggled=true&utm_source=chatgpt.com)

# 十、然后 Function 做判断

伪代码：

```js
for (const line of input.cart.lines) {

  const variantId = line.merchandise.id;

  const isTarget =
    config.targetVariantIds.includes(variantId);

  if (!isTarget) {
    continue;
  }

  const originalPrice =
    Number(line.cost.amountPerQuantity.amount);

  const campaignPrice =
    Number(config.price);

  const discount =
    originalPrice - campaignPrice;

  if (discount <= 0) {
    continue;
  }

  // 创建 discount candidate
}
```

例如：

```text
Variant
123

原价
29.99

活动价
19.99

↓

Discount
10.00
```

# 十五、Theme 不一定要直接读取 Function 的配置

这一点也非常重要。

你可能会想：

> “既然 Function 有配置，Theme 直接读取 Function 配置不就行了？”

不一定。

因为：

```text
Function Configuration
```

的主要责任是：

> **Function runtime configuration**

而：

```text
Campaign Metaobject
```

的责任是：

> **业务内容/活动数据**

这两个概念最好不要混在一起。

# 十七、如果活动有 1000 个商品怎么办？

这个问题就开始有意思了。

比如：

```text
Summer Sale
```

有：

```text
10,000 个 Variant
```

你不能简单在 Function 配置里塞一个超大的数组。

因为 Shopify Functions 的 input query、metafield 和运行时都有相应的大小/复杂度限制；官方也建议复杂配置合理使用 JSON，并注意输入大小和查询复杂度。 [Use variables in input queries](https://shopify.dev/docs/apps/build/functions/input-queries/use-variables-input-queries?utm_source=chatgpt.com) [Function APIs](https://shopify.dev/docs/api/functions/unstable?utm_source=chatgpt.com)

这时候通常要考虑：

```text
Product / Variant Metafield
```

例如：

```text
Variant
custom.campaign_price

= 19.99
```

或者：

```text
Variant
custom.campaign_id

= summer_sale
```

Function 直接读取目标 Variant 的相关数据。

## 🧠 今天最重要的 5 个结论

你把下面这 5 个记住，第 12 课就算真正掌握了：

**1. Metafield 不只是给商品加字段。**

它也可以作为 Shopify Functions 的配置数据。 [Metafields for input queries](https://shopify.dev/docs/apps/build/functions/input-queries/metafields-for-input-queries?utm_source=chatgpt.com)

**2. Function 不应该把活动规则硬编码。**

应该：

```text
Function Logic
+
Configuration
```

**3. 活动业务数据和 Function 配置可以分开。**

```text
Metaobject
=
Campaign Business Data

Discount Metafield
=
Function Configuration
```

**4. 浏览器永远不是最终价格的可信来源。**

```text
Browser
→ 提出购买请求

Shopify
→ 决定最终交易结果
```

**5. Discount Function 是“计算优惠”的核心能力。**

Shopify 当前 Discount Function API 支持商品、订单和配送三类折扣，并可通过 metafield 配置 Function 行为。 [Discount Function API](https://shopify.dev/docs/api/functions/2026-01/discount?utm_source=chatgpt.com) [DiscountAutomaticAppInput - GraphQL Admin](https://shopify.dev/docs/api/admin-graphql/2026-01/input-objects/DiscountAutomaticAppInput?utm_source=chatgpt.com)
