前面十一节课，我们已经接触过很多 ARIA 属性，例如 `aria-label`、`aria-hidden`、`aria-expanded`、`aria-selected`、`aria-modal` 和 `aria-activedescendant`。

- 哪些属性是必须提供的？
- 组件内部是否存在特定的父子结构要求？
- 哪些行为需要 JavaScript 实现？
- 如何判断当前 ARIA 实现是否正确？

## 1. 重新认识 WAI-ARIA

WAI-ARIA 的全称是：

**Web Accessibility Initiative – Accessible Rich Internet Applications**

它是 W3C 制定的一套用于表达 Web 内容及交互组件无障碍语义的技术规范。

我们可以通过一个简单的例子理解它存在的意义。

### 1.1 原生 HTML 的表达能力

```html
<button type="button">
  Add to cart
</button>
```

浏览器能够直接识别：

```text
Role: button
Name: Add to cart
Focusable: true
```

同时，浏览器还会提供原生的鼠标、键盘激活行为。

但 HTML 并没有为所有复杂 UI 组件提供对应的原生标签。

例如，HTML 中不存在专门的：

```html
<tabs>
<tab>
<tab-panel>
<combobox>
<tree-view>
```

这里就需要 ARIA 补充相应的语义。

### 1.2 ARIA 如何发挥作用？

假设我们开发了一个 Tabs 组件：

```html
<div role="tablist" aria-label="Product information">

  <button
    role="tab"
    aria-selected="true"
    aria-controls="description-panel"
  >
    Description
  </button>

  <button
    role="tab"
    aria-selected="false"
    aria-controls="reviews-panel"
    tabindex="-1"
  >
    Reviews
  </button>

</div>
```

通过这些属性，浏览器可以知道它不是两个普通按钮，而是一个标签页组件中的两个选项。

ARIA 通过浏览器的无障碍映射机制影响 Accessibility Tree，并进一步影响辅助技术获取的信息。

但是，ARIA 本身不会自动实现以下功能：

| 功能 | ARIA 是否自动实现 |
|---|---|
| 改变元素的视觉样式 | 否 |
| 让普通 div 获得键盘焦点 | 否 |
| 实现 Enter、Space 激活 | 否 |
| 实现方向键导航 | 否 |
| 打开或关闭弹窗 | 否 |
| 阻止重复提交 | 否 |
| 表达组件角色、状态、关系 | 是 |

**ARIA 是语义声明机制，而不是 UI 组件库，也不是交互行为实现机制。**

## 2. ARIA 的三大组成部分：Role、State、Property

ARIA 的整个体系主要由三部分组成。

| 类型 | 解决的问题 | 示例 |
|---|---|---|
| Role（角色） | 这个元素是什么？ | `button`、`dialog`、`tab` |
| State（状态） | 元素当前处于什么状态？ | `aria-expanded`、`aria-checked` |
| Property（属性） | 元素具有什么特征或关系？ | `aria-label`、`aria-controls` |

例如一个购物车触发按钮：

```html
<button
  type="button"
  aria-label="Open shopping cart"
  aria-haspopup="dialog"
  aria-controls="cart-drawer"
>
  <svg aria-hidden="true">
    <!-- Cart icon -->
  </svg>
</button>
```

这里：

- Role：button，由原生 HTML 提供。
- Property：`aria-label`，定义按钮名称。
- Property：`aria-haspopup`，声明按钮可以打开哪种弹出组件。
- Property：`aria-controls`，表达按钮控制的目标区域。

如果业务还需要表达当前展开状态，则可以根据组件模式使用 `aria-expanded`。

### 2.1 State 和 Property 的区别

State 通常表示比较容易随用户操作变化的状态，而 Property 通常表示相对稳定的特征。

但这不是绝对的。

例如 `aria-valuenow` 在规范中属于 Property，却会随着 Slider 的操作不断变化。

因此，不要简单地理解为 State 可以变化、Property 不可以变化。

## 3. Implicit Role 与 Explicit Role

浏览器获取元素 Role 的方式主要有两种。

### 3.1 Implicit Role（隐式角色）

HTML 元素本身提供的无障碍角色。

| HTML 元素 | 默认隐式 Role |
|---|---|
| `<button>` | button |
| `<a href="...">` | link |
| `<input type="checkbox">` | checkbox |
| `<input type="radio">` | radio |
| `<input type="range">` | slider |
| `<input type="number">` | spinbutton |
| `<textarea>` | textbox |
| `<h1>` ～ `<h6>` | heading |
| `<ul>` | list |
| `<li>` | listitem |
| `<nav>` | navigation |
| `<main>` | main |
| `<dialog>` | dialog |

所以：

```html
<button role="button">
  Add to cart
</button>
```

这里的 `role="button"` 通常属于冗余声明。

直接使用 button 即可。

### 3.2 Explicit Role（显式角色）

通过 role 属性主动指定元素的角色。

```html
<div role="button" tabindex="0">
  Add to cart
</div>
```

这里使用了显式 Role。

某些原生元素也可以在规范允许的情况下改变其角色。

例如：

```html
<button
  type="button"
  role="switch"
  aria-checked="false"
>
  Email notifications
</button>
```

这个元素仍然具有原生 button 的键盘激活能力，但它的无障碍角色变成了 switch。

### 3.3 是否可以任意覆盖原生 Role？

不可以。

并不是所有 HTML 元素都允许设置任意 Role。

例如：

```html
<!-- 不合理 -->
<input type="text" role="heading">

<button role="navigation">
  Add to cart
</button>
```

HTML 与 ARIA 之间存在明确的使用约束。

W3C 有一份专门的规范：[ARIA in HTML](https://www.w3.org/TR/html-aria/)，它规定了每种 HTML 元素的默认语义，以及允许使用哪些显式 Role 和 ARIA 属性。<Cite ref="turn697692search0"/>

以后开发组件时，遇到不确定的角色覆盖问题，可以直接查阅这份规范。

### 3.4 一个元素能不能拥有多个 Role？

你可能会看到这样的代码：

```html
<div role="switch checkbox">
  Notifications
</div>
```

这并不是同时声明两种角色。

多个 Role token 可以用于后备机制，浏览器通常选择第一个能够识别并处理的非抽象角色。

因此，上面的写法不能理解为该元素既是 switch，又是 checkbox。

另外，不能使用逗号分隔 Role。

```html
<!-- 错误 -->
<div role="switch,checkbox"></div>
```

日常业务开发中，通常为一个元素选择一个明确的角色即可。

WAI-ARIA 1.2 将角色划分为多个类别。

### 4.1 Abstract Roles：抽象角色

抽象角色主要用于规范内部建立角色继承体系。

例如：

```text
roletype
widget
input
range
structure
command
composite
```

这些角色不能直接用于业务 HTML。

```html
<!-- 错误 -->
<div role="widget"></div>

<!-- 错误 -->
<div role="range"></div>
```

应该使用具体角色，例如 slider、spinbutton、button。

可以类比 TypeScript 中的抽象类：它们用于建立基础定义，而不是让开发者直接创建对应的业务实例。

### 4.2 Widget Roles：交互组件角色

这一类是前端开发中使用频率最高的角色。

| Role | 常见用途 |
|---|---|
| button | 普通操作按钮 |
| checkbox | 多选控件 |
| radio | 单选控件 |
| switch | 开关控件 |
| textbox | 文本输入 |
| slider | 滑块 |
| spinbutton | 数值输入 |
| combobox | 组合输入控件 |
| option | 列表选项 |
| tab | 标签页选项 |
| menuitem | 命令菜单项 |
| treeitem | 树形节点 |

还有一类复合组件角色：

| Role | 常见用途 |
|---|---|
| tablist | Tabs 标签列表 |
| listbox | 单选或多选列表 |
| radiogroup | 单选组 |
| menu | 命令菜单 |
| menubar | 菜单栏 |
| grid | 具有二维结构的交互网格 |
| tree | 树形组件 |

上一课学习的 Roving Tabindex 和 aria-activedescendant，主要就是为这些复合组件服务的。

特别注意，CSS Grid 与 ARIA Grid 是完全不同的概念。

```html
<ul class="product-grid">
  <!-- Product cards -->
</ul>
```

即使商品列表使用 `display: grid` 布局，也不代表应该设置 `role="grid"`。

ARIA grid 会表达一种具有特定行列关系和键盘交互模式的组件，而普通商品列表通常只需要 list 语义。

### 4.3 Document Structure Roles

这类 Role 用于描述文档结构，包括：

`article`、`heading`、`list`、`listitem`、`table`、`row`、`cell`、`img`、`figure`、`group`、`separator` 等。

第 5 课学习的 HTML 语义化，实际上已经覆盖了其中很多角色。

### 4.4 Live Region 与 Window Roles

| Role | 用途 |
|---|---|
| `alert` | 需要及时通知的重要消息 |
| `status` | 普通业务状态反馈 |
| `log` | 按顺序追加的信息 |
| `timer` | 时间或计时信息 |
| `marquee` | 非重要的频繁变化信息 |
| `dialog` | 对话框 |
| `alertdialog` | 需要用户注意并作出响应的对话框 |

其中 Live Region 将在第 14 课完整讲解，Modal 和 Dialog 将在第 15 课详细实现。

具体角色可以从其父级抽象角色继承某些状态和属性。

例如，slider、spinbutton 等具有数值范围特征的角色，都可以涉及 `aria-valuenow` 等属性。

不过，需要区分两种完全不同的继承概念：

| 概念 | 含义 |
|---|---|
| Role Inheritance | 规范中角色与角色之间的继承关系 |
| DOM Inheritance | HTML 父子元素之间的状态或属性影响 |

ARIA Role 的继承，并不意味着父级 DOM 元素的所有 ARIA 属性会自动传递给后代元素。

例如：

```html
<div aria-label="Product information">
  <button>Add to cart</button>
</div>
```

内部按钮不会因此自动获得 `Product information` 这个名称。普通 div 在 generic 语义下也不允许通过这种方式命名。

## 6. 如何阅读一个 ARIA Role 的规范？

这是本节课最值得掌握的方法。

以后你不需要记住所有 Role 的属性，只要能够正确阅读 W3C 的角色定义即可。

打开 [WAI-ARIA 1.2 — checkbox](https://www.w3.org/TR/wai-aria-1.2/#checkbox)。

角色定义中会包含以下信息：

| 规范字段 | 需要关注什么 |
|---|---|
| Superclass Role | 继承自哪些角色 |
| Subclass Roles | 有哪些子角色 |
| Required States and Properties | 必须提供的状态和属性 |
| Supported States and Properties | 可以使用的额外属性 |
| Inherited States and Properties | 从角色体系继承的属性 |
| Prohibited States and Properties | 禁止使用的属性 |
| Required Owned Elements | 必须具有哪些所属元素 |
| Required Context Role | 必须位于何种语义上下文中 |
| Name From | 可访问名称可以从哪里获取 |
| Accessible Name Required | 是否必须提供名称 |
| Children Presentational | 子元素的语义是否会被扁平化 |
| Implicit Value for Role | 角色提供哪些默认属性值 |

不同角色的定义中不一定包含所有这些字段。

### 6.1 常见角色及其必需属性

| Role | 关键必需属性或结构 |
|---|---|
| checkbox | `aria-checked` |
| radio | `aria-checked`，符合单选组上下文 |
| switch | `aria-checked` |
| slider | `aria-valuenow` |
| heading | `aria-level` |
| combobox | `aria-expanded`、`aria-controls` |
| tab | `aria-selected`（存在默认值） |
| option | `aria-selected`（存在默认值） |
| dialog | 可访问名称 |
| tablist | 包含 tab 角色 |

这张表针对 ARIA 角色的核心要求，不是每个组件的完整实现清单。

原生 HTML 元素可以通过自身语义和属性满足相应要求，并不需要重复声明全部 ARIA 属性。例如原生 checkbox 使用 checked 即可。<Cite refs={["turn697692search6","turn697692search3","turn126013search0"]}/>

### 6.2 Required、Supported 和 Prohibited 的区别

以自定义复选框为例：

```html
<div
  role="checkbox"
  tabindex="0"
  aria-label="In stock"
  aria-checked="false"
>
  <!-- Custom checkbox -->
</div>
```

这里的 `aria-checked` 对自定义 checkbox 来说是必需的状态。

但是：

```html
<div
  role="checkbox"
  tabindex="0"
  aria-selected="true"
>
  In stock
</div>
```

就不合理。

因为 checkbox 应通过 checked 表达选中状态，而不是 selected。

即使浏览器没有抛出任何 JavaScript 错误，也不代表 ARIA 使用正确。

**ARIA 属性并不是任意元素都可以任意组合的。**

## 7. Required Owned Elements 与 Required Context Role

这是许多前端开发者学习 ARIA 时容易忽略的部分。

ARIA 不仅规定单个元素的语义，还规定组件之间的结构关系。

### 7.1 Required Owned Elements

表示一个角色必须具有某些类型的所属元素，才能形成完整的组件结构。

例如：

```html
<div role="tablist">
  <button role="tab">Description</button>
  <button role="tab">Reviews</button>
</div>
```

tablist 需要包含 tab。

类似的结构还有：

| 父级 Role | 所需的内部角色 |
|---|---|
| tablist | tab |
| listbox | option，或包含 option 的 group |
| radiogroup | radio |
| menu | menuitem、menuitemcheckbox 等 |
| list | listitem |
| table | row，或包含 row 的 rowgroup |
| row | cell、columnheader、rowheader 等 |
| tree | treeitem，或相应的分组结构 |

### 7.2 Required Context Role

从子元素的角度看，它必须位于合理的语义上下文中。

例如：

```html
<!-- 缺少必要上下文 -->
<div role="option">
  Cotton T-shirt
</div>
```

一个独立的 option 没有对应的列表组件，会造成语义结构不完整。

更合理的结构：

```html
<div role="listbox" aria-label="Products">

    Cotton T-shirt
  </div>

  <div role="option" aria-selected="false">
    Linen shirt
  </div>

</div>
```

## 8. aria-checked、aria-selected、aria-pressed、aria-current

接下来，我们系统研究最容易混淆的四个状态属性。

它们都可以在某种程度上表达“选中”，但实际上含义完全不同。

### 8.1 aria-checked：勾选状态

主要适用于 checkbox、radio、switch 等角色。

```html
<div
  role="checkbox"
  aria-checked="true"
  tabindex="0"
>
  In stock
</div>
```

它表达的是一个控件是否被勾选。

对于支持三态的 checkbox，还有：

```html
aria-checked="mixed"
```

例如 Collection 筛选中的全选功能。

{@body const [filters,setFilters]=DIL.useState([true,false,true])}
{@body const checkedCount=filters.filter(Boolean).length}
{@body const checkState=checkedCount===0?"false":checkedCount===filters.length?"true":"mixed"}
<card gap={3}>
  **三态 Checkbox 实验室**
  <pressable onClick={()=>setFilters(Array(3).fill(checkState!=="true"))} padding={1}>
    <row align="center">
      <box size="22px" border={{size:1,color:checkState==="false"?"#888888":"#39866B"}} background={checkState==="false"?"surface":"#39866B"} radius="sm" align="center" justify="center">
        {#if checkState!=="false"}<icon name={checkState==="mixed"?"minus":"check"} color="#FFFFFF" size="sm"/>{/if}
      </box>
      **Select all colors**
    </row>
  </pressable>
  <box padding={{left:7}} gap={2}>
    {#each ["Black","Beige","Blue"] as n,i}

  <row align="center">

    <text size="sm">Select all colors, checkbox, {checkState==="mixed"?"partially checked":checkState==="true"?"checked":"not checked"}.</text>
  </row>
</card>

需要注意，radio 和 switch 不支持 mixed 状态。

如果使用原生 checkbox，实现三态应该优先使用 DOM 的 `indeterminate` 属性：

```javascript
const selectAll = document.querySelector('#select-all');

selectAll.checked = false;

selectAll.indeterminate = true;
```

`indeterminate` 是 DOM Property，而不是普通 HTML Attribute。

因此下面的写法不能正确建立原生三态：

```html
<input type="checkbox" indeterminate>
```

另外，indeterminate 主要表达部分选中的状态，不会改变 checkbox 的实际 checked 值及其表单提交规则。

### 8.2 aria-selected：选择状态

主要用于 tab、option、row、gridcell 等支持选择语义的角色。

例如 Tabs：

```html
<div role="tablist" aria-label="Product details">
  <button role="tab" aria-selected="true">
    Description
  </button>

  <button role="tab" aria-selected="false">
    Reviews
  </button>
</div>
```

它表示组件内部当前选中了哪个项目。

但不应该将其随意添加给普通 button：

```html
<!-- 不推荐 -->
<button aria-selected="true">
  Add to wishlist
</button>
```

普通按钮如果具有持续的开启、关闭状态，通常应该考虑 `aria-pressed`。

### 8.3 aria-pressed：切换按钮状态

用于 Toggle Button，即可以在按下和未按下状态之间切换的按钮。

例如商品收藏：

```html
<button
  type="button"
  aria-label="Wishlist"
  aria-pressed="false"
>
  <svg aria-hidden="true">
    <!-- Heart icon -->
  </svg>
</button>
```

JavaScript：

```javascript
button.addEventListener('click', () => {
  const pressed =
    button.getAttribute('aria-pressed') === 'true';

  button.setAttribute(
    'aria-pressed',
    String(!pressed)
  );
});
```

这里有一个非常重要的设计原则：

如果使用 aria-pressed，按钮的名称通常应该保持稳定。

例如：

```html
<button aria-pressed="false">Mute</button>
```

点击后：

```html
<button aria-pressed="true">Mute</button>
```

另一种方案是不使用 aria-pressed，而是通过名称描述下一步操作：

```html
<button>Mute</button>
```

点击后：

```html
<button>Unmute</button>
```

两种都是有效的设计思路，但不要无意中混合两种模型，产生类似“Unmute，pressed”这样容易混淆的反馈。<Cite ref="turn126013search3"/>

### 8.4 aria-current：当前位置

它主要表示某个元素是当前集合、流程或者导航中的当前位置。

例如 Header 导航：

```html
<nav aria-label="Main">
  <a href="/">Home</a>

  <a
    href="/collections/clothing"
    aria-current="page"
  >
    Clothing
  </a>

  <a href="/collections/sale">Sale</a>
</nav>
```

还可以用于面包屑、分页、步骤条等组件。

`aria-current` 支持以下常见取值：

| 值 | 含义 |
|---|---|
| `page` | 当前页面 |
| `step` | 当前流程步骤 |
| `location` | 当前位置 |
| `date` | 当前日期 |
| `time` | 当前时间 |
| `true` | 通用当前位置 |
| `false` | 非当前位置 |

## 9. aria-expanded、aria-haspopup、aria-controls、aria-owns

这一组属性主要涉及组件的展开状态和关联关系。

### 9.1 aria-expanded

表达某个可展开区域当前是展开还是折叠。

```html
<button
  type="button"
  aria-expanded="false"
  aria-controls="shipping-content"
>
  Shipping & Returns
</button>

<div id="shipping-content" hidden>
  Free shipping on orders over $50.
</div>
```

JavaScript 必须同时更新：

```javascript
button.setAttribute('aria-expanded', 'true');
content.hidden = false;
```

`aria-expanded` 本身不会控制元素的显示与隐藏。

另外，属性缺失与 `aria-expanded="false"` 不完全相同。

缺失通常意味着没有显式声明展开状态；false 则明确表达该组件当前处于折叠状态。部分角色还有自己的隐式默认值。

### 9.2 aria-haspopup

表示某个控件可以打开特定类型的弹出组件。

| 值 | 对应弹出组件 |
|---|---|
| `false` | 没有声明此类弹出组件 |
| `true` | menu |
| `menu` | menu |
| `listbox` | listbox |
| `tree` | tree |
| `grid` | grid |
| `dialog` | dialog |

特别注意：

```html
aria-haspopup="true"
```

并不泛指所有类型的弹窗，而是等价于：

```html
aria-haspopup="menu"
```

所以，如果一个按钮打开的是 Cart Drawer，并且 Drawer 具有 dialog 语义，那么可以使用：

```html
<button aria-haspopup="dialog">
  Open cart
</button>
```

而不是习惯性地写 `aria-haspopup="true"`。

Tooltip 不属于这个属性所定义的弹出类型。

普通 Shopify Mega Menu 如果只是展开一组导航链接，也不应该仅仅因为它叫 Menu 就添加 `aria-haspopup="menu"`。

### 9.3 aria-controls

表示当前元素控制另一个元素的内容或状态。

```html
<button
  aria-expanded="false"
  aria-controls="filter-panel"
>
  Filters
</button>

<div id="filter-panel" hidden>
  <!-- Filters -->
</div>
```

这里存在从 button 到 filter-panel 的控制关系。

但是：

- 不会自动执行展开操作。
- 不会改变 DOM 结构。
- 不会自动移动焦点。
- 不会自动将目标元素变为该按钮的子元素。

### 9.4 aria-owns

这是一个更复杂、也更应该谨慎使用的属性。

它用于在 DOM 层级无法表达正确所属关系时，建立 Accessibility Tree 中的逻辑父子关系。

假设某个 Listbox 的 option 因为特殊渲染机制出现在其他位置：

```html
<div
  role="listbox"
  aria-label="Sizes"
  aria-owns="size-s size-m size-l"
></div>

<div id="size-s" role="option">S</div>
<div id="size-m" role="option">M</div>
<div id="size-l" role="option">L</div>
```

这几个 option 并不是 listbox 的 DOM 子元素，但 aria-owns 可以表达其无障碍所属关系。

实际开发中，优先通过正确的 DOM 嵌套建立关系。

尤其需要注意，现代 Combobox 通常使用 `aria-controls` 关联弹出列表，不应该机械地使用早期实现中的 `aria-owns`。

### 9.5 四种属性对比

| 属性 | 核心职责 |
|---|---|
| `aria-expanded` | 当前是否展开 |
| `aria-haspopup` | 可以打开什么类型的弹出组件 |
| `aria-controls` | 控制哪个元素 |
| `aria-owns` | 哪些元素在语义上属于自己 |

这几个属性可能同时出现在一个复杂组件中，但每个属性都有自己的职责。

## 10. aria-hidden、aria-disabled、aria-readonly、aria-required

前面的课程中已经分别介绍过这些属性，这里从 ARIA 状态体系的角度统一理解。

| ARIA 属性 | 表达含义 | 不会自动实现的行为 |
|---|---|---|
| `aria-hidden` | 从辅助技术中隐藏 | 视觉隐藏、禁止点击 |
| `aria-disabled` | 控件不可用 | 禁止点击、禁止聚焦 |
| `aria-readonly` | 控件只读 | 禁止用户编辑 |
| `aria-required` | 控件必填 | 表单必填验证 |
| `aria-invalid` | 当前值无效 | 输入验证、阻止提交 |
| `aria-modal` | 当前对话框为模态 | 背景隔离、焦点限制 |

这些属性有一个共同特点：它们负责表达语义，不负责实现实际行为。

### 10.1 原生 HTML 与 ARIA 对照

| 原生 HTML | 对应的 ARIA 语义 |
|---|---|
| `disabled` | `aria-disabled="true"` |
| `readonly` | `aria-readonly="true"` |
| `required` | `aria-required="true"` |
| `checked` | `aria-checked="true"` |
| `selected` | `aria-selected="true"` |
| `<details open>` | 展开状态 |

这两列表示相关的语义，并不代表实际功能完全等价。

例如下面的写法存在状态冲突：

```html
<input
  type="checkbox"
  checked
  aria-checked="false"
>
```

HTML 表示已勾选，ARIA 却声明未勾选。

对于存在对应原生语义的 HTML 控件，应该通过原生属性管理状态，不要通过冲突的 ARIA 属性覆盖它。<Cite ref="turn697692search0"/>

### 10.2 ARIA 属性不是 HTML 布尔属性

这是一个非常容易被 JavaScript 开发者忽略的细节。

```javascript
button.setAttribute('aria-expanded', false);
```

最终 HTML 是：

```html
aria-expanded="false"
```

这是正确的。

但对于原生布尔属性：

```javascript
button.setAttribute('disabled', false);
```

最终 HTML 是：

```html
<button disabled="false">
  Add to cart
</button>
```

按钮仍然会被禁用，因为 disabled 是根据属性是否存在来判断状态的。

正确方式：

```javascript
button.disabled = false;
```

或者：

```javascript
button.removeAttribute('disabled');
```

同理，下面的代码也存在问题：

```javascript
button.toggleAttribute('aria-expanded');
```

toggleAttribute 会在存在与不存在之间切换属性，并不会自动生成合法的 `"true"` 和 `"false"`。

推荐：

```javascript
button.setAttribute(
  'aria-expanded',
  String(isOpen)
);
```

## 11. aria-busy、aria-live、aria-atomic、aria-relevant

这一组属性用于处理动态内容。

### 11.1 aria-busy

表示某个元素或区域正在更新。

例如 Shopify Collection AJAX 筛选：

```html
<div id="product-grid" aria-busy="false">
  <!-- Products -->
</div>
```

请求开始：

```javascript
productGrid.setAttribute('aria-busy', 'true');
```

更新完成：

```javascript
productGrid.innerHTML = newHTML;

productGrid.setAttribute('aria-busy', 'false');
```

aria-busy 可以帮助辅助技术判断当前区域的更新是否已经完成，并可能延迟对更新内容的通知。

但是它不会：

- 自动展示 Loading Spinner。
- 自动禁用控件。
- 自动发起或者取消网络请求。
- 保证屏幕阅读器主动播报 Loading。

所以，如果希望明确通知用户正在加载，还需要提供适当的状态消息。

### 11.2 Collection 筛选交互演示

  <grid columns={2}>
    <grid-item><button block variant="outline" color="secondary" disabled={loading} onClick={()=>setLoading(true)}>开始请求</button></grid-item>
    <grid-item><button block disabled={!loading} onClick={()=>{setLoading(false);setFiltered(true)}}>模拟请求完成</button></grid-item>
  </grid>
  <divider/>
  <row>
    <caption>Product grid</caption>
    <spacer/>
    <text size="sm">{`aria-busy="${loading}"`}</text>
  </row>
  <row align="start">
    <icon name="volume-2"/>
    <box flex={1} gap={1}>
      <caption>独立的 Live Region 消息</caption>
      <text size="sm">{loading?"Loading products.":filtered?"8 products found.":"等待筛选操作。"}</text>
    </box>
  </row>
  <button block variant="ghost" color="secondary" onClick={()=>{setLoading(false);setFiltered(false)}}>重置</button>
  <caption>手动模拟 AJAX 请求的两个阶段，不会发送真实网络请求。</caption>
</card>

### 11.3 Live Region 相关属性预览

| 属性 | 作用 |
|---|---|
| `aria-live` | 动态消息的通知优先级 |
| `aria-atomic` | 更新时是否读取整个区域 |
| `aria-relevant` | 哪些类型的变化需要通知 |
| `aria-busy` | 区域是否正在更新 |

例如：

```html
<div
  id="cart-status"
  aria-live="polite"
  aria-atomic="true"
></div>
```

```javascript
cartStatus.textContent =
  'Cotton T-shirt added to your cart.';
```

这套机制将在第 14 课深入讲解，包括为什么某些 Live Region 明明设置正确，却没有被屏幕阅读器播报。

## 12. 数值型、方向型和集合型 ARIA 属性

除了前面常见的状态属性，ARIA 还提供了一些更加专业的组件描述能力。

### 12.1 aria-valuemin、aria-valuemax、aria-valuenow、aria-valuetext

主要用于 slider、spinbutton、progressbar 等数值型组件。

例如自定义 Collection 价格筛选 Slider：

```html
<div
  role="slider"
  tabindex="0"
  aria-label="Maximum price"
  aria-valuemin="0"
  aria-valuemax="500"
  aria-valuenow="150"
  aria-valuetext="150 dollars"
></div>
```

{@body const [price,setPrice]=DIL.useState(150)}
<card gap={3}>
  <row align="center">
    **Maximum price**
    <spacer/>
    <title size="xl">${price}</title>
  </row>
  <slider min={0} max={500} step={10} value={price} onChange={setPrice} marks={[{value:0,label:"$0"},{value:250,label:"$250"},{value:500,label:"$500"}]}/>
  <divider/>
  **Accessibility Properties**
  {#each [["Role","slider"],["Name","Maximum price"],["aria-valuemin","0"],["aria-valuemax","500"],["aria-valuenow",String(price)],["aria-valuetext",`${price} dollars`]] as p}
    <row><caption>{p[0]}</caption><spacer/><text size="sm">{p[1]}</text></row>
  {/each}
  <row align="center">
    <icon name="volume-2"/>
    <text size="sm">Maximum price, slider, {price} dollars.</text>
  </row>
</card>

其中：

- `aria-valuenow` 表达实际数值。
- `aria-valuetext` 表达更容易理解的文本形式。

例如商品尺寸滑块内部使用 1、2、3、4 表示不同尺寸，可以使用 `aria-valuetext="Medium"`，而不是让用户只能听到数字 2。

对于普通单滑块，仍然建议优先使用原生 HTML：

```html
<label for="max-price">Maximum price</label>

<input
  type="range"
  id="max-price"
  min="0"
  max="500"
  step="10"
  value="150"
>
```

浏览器已经能够从 min、max、value 中获取相应的无障碍数值。

### 12.2 aria-orientation

用于表达支持该属性的组件的排列方向。

<grid columns={2} gap={3}>
  <grid-item>
    <box border radius="md" padding={3} gap={2}>
      <caption>horizontal</caption>
      <row gap={1}>
        {#each ["A","B","C"] as t,i}
          <box flex={1} border radius="sm" padding={2} align="center" background={i===0?"surface-tertiary":"surface"}>{t}</box>
        {/each}
      </row>
      <row justify="center"><icon name="arrow-left"/><icon name="arrow-right"/></row>
      <caption>通常使用左右方向键。</caption>
    </box>
  </grid-item>
  <grid-item>
    <box border radius="md" padding={3} gap={2}>
      <caption>vertical</caption>
      {#each ["A","B","C"] as t,i}
        <box border radius="sm" padding={1} align="center" background={i===0?"surface-tertiary":"surface"}>{t}</box>
      {/each}
      <row justify="center"><icon name="arrow-up"/><icon name="arrow-down"/></row>
      <caption>通常使用上下方向键。</caption>
    </box>
  </grid-item>
</grid>

例如纵向 Tabs：

```html
<div
  role="tablist"
  aria-label="Account settings"
  aria-orientation="vertical"
>
  <!-- Tabs -->
</div>
```

`aria-orientation` 不会改变 CSS 布局，也不会自动更改键盘事件逻辑。

### 12.3 aria-posinset 与 aria-setsize

这两个属性主要用于表达元素在集合中的位置和集合的总大小。

例如虚拟列表中有 1000 个选项，但 DOM 中只渲染了其中 10 个。

```html
<div role="listbox" aria-label="Products">

  <div
    role="option"
    aria-posinset="101"
    aria-setsize="1000"
    aria-selected="false"
  >
    Product 101
  </div>

  <div
    role="option"
    aria-posinset="102"
    aria-setsize="1000"
    aria-selected="false"
  >
    Product 102
  </div>

</div>
```

辅助技术可以知道当前元素在完整逻辑集合中的位置，而不是仅根据 DOM 中实际存在的几个元素计算。

| 属性 | 含义 |
|---|---|
| `aria-posinset` | 当前元素在集合中的位置，从 1 开始 |
| `aria-setsize` | 集合总大小，未知时可使用 -1 |
| `aria-level` | 标题或树形等结构中的层级 |
| `aria-rowcount` | 表格或网格的总行数 |
| `aria-rowindex` | 当前行在完整结构中的位置 |

这些属性对于 Virtual List、Tree View、复杂数据网格等组件非常有价值。

如果浏览器已经能够根据完整的 DOM 结构计算这些信息，通常不需要额外手动声明。

## 13. role="presentation" 与 role="none"

这两个 Role 具有相同的语义用途：移除元素自身不需要的结构语义。

它们与 aria-hidden 有本质区别。

例如：

```html
<ul role="presentation">
  <li>
    <a href="/collections/clothing">
      Clothing
    </a>
  </li>

  <li>
    <a href="/collections/sale">
      Sale
    </a>
  </li>
</ul>
```

在这个例子中，列表及其相关列表项的结构语义会被移除，但内部链接仍然可以被辅助技术访问。

{@body const [semanticMode,setSemanticMode]=DIL.useState("normal")}
<card gap={3}>
  **语义隐藏实验室**
  <radio-group direction="col" value={semanticMode} onChange={setSemanticMode}>
    <radio value="normal">普通 ul 列表</radio>
    <radio value="presentation">ul role="presentation"</radio>
    <radio value="hidden">ul aria-hidden="true"</radio>
  </radio-group>
  <grid columns={2} gap={2}>
    <grid-item>
      <box border radius="md" padding={3} gap={2}>
        <caption>视觉页面</caption>
        <text size="sm" underline={true}>• Clothing</text>
        <text size="sm" underline={true}>• Sale</text>
      </box>
    </grid-item>
    <grid-item>
      <box border radius="md" padding={3} gap={2}>
        <caption>Accessibility Tree</caption>
        {#if semanticMode==="normal"}
          <text size="sm">list</text>
          <box padding={{left:2}} gap={1}>
            <text size="xs">listitem</text>
            <box padding={{left:2}}><text size="xs">link "Clothing"</text></box>
            <text size="xs">listitem</text>
            <box padding={{left:2}}><text size="xs">link "Sale"</text></box>
          </box>
        {:else if semanticMode==="presentation"}
          <text size="sm">link "Clothing"</text>
          <text size="sm">link "Sale"</text>
        {:else}
          <caption>整个列表子树应被隐藏。</caption>
        {/if}
      </box>
    </grid-item>
  </grid>
  {#if semanticMode==="hidden"}
    <text color="danger" size="sm">这是错误用法示范：内部链接仍然可能获得键盘焦点，浏览器也可能针对焦点冲突采取保护措施。</text>
  {:else if semanticMode==="presentation"}
    <caption>列表语义被移除，但链接语义仍然存在。</caption>
  {:else}
    <caption>完整保留列表及链接语义。</caption>
  {/if}
</card>

| 对比项 | role="presentation" / none | aria-hidden="true" |
|---|---|---|
| 移除自身语义 | 是 | 是 |
| 移除所有子元素语义 | 通常否，有结构性例外 | 是 |
| 保留文字内容 | 通常是 | 通常否 |
| 改变视觉表现 | 否 | 否 |
| 自动禁止键盘操作 | 否 | 否 |

浏览器也存在相关冲突处理规则。例如在可聚焦元素上设置 presentation 时，浏览器可能忽略这个 Role，保留原来的语义。<Cite ref="turn697692search16"/>

因此，不要通过 role="presentation" 来隐藏按钮或其他交互控件。

### 13.1 Children Presentational

ARIA 中还有一个相关概念，叫 Children Presentational。

某些角色的后代元素不会作为独立的语义结构暴露给辅助技术。

例如：

```html
<button type="button">
  <h3>Add to cart</h3>
</button>
```

这本身不是合理的 HTML 结构。即使浏览器进行解析，内部标题通常也不会成为独立的 heading 节点，而是参与按钮名称计算。

简化后的无障碍结果：

```text
button "Add to cart"
```

常见具有此类特征的角色包括 button、checkbox、radio、switch、tab、slider、progressbar、img 等。

所以不要尝试在一个普通按钮内部再构建具有独立语义的复杂交互组件，也不要在 listbox 的 option 内嵌套多个独立操作按钮。

如果一个选项确实需要多个内部交互目标，可能需要重新选择组件模式。

## 14. ARIA 与 JavaScript：如何保持状态同步？

这是实际业务开发中非常重要的工程设计问题。

假设我们有一个自定义 Disclosure 组件。

不推荐分别维护多个独立状态：

```javascript
let isVisible = false;
let isExpanded = false;
let isHiddenFromScreenReader = true;
```

如果某次更新只修改了其中一个状态，就可能造成：

```text
视觉：已展开
ARIA：未展开
键盘：可以访问
辅助技术：无法访问
```

比较合理的方案是采用 Single Source of Truth（单一状态来源）。

<box border radius="lg" padding={3} gap={3}>
  <box border={{size:1,color:"#5185C5"}} background="#5185C510" radius="md" padding={3} align="center">
    **业务状态**
    <title size="xl">isOpen</title>
  </box>
  <box align="center"><icon name="arrow-down" color="secondary"/></box>
  <grid columns={2} gap={2}>
    {#each [{t:"CSS",d:"展开样式、动画"},{t:"HTML",d:"hidden、inert"},{t:"ARIA",d:"aria-expanded"},{t:"JavaScript",d:"键盘交互、业务行为"}] as p}
      <grid-item>
        <box border radius="md" padding={3} gap={1}>
          **{p.t}**
          <caption>{p.d}</caption>
        </box>
      </grid-item>
    {/each}
  </grid>
  <caption>所有表现都从同一业务状态推导，而不是各自维护。</caption>
</box>

### 14.1 原生 JavaScript 实现

```html
<button
  id="filter-toggle"
  type="button"
  aria-expanded="false"
  aria-controls="filter-panel"
>
  Filters
</button>

<div id="filter-panel" hidden>
  <!-- Filter controls -->
</div>
```

```javascript
const button = document.querySelector('#filter-toggle');
const panel = document.querySelector('#filter-panel');

let isOpen = false;

function render() {
  if (
    !isOpen &&
    panel.contains(document.activeElement)
  ) {
    button.focus();
  }

  button.setAttribute(
    'aria-expanded',
    String(isOpen)
  );

  panel.hidden = !isOpen;
}

function setOpen(nextState) {
  isOpen = nextState;

  render();
}

button.addEventListener('click', () => {
  setOpen(!isOpen);
});

render();
```

甚至可以直接通过 ARIA 状态控制 CSS：

```css
.filter-toggle[aria-expanded="true"] .icon {
  transform: rotate(180deg);
}
```

这样就不需要额外维护一个表示相同状态的 `.is-expanded` class。

### 14.2 React 中的实现

```jsx
function Disclosure({ children }) {
  const [isOpen, setIsOpen] = useState(false);
  const panelId = useId();

  return (
    <>
      <button
        type="button"
        aria-expanded={isOpen}
        aria-controls={panelId}
        onClick={() => setIsOpen(v => !v)}
      >
        Filters
      </button>

      <div id={panelId} hidden={!isOpen}>
        {children}
      </div>
    </>
  );
}
```

在 React 中，ARIA 属性同样应该由组件的实际业务状态推导。

这个示例只包含基本展开行为。如果组件还允许通过外部事件关闭，并且关闭时焦点可能位于内部，则需要补充上一课学习的焦点恢复机制。

## 15. ARIA 的五条经典使用原则

早期 W3C Using ARIA 指南中的五条原则非常值得记忆。目前这份历史文档已停止维护，保留了四条规则；这里将可访问名称要求一起整理为日常开发的五条工程原则。<Cite refs={["turn697692search5","turn126013search6"]}/>

<box border radius="lg" padding={3} gap={3}>
  {#each [{n:1,t:"Native HTML First",d:"如果原生 HTML 已经能够提供所需语义和行为，优先使用原生 HTML。",code:"<button> 优于 div + role=button"},{n:2,t:"Don't Change Native Semantics Unnecessarily",d:"不要在没有必要的情况下改变原生元素的语义。",code:"不要把普通标题随意改成 button"},{n:3,t:"Keyboard Accessible",d:"所有交互型 ARIA 控件必须具有对应的键盘操作能力。",code:"role=button 还需要 Enter / Space 行为"},{n:4,t:"Don't Hide Focusable Elements",d:"不要将仍可聚焦的控件从辅助技术中隐藏。",code:"避免 button + aria-hidden=true"},{n:5,t:"Accessible Name",d:"所有需要名称的交互控件都应该拥有明确且准确的可访问名称。",code:"纯图标按钮需要有效名称"}] as r}
    <row align="start" gap={3}>
      <box background="surface-tertiary" size="30px" radius="md" align="center" justify="center">**{r.n}**</box>
      <box flex={1} gap={2}>
        **{r.t}**
        <text size="sm">{r.d}</text>
        <box background="surface-tertiary" radius="sm" padding={2}><text size="xs">{r.code}</text></box>
      </box>
    </row>
  {/each}
</box>

WAI-ARIA APG 还有一句非常著名的原则：

**No ARIA is better than Bad ARIA.**

错误的 ARIA 有时比不使用 ARIA 更糟糕，因为它可能向辅助技术用户提供错误的角色、状态或者操作预期。<Cite ref="turn697692search23"/>

例如一个普通导航链接本来完全可以正常工作：

```html
<a href="/collections/all">
  Products
</a>
```

开发者为了所谓的无障碍优化，改成：

```html
<a
  href="/collections/all"
  role="menuitem"
  aria-selected="true"
>
  Products
</a>
```

反而可能破坏原来合理的链接语义，并引入角色上下文及状态属性错误。

## 16. Shopify Theme 常见 ARIA 错误及修复

### 16.1 Mega Menu 错误使用 ARIA Menu

不推荐：

```liquid
<nav role="menu">
  {% for link in section.settings.menu.links %}
    <a
      role="menuitem"
      href="{{ link.url }}"
    >
      {{ link.title | escape }}
    </a>
  {% endfor %}
</nav>
```

普通网站导航通常应该使用：

```liquid
<nav aria-label="Main">
  <ul>
    {% for link in section.settings.menu.links %}
      <li>
        <a
          href="{{ link.url }}"
          {% if link.current %}
            aria-current="page"
          {% endif %}
        >
          {{ link.title | escape }}
        </a>
      </li>
    {% endfor %}
  </ul>
</nav>
```

如果存在子导航，可以通过 Disclosure Pattern 实现展开与折叠，而不必使用完整的 ARIA Menu 模式。

### 16.2 Variant Picker 使用错误的状态属性

<box border radius="lg" padding={3} gap={2}>
  **Size: M**
  <row gap={2}>
    {#each ["S","M","L","XL"] as s,i}
      <box flex={1} border={{size:i===1?2:1,color:i===1?"#333333":"#88888850"}} radius="sm" padding={3} align="center">
        <row align="center" gap=1>
          {#if i===1}<icon name="check" size="xs"/>{/if}
          {s}
        </row>
      </box>
    {/each}
  </row>
  <caption>单选型商品尺寸选择器。</caption>
</box>

不推荐：

```html
<button aria-selected="true">M</button>
```

更合理的是使用原生 Radio Group：

```liquid
<fieldset>
  <legend>Size</legend>

  {% for value in option.values %}
    <label>
      <input
        type="radio"
        name="Size-{{ section.id }}"
        value="{{ value | escape }}"
        {% if value == option.selected_value %}
          checked
        {% endif %}
      >

      {{ value | escape }}
    </label>
  {% endfor %}
</fieldset>
```

这里省略了真实商品变体选择器中的产品表单绑定、多个商品实例的唯一标识、库存判断及变体更新逻辑，主要展示单选语义。

原生 radio 已经能够提供 checked 状态和基础键盘导航，因此不需要自己重复构建 ARIA Radio Group。

### 16.3 aria-label 覆盖可见文字

```html
<button aria-label="Purchase product">
  Add to cart
</button>
```

视觉用户看到的是 Add to cart，但辅助技术获得的名称可能是 Purchase product。

这还可能导致语音控制用户无法通过可见文字定位按钮，涉及 WCAG 2.5.3 Label in Name。

可以改为：

```html
<button>
  Add to cart
</button>
```

或者需要区分不同商品时：

```html
<button aria-label="Add to cart: Cotton T-shirt">
  Add to cart
</button>
```

这样可访问名称仍然包含可见文字。

### 16.4 常见错误汇总

| 错误实现 | 推荐处理 |
|---|---|
| 普通商品 Grid 使用 `role="grid"` | 使用正常列表语义 |
| 普通导航使用 `role="menu"` | 使用 nav、链接和 Disclosure |
| 收藏按钮使用 `aria-selected` | 使用 `aria-pressed` |
| 商品尺寸使用无语义 div | 使用原生 radio |
| Cart Drawer 使用 `aria-haspopup="true"` | 根据实际角色使用 dialog |
| `aria-modal` 代替焦点隔离 | 使用原生 dialog 或完整模态逻辑 |
| `aria-controls` 指向不存在的 ID | 建立有效的引用关系 |
| AJAX 更新后 ARIA 状态不变 | 根据业务状态同步更新 |
| 普通 div 随意设置 `aria-label` | 选择允许命名且符合用途的语义 |
| 原生 checked 与 aria-checked 冲突 | 使用原生状态 |

## 17. ARIA 的 JavaScript DOM API

除了常见的 setAttribute、getAttribute，现代浏览器还提供了 ARIA 属性反射 API。

### 17.1 传统方式

```javascript
element.setAttribute('aria-expanded', 'true');

element.getAttribute('aria-expanded');

element.removeAttribute('aria-expanded');
```

### 17.2 ARIA Reflection

```javascript
element.ariaExpanded = 'true';

element.ariaPressed = 'false';

element.ariaLabel = 'Open shopping cart';

element.ariaBusy = 'true';
```

对应关系如下：

| HTML Attribute | DOM Property |
|---|---|
| `aria-label` | `ariaLabel` |
| `aria-expanded` | `ariaExpanded` |
| `aria-pressed` | `ariaPressed` |
| `aria-checked` | `ariaChecked` |
| `aria-hidden` | `ariaHidden` |
| `aria-busy` | `ariaBusy` |
| `aria-selected` | `ariaSelected` |
| `aria-current` | `ariaCurrent` |

例如：

```javascript
button.ariaExpanded = 'true';

console.log(
  button.getAttribute('aria-expanded')
);

// "true"
```

使用这些 API 前，可以针对目标浏览器进行特性检测：

```javascript
if ('ariaExpanded' in button) {
  button.ariaExpanded = String(isOpen);
} else {
  button.setAttribute(
    'aria-expanded',
    String(isOpen)
  );
}
```

对于需要覆盖较广浏览器版本的 Shopify Theme，传统 setAttribute 方案仍然十分实用。

### 17.3 Boolean 转换陷阱

注意，很多 ARIA 状态通过字符串表示。

```javascript
const expanded = Boolean(
  button.getAttribute('aria-expanded')
);
```

这段代码存在问题。

因为：

```javascript
Boolean('false'); // true
```

正确方式：

```javascript
const expanded =
  button.getAttribute('aria-expanded') === 'true';
```

## 18. 如何检测网站中的 ARIA 使用错误？

### 18.1 获取页面所有显式 ARIA 声明

在 Chrome DevTools Console 中执行：

```javascript
const elements = [...document.querySelectorAll('*')];

const result = elements
  .map(element => {
    const attributes = [...element.attributes]
      .filter(attr =>
        attr.name === 'role' ||
        attr.name.startsWith('aria-')
      );

    return {
      element,

      attributes: Object.fromEntries(
        attributes.map(attr => [
          attr.name,
          attr.value
        ])
      )
    };
  })
  .filter(item =>
    Object.keys(item.attributes).length > 0
  );

console.log(result);
```

可以快速查看当前页面的显式 Role 和 ARIA 属性。

但这里获取的是 HTML 声明，而不是浏览器最终计算后的 Accessibility Tree。

### 18.2 检测失效的 ARIA ID 引用

```javascript
const relationAttributes = [
  'aria-controls',
  'aria-owns',
  'aria-labelledby',
  'aria-describedby',
  'aria-errormessage',
  'aria-activedescendant',
  'aria-details',
  'aria-flowto'
];

const problems = [];

relationAttributes.forEach(attribute => {
  document.querySelectorAll(`[${attribute}]`)
    .forEach(element => {
      const ids = element
        .getAttribute(attribute)
        .trim()
        .split(/\s+/)
        .filter(Boolean);

      ids.forEach(id => {
        if (!document.getElementById(id)) {
          problems.push({
            element,
            attribute,
            missingId: id
          });
        }
      });
    });
});

console.table(problems);
```

这个脚本特别适合排查普通 DOM 环境中，Shopify Section Rendering 更新后产生的无效引用。

不过，存在对应 ID 并不意味着引用一定符合规范。还需要检查目标角色、所属关系和实际业务状态。Shadow DOM 中的引用关系也需要单独处理。

### 18.3 axe 中常见的 ARIA 检测规则

| Rule ID | 检测内容 |
|---|---|
| `aria-roles` | Role 是否有效 |
| `aria-valid-attr` | ARIA 属性名称是否有效 |
| `aria-valid-attr-value` | 属性值是否合法 |
| `aria-allowed-attr` | 当前角色是否允许使用该属性 |
| `aria-required-attr` | 是否缺少必需属性 |
| `aria-required-children` | 是否缺少必要子角色 |
| `aria-required-parent` | 是否缺少必要父级角色 |
| `aria-hidden-focus` | 隐藏区域是否包含可聚焦控件 |
| `aria-prohibited-attr` | 是否使用禁止的属性 |

第 24 课会详细讲解如何使用 axe 进行实际网站的无障碍审计。
