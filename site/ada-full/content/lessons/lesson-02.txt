## 1. 什么是辅助技术？

Assistive Technology，简称 AT，指帮助残障人士获取信息、操作设备和使用软件的硬件或软件。

屏幕阅读器只是辅助技术中的一种。

这也说明了一个问题：**无障碍开发并不等于针对屏幕阅读器进行开发。**

即使网站能够被屏幕阅读器正确识别，也可能存在颜色对比度、缩放、键盘操作等其他无障碍问题。

## 2. 屏幕阅读器到底在读什么？

很多前端开发者最初会认为，屏幕阅读器就是一个将网页文字转换成语音的软件。

实际上，它需要获取的信息远比文字丰富。

例如：

```html
<button type="button" disabled>
  Add to cart
</button>
```

屏幕阅读器可能会播报：

> Add to cart, button, unavailable.

即：添加到购物车，按钮，不可用。

它不仅获取了文字，还获取了元素的类型和当前状态。

对于前端开发来说，我们需要特别关注元素的五类信息：

| 信息 | 含义 | 示例 |
|---|---|---|
| Role | 元素是什么 | button、link、checkbox |
| Name | 元素叫什么 | Add to cart |
| Description | 补充说明 | Minimum order quantity is 2 |
| State / Property | 元素的状态或属性 | disabled、expanded、required |
| Value | 元素当前的值 | 输入框内容、滑块数值 |

这些信息决定了辅助技术如何理解一个页面。

### 2.1 相同的视觉效果，不同的无障碍表现

例如，我们使用三种方式实现一个外观完全一样的按钮。

```html
<!-- 方案 A -->
<div onclick="addToCart()">Add to cart</div>

<!-- 方案 B -->
<div role="button" onclick="addToCart()">
  Add to cart
</div>

<!-- 方案 C -->
<button type="button" onclick="addToCart()">
  Add to cart
</button>
```

  {#each [{tag:"方案 A：div",role:"generic 或普通文本",focus:false,keyboard:false},{tag:"方案 B：div + role",role:"button",focus:false,keyboard:false},{tag:"方案 C：原生 button",role:"button",focus:true,keyboard:true}] as item}
    <box gap={2}>
      <row align="center">
        **{item.tag}**
        <spacer/>
        <box background="#202020" theme="dark" radius="md" padding={{x:4,y:2}}>
          <text color="#FFFFFF" weight="medium" size="sm">Add to cart</text>
        </box>
      </row>
      <box background="surface-tertiary" radius="md" padding={3} gap={1}>
        <row><caption>Role</caption><spacer/><text size="sm">{item.role}</text></row>
        <row><caption>Tab 键访问</caption><spacer/><icon name={item.focus?"check-circle":"x-circle"} color={item.focus?"success":"danger"}/></row>
        <row><caption>原生键盘激活</caption><spacer/><icon name={item.keyboard?"check-circle":"x-circle"} color={item.keyboard?"success":"danger"}/></row>

    </box>
  {/each}
</box>

方案 B 虽然通过 `role="button"` 补充了按钮语义，但是它仍然不是一个真正具备原生交互能力的按钮。

如果坚持使用 `div`，通常还需要自己实现：

```html
<div role="button" tabindex="0">
  Add to cart
</div>
```

以及 Enter、Space 键处理、禁用行为、焦点样式等逻辑。

而原生 `button` 已经提供了大量基础能力。

**这就是为什么无障碍开发始终强调 Native HTML First（原生 HTML 优先）。**

## 3. 主流屏幕阅读器有哪些？

| 屏幕阅读器 | 支持平台 | 收费情况 |
|---|---|---|
| [NVDA](https://www.nvaccess.org/) | Windows | 免费、开源 |
| [JAWS](https://www.freedomscientific.com/products/software/jaws/) | Windows | 商业软件 |
| VoiceOver | macOS、iOS | 系统内置 |
| TalkBack | Android | 免费 |
| Narrator（讲述人） | Windows | 系统内置 |
| ChromeVox | ChromeOS | 系统内置 |

需要注意，屏幕阅读器与浏览器之间存在兼容性差异。

同样的 HTML 代码，在不同的操作系统、浏览器、屏幕阅读器组合下，可能产生不同的播报效果。

在实际项目中，我建议至少覆盖以下测试组合：

| 操作系统 | 浏览器 | 屏幕阅读器 |
|---|---|---|
| Windows | Chrome | NVDA |
| Windows | Firefox | NVDA |
| Windows | Chrome / Edge | JAWS |
| macOS | Safari | VoiceOver |
| iOS | Safari | VoiceOver |
| Android | Chrome | TalkBack |

你目前使用 Windows 电脑，同时有 iPhone，因此可以优先使用 **NVDA + Chrome** 进行桌面端测试，再使用 iPhone 自带的 VoiceOver 进行移动端测试。

不需要一开始就购买 JAWS。

### 4.1 Browse Mode（浏览模式）

假设现在有一个商品详情页：

  <text size="sm">Made from 100% soft cotton. Designed for everyday comfort.</text>

普通用户打开页面后，可以通过视觉快速了解页面结构。

但如果屏幕阅读器用户只能使用 Tab 键逐个访问元素，那么他可能需要经过大量导航链接和按钮，才能找到想要阅读的商品信息。

因此，屏幕阅读器提供了基于语义的快速导航能力。

在 NVDA 的浏览模式下：

| 按键 | 功能 |
|---|---|
| `H` | 跳转到下一个标题 |
| `1` | 跳转到下一个一级标题 |
| `2` | 跳转到下一个二级标题 |
| `B` | 跳转到下一个按钮 |
| `K` | 跳转到下一个链接 |
| `G` | 跳转到下一个图形 |
| `E` | 跳转到下一个文本输入框 |
| `F` | 跳转到下一个表单控件 |
| `R` | 跳转到下一个单选按钮 |
| `X` | 跳转到下一个复选框 |
| `D` | 跳转到下一个地标区域 |
| `T` | 跳转到下一个表格 |
| `L` | 跳转到下一个列表 |

配合 `Shift` 可以向相反方向导航。<Cite ref="turn350539view0"/>

例如，用户想直接找到加购按钮，只需要使用 `B` 键导航到对应按钮即可。

现在你应该能够理解为什么 HTML 语义化如此重要了。

如果我们把所有标题都写成：

```html
<div class="heading">Cotton T-shirt</div>

<div class="heading">Product description</div>

<div class="heading">Shipping & Returns</div>
```

即使通过 CSS 将它们设计成了标题样式，屏幕阅读器仍然无法将它们当作标题进行快速导航。

正确的方式是：

```html
<h1>Cotton T-shirt</h1>

<h2>Product description</h2>

<h2>Shipping & Returns</h2>
```

**HTML 语义不仅影响屏幕阅读器播报的内容，还直接决定了用户能够使用哪些导航方式。**

### 4.3 Focus Mode（焦点模式）

假设用户现在找到了一个搜索输入框：

```html
<label for="search">Search products</label>

<input
  type="search"
  id="search"
  name="q"
>
```

用户准备输入 `hat`。

但是在浏览模式下，`H` 代表跳转到标题，`T` 代表跳转到表格。

如果屏幕阅读器一直拦截这些按键，用户就无法正常输入文字。

这时就需要切换到焦点模式。

NVDA 在进入某些输入框、下拉选择框等控件时，会根据元素类型、用户操作和设置自动切换模式。

用户也可以通过 `NVDA + Space` 手动切换浏览模式与焦点模式。<Cite ref="turn902691search1"/>

这种模式切换在以下组件中特别重要：

- Combobox 搜索建议框
- Listbox 列表选择器
- Slider 滑块
- 富文本编辑器
- 自定义日期选择器
- Grid 交互式数据表格

当你使用正确的原生 HTML 或 ARIA Role 时，辅助技术才能更准确地判断当前组件的类型，并为用户提供合适的操作方式。

## 5. Virtual Cursor（虚拟光标）与 DOM Focus

这一部分涉及一个非常容易被前端开发人员忽略的概念。

我们平时所说的焦点，通常指 DOM Focus。

例如：

```javascript
document.activeElement
```

或者：

```javascript
element.focus();
```

但是屏幕阅读器在浏览网页时，还可以维护自己的阅读位置，也就是 Virtual Cursor（虚拟光标）。

### 5.1 两者有什么区别？

假设网页中有以下内容：

```html
<h1>Product details</h1>

<p>Made from 100% cotton.</p>

<p>Machine washable.</p>

<button>Add to cart</button>

<a href="/collections/all">Continue shopping</a>
```

如果使用普通的 Tab 键导航，通常只会停留在按钮和链接上。

但屏幕阅读器的虚拟光标可以访问标题、段落等非交互内容。

    <row align="center" gap={1}><box size="10px" background="#39866B" radius="sm"/><caption>Virtual Cursor</caption></row>
  </row>
  {#each items as item,i}
    <row align="center" gap={2}>
      <box width="52px" align="end">
        {#if domPos===i}<text color="#5185C5" size="xs" weight="medium">Focus →</text>{/if}
      </box>
      <box flex={1} border={{size:domPos===i?2:1,color:domPos===i?"#5185C5":virtualPos===i?"#39866B":"#88888840"}} background={virtualPos===i?"#39866B17":"surface"} radius="md" padding={2}>
        <caption>{item.tag}</caption>
        <text weight={item.tag==="h1"?"medium":"normal"}>{item.name}</text>
      </box>
      <box width="52px">
        {#if virtualPos===i}<text color="#39866B" size="xs" weight="medium">← Cursor</text>{/if}
      </box>
    </row>
  {/each}
  <grid columns={2}>
    <grid-item><button block color="secondary" variant="outline" onClick={()=>setDomPos(v=>v===3?4:3)}>Tab · 移动焦点</button></grid-item>
    <grid-item><button block color="secondary" variant="outline" onClick={()=>setVirtualPos(v=>(v+1)%5)}>↓ · 移动虚拟光标</button></grid-item>
  </grid>
  <button variant="ghost" color="secondary" block onClick={()=>{setDomPos(-1);setVirtualPos(-1)}}>重置</button>
  <divider/>
  <caption>简化演示两种位置的区别。实际屏幕阅读器可能会根据导航操作同步阅读位置和 DOM 焦点。</caption>
</card>

两者的核心区别如下：

| 特性 | DOM Focus | Virtual Cursor |
|---|---|---|
| 管理者 | 浏览器 | 屏幕阅读器 |
| 主要用途 | 交互操作 | 阅读和导航 |
| 能访问普通段落 | 默认不能聚焦 | 可以阅读 |
| 能访问标题 | 默认不能聚焦 | 可以阅读 |
| 能访问按钮 | 可以 | 可以 |
| 能通过 JS 直接获取 | 可以 | 通常不可以 |
| 移动时触发 focus 事件 | 焦点变化时会触发 | 不一定 |
| 与 `document.activeElement` 一致 | 是 | 不一定 |

### 5.2 对前端开发有什么影响？

假设你希望屏幕阅读器用户能够阅读商品描述，于是这样写：

```html
<h1 tabindex="0">Product details</h1>

<p tabindex="0">Made from 100% cotton.</p>

<p tabindex="0">Machine washable.</p>
```

实际上，这是没有必要的。

普通文本不需要成为键盘焦点元素，也能够被屏幕阅读器阅读。

反而添加大量 `tabindex="0"` 会使正常键盘导航变得冗长。

所以请记住：

**可被屏幕阅读器阅读（Readable），不等于可聚焦（Focusable），也不等于可交互（Interactive）。**

| HTML 元素 | 可读取 | 默认可聚焦 | 原生可交互 |
|---|---|---|---|
| `h1` | 是 | 否 | 否 |
| `p` | 是 | 否 | 否 |
| `img`（有有效 alt） | 是 | 否 | 否 |
| `button` | 是 | 是 | 是 |
| `a`（有 href） | 是 | 是 | 是 |
| `input` | 是 | 是 | 是 |
| `button disabled` | 通常是 | 否 | 否 |

以上假设元素没有被隐藏，也没有其他改变其行为的属性。

## 6. 屏幕阅读器是如何感知动态内容的？

我们刚才介绍的主要是静态内容的阅读和导航。

但是现在的网站有大量动态内容，尤其是 Shopify Theme 开发中的：

- AJAX 加购
- Section Rendering
- Collection 异步筛选
- Predictive Search
- Variant 切换与价格更新

假设用户点击 Add to cart 按钮后，我们通过 JavaScript 更新页面中的购物车数量。

```html
<button id="add-to-cart">
  Add to cart
</button>

<span id="cart-count">0</span>
```

```javascript
document
  .querySelector('#add-to-cart')
  .addEventListener('click', () => {
    document.querySelector('#cart-count').textContent = '1';
  });
```

对于视觉用户而言，能够看到购物车数量已经从 0 变成了 1。

但是对于屏幕阅读器用户而言，如果当前焦点仍在加购按钮上，这个数量变化不一定会被自动播报。

用户可能根本不知道自己是否加购成功。

### 6.1 Live Region（实时区域）

ARIA 为我们提供了 Live Region 机制。

例如：

```html
<button id="add-to-cart">
  Add to cart
</button>

<span id="cart-count">0</span>

<div
  id="cart-status"
  role="status"
  class="visually-hidden"
></div>
```

在加购成功之后：

```javascript
document.querySelector('#cart-count').textContent = '1';

document.querySelector('#cart-status').textContent =
  'Cotton T-shirt added to your cart. Your cart has 1 item.';
```

`role="status"` 隐含了 `aria-live="polite"`，可以让辅助技术在合适的时机通知用户内容发生了变化。

通常应提前将这个空的状态区域放在 DOM 中，等操作成功后再更新它的文本。

### 6.2 两种方式的区别

{@body const [countA,setCountA]=DIL.useState(0)}
{@body const [countB,setCountB]=DIL.useState(0)}

## 7. 为什么不建议随意使用 role="application"？

理解了浏览模式和焦点模式之后，就能理解这个问题了。

有些开发人员在开发复杂的 SPA 应用时，可能会使用：

```html
<body role="application">
  <!-- 整个网站 -->
</body>
```

他们认为网站是一个 Web Application，因此应该使用这个 Role。

实际上，这通常是错误的做法。

`role="application"` 可能会使屏幕阅读器放弃常规的文档浏览模式，将更多键盘操作交给应用本身处理。

这意味着用户可能失去原本熟悉的标题导航、链接导航、段落阅读等操作方式。

| 普通网页 | role="application" 区域 |
|---|---|
| 屏幕阅读器提供文档导航 | 更多交互由应用自己负责 |
| 支持常规语义导航 | 部分常规导航可能受影响 |
| 使用标准 HTML 即可获得许多能力 | 开发者需要承担更多键盘交互责任 |

对于 Shopify 网站、普通 SPA、管理后台等，通常不应该仅仅因为它们属于 Web Application，就添加 `role="application"`。

这个 Role 应当仅在确实需要特殊交互模型的区域谨慎使用。

## 12. 本课总结

本节课最需要掌握的是以下六个概念。

| 核心概念 | 理解重点 |
|---|---|
| Assistive Technology | 屏幕阅读器只是辅助技术的一种 |
| Screen Reader | 不仅阅读文字，还获取语义、状态、属性 |
| Browse Mode | 阅读内容与基于语义的快速导航 |
| Focus Mode | 操作控件与输入信息 |
| Virtual Cursor | 屏幕阅读器维护的阅读位置 |
| Live Region | 通知辅助技术动态内容变化 |

尤其要记住以下几个开发原则：

- 优先使用原生 HTML 元素。
- 不要为了让屏幕阅读器读取文本而随意添加 `tabindex`。
- 不要将键盘可访问性与屏幕阅读器可访问性混为一谈。
- 不仅要保证用户能够操作，还要保证用户能够感知操作结果。
- 自动化检测不能替代真实辅助技术测试。
