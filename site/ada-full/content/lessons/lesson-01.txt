## 1. 什么是网站无障碍？

网站无障碍（Web Accessibility），简单来说，就是让具有不同身体条件、感知能力和操作能力的用户，都能够获取网站信息并使用网站功能。

对于一个电商网站，普通用户的操作流程可能是：

<box border radius="lg" padding={3} gap={1}>
  {#each ["浏览商品","查看商品详情","选择颜色、尺寸","添加到购物车","完成结算"] as step,i}
    <box background="surface" border radius="md" padding={2} align="center">
      **{step}**
    </box>
    {#if i<4}
      <box align="center"><icon name="arrow-down" color="secondary"/></box>
    {/if}
  {/each}
</box>

对于一位看不见屏幕、无法使用鼠标的用户，我们需要确保他同样能够独立完成上述流程，而不是只能访问其中某几个页面。

这就是无障碍开发的核心目标：**提供等价的信息和操作能力，而不是要求所有用户使用完全相同的交互方式。**

实际上，无障碍设计不仅服务于永久性残障用户，也服务于暂时性和情境性受限的用户。

| 永久性障碍 | 暂时性障碍 | 情境性障碍 |
|---|---|---|
| 单臂残障 | 手臂骨折 | 一只手抱着宝宝 |
| 低视力 | 眼部术后 | 阳光下看手机 |
| 听力障碍 | 耳部感染 | 嘈杂的公共场所 |
| 运动障碍 | 手部受伤 | 鼠标损坏 |

因此，无障碍并不是一个针对少数用户的额外功能，而是网站基础体验的一部分。

### 3.1 ADA

全称：Americans with Disabilities Act。

即《美国残疾人法案》，于 1990 年颁布。

**ADA 是法律，而不是前端技术规范。**

它要求适用范围内的组织不得歧视残障人士，应当提供平等获取商品、服务和信息的机会。

对于网站开发，我们主要关注：

| 分类 | 适用对象 |
|---|---|
| ADA Title I | 就业领域 |
| ADA Title II | 州和地方政府及公共服务 |
| ADA Title III | 面向公众提供服务的适用商业机构 |

跨境电商网站主要关注 Title III。

美国司法部认为 ADA 适用于相关机构的网站内容。但对于私人商业网站，具体法律适用范围还涉及司法辖区、经营模式等因素，不能简单理解为所有网站都被法律统一强制要求达到 WCAG 2.2 AA。

目前，美国司法部针对州和地方政府的 Title II 网站规则明确采用 WCAG 2.1 AA 作为技术标准，而 Title III 并没有一项同样普遍适用的具体网站技术标准规则。<Cite refs={["turn717238search2","turn717238search16"]}/>

因此，我们在实际开发中通常将 WCAG AA 作为重要的技术合规目标，但技术达标不等于获得法律免责。

### 3.3 WCAG

全称：Web Content Accessibility Guidelines。

由 W3C 制定，是网站无障碍开发最重要的技术标准之一。

主要版本如下：

| 版本 | 发布时间 | 主要特点 |
|---|---|---|
| WCAG 1.0 | 1999 年 | 早期网页无障碍规范 |
| WCAG 2.0 | 2008 年 | 建立四大核心原则 |
| WCAG 2.1 | 2018 年 | 加强移动端、低视力及认知障碍支持 |
| WCAG 2.2 | 2023 年 | 加强焦点、点击区域、拖拽及身份验证等要求 |

WCAG 将成功准则分为三个级别。<Cite refs={["turn717238search3","turn717238search4"]}/>

举几个具体的 WCAG 2.2 准则：

| 要求 | 编号 | 级别 |
|---|---|---|
| 非文本内容提供替代信息 | 1.1.1 | A |
| 支持键盘操作 | 2.1.1 | A |
| 不仅依靠颜色传递信息 | 1.4.1 | A |
| 普通文字对比度至少 4.5:1 | 1.4.3 | AA |
| 支持文字放大至 200% | 1.4.4 | AA |
| 键盘焦点可见 | 2.4.7 | AA |
| 焦点元素不被完全遮挡 | 2.4.11 | AA |
| 点击目标至少 24×24 CSS px，允许规定的例外 | 2.5.8 | AA |
| 普通文字对比度至少 7:1 | 1.4.6 | AAA |

以后我们收到一份 ADA 审计报告时，通常就可以根据这些编号找到对应的规范、失败原因和修复方案。

### 3.4 WAI-ARIA

全称：Web Accessibility Initiative – Accessible Rich Internet Applications。

它是一套补充 Web 元素无障碍语义的技术规范。

例如：

```html
<button
  aria-expanded="false"
  aria-controls="cart-drawer"
>
  Shopping Cart
</button>
```

其中：

`aria-expanded` 告诉辅助技术这个按钮控制的内容是否处于展开状态。

`aria-controls` 表示这个按钮与哪个元素存在控制关系。

ARIA 主要解决三个问题：

| 类型 | 作用 | 示例 |
|---|---|---|
| Role | 元素是什么 | `role="dialog"` |
| State | 元素当前是什么状态 | `aria-expanded` |
| Property | 元素具有什么属性或关系 | `aria-label` |

但是请从现在开始牢记一个非常重要的原则：

**ARIA 主要负责描述语义，而不是实现功能。**

例如 `aria-expanded="true"` 不会自动展开弹窗，`role="button"` 不会自动实现按钮的键盘交互。这些功能仍然需要原生 HTML 或 JavaScript 实现。

W3C 也强调，错误地使用 ARIA 比不使用 ARIA 更糟糕。<Cite ref="turn717238search0"/>

## 4. 无障碍开发究竟在开发什么？

假设我们现在要开发一个电商网站的购物车按钮。

### 4.1 普通开发方式

```html
<div class="cart-icon" onclick="openCart()">
  <svg>
    <!-- 购物车图标 -->
  </svg>
</div>
```

从普通用户的角度看，这段代码似乎没有任何问题。

用户可以看到购物车图标，点击之后也能够打开购物车。

但是从无障碍角度来看，就存在很多问题。

它存在以下问题：

- `div` 没有原生按钮语义。
- 元素默认无法通过 Tab 键获得焦点。
- 没有原生 Enter、Space 键激活行为。
- SVG 图标没有提供明确的功能名称。
- 辅助技术无法得知它控制的弹窗是否已经打开。

### 4.2 无障碍开发方式

```html
<button
  type="button"
  class="cart-icon"
  aria-label="Open shopping cart"
  aria-haspopup="dialog"
  onclick="openCart()"
>
  <svg aria-hidden="true" focusable="false">
    <!-- 购物车图标 -->
  </svg>
</button>
```

这里我们使用了原生的 `button` 元素，并补充了必要的 ARIA 属性。

| 代码 | 作用 |
|---|---|
| `button` | 提供原生按钮语义和键盘行为 |
| `type="button"` | 避免意外提交表单 |
| `aria-label` | 为纯图标按钮提供可访问名称 |
| `aria-haspopup="dialog"` | 表示按钮会打开一个对话框 |
| `aria-hidden="true"` | 将装饰性 SVG 从无障碍树中隐藏 |
| `focusable="false"` | 避免 SVG 在部分环境中获得焦点 |

注意，这只是购物车**入口按钮**的无障碍实现。购物车弹窗本身还需要处理焦点转移、关闭操作、背景内容隔离等问题，后面的课程会详细介绍。

例如下面的代码：

```html
<button aria-label="Open shopping cart">
  <svg aria-hidden="true"></svg>
</button>
```

在无障碍树中，可以简化理解为：

<box border radius="lg" padding={3} gap={2}>
  <row>
    <icon name="chevron-down" color="secondary"/>
    <icon name="file-code" color="secondary"/>
    **RootWebArea**
  </row>
  <box padding={{left:5}} gap={2}>
    <row>
      <icon name="chevron-down" color="secondary"/>
      <text color="success" weight="medium">button</text>
      <text size="sm">"Open shopping cart"</text>
    </row>
    <box background="surface-tertiary" radius="md" padding={3} gap={1}>
      <row><caption>Role</caption><spacer/><text size="sm">button</text></row>
      <row><caption>Name</caption><spacer/><text size="sm">Open shopping cart</text></row>
      <row><caption>Focusable</caption><spacer/><text size="sm" color="success">true</text></row>
    </box>
  </box>
  <divider/>
  <row align="center">
    <icon name="volume-2" size="xl"/>
    <box flex={1} gap=1>
      <caption>屏幕阅读器可能播报</caption>
      “Open shopping cart, button.”
    </box>
  </row>
</box>

你可以将无障碍树理解为浏览器为辅助技术提供的一种语义化页面结构。

因此，前端开发实际上需要同时关注两种页面表现：

- 视觉表现：页面是否美观，布局是否合理。
- 无障碍表现：元素是什么、叫什么、处于什么状态、如何操作。

第 3 课我们会深入研究 DOM Tree、Render Tree 和 Accessibility Tree 之间的关系。

## 6. WCAG 的四大核心原则

WCAG 的所有成功准则都围绕四大原则展开，简称 **POUR**。<Cite ref="turn717238search6"/>

<grid columns={2} gap={3}>
  <grid-item>
    <box border radius="lg" padding={3} gap={2}>
      <icon name="eye" size="3xl" color="#5185C5"/>
      <title size="xl">P</title>
      **Perceivable · 可感知**

      用户能够获取网站信息。

      <caption>图片 alt、视频字幕、文字对比度。</caption>
    </box>
  </grid-item>
  <grid-item>
    <box border radius="lg" padding={3} gap={2}>
      <icon name="keyboard" size="3xl" color="#39866B"/>
      <title size="xl">O</title>
      **Operable · 可操作**

      用户能够使用网站功能。

      <caption>键盘操作、焦点管理、替代拖拽操作。</caption>
    </box>
  </grid-item>
  <grid-item>
    <box border radius="lg" padding={3} gap={2}>
      <icon name="brain" size="3xl" color="#9673C5"/>
      <title size="xl">U</title>
      **Understandable · 可理解**

      用户能够理解信息与操作方式。

      <caption>表单标签、错误提示、交互一致性。</caption>
    </box>
  </grid-item>
  <grid-item>
    <box border radius="lg" padding={3} gap={2}>
      <icon name="shield-check" size="3xl" color="#C6914A"/>
      <title size="xl">R</title>
      **Robust · 健壮性**

      内容能够被不同用户代理和辅助技术正确解释。

      <caption>HTML 语义化、ARIA、辅助技术兼容。</caption>
    </box>
  </grid-item>
</grid>

例如，在 Shopify 商品详情页中：

| 原则 | 典型问题 |
|---|---|
| 可感知 | 商品颜色选项仅使用色块，没有名称 |
| 可操作 | 商品图片轮播只能通过鼠标拖动 |
| 可理解 | 加购失败只显示红色边框，没有错误原因 |
| 健壮性 | 自定义下拉框没有角色和选中状态信息 |

后面我们会专门用一节课深入学习这四大原则。

## 8. 几个常见的认知误区

| 常见误区 | 正确理解 |
|---|---|
| 给所有图片加 alt 就完成 ADA 了 | 图片只是无障碍的一小部分 |
| 所有元素都应该加 ARIA | 优先使用原生 HTML 语义 |
| 所有元素都需要 tabindex | 只有合适的交互元素才应进入正常焦点顺序 |
| 使用 Dawn 就不需要考虑 ADA | 自定义代码、商品内容、第三方 App 都可能引入问题 |
| 安装一个 ADA 无障碍插件就行 | 插件无法替代底层代码和交互逻辑的修复 |
| Lighthouse 无障碍得分 100 就合规 | 自动化检测无法覆盖全部无障碍问题 |
| ADA 会影响网站的美观程度 | 大量无障碍优化并不改变视觉设计 |

## 9. 本课实践：检查一个网站的键盘无障碍能力

暂时不需要安装任何工具，也不需要编写代码。

打开你正在开发的 Shopify 网站，然后放开鼠标，仅使用键盘完成操作。

| 按键 | 主要用途 |
|---|---|
| `Tab` | 移动到下一个可聚焦元素 |
| `Shift + Tab` | 移动到上一个可聚焦元素 |
| `Enter` | 激活按钮或链接等控件 |
| `Space` | 激活按钮、切换复选框等 |
| `Esc` | 关闭支持该操作的弹窗或菜单 |
| `↑ ↓ ← →` | 操作支持方向键的复合组件 |

{@body const tasks=["能否通过键盘访问 Header 导航？","当前焦点所在的元素是否清晰可见？","能否打开搜索框并选择搜索结果？","能否选择商品颜色和尺寸？","能否将商品添加到购物车？","打开购物车弹窗后，焦点是否正确转移？","能否通过 Esc 关闭购物车弹窗？","关闭弹窗后，焦点是否返回合理位置？","能否修改商品数量、删除商品并进入结算？"]}
{@body const [checked,setChecked]=DIL.useState(Array(9).fill(false))}
<card gap={3}>
  <row align="center">
    **键盘无障碍测试清单**
    <spacer/>
    <caption>{checked.filter(Boolean).length} / 9 通过</caption>
  </row>
  <box height={6} background="surface-tertiary" radius="full" clip={true}>
    <box height={6} background="#39866B" radius="full" width={`${checked.filter(Boolean).length/9*100}%`}/>
  </box>
  {#each tasks as task,i}
    <checkbox key={i} checked={checked[i]} onChange={v=>setChecked(old=>old.map((x,j)=>j===i?v:x))}>{task}</checkbox>
  {/each}
  <divider/>
  <row>
    <caption>勾选测试通过的项目</caption>
    <spacer/>
    <button size="sm" variant="ghost" onClick={()=>setChecked(Array(9).fill(false))}>重置</button>
  </row>
</card>

这也是日常前端开发完成后，最简单、成本最低的无障碍测试方式之一。

## 本课总结

第一课暂时不需要记住具体的 ARIA 属性和 WCAG 编号，重点是建立正确的知识框架。

ADA 是法律，WCAG 是技术标准，ARIA 是开发技术，A11y 是我们最终要实现的目标。

无障碍也不应该是网站开发完成之后才进行的一项补救工作，而应该贯穿 UI 设计、HTML 编写、CSS 样式、JavaScript 交互、组件封装以及测试验收的整个生命周期。

**下一课：辅助技术与屏幕阅读器（Screen Reader）**

我们将重点学习屏幕阅读器的工作原理、NVDA、JAWS、VoiceOver 的区别、浏览模式与焦点模式，以及如何在 Windows 电脑上实际使用屏幕阅读器测试网站。

理解残障用户是如何使用网站的，才能真正理解后面那些无障碍开发规范为什么存在。
