## 2. 商品详情页的 HTML 语义设计

一个商品详情页可以采用如下基础语义结构：

```liquid
<main id="MainContent">

  <nav aria-label="Breadcrumb">
    <ol>
      <li>
        <a href="{{ routes.root_url }}">Home</a>
      </li>

      <li aria-current="page">
        {{ product.title | escape }}
      </li>
    </ol>
  </nav>

  <div class="product">

    <section aria-label="Product media">
      <!-- Product gallery -->
    </section>

    <div class="product-info">

      <h1>{{ product.title | escape }}</h1>

      <!-- Rating -->
      <!-- Price -->
      <!-- Variant picker -->
      <!-- Quantity selector -->
      <!-- Product form -->

    </div>

  </div>

  <section aria-labelledby="details-title">
    <h2 id="details-title">Product details</h2>

    {{ product.description }}
  </section>

  <section aria-labelledby="reviews-title">
    <h2 id="reviews-title">Customer reviews</h2>
  </section>

</main>
```

这里的 main 通常已经由 Shopify 的 `layout/theme.liquid` 提供，因此在实际 `main-product.liquid` Section 中，不需要再创建一个 main。

有几个容易忽略的细节：

- 商品名称应该作为 PDP 的主要 H1。
- 不要因为需要大字号，就将价格、库存、颜色名称都设置为标题。
- 商家通过富文本编辑器填写的 product.description，同样需要检查标题层级、图片 alt 和表格语义。
- 第三方评论 App 生成的内容，也是整个页面无障碍审计的一部分。

## 3. 商品价格的无障碍表达

### 3.1 原价与促销价

<grid columns={2} gap={3}>
  <grid-item>
    <box border radius="md" padding={3} gap={2}>
      <caption>视觉界面</caption>
      <row align="center" wrap="wrap">
        <title size="xl" color="#B44444">$29.99</title>
        <text lineThrough={true} color="secondary">$49.99</text>
      </row>
      <divider/>
      <caption>可能获得的文字信息</caption>
      <text size="sm">$29.99, $49.99</text>
      <caption>两个金额的业务含义不明确。</caption>
    </box>
  </grid-item>
  <grid-item>
    <box border radius="md" padding={3} gap={2}>
      <caption>优化后的语义</caption>
      <row align="center" wrap="wrap">
        <title size="xl" color="#B44444">$29.99</title>
        <text lineThrough={true} color="secondary">$49.99</text>
      </row>
      <divider/>
      <caption>屏幕阅读器播报示意</caption>
      <text size="sm">Sale price: $29.99. Regular price: $49.99.</text>
    </box>
  </grid-item>
</grid>

屏幕阅读器不一定会主动解释删除线的含义。

因此，不能仅依赖红色和删除线来区分两个价格。

### 3.2 Liquid 实现

```liquid
{% assign variant = product.selected_or_first_available_variant %}

<div id="Price-{{ section.id }}" role="status">

  {% if variant %}

    {% if variant.compare_at_price > variant.price %}

      <span class="visually-hidden">
        Sale price:
      </span>

      <span class="price--sale">
        {{ variant.price | money_with_currency }}
      </span>

      <span class="visually-hidden">
        Regular price:
      </span>

      <s class="price--regular">
        {{ variant.compare_at_price | money_with_currency }}
      </s>

    {% else %}

      <span class="visually-hidden">Price:</span>

      <span>
        {{ variant.price | money_with_currency }}
      </span>

    {% endif %}

  {% endif %}

</div>
```

这里需要区分几个 Shopify 属性：

| 属性 | 含义 |
|---|---|
| `product.price` | 商品的最低变体价格 |
| `product.price_min` | 最低变体价格 |
| `product.price_max` | 最高变体价格 |
| `variant.price` | 当前具体变体的价格 |
| `variant.compare_at_price` | 当前变体的对比价格 |

商品详情页已经选定具体 Variant 时，通常应该展示该 Variant 的实际价格，而不是始终展示 product.price。

### 3.3 变体切换后的价格通知

可以采用两种方案：

| 方案 | 实现 |
|---|---|
| 价格区域独立通知 | 给价格容器添加 `role="status"` |
| 统一状态通知 | 将价格、库存等组合成一条消息 |

例如：

```javascript
announcer.announce(
  'Price: $39.99. In stock.'
);
```

采用统一通知方案时，就不应该让价格区域和库存区域同时重复播报这些信息。

对于跨境电商，价格格式、货币信息和无障碍标签应由当前 Shopify Markets 配置及 locale 文件共同决定。

## 4. Variant Picker 的 Shopify 数据模型

之前我们已经学习过 Shopify Product、Option 和 Variant 的关系，现在从无障碍组件开发的角度重新理解它们。

假设一个商品有两个 Option：

<box border radius="lg" padding={3} gap={3}>
  <box border radius="md" padding={2} align="center">
    **Product**
    <caption>Cotton T-shirt</caption>
  </box>
  <box align="center"><icon name="arrow-down" color="secondary"/></box>
  <grid columns={2}>
    <grid-item>
      <box border radius="md" padding={3} gap={2}>
        **Option 1 · Color**
        White
        Black
        Blue
      </box>
    </grid-item>
    <grid-item>
      <box border radius="md" padding={3} gap={2}>
        **Option 2 · Size**
        S
        M
        L
      </box>
    </grid-item>
  </grid>
  <box align="center"><icon name="arrow-down" color="secondary"/></box>
  <box background="surface-tertiary" radius="md" padding={3} gap={2}>
    **Variant · 具体商品变体**
    <row><caption>Color</caption><spacer/>Black</row>
    <row><caption>Size</caption><spacer/>M</row>
    <row><caption>Variant ID</caption><spacer/>10005</row>
    <row><caption>Price</caption><spacer/>$39.99</row>
    <row><caption>Available</caption><spacer/>true</row>
    <row><caption>Featured media</caption><spacer/>Black T-shirt</row>
  </box>
</box>

Option Value 本身不是最终加购对象。

用户选择的 Color 和 Size 组合起来，才能确定具体 Variant，最终将 Variant ID 提交给购物车。

因此，Variant Picker 本质上是一个**多组选项共同决定最终商品状态的表单组件**。

### 4.1 三种必须区分的业务状态

| 状态 | Variant 是否存在 | 是否可购买 |
|---|:---:|:---:|
| Available | 是 | 是 |
| Sold out / 不可购买 | 是 | 否 |
| Unavailable combination | 否 | 否 |

例如：

| Color / Size | S | M | L |
|---|---|---|---|
| White | 有货 | 有货 | 有货 |
| Black | 有货 | 售罄 | 有货 |
| Blue | 有货 | 售罄 | 不存在 |

Black + M 是一个真实存在但无法购买的 Variant。

Blue + L 则是一个根本不存在的组合。

Shopify 官方文档明确指出，当 `option_values` 对应的组合不存在时，`selected_variant` 和 `selected_or_first_available_variant` 可以返回 null。<Cite refs={["turn712220search11","turn712220search2"]}/>

此外，`variant.available` 表示是否可购买，并不简单等同于库存数量大于零。继续销售缺货商品等库存策略也会影响其结果。

### 4.2 Variant Picker 交互实验

## 5. Variant Picker 为什么优先使用原生 Radio？

很多自定义 Theme 会使用普通按钮实现颜色和尺寸选择。

```html
<button class="size active">S</button>
<button class="size">M</button>
<button class="size">L</button>
```

这种写法虽然可以正常点击，但普通 button 本身并不会表达这些按钮之间的互斥选择关系。

如果每个 Option 只能选择一个值，那么最符合业务语义的通常是原生 Radio Group。

### 5.1 推荐 Liquid 实现

```liquid
{% for option in product.options_with_values %}

  <fieldset class="variant-option">

    <legend>
      {{ option.name | escape }}
    </legend>

    {% for value in option.values %}

      {% assign input_id = section.id
        | append: '-'
        | append: option.position
        | append: '-'
        | append: value.id
      %}

      <input
        type="radio"
        class="variant-input visually-hidden"
        id="{{ input_id }}"
        name="option-{{ section.id }}-{{ option.position }}"
        value="{{ value | escape }}"
        data-option-value-id="{{ value.id }}"
        {% if value.selected %}checked{% endif %}
      >

      <label for="{{ input_id }}">
        {{ value | escape }}

        {% unless value.available %}
          <span class="option-unavailable">
            Sold out or unavailable
          </span>
        {% endunless %}
      </label>

    {% endfor %}

  </fieldset>

{% endfor %}
```

这里使用 `product.options_with_values` 获取所有 Option Group，使用 `value.id` 关联具体 Option Value。

`fieldset` 与 `legend` 负责表达组选项关系，而原生 radio 自动提供：

| 能力 | 是否需要手动实现 |
|---|---|
| Radio 角色 | 否 |
| Checked 状态 | 否 |
| 单组互斥 | 否 |
| 方向键切换 | 否 |
| Space 选中 | 否 |
| Radio Group 的常规 Tab 入口 | 否 |

没有必要额外实现 Roving Tabindex，也不需要添加 `aria-checked` 或 `role="radio"`。

此处 `value.available` 是 Shopify 在当前选项上下文中计算的可购买状态，并非全局库存状态。后面我们会进一步讲解这一点。

### 5.2 不要使用 display:none 隐藏 Radio

常见错误：

```css
.variant-input {
  display: none;
}
```

这样虽然可以点击 label，但真正的 Radio 已经无法通过键盘正常访问。

正确做法是使用第 9 课介绍过的 `visually-hidden`，再通过相邻选择器实现自定义样式。

```css
.variant-input + label {
  display: inline-flex;
  align-items: center;
  justify-content: center;

  min-width: 44px;
  min-height: 44px;

  padding: 8px 16px;
  border: 1px solid #888;
  border-radius: 4px;

  cursor: pointer;
}

.variant-input:checked + label {
  border: 2px solid currentColor;
  font-weight: 700;
}

.variant-input:focus-visible + label {
  outline: 2px solid #005fcc;
  outline-offset: 4px;
}
```

<grid columns={3} gap={2}>
  <grid-item>
    <box border radius="md" padding={3} align="center">
      <box border radius="sm" size="44px" align="center" justify="center">S</box>
      <caption>默认</caption>
    </box>
  </grid-item>
  <grid-item>

## 6. Color Swatch 颜色选择器

颜色选择器是商品详情页中非常典型的 WCAG 1.4.1 Use of Color 应用场景。

### 6.1 三种不同的颜色选择器

<box border radius="lg" padding={3} gap={3}>
  **方案一：仅显示颜色**
  <row gap={3}>
    {#each ["#F8F7F1","#303030","#8299B3","#C1AD92","#A86767"] as c}
      <box size="36px" radius="full" background={c} border/>
    {/each}
  </row>
  <caption>用户需要仅凭颜色识别各个选项，缺少明确名称和选中提示。</caption>
  <divider/>
  **方案二：颜色 + 当前选择名称**
  <text size="sm">Color: Blue</text>
  <row gap={3}>
    {#each ["#F8F7F1","#303030","#8299B3","#C1AD92","#A86767"] as c,i}
      <box border={{size:i===2?2:1,color:i===2?"#3978BC":"#88888870"}} size="36px" radius="full" padding={1}>
        <box background={c} radius="full" size="100%" align="center" justify="center">{#if i===2}<icon name="check" color="#111111" size="sm"/>{/if}</box>
      </box>
    {/each}
  </row>
  <caption>比第一种更好，但仍应为每个选项提供可访问名称，并让视觉用户能够识别候选颜色。</caption>
  <divider/>
  **方案三：颜色 + 独立名称 + 选中标记**
  <row justify="between" gap={1}>
    {#each [{c:"#F8F7F1",n:"White"},{c:"#303030",n:"Black"},{c:"#8299B3",n:"Blue"},{c:"#C1AD92",n:"Beige"},{c:"#A86767",n:"Red"}] as c,i}
      <box align="center" gap={1}>
        <box border={{size:i===2?2:1,color:i===2?"#3978BC":"#88888870"}} size="36px" radius="full" padding={1}>
          <box background={c.c} radius="full" size="100%" align="center" justify="center">{#if i===2}<icon name="check" color="#111111" size="sm"/>{/if}</box>
        </box>
        <text size="xs" weight={i===2?"bold":"normal"}>{c.n}</text>
      </box>
    {/each}
  </row>
  <caption>颜色、文字和选中标记共同表达信息，对色觉障碍用户更加友好。</caption>
</box>

WCAG 1.4.1 要求不能仅使用颜色传递信息、指示操作或区分状态。为颜色选项提供文字名称、为选中状态提供边框或勾号，是很实用的解决方式。<Cite ref="turn712220search12"/>

### 6.3 Shopify 原生 Swatch 数据

在 Shopify Liquid 中，`product_option_value` 可以提供 swatch 信息，例如：


## 7. Sold Out 的选项到底应该不应该 Disabled？

这是 Shopify Variant Picker 开发中非常值得讨论的问题。

假设当前选中 Black，M 尺寸已经售罄。

<grid columns={2} gap={3}>
  <grid-item>
    <box border radius="md" padding={3} gap={2}>
      **方案 A：真正禁用**
      <row gap={1}>
        {#each ["S","M","L"] as s,i}
          <box flex={1} border radius="sm" padding={2} align="center" background={i===1?"surface-tertiary":"surface"}>
            <text color={i===1?"secondary":"default"} lineThrough={i===1}>{s}</text>
          </box>
        {/each}
      </row>
      <caption>M 无法被选中，通常不参与键盘焦点导航。</caption>
      <text size="xs">disabled = true</text>
    </box>
  </grid-item>
  <grid-item>
    <box border radius="md" padding={3} gap={2}>
      **方案 B：允许选择**
      <row gap={1}>
        {#each ["S","M","L"] as s,i}
          <box flex={1} border={{size:i===1?2:1,color:i===1?"#3978BC":"#88888860"}} radius="sm" padding={2} align="center">
            <text lineThrough={i===1}>{s}</text>
          </box>
        {/each}
      </row>
      <box background="surface-tertiary" radius="sm" padding={2} align="center">
        <text color="secondary" size="sm">Sold out</text>
      </box>
      <caption>可以查看该变体，但不能加购。</caption>
    </box>
  </grid-item>
</grid>

这两种方案都可能是合理的业务设计，关键在于真实交互与语义是否一致。

| 实现方式 | 能聚焦 | 能选择 | 语义 |
|---|:---:|:---:|---|
| `disabled` | 否 | 否 | 原生禁用 |
| `aria-disabled="true"` | 可以 | 需 JS 阻止 | 表达操作不可用 |
| `.disabled` CSS class | 可以 | 可以 | 仅改变样式 |
| 普通 Radio + 售罄文字 | 可以 | 可以 | 可以选择，但商品无法购买 |

### 7.1 为什么我更推荐允许选择售罄变体？

因为用户可能希望：

- 查看售罄颜色对应的商品图片。
- 查看该变体的价格及规格。
- 使用到货通知功能。
- 在切换其他 Option 后找到可购买的组合。

例如 Black + M 售罄，但 White + M 有货。如果在当前状态下不合理地禁用其他选项，可能导致用户无法顺利切换到一个有效组合。

因此，可以允许用户选中售罄变体，同时禁用 Add to cart。

```html
<input
  type="radio"
  name="size"
  id="size-m"
  value="M"
>

<label for="size-m">
  M
  <span>Sold out</span>
</label>
```

这里不应该再添加 `aria-disabled="true"`，因为该 Radio 实际上仍然允许选择。

**Radio 是否可以选择，与选中的商品是否可以购买，是两个不同的状态。**

## 8. Shopify 高变体商品：为什么不再推荐遍历全部 Variants？

这是近年来 Shopify Theme 开发中很重要的一项架构变化。

传统 Theme 经常这样实现：

```liquid
<script type="application/json" id="VariantsData">
  {{ product.variants | json }}
</script>
```

JavaScript 获取所有 Variant 后，在浏览器中查找匹配的组合：

```javascript
const variant = variants.find(variant =>
  variant.options.every(
    (value, index) => value === selectedOptions[index]
  )
);
```

对于数量较少、数据完整的商品，这种实现非常直观。

但是 Shopify 已经支持高变体数量商品，不能再假设 `product.variants` 一定提供整个变体集合。官方高变体商品开发指南明确说明了 Liquid 中变体集合的限制，并推荐使用 `product_option_value` 与服务端选项状态更新机制。<Cite ref="turn712220search2"/>

### 8.1 新旧架构对比

<grid columns={2} gap={2}>
  <grid-item>
    <box border radius="md" padding={3} gap={2}>
      **传统方案**
      {#each ["Liquid 输出所有 Variant","浏览器保存变体数组","用户选择 Option","JS 查找匹配 Variant","更新 UI"] as t,i}
        <box background="surface-tertiary" radius="sm" padding={2}><text size="xs">{t}</text></box>
        {#if i<4}<box align="center"><icon name="arrow-down" size="xs" color="secondary"/></box>{/if}
      {/each}
    </box>
  </grid-item>
  <grid-item>
    <box border radius="md" padding={3} gap={2}>
      **现代方案**
      {#each ["Liquid 输出 Option Value","用户选择 Option","提交 option_values","Shopify 渲染最新 Section","同步 Variant 与 UI"] as t,i}
        <box background="surface-tertiary" radius="sm" padding={2}><text size="xs">{t}</text></box>
        {#if i<4}<box align="center"><icon name="arrow-down" size="xs" color="secondary"/></box>{/if}
      {/each}
    </box>
  </grid-item>
</grid>

现代方案不需要在客户端预先保存所有组合。

请求示例：

```text
/products/cotton-tshirt
  ?section_id=template--123__main
  &option_values=111,222
```

这里的 `111,222` 是 Option Value ID，而不是 Variant ID。

### 8.2 product_option_value.available 的特殊含义

这是非常容易误解的属性。

假设 Option 顺序为：

```text
Color → Size → Material
```

`product_option_value.available` 会考虑之前已选 Option 的上下文，判断当前值是否存在可购买的后续组合。

例如判断 Black 是否 available，不一定意味着 Black + 当前 Size + 当前 Material 这个完整组合有货；判断 Size 时，则会考虑前面已经选择的 Color。

因此：

```liquid
{% unless value.available %}
  Sold out or unavailable
{% endunless %}
```

可以作为选项级可购买性提示，但不能简单理解为当前完整 Variant 的库存状态。

最终加购按钮仍然需要根据实际选定的 Variant 判断。

## 9. 实战：Variant Picker 与 Section Rendering

接下来实现一个与现代 Shopify 数据模型配合的无障碍更新方案。

### 9.1 状态更新的正确顺序

<box border radius="lg" padding={3} gap={1}>
  {#each [{t:"① 用户切换 Radio / Select",d:"保留用户当前焦点"},{t:"② 进入 Loading 状态",d:"暂时禁止加购及动态结算，避免提交旧 Variant"},{t:"③ 请求 Shopify Section",d:"传入所有已选 Option Value ID"},{t:"④ 验证服务器响应",d:"确保不是过期请求，并解析最新 Variant"},{t:"⑤ 更新商品业务状态",d:"Variant ID、价格、库存、图库、数量规则"},{t:"⑥ 同步无障碍状态",d:"恢复适当焦点、更新选项状态和通知消息"},{t:"⑦ 结束 Loading",d:"只在 Variant 可购买时重新允许提交"}] as item,i}
    <box border radius="md" padding={2} gap={1}>
      **{item.t}**
      <caption>{item.d}</caption>
    </box>
    {#if i<6}<box align="center"><icon name="arrow-down" color="secondary" size="sm"/></box>{/if}
  {/each}
</box>

这里最关键的原则是：**视觉界面显示的新 Variant，必须和商品表单中实际提交的 Variant 一致。**

### 9.2 Liquid：提供服务端选中状态

在商品信息区域输出当前 Variant：

```liquid
<script type="application/json" data-selected-variant>
  {{ product.selected_or_first_available_variant | json }}
</script>
```

商品表单：

```liquid
{% assign variant = product.selected_or_first_available_variant %}

{% form 'product', product %}

  <input
    type="hidden"
    name="id"
    value="{{ variant.id }}"
  >

  <button
    type="submit"
    data-add-button
    {% unless variant.available %}disabled{% endunless %}
  >
    {% if variant == blank %}
      Unavailable
    {% elsif variant.available %}
      Add to cart
    {% else %}
      Sold out
    {% endif %}
  </button>

{% endform %}
```

这里假设由 JavaScript 增强的 Picker 已经完成初始化。正式项目仍应为脚本加载失败时提供可靠的原生变体选择或其他可用回退方式。

### 9.3 JavaScript：获取新的 Variant 状态

以下为同一商品内的教学实现，假设当前 Section 和服务端返回的 Section 均包含 `[data-product-info]`、`[data-variant-picker]`、`[data-selected-variant]` 等自定义标记。

```javascript
const root = document.querySelector('[data-product-info]');

const picker = root.querySelector('[data-variant-picker]');
const variantInput = root.querySelector('input[name="id"]');
const addButton = root.querySelector('[data-add-button]');
const status = root.querySelector('[data-variant-status]');

let controller;
let requestVersion = 0;
let pending = false;

async function updateVariant() {
  const version = ++requestVersion;

  controller?.abort();
  controller = new AbortController();

  const selectedIds = [
    ...picker.querySelectorAll(
      'input[type="radio"]:checked[data-option-value-id]'
    )
  ].map(input => input.dataset.optionValueId);

  pending = true;

  // 清除旧 Variant，防止误加购
  variantInput.value = '';
  addButton.disabled = true;

  picker.setAttribute('aria-busy', 'true');

  try {
    const url = new URL(
      root.dataset.productUrl,
      window.location.origin
    );

    url.searchParams.set(
      'section_id',
      root.dataset.sectionId
    );

    url.searchParams.set(
      'option_values',
      selectedIds.join(',')
    );

    const response = await fetch(url, {
      signal: controller.signal
    });

    if (!response.ok) {
      throw new Error('Variant request failed');
    }

    const html = new DOMParser().parseFromString(
      await response.text(),
      'text/html'
    );

    if (version !== requestVersion) return;

    const nextRoot = html.querySelector('[data-product-info]');

    if (!nextRoot) {
      throw new Error('Invalid product response');
    }

    const variant = JSON.parse(
      nextRoot.querySelector(
        '[data-selected-variant]'
      ).textContent
    );

    applyVariant(variant, nextRoot);

  } catch (error) {
    if (
      error.name === 'AbortError' ||
      version !== requestVersion
    ) return;

    variantInput.value = '';
    addButton.disabled = true;
    addButton.textContent = 'Unavailable';

    status.textContent =
      'Unable to update product options. Please try again.';

  } finally {
    if (version === requestVersion) {
      pending = false;

      picker.setAttribute('aria-busy', 'false');
    }
  }
}

picker.addEventListener('change', event => {
  if (event.target.matches('input[type="radio"]')) {
    updateVariant();
  }
});
```

生产环境需要在请求期间同时处理加速结账等其他购买入口，并在商品表单的提交逻辑中检查 pending、Variant ID 和可购买状态，而不是只禁用一个按钮。

### 9.4 应用服务端状态

```javascript
function applyVariant(variant, nextRoot) {
  // 服务端 HTML 已处理当前市场的价格格式
  const price = root.querySelector('[data-price]');
  const nextPrice = nextRoot.querySelector('[data-price]');

  if (price && nextPrice) {
    price.innerHTML = nextPrice.innerHTML;
  }

  const inventory = root.querySelector('[data-inventory]');
  const nextInventory =
    nextRoot.querySelector('[data-inventory]');

  if (inventory && nextInventory) {
    inventory.innerHTML = nextInventory.innerHTML;
  }

  variantInput.value = variant?.id ?? '';

  addButton.disabled = !variant?.available;

  addButton.textContent = !variant
    ? 'Unavailable'
    : variant.available
      ? 'Add to cart'
      : 'Sold out';

  if (!variant) {
    status.textContent =
      'This product combination is unavailable.';

    return;
  }

  const formattedPrice = price?.textContent.trim() || '';

  status.textContent = [
    formattedPrice,
    variant.available ? 'Available to purchase.' : 'Sold out.'
  ].filter(Boolean).join(' ');
}
```

这里选择由 Liquid 渲染价格，而不是直接在 JavaScript 中使用：

```javascript
variant.price / 100
```

这样可以减少自行处理币种、小数格式及 Markets 定价时的错误。

上述代码主要演示请求竞争、提交保护和状态同步，并不是完整的生产级 Variant Picker。实际项目还需更新每个 Option Value 的可用状态、数量规则、媒体、动态结算入口以及相关的显示隐藏属性；同时要提供失败重试机制。

### 9.5 Section Rendering 后如何恢复焦点？

如果只更新价格和库存等区域，Radio DOM 不变，焦点通常可以自然保留。

如果必须替换整个 Variant Picker，就应当在替换前记录当前焦点对应的稳定标识。

```javascript
const active = document.activeElement;

const activeOptionId = picker.contains(active)
  ? active.dataset.optionValueId
  : null;

// 更新 Picker 内部 DOM
picker.innerHTML = nextPicker.innerHTML;

if (activeOptionId) {
  const nextInput = [
    ...picker.querySelectorAll('[data-option-value-id]')
  ].find(input =>
    input.dataset.optionValueId === activeOptionId
  );

  if (nextInput && !nextInput.disabled) {
    nextInput.focus();
  }
}
```

应当在真正进行 DOM 替换时检查焦点，而不是只在异步请求开始时记录焦点。因为请求等待期间，用户可能已经主动移动到了 Quantity 或其他控件。

如果原 Option 已经不存在，还需要提供当前 Option Group 或其他合理的备用焦点。

**变体切换通常不应该自动把焦点移动到价格、库存或商品图片。** 用户可能还需要继续选择尺寸，因此应当尽量保留原来的操作位置。

### 10.1 商品图片 alt 应该如何设置？

| 图片类型 | 推荐 alt |
|---|---|
| 商品正面 | White cotton T-shirt, front view |
| 商品背面 | Back view of white cotton T-shirt |
| 领口细节 | Close-up of ribbed crew neckline |
| 材质细节 | Close-up of woven cotton fabric |
| 模特穿着 | Model wearing a white regular-fit T-shirt |

不建议所有商品图片都使用同一个 alt：

```liquid
alt="{{ product.title }}"
```

虽然每张图片都有 alt，但用户无法区分这些图片所表达的不同商品信息。

更合理的是在 Shopify 后台为每张商品媒体维护独立且有意义的 alt。

```liquid
{{
  media.preview_image
  | image_url: width: 1600
  | image_tag: alt: media.alt
}}
```

商品图片的准确描述不能仅依靠前端自动生成，因为 JavaScript 和 Liquid 不一定知道图片实际展示了什么。

### 10.2 缩略图应该是 button 还是 img？

缩略图的业务作用是切换当前展示的商品媒体，所以应该具有按钮语义。

```liquid
<div role="group" aria-label="Choose product image">

  {% for media in product.media %}

    <button
      type="button"
      data-media-id="{{ media.id }}"
      aria-label="Show image {{ forloop.index }}: {{ media.alt | escape }}"
      aria-controls="ProductGallery-{{ section.id }}"
      {% if forloop.first %}
        aria-current="true"
      {% endif %}
    >
      {{
        media.preview_image
        | image_url: width: 120
        | image_tag: alt: ''
      }}
    </button>

  {% endfor %}

</div>
```

此例针对纯图片 Gallery，默认第一张图片为当前媒体。如果商品还包含视频或 3D 模型，需要根据 `media.media_type` 生成对应名称；如果初始媒体来自已选 Variant，则应该根据其实际媒体 ID 标记 `aria-current`。

### 12.1 推荐 HTML 结构

```html
<label for="quantity">Quantity</label>

<div class="quantity-selector">

  <button
    type="button"
    data-minus
    aria-label="Decrease quantity"
    aria-controls="quantity"
  >
    −
  </button>

  <input
    id="quantity"
    type="number"
    name="quantity"
    value="1"
    min="1"
    max="10"
    step="1"
    required
    aria-describedby="quantity-rules"
  >

  <button
    type="button"
    data-plus
    aria-label="Increase quantity"
    aria-controls="quantity"
  >
    +
  </button>

</div>

<p id="quantity-rules">
  Minimum: 1. Maximum: 10.
</p>
```

原生 `input[type="number"]` 已经具有 spinbutton 语义、当前值和数值范围信息。

不需要添加：

```html
role="spinbutton"
aria-valuenow="1"
aria-valuemin="1"
aria-valuemax="10"
```

浏览器会根据原生属性计算这些信息。

### 12.2 JavaScript 实现

```javascript
const input = document.querySelector('#quantity');

const minus = document.querySelector('[data-minus]');
const plus = document.querySelector('[data-plus]');

function syncButtons() {
  const value = input.valueAsNumber;
  const valid = input.validity.valid;

  minus.setAttribute(
    'aria-disabled',
    String(!valid || value <= Number(input.min))
  );

  plus.setAttribute(
    'aria-disabled',
    String(!valid || (
      input.max !== '' && value >= Number(input.max)
    ))
  );
}

function changeQuantity(button, direction) {
  if (button.getAttribute('aria-disabled') === 'true') {
    return;
  }

  if (direction > 0) {
    input.stepUp();
  } else {
    input.stepDown();
  }

  input.dispatchEvent(
    new Event('input', { bubbles: true })
  );

  input.dispatchEvent(
    new Event('change', { bubbles: true })
  );
}

minus.addEventListener('click', () => {
  changeQuantity(minus, -1);
});

plus.addEventListener('click', () => {
  changeQuantity(plus, 1);
});

input.addEventListener('input', syncButtons);

syncButtons();
```

这里使用原生 `stepUp()` 和 `stepDown()`，而不是自己直接进行 `value + 1`。

同时使用 `aria-disabled` 保留加减按钮的焦点。当用户连续点击加号到达最大数量时，不会因为按钮突然被原生禁用而丢失焦点。

### 12.3 Shopify Quantity Rule

Shopify 的数量限制不一定是 min=1、step=1。

实际项目需要根据 Variant 的数量规则处理：

```liquid
<input
  type="number"
  name="quantity"
  min="{{ variant.quantity_rule.min }}"
  step="{{ variant.quantity_rule.increment }}"
  {% if variant.quantity_rule.max != null %}
    max="{{ variant.quantity_rule.max }}"
  {% endif %}
  value="{{ variant.quantity_rule.min }}"
  required
>
```

{@body const [quantity21,setQuantity21]=DIL.useState(1)}

    <title size="2xl" tabularNums={true}>{quantity21}</title>
    <button uniform variant="outline" color="secondary" disabled={quantity21>=maximum21} onClick={()=>setQuantity21(n=>n+step21)}><icon name="plus"/></button>
  </row>
  <grid columns={3}>
    <grid-item><box align="center"><caption>Minimum</caption>**{step21}**</box></grid-item>
    <grid-item><box align="center"><caption>Step</caption>**{step21}**</box></grid-item>
    <grid-item><box align="center"><caption>Maximum</caption>**{maximum21}**</box></grid-item>
  </grid>
  <divider/>
  <box background="surface-tertiary" radius="sm" padding={3}>

当 Variant 切换时，需要重新获取数量规则，并确保当前 Quantity 满足新的限制。如果自动调整了数量，且这对购买结果有实质影响，应该让用户感知这一变化。

### 14.3 product-variant-options.liquid

这部分源码特别值得学习。

Dawn 会根据 `value.available` 判断选项是否处于不可购买状态。在按钮式选项中，它使用 `disabled` CSS class，而不是直接给 Radio 添加原生 `disabled` 属性，并通过隐藏的辅助文字表达售罄或不可用信息。<Cite ref="turn659638view1"/>

可以将其设计思想简化为：

```liquid
<input
  type="radio"
  {% if value.selected %}checked{% endif %}
  {% unless value.available %}class="disabled"{% endunless %}
>

<label>
  <!-- Option name -->
  <!-- Accessible availability information -->
</label>
```

以上为省略 ID 和其他属性的结构示意，并不是完整可运行代码。

这正好对应我们第 7 节讨论的策略：

**允许用户选择不可购买的选项，但是根据最终 Variant 状态决定能否加购。**

| 方法 | 职责 |
|---|---|

### 14.6 Dawn 如何解决焦点丢失？

在 `renderProductInfo()` 的请求完成逻辑中，Dawn 会执行：

```javascript
document.querySelector(`#${targetId}`)?.focus();
```

它通过之前选项的 ID 找到新渲染后的元素，并恢复焦点。

这段代码虽然很简单，但意义非常重要。

因为 Variant Picker 在 Section Rendering 后可能已被整体替换，原来的 Radio 节点已经不存在。

不过，从组件审查角度看，还需要验证一个边缘场景：如果请求耗时较长，用户在响应返回前已经主动将焦点移到其他控件，是否仍然应该恢复到之前的选项？

新项目可以在 DOM 更新前判断焦点是否仍处于受影响区域，避免不必要的焦点抢夺。

这属于基于源码提出的改进方向，并不是已经实测确认的 Dawn 缺陷。

## 15. 商品详情页的自动化测试

对于 PDP，单独验证每个组件是否存在 ARIA 属性是不够的。

更重要的是验证业务状态与无障碍状态是否保持一致。

### 15.1 测试 Variant Picker

```javascript
import { test, expect } from '@playwright/test';

test('variant picker keyboard interaction', async ({ page }) => {
  await page.goto('/products/cotton-tshirt');

  const colorGroup = page.getByRole('group', {
    name: 'Color',
    exact: true
  });

  const white = colorGroup.getByRole('radio', {
    name: 'White',
    exact: true
  });

  const black = colorGroup.getByRole('radio', {
    name: 'Black',
    exact: true
  });

  await white.focus();

  await page.keyboard.press('ArrowRight');

  await expect(black).toBeChecked();
  await expect(black).toBeFocused();

  await expect(
    page.locator('input[name="id"]').first()
  ).toHaveValue('10004');
});
```

该测试假设 White 和 Black 相邻，初始尺寸为 S，且 Black + S 对应测试 Variant ID 10004。

### 15.2 测试售罄变体

```javascript
test('sold out variant cannot be purchased', async ({ page }) => {
  await page.goto('/products/cotton-tshirt');

  await page.getByRole('radio', {
    name: 'Black',
    exact: true
  }).check();

  await page.getByRole('radio', {
    name: /^M\b/
  }).check();

  const addButton = page.locator('[data-add-button]');

  await expect(addButton).toHaveText('Sold out');

  await expect(addButton).toBeDisabled();
});
```

### 15.3 测试不存在的组合

```javascript
test('unavailable combination clears variant id', async ({ page }) => {
  await page.goto('/products/cotton-tshirt');

  await page.getByRole('radio', {
    name: 'Blue',
    exact: true
  }).check();

  await page.getByRole('radio', {
```

以上测试使用本课的教学商品及组件结构。实际测试应使用固定商品数据或 API Mock，并等待每次异步变体更新完成后再执行下一次选择。

### 15.4 PDP 边缘场景测试

| 测试场景 | 预期结果 |
|---|---|
| 快速切换三个颜色 | 只采用最新请求结果 |
| 请求过程中点击加购 | 不提交旧 Variant |
| 切换到售罄变体 | 显示售罄且禁止购买 |
| 选择不存在的组合 | 清除旧 Variant ID |
| 变体请求失败 | 明确提示，不允许错误加购 |
| 请求期间焦点移至其他控件 | 不擅自抢回焦点 |
| 切换颜色导致主图变化 | 焦点保留在颜色选项 |
| 数量规则发生变化 | 数量值与新规则保持一致 |
| 图片放大弹窗关闭 | 恢复原触发元素焦点 |
| 切换不同币种 | 价格及无障碍文字正确 |

| 层面 | 应有的结果 |
|---|---|
| 数据层 | 找到 Black + M 对应 Variant |
