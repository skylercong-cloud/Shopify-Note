## 2. Product Grid：商品列表的语义结构

在开发 Collection 页面时，很多开发者会直接使用大量 div 来实现 Grid 布局。

```html
<div class="product-grid">
  <div class="product-card">...</div>
  <div class="product-card">...</div>
  <div class="product-card">...</div>
</div>
```

视觉上没有问题，但缺少商品之间的列表关系。

更推荐使用原生列表语义：

```liquid
{% paginate collection.products by 24 %}

  <ul class="product-grid" role="list">

    {% for product in collection.products %}
      <li>
        {% render 'card-product', card_product: product %}
      </li>
    {% endfor %}

  </ul>

  {% render 'pagination', paginate: paginate %}

{% endpaginate %}
```

对应的 Accessibility Tree：

<box border radius="lg" padding={3} gap={2}>
  **main**
  <box padding={{left:3}} gap={2}>
    <text size="sm">heading level 1 "Clothing"</text>
    <text size="sm">status "48 products found"</text>
    <box border radius="md" padding={3} gap={2}>
      **list · 24 items**
      {#each ["Cotton T-shirt","Classic shirt","Linen top"] as p}
        <box padding={{left:3}} gap={1}>
          <caption>listitem</caption>
          <text size="sm">heading level 2 "{p}"</text>
          <text size="sm">link "{p}"</text>
          <text size="sm">button "Quick add: {p}"</text>
        </box>
      {/each}
      <caption>...其余商品</caption>
    </box>
    <text size="sm">navigation "Pagination"</text>
  </box>
</box>

需要特别注意：视觉上的 CSS Grid，并不意味着应该使用 `role="grid"`。

ARIA Grid 是一种具有特定方向键导航机制的复合组件，例如可编辑数据表格。普通电商商品列表使用 `ul` 和 `li` 通常就足够了。

这里显式添加 `role="list"`，也是为了应对部分 Safari 环境在使用 `list-style: none` 后可能出现的列表语义丢失问题。

## 3. Product Card 商品卡片

### 3.1 图片和商品名称是否应该分别使用链接？

如果图片和商品名称都跳转到同一个 PDP，可以考虑将它们合并为一个链接。

24 张商品卡片就可以减少 24 个重复的 Tab 停靠点。

### 3.2 推荐 HTML 与 Liquid

```liquid
<article class="product-card">

  <a href="{{ product.url }}"
    aria-labelledby="ProductTitle-{{ section.id }}-{{ product.id }}"
  >
    {{
      product.featured_image
      | image_url: width: 600
      | image_tag: loading: 'lazy'
    }}

    <h2 id="ProductTitle-{{ section.id }}-{{ product.id }}">
      {{ product.title | escape }}
    </h2>
  </a>

  <p>
    {{ product.price | money_with_currency }}
  </p>

  <button type="button"
    aria-label="Quick add: {{ product.title | escape }}"
    aria-haspopup="dialog"
  >
    Quick add
  </button>

</article>
```

这里假设商品图片主要用于识别商品，链接名称由商品标题提供；如果图片表达了额外的重要商品信息，还需要保证这些信息具有适当的文本替代。

Quick Add 按钮必须位于商品链接之外。

下面这种嵌套是不合理的：

```html
<a href="/products/shirt">

  <img src="shirt.jpg" alt="Cotton T-shirt">

  <button>Add to cart</button>

</a>
```

链接内部不能嵌套其他交互控件。

### 3.3 为什么 Quick Add 需要包含商品名称？

假设页面上有 24 个 Quick Add 按钮。

如果每一个按钮的 Accessible Name 都只是：

```text
Quick add
```

屏幕阅读器用户通过按钮列表浏览页面时，很难区分对应商品。

更合理的名称是：

```text
Quick add: Cotton T-shirt
Quick add: Linen shirt
Quick add: Classic jacket
```

而且保留了视觉按钮上的 Quick add 文字，符合 Label in Name 的设计要求。

## 4. Shopify Faceted Search 数据模型

Shopify Storefront Filtering 支持基于商品数据、Variant Option、Metafield、价格、可购买性等条件筛选商品。商家可以通过 Search & Discovery App 等方式配置筛选条件，Theme 则负责渲染及交互。<Cite refs={["turn175122search3","turn175122search8"]}/>

### 4.1 Filter 对象

```liquid
{% for filter in collection.filters %}
  {{ filter.label }}
  {{ filter.type }}
{% endfor %}
```

| 属性 | 作用 |
|---|---|
| `filter.label` | 筛选组名称 |
| `filter.type` | 筛选类型 |
| `filter.values` | 候选筛选值 |
| `filter.active_values` | 已选择的筛选值 |
| `filter.min_value` | 当前最低价格筛选值 |
| `filter.max_value` | 当前最高价格筛选值 |
| `filter.range_max` | 筛选范围最高价格 |
| `filter.url_to_remove` | 清除整个筛选组的 URL |

### 4.2 Filter Value 对象

| 属性 | 作用 |
|---|---|
| `value.label` | 用户看到的名称 |
| `value.value` | 实际筛选值 |
| `value.param_name` | URL 参数名称 |
| `value.active` | 是否已经选中 |
| `value.count` | 匹配该值的商品数量 |
| `value.url_to_remove` | 移除该筛选值的 URL |

这些属性由 Shopify 提供，因此 Theme 不需要自行猜测每个筛选条件应该对应什么 URL 参数。<Cite refs={["turn175122search5","turn175122search6"]}/>

### 4.3 数据与 URL 的关系

<box border radius="lg" padding={3} gap={2}>
  <box border radius="md" padding={3} gap={2}>
    **Shopify Filter**
    <row><caption>label</caption><spacer/>Color</row>
    <row><caption>type</caption><spacer/>list</row>
  </box>
  <box align="center"><icon name="arrow-down" color="secondary"/></box>
  <box border radius="md" padding={3} gap={2}>
    **Filter Value**
    <row><caption>label</caption><spacer/>Black</row>
    <row><caption>value</caption><spacer/>Black</row>
    <row><caption>active</caption><spacer/>true</row>
    <caption>param_name</caption>
    <text size="sm">filter.v.option.color</text>
  </box>
  <box align="center"><icon name="arrow-down" color="secondary"/></box>
  <box background="surface-tertiary" radius="md" padding={3}>
    **URL**
    <text size="xs">/collections/clothing?filter.v.option.color=Black</text>
  </box>
</box>

多个筛选值可以通过 URL 参数提交给 Shopify，服务器负责根据筛选条件计算商品集合。

这意味着无障碍开发不需要重新实现商品筛选算法，而是需要保证 Shopify 返回的筛选状态能够正确映射到前端控件。

## 5. Checkbox 与多选筛选的完整实现

商品筛选器通常由多个可展开的筛选组组成。

<box border radius="md" padding={3} gap={2}>
  <row align="center">
    **Color**
    <spacer/><caption>2 selected</caption><icon name="chevron-up" size="sm"/>
  </row>
  <divider/>
  {#each [{n:"Black",c:"#333333",count:18,checked:true},{n:"White",c:"#FAF9F5",count:12,checked:false},{n:"Blue",c:"#8198B2",count:8,checked:true},{n:"Red",c:"#AC6868",count:0,checked:false}] as p}
    <row align="center">
      <icon name={p.checked?"square-check":"square"} color={p.count===0?"secondary":"default"}/>
      <box size="18px" radius="full" border background={p.c}/>
      <text size="sm" color={p.count===0?"secondary":"default"}>{p.n}</text>
      <spacer/>
      <caption>({p.count})</caption>
    </row>
  {/each}
</box>

### 5.1 Liquid 实现

```liquid
<form
  id="CollectionFilters"
  action="{{ collection.url }}"
  method="get"
>

  {% for filter in collection.filters %}

    {% case filter.type %}

      {% when 'boolean', 'list' %}

        <details
          id="Facet-{{ section.id }}-{{ forloop.index }}"
          {% if filter.active_values.size > 0 %}open{% endif %}
        >
          <summary>
            {{ filter.label | escape }}

            {% if filter.active_values.size > 0 %}
              ({{ filter.active_values.size }} selected)
            {% endif %}
          </summary>

          <fieldset>
            <legend class="visually-hidden">
              {{ filter.label | escape }}
            </legend>

            {% for value in filter.values %}

              {% assign input_id = section.id
                | append: '-'
                | append: value.param_name
                | append: '-'
                | append: forloop.index
              %}

              <div class="filter-option">

                <input
                  type="checkbox"
                  id="{{ input_id | escape }}"
                  name="{{ value.param_name }}"
                  value="{{ value.value | escape }}"
                  {% if value.active %}checked{% endif %}
                  {% if value.count == 0 and value.active == false %}
                    disabled
                  {% endif %}
                >

                <label for="{{ input_id | escape }}">
                  {{ value.label | escape }}
                  ({{ value.count }})
                </label>

              </div>

            {% endfor %}

          </fieldset>

        </details>

    {% endcase %}

  {% endfor %}

  <button type="submit">
    Apply filters
  </button>

</form>
```

这段代码采用原生 GET Form，即使 JavaScript 加载失败，也能通过完整页面请求实现筛选。

### 5.2 Fieldset 与 Legend 的作用

当屏幕阅读器用户进入某个筛选组时，可以获得类似这样的信息：

```text
Color, grouping
Black, checkbox, checked, 18
White, checkbox, not checked, 12
Blue, checkbox, checked, 8
```

而不是只有：

```text
Black
White
Blue
```

尤其当页面上存在多个名称相似的筛选选项时，分组信息十分重要。

### 5.3 为什么 count 为 0 的选项不能全部禁用？

注意前面的 Liquid 判断：

```liquid
{% if value.count == 0 and value.active == false %}
  disabled
{% endif %}
```

如果某个筛选条件已经被选中，即使当前匹配数量为 0，也应该允许用户取消它。

否则用户可能无法通过原来的筛选控件解除限制。

这与上一课的 Sold Out Variant 有相似之处：**业务上的不可用状态，并不一定意味着控件本身应该被禁止操作。**

### 5.4 实时筛选还是点击 Apply？

| 方案 | 优点 | 缺点 |
|---|---|---|
| 每次 change 立即更新 | 反馈及时 | 可能频繁请求和播报 |
| Debounce 后更新 | 减少请求次数 | 仍需处理请求竞争 |
| 点击 Apply 后更新 | 操作可预测，可批量选择 | 多一次确认操作 |

对于桌面端筛选，可以采用实时更新。

对于移动端模态 Filter Drawer，我更推荐先选择多个条件，再点击 Apply 或 View results，避免用户每次选择 Checkbox 都触发页面跳动。

## 6. Price Range：价格范围筛选

价格范围筛选是 Collection 页面中较复杂的一类控件。

通常存在三种实现方式。

<box border radius="lg" padding={3} gap={3}>
  **方案一：两个数字输入框**
  <grid columns={2}>
    <grid-item><label>Minimum price</label><box border radius="sm" padding={3}>$ 20</box></grid-item>
    <grid-item><label>Maximum price</label><box border radius="sm" padding={3}>$ 150</box></grid-item>
  </grid>
  <caption>实现简单，适合精确输入。</caption>
  <divider/>
  **方案二：双滑块**
  <svg viewBox="0 0 320 68" width="100%">
    <path d="M15 32 H305" stroke="currentColor" strokeOpacity=".2" strokeWidth="5" strokeLinecap="round"/>
    <path d="M44 32 H232" stroke="#3978BC" strokeWidth="5"/>
    <circle cx="44" cy="32" r="10" fill="#FFFFFF" stroke="#3978BC" strokeWidth="2"/>
    <circle cx="232" cy="32" r="10" fill="#FFFFFF" stroke="#3978BC" strokeWidth="2"/>
    <text x="44" y="13" fontSize="12" textAnchor="middle" fill="currentColor">$20</text>
    <text x="232" y="13" fontSize="12" textAnchor="middle" fill="currentColor">$150</text>

  <divider/>
  **方案三：双滑块 + 数字输入框**
  <svg viewBox="0 0 320 40" width="100%">
    <path d="M15 20 H305" stroke="currentColor" strokeOpacity=".2" strokeWidth="5" strokeLinecap="round"/>

    <circle cx="232" cy="20" r="10" fill="#FFFFFF" stroke="#3978BC" strokeWidth="2"/>

  <grid columns={2}>
    <grid-item><label>From</label><box border radius="sm" padding={2}>$ 20</box></grid-item>
    <grid-item><label>To</label><box border radius="sm" padding={2}>$ 150</box></grid-item>
  </grid>

如果设计没有强制要求双滑块，两个原生输入框往往是成本最低、兼容性最好的方案。

Dawn 当前公开源码中的 `price-facet.liquid` 也采用了两个文字输入框，并使用 `inputmode="decimal"` 提示移动端显示适合数字输入的键盘。<Cite ref="turn440670view1"/>

### 6.1 原生 Range Slider 的语义

```html
<label for="price">
  Maximum price (USD)
</label>

<input
  id="price"
  type="range"
  min="0"
  max="200"
  step="1"
  value="100"
>
```

原生 `input[type="range"]` 已经提供 slider 语义、当前值、最小值、最大值以及键盘操作。

所以不需要重复设置：

```html
role="slider"
aria-valuemin="0"
aria-valuemax="200"
aria-valuenow="100"
```

### 6.2 自定义双滑块的 ARIA 结构

HTML 没有直接提供一个拥有两个 Thumb 的原生 Range Input。

如果完全自定义双滑块，需要为每一个 Thumb 分别提供 Slider 语义。

```html
<div role="group" aria-label="Price range">

  <div class="range-track">

    <div
      role="slider"
      tabindex="0"
      aria-label="Minimum price"
      aria-valuemin="0"
      aria-valuemax="150"
      aria-valuenow="20"
      aria-valuetext="20 US dollars"
    ></div>

    <div
      role="slider"
      tabindex="0"
      aria-label="Maximum price"
      aria-valuemin="20"
      aria-valuemax="200"
      aria-valuenow="150"
      aria-valuetext="150 US dollars"
    ></div>

  </div>

</div>
```

这里有一个重要的细节：两个 Slider 的取值范围是相互约束的。

最低价格不能超过最高价格，最高价格不能低于最低价格。因此，一个 Thumb 的值改变之后，另一个 Thumb 对应的 ARIA 边界也必须更新。

### 6.3 键盘操作规范

| 按键 | 行为 |
|---|---|
| Tab | 在两个 Thumb 之间移动焦点 |
| Shift + Tab | 反向移动 |
| ArrowRight / Up | 增加当前值 |
| ArrowLeft / Down | 减少当前值 |
| Home | 移动至当前允许的最小值 |
| End | 移动至当前允许的最大值 |
| PageUp / PageDown | 可选，进行较大幅度调整 |

两个 Thumb 都应该保留键盘访问入口，而且 Tab 顺序不应因两个滑块的视觉位置变化而改变。W3C APG 对双滑块的相互约束及触屏辅助技术兼容性有专门的设计指导。<Cite ref="turn175122search1"/>

### 6.5 JavaScript 核心实现

下面是自定义 Thumb 的键盘与语义状态管理代码。

```javascript
const state = {
  min: 20,
  max: 150,
  lowerLimit: 0,
  upperLimit: 200,
  step: 1
};

const minThumb = document.querySelector('[data-thumb="min"]');
const maxThumb = document.querySelector('[data-thumb="max"]');

const currency = new Intl.NumberFormat('en-US', {
  style: 'currency',
  currency: 'USD'
});

function setPrice(type, value) {
  if (type === 'min') {
    state.min = Math.max(
      state.lowerLimit,
      Math.min(value, state.max)
    );
  } else {
    state.max = Math.min(
      state.upperLimit,
      Math.max(value, state.min)
    );
  }

  render();
}

function render() {
  minThumb.setAttribute(
    'aria-valuemin', state.lowerLimit
  );

  minThumb.setAttribute(
    'aria-valuemax', state.max
  );

  minThumb.setAttribute(
    'aria-valuenow', state.min
  );

  minThumb.setAttribute(
    'aria-valuetext', currency.format(state.min)
  );

  maxThumb.setAttribute(
    'aria-valuemin', state.min
  );

  maxThumb.setAttribute(
    'aria-valuemax', state.upperLimit
  );

  maxThumb.setAttribute(
    'aria-valuenow', state.max
  );

  maxThumb.setAttribute(
    'aria-valuetext', currency.format(state.max)
  );

  // 此处同步视觉位置及价格输入框
}

function onKeydown(event, type) {
  const min = type === 'min'
    ? state.lowerLimit
    : state.min;

  const max = type === 'min'
    ? state.max
    : state.upperLimit;

  let value = state[type];

  switch (event.key) {
    case 'ArrowRight':
    case 'ArrowUp':
      value += state.step;
      break;

    case 'ArrowLeft':
    case 'ArrowDown':
      value -= state.step;
      break;

    case 'Home':
      value = min;
      break;

    case 'End':
      value = max;
      break;

    default:
      return;
  }

  event.preventDefault();

  setPrice(type, value);
}

minThumb.addEventListener('keydown', event => {
  onKeydown(event, 'min');
});

maxThumb.addEventListener('keydown', event => {
  onKeydown(event, 'max');
});

render();
```

以上仅实现键盘操作和 ARIA 数值约束，尚未包含指针拖拽、触屏、轨道点击、视觉位置计算等完整功能。

正式项目建议优先使用原生 Range Input 或经过充分无障碍验证的组件库，并提供两个可直接输入价格的字段作为替代操作。

### 6.6 Shopify 价格参数

Shopify 原生筛选通常使用：

```text
filter.v.price.gte=20
filter.v.price.lte=150
```

不过在 Liquid 中，仍然应该优先使用：

```liquid
{{ filter.min_value.param_name }}
{{ filter.max_value.param_name }}
```

特别注意，Liquid 中的价格数值与 URL 中用户输入的货币金额不能不加区分地直接使用。

正式项目需要正确处理当前币种、金额单位、小数分隔符以及区域格式。

### 7.1 使用 Shopify 原生移除 URL

```liquid
<div class="active-filters">

  <h2 class="visually-hidden">
    Applied filters
  </h2>

  <ul role="list">

    {% for filter in collection.filters %}

      {% for value in filter.active_values %}

            href="{{ value.url_to_remove }}"
```

这里使用链接，而不是普通 span。

这样在 JavaScript 不可用时，用户仍然能够访问对应 URL 来移除筛选条件；JavaScript 可用时，则可以拦截链接执行 AJAX 更新。

价格范围属于特殊筛选类型，应根据 `filter.min_value` 和 `filter.max_value` 另外生成对应的价格 Chip。

### 7.2 删除 Chip 之后，焦点应该去哪里？

这是 Active Filters 最容易遗漏的问题。

<box border radius="lg" padding={3} gap={3}>
  <caption>删除前</caption>
  <row wrap="wrap" gap={2}>
    <box border radius="full" padding={2}><text size="sm">Black ×</text></box>
    <box border={{size:2,color:"#3978BC"}} radius="full" padding={2}><text size="sm">Size M ×</text></box>
    <box border radius="full" padding={2}><text size="sm">In stock ×</text></box>
  </row>
  <box align="center"><icon name="arrow-down"/><caption>删除 Size M</caption></box>
  <caption>删除后</caption>
  <row wrap="wrap" gap={2}>
    <box border radius="full" padding={2}><text size="sm">Black ×</text></box>
    <box border={{size:2,color:"#3978BC"}} radius="full" padding={2}><text size="sm">In stock ×</text></box>
  </row>
  <caption>原焦点元素已被删除，将焦点移至下一个合理的删除控件。</caption>
</box>

推荐焦点恢复顺序：

1. 如果还有下一个 Chip，聚焦下一项。
2. 如果没有下一项，聚焦上一项。
3. 如果所有 Chip 都被删除，聚焦筛选入口或商品结果标题。
4. 如果用户在请求期间主动移动了焦点，则不要擅自抢回焦点。

不能简单地在更新完成后执行：

```javascript
document.body.focus();
```

也不应该每删除一个筛选条件，就将用户送回页面顶部。

## 8. Sort By 排序与 WCAG On Input

Shopify Collection 原生排序通常采用 `collection.sort_options`。

```liquid
{% assign sort_by = collection.sort_by
  | default: collection.default_sort_by
%}

<label for="SortBy">
  Sort by
</label>

<select id="SortBy" name="sort_by">

  {% for option in collection.sort_options %}

    <option
      value="{{ option.value | escape }}"
      {% if option.value == sort_by %}
        selected
      {% endif %}
    >
      {{ option.name | escape }}
    </option>

  {% endfor %}

</select>
```

### 8.1 修改 Select 后立即排序，是否违反 ADA 无障碍要求？

不一定。

WCAG 3.2.2 On Input 主要限制的是控件值变化后产生用户未预期的上下文变化，而不是禁止所有动态内容更新。<Cite ref="turn440670view2"/>

| 排序行为 | 无障碍判断 |
|---|---|
| 选择后 AJAX 更新商品列表，保留焦点 | 通常可以 |
| 选择后立即刷新整个页面，且没有提前说明 | 可能违反 3.2.2 |
| 选择后自动聚焦商品列表 | 可能造成意外的上下文变化 |
| 点击 Apply sort 后进行页面跳转 | 用户主动触发，通常合理 |
| 选择后只更新 URL 和商品顺序 | 通常可以，仍需验证整体行为 |

因此，很多 Shopify Theme 使用下面的代码，并不意味着一定违反 WCAG：

```javascript
select.addEventListener('change', event => {
  updateCollection(event.target.value);
});
```

关键在于更新过程中是否保留用户的操作上下文。

### 8.2 排序完成后如何通知？

假设排序之前有 48 件商品，排序之后仍然有 48 件商品。

如果仅仅更新 Live Region：

```javascript
status.textContent = '48 products found.';
```

由于文字没有发生实质变化，屏幕阅读器可能不会播报。

更有意义的方式是补充排序信息：

```javascript
status.textContent =
  '48 products, sorted by price, low to high.';
```

这样用户可以明确知道排序操作已经生效。

### 9.1 Draft State 与 Applied State

移动端筛选有一个非常值得学习的状态管理思想。

```javascript
const state = {
  draftFilters: {
    color: ['Black', 'Blue']
  },

  appliedFilters: {
    color: ['Black']
  }
};
```

| 状态 | 含义 |
|---|---|
| draftFilters | 用户在抽屉中正在编辑的条件 |
| appliedFilters | 当前 Collection 实际使用的条件 |

如果采用 Apply 模式，用户关闭 Drawer 时，可以丢弃尚未确认的 draftFilters。

点击 Apply 时，再将 Draft State 应用到 Collection。

{@body const [draft22,setDraft22]=DIL.useState(["Black"])}
{@body const [applied22,setApplied22]=DIL.useState(["Black"])}
{@body const [drawer22,setDrawer22]=DIL.useState(false)}
<card gap={3}>
  **筛选状态实验室**
  <row align="center">
    <box flex={1} gap={1}>
      <caption>Collection 已应用的颜色</caption>
      **{applied22.join(", ")||"All colors"}**
    </box>
    <button variant="outline" color="secondary" disabled={drawer22} onClick={()=>{setDraft22([...applied22]);setDrawer22(true)}}><icon name="sliders-horizontal" size="sm"/> Filters</button>
  </row>
  {#if drawer22}
    <box border radius="md" padding={3} gap={2}>
      <row align="center">**Filters**<spacer/><button uniform variant="ghost" color="secondary" onClick={()=>{setDraft22([...applied22]);setDrawer22(false)}}><icon name="x"/></button></row>
      {#each ["Black","White","Blue"] as c}
        <checkbox checked={draft22.includes(c)} onChange={v=>setDraft22(old=>v?[...old,c]:old.filter(x=>x!==c))}>{c}</checkbox>
      {/each}
      <button block onClick={()=>{setApplied22([...draft22]);setDrawer22(false)}}>Apply filters</button>
      <button block color="secondary" variant="ghost" onClick={()=>{setDraft22([...applied22]);setDrawer22(false)}}>Cancel</button>
    </box>

### 10.1 为什么不能只更新 Product Grid？

假设初始 Collection 数据为：

| 筛选条件 | 商品数量 |
|---|---:|
| Black | 18 |
| White | 12 |
| Blue | 8 |

选择 Size M 之后，可能变成：

| 筛选条件 | 商品数量 |
|---|---:|
| Black | 6 |
| White | 4 |
| Blue | 0 |

因此筛选之后，不仅需要更新商品列表，还需要更新其他 Filter Value 的 count 和 disabled 状态。

否则，用户看到的筛选器就不再与真实商品数据一致。

### 10.2 推荐 DOM 架构

```html

  data-section-id="template--123__product-grid"

  </div>

    <!-- Removable filters -->
  </div>

    Products
  </h2>

    id="ProductCount"
    role="status"
    aria-atomic="true"

  </p>

```

其中 ProductCount、ResultsTitle、CollectionError 尽量保留原 DOM 节点，而不是每次都整体替换。

这样可以稳定地承担 Live Region、备用焦点及错误反馈职责。

### 10.3 使用 FormData 生成 URL

```javascript
function getFilterURL(form) {
  const url = new URL(
    form.action,
    window.location.origin
  );

  const params = new URLSearchParams(
    new FormData(form)
  );

  // 筛选或排序变化后回到第一页
  params.delete('page');

  // 移除空的价格筛选字段
  for (const key of [
    'filter.v.price.gte',
    'filter.v.price.lte'
  ]) {
    if (params.get(key) === '') {
      params.delete(key);
    }
  }

  url.search = params.toString();

  return url;
}
```

例如两个颜色选项使用相同的 name：

```html
<input
  type="checkbox"
  name="filter.v.option.color"
  value="Black"
  checked
>

<input
  type="checkbox"
  name="filter.v.option.color"
  value="Blue"
  checked
>
```

FormData 可以保留多个同名字段，而不是只留下最后一个值。

因此不要随意将 FormData 转换为普通 Object，否则可能丢失多选筛选条件。

该方案假设排序与筛选字段处于同一个 GET Form 中；如果桌面端和移动端使用不同表单，需要额外合并适当的字段。

必须同时考虑 AbortController 和请求版本控制。

### 11.1 主请求逻辑

```javascript
let controller;
let requestVersion = 0;

async function updateCollection(
  pageURL,
  { pushHistory = true } = {}
) {
  const version = ++requestVersion;

  controller?.abort();
  controller = new AbortController();

  const root = document.querySelector('#CollectionRoot');

  const grid = root.querySelector('#ProductGridContainer');
  const count = root.querySelector('#ProductCount');
  const error = root.querySelector('#CollectionError');

  grid.setAttribute('aria-busy', 'true');
  error.textContent = '';

  try {
    const requestURL = new URL(pageURL);

    requestURL.searchParams.set(
      'section_id',
      root.dataset.sectionId
    );

    const response = await fetch(requestURL, {
      signal: controller.signal
    });

    if (!response.ok) {
      throw new Error('Request failed');
    }

    const html = new DOMParser().parseFromString(
      await response.text(),
      'text/html'
    );

    if (version !== requestVersion) return;

    const nextRoot = html.querySelector('#CollectionRoot');

    if (!nextRoot) {
      throw new Error('Invalid section response');
    }

    renderCollection(root, nextRoot);

    const nextCount = nextRoot.querySelector('#ProductCount');

    count.textContent = nextCount.textContent.trim();

    if (pushHistory && pageURL.href !== location.href) {
      history.pushState(null, '', pageURL);
    }

  } catch (err) {
    if (
      err.name === 'AbortError' ||
      version !== requestVersion
    ) return;

    error.textContent =
      'Unable to update products. Previous results are still displayed. Please try again.';

  } finally {
    if (version === requestVersion) {
      grid.setAttribute('aria-busy', 'false');
    }
  }
}
```

这里将页面 URL 和 Section 请求 URL 分开。

浏览器地址栏中的 URL 不应该包含用于内部 HTML 渲染的 `section_id` 参数。

另外，请求失败后应明确告诉用户目前显示的是旧结果，而不是让用户误认为新筛选条件已经生效。

### 12.2 保存 Accordion 的展开状态

筛选器不仅需要恢复焦点，还应该保留用户已经展开的筛选组。

```javascript
function captureOpenFacets(root) {
  return new Set(
    [...root.querySelectorAll('details[open][id]')]
      .map(details => details.id)
  );
}
```

更新之后：

```javascript
function restoreOpenFacets(root, openIds) {
  root.querySelectorAll('details[id]')
    .forEach(details => {
      details.open = openIds.has(details.id);
    });
}
```

正式实现应当使用稳定的筛选组标识，而不是依赖可能因筛选组增删而变化的索引。

### 12.3 统一渲染方法

下面补齐上一节的 `renderCollection()`。

```javascript
function renderCollection(root, nextRoot) {
  const regions = [
    'FacetPanel',
    'ActiveFilters',
    'ProductGridContainer'
  ];

  const pairs = regions.map(id => ({
    current: root.querySelector(`#${id}`),
    next: nextRoot.querySelector(`#${id}`)
  }));

  if (pairs.some(pair => !pair.current || !pair.next)) {
    throw new Error('Missing collection region');
  }

  // 在真正替换 DOM 之前获取焦点
  const active = document.activeElement;

  const affected = pairs.find(pair =>
    pair.current.contains(active)
  );

  const focusKey = affected
    ? active.dataset.focusKey
    : null;

  const focusId = affected
    ? active.id
    : null;

  const openFacets = captureOpenFacets(root);

  pairs.forEach(({ current, next }) => {
    current.innerHTML = next.innerHTML;
  });

  restoreOpenFacets(root, openFacets);

  // 用户焦点不在更新范围内，不主动移动焦点
  if (!affected || active.isConnected) return;

  const replacement = focusKey
    ? [...affected.current.querySelectorAll('[data-focus-key]')]
        .find(element =>
          element.dataset.focusKey === focusKey
        )
    : focusId
      ? document.getElementById(focusId)
      : null;

  const candidates = [
    replacement,

    affected.current.querySelector(
      'a[href], button:not(:disabled)'
    ),

    root.querySelector('#ResultsTitle')
  ];

  for (const element of candidates) {
    if (!element?.isConnected) continue;

    if (element.matches(':disabled')) continue;

    if (element.closest('[inert], [hidden]')) continue;

    element.focus();

    if (document.activeElement === element) {
      break;
    }
  }
}
```

这段代码展示的是通用恢复机制。

如果删除 Active Filter，应进一步记录原 Chip 相邻的业务标识，以便优先恢复到下一项或上一项，而不是总是恢复到第一个链接。

**更理想的优化是：如果某个控件没有必要被销毁，就不要销毁它。**

例如仅更新 Checkbox 对应的数量、disabled 状态以及 label 内容，而不是替换整个 Checkbox 节点。

虽然我们跳过了第 19 课 SPA 路由，本节仍然需要介绍 Collection 特有的 History 管理。

假设用户进行了以下操作：

<box border radius="lg" padding={3} gap={2}>

当用户点击浏览器返回按钮时，不应该只是地址栏发生变化。

商品列表、Checkbox、Sort By、Active Filters 和结果数量都需要恢复到对应 URL 的状态。

```javascript

  updateCollection(
    new URL(window.location.href),
    { pushHistory: false }
  );
});
```

这里必须设置 `pushHistory: false`，否则浏览器执行返回操作时，又会创建新的历史记录。

### pushState 与 replaceState

| API | 推荐场景 |
|---|---|
| `history.pushState()` | 用户完成一次新的筛选操作 |
| `history.replaceState()` | 替换当前记录或初始化状态 |
| `popstate` | 浏览器前进与后退 |

价格滑块拖动时，不建议每移动一个像素就调用 pushState。

可以在用户结束拖动、确认价格范围或点击 Apply 后，再提交新的筛选状态。

在生产环境中，还应处理历史恢复请求失败、URL 与显示结果不一致、滚动位置恢复等情况。

### 15.2 AJAX Pagination 的焦点应该移到哪里？

这里与筛选操作略有不同。

| 操作 | 推荐焦点策略 |
|---|---|
| Checkbox 筛选 | 保留 Checkbox 焦点 |
| 商品排序 | 保留 Select 焦点 |
| 删除 Active Filter | 恢复相邻控件 |
| 点击下一页 | 通常移至新结果标题 |
| 加载更多商品 | 保留或移至第一项新增内容，视业务设计 |

分页操作的目的是浏览下一批商品。如果用户点击 Next 后仍然停留在页面最底部，可能需要反复向上查找新商品。

对于 AJAX 分页，可以在完成更新后执行：

```javascript
const heading = document.querySelector('#ResultsTitle');

heading.focus({
  preventScroll: true
});

heading.scrollIntoView({
  block: 'start',
  behavior: 'instant'
});
```

同时确保 Sticky Header 不会完全遮挡该标题。

这是根据分页业务目标进行的焦点管理，而不是一律要求所有 AJAX 操作都移动焦点。

| 对比项 | Pagination | Load More | Infinite Scroll |
|---|---|---|---|
| 键盘操作 | 简单 | 较简单 | 较复杂 |

| URL 状态管理 | 容易 | 中等 | 较复杂 |

对于需要兼顾无障碍和 SEO 的 Shopify Theme，我通常优先采用 Pagination 或具有分页回退链接的 Load More。

### 16.1 Load More 的关键问题

假设当前页面有 24 张商品卡片，后面是 Load More 按钮。

用户点击后，新的 24 张商品被追加在按钮之前。

```text
Product 1
...
Product 24
Product 25   ← 新增
...
Product 48   ← 新增
Load more    ← 当前焦点
Footer
```

如果焦点始终停留在 Load More，那么用户再次按 Tab，可能直接进入 Footer，跳过刚刚加载的 24 件商品。

一种合理的策略是加载成功后将焦点移动至第一张新增商品的链接。

```javascript
const firstNewProduct =
  newProducts[0]?.querySelector('a[href]');

firstNewProduct?.focus();
```

另一种策略是重新设计 DOM 顺序，让保留在 Load More 按钮上的焦点能够自然进入新增内容。

无论哪种方式，都应该保证用户可以顺利访问刚加载的商品。

### 16.2 加载更多的状态通知

```html
<p role="status" id="LoadMoreStatus"></p>

<button type="button" id="LoadMoreButton">
  Load more products
</button>
```

请求完成：

```javascript
status.textContent =
  '24 more products loaded. Showing 48 of 120 products.';
```

当所有商品加载完成时，如果 Load More 按钮即将消失，需要先处理其焦点。

### 16.3 Infinite Scroll 的问题

Infinite Scroll 本身不是 WCAG 禁止的交互模式，但实现不当容易产生以下问题：

- 用户难以访问 Footer。
- 自动加载没有明确通知。
- DOM 数量持续增长，影响辅助技术和页面性能。
- 虚拟列表移除了用户正在访问的内容。
- 返回商品列表时无法恢复原来的浏览位置。
- 加载失败后没有手动重试入口。

因此，不建议只为了追求视觉体验，就将所有 Collection 分页改成无限滚动。

### 17.4 renderFilters() 为什么不直接替换整个筛选器？

这是 Dawn 中非常值得深入理解的一部分。

它会识别触发当前更新的筛选组，将该筛选组与其他筛选组区别处理。

可以将其核心思想概括为：

```javascript
// 教学伪代码
const activeFacet = getTriggeredFacet(event);

const otherFacets = getNewFacets()
  .filter(facet => facet.id !== activeFacet.id);

renderOtherFacets(otherFacets);

updateActiveFacetCounts(activeFacet);
```

这样能够尽可能保留当前操作区域，再更新其他筛选组及相关信息。

实际源码还会处理服务器不再返回的筛选组、新增筛选组、移动端数量以及适用的焦点恢复。

### 17.5 renderProductCount()

Dawn 更新商品数量时，主要更新现有计数容器的内容，而不是每次重新建立整个计数容器。

它还会同步桌面端结果数量及 Loading 状态。

这与第 14 课中保持 Live Region 节点稳定的思想一致。

### 17.6 源码有哪些值得进一步审查的地方？

在本次查阅的 `facets.js` 中，`renderSectionFromFetch()` 使用 fetch 请求并将返回的 HTML 交给后续渲染逻辑。在该方法中没有看到显式的 AbortController 或最新请求版本校验。<Cite ref="turn440670view0"/>

因此扩展 Dawn 时，可以重点检查：

| Dawn 机制 | 建议审查的场景 |
|---|---|
| 800ms Debounce | 慢网络下仍可能出现请求竞争 |
| Section HTML 缓存 | 缓存结果是否仍符合当前业务状态 |
| DOM 局部替换 | 用户焦点是否丢失 |
| 当前筛选组特殊处理 | Checkbox 状态与数量是否一致 |
| 桌面、移动两套表单 | ID 与业务状态是否重复或冲突 |
| History API | 返回时是否完整恢复筛选 |
| Loading Spinner | 请求失败后是否正确清理 |
| Product Count | 相同数量的排序结果是否能够被感知 |

这些是基于源码提出的工程审查点，并不代表已经通过实际辅助技术测试确认的 Dawn 缺陷。

```javascript
test('back restores applied filters', async ({ page }) => {

  });
```
