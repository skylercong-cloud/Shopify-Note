| 类型 | 背景可操作 | 是否限制焦点 | 常见场景 |
|---|---|---|---|
| Modal Dialog | 否 | 是 | Quick Add、尺寸说明 |
| Non-modal Dialog | 是 | 否 | 帮助面板 |
| Modal Drawer | 否 | 是 | Cart Drawer、移动端筛选 |
| Non-modal Drawer | 是 | 否 | 常驻筛选侧栏 |
| Popover | 通常是 | 通常否 | 国家选择、辅助信息 |
| Alert Dialog | 否 | 是 | 重要操作确认 |

最重要的认知是：

**Drawer 不是一种独立的 ARIA Role，而是一种视觉布局形式。**

ARIA 中没有 `role="drawer"`，也没有 `role="modal"`。

如果购物车抽屉具有模态行为，那么它在无障碍语义上就是一个 Modal Dialog。

## 2. 一个合格的 Modal 需要实现什么？

根据 WAI-ARIA APG 的 Modal Dialog Pattern，一个完整的模态弹窗应该具有明确的名称、合理的初始焦点、内部键盘导航、背景交互隔离，以及关闭后的焦点恢复。<Cite ref="turn171841search8"/>

| 技术 | 在 Modal 中的职责 |
|---|---|
| Role | 表达 dialog 或 alertdialog 语义 |
| Accessible Name | 告诉用户当前是什么弹窗 |
| Initial Focus | 打开时将焦点移入弹窗 |
| Focus Trap | 限制页面内的焦点导航范围 |
| Inert | 禁止背景区域交互 |
| Scroll Lock | 防止背景页面意外滚动 |
| Escape | 提供键盘退出机制 |
| Focus Restoration | 关闭后恢复操作位置 |
| Live Region | 通知弹窗内部的异步业务变化 |
| Reduced Motion | 支持减少运动偏好 |

其中 Scroll Lock 属于常见的交互设计需求，不是所有 Modal 都必须采用相同的滚动锁定技术。

这些内容实际上都是前面课程的综合应用。

## 3. 原生 dialog 完整 API

过去，我们通常使用 div 模拟弹窗。

```html
<div
  role="dialog"
  aria-modal="true"
  aria-labelledby="modal-title"
>
  ...
</div>
```

现在，现代浏览器已经提供了原生 HTML dialog 元素。

```html
<dialog aria-labelledby="modal-title">
  <h2 id="modal-title">Your cart</h2>
</dialog>
```

两者最大的区别在于，原生 dialog 不仅提供语义，还提供一系列浏览器级别的交互行为。

### 3.1 常用 API

| API | 作用 |
|---|---|
| `showModal()` | 以模态方式打开 |
| `show()` | 以非模态方式打开 |
| `close(value)` | 直接关闭 |
| `requestClose(value)` | 请求关闭，允许取消 |
| `open` | 当前是否处于打开状态 |
| `returnValue` | 弹窗关闭时的返回值 |
| `closedBy` | 控制允许哪些用户关闭方式 |
| `cancel` 事件 | 关闭请求发生时触发 |
| `close` 事件 | 弹窗关闭后触发 |

其中 `requestClose()`、`closedBy` 属于相对较新的能力，使用时需要考虑目标浏览器兼容性。<Cite refs={["turn171841search14","turn171841search26"]}/>

### 3.2 showModal() 与 show()

```javascript
const dialog = document.querySelector('dialog');

// 模态打开
dialog.showModal();

// 非模态打开
dialog.show();
```

实际开发时应该根据组件类型选择其中一种，而不是连续调用两者。

| 能力 | showModal() | show() |
|---|---|---|
| 原生 dialog 语义 | 有 | 有 |
| 进入 Top Layer | 是 | 否 |
| `::backdrop` 遮罩 | 有 | 无 |
| 背景自动隔离 | 是 | 否 |
| 背景正常 Tab 访问 | 否 | 是 |
| 原生焦点初始化 | 有 | 有 |
| 默认 Esc 关闭 | 支持 | 通常不支持 |

特别注意：

```html
<dialog open>
  Your cart
</dialog>
```

直接添加 `open` 属性只是显示 dialog，不会建立真正的模态行为。

同样，不建议通过下面的方式关闭一个已经使用 showModal() 打开的弹窗：

```javascript
dialog.removeAttribute('open');
```

应该使用：

```javascript
dialog.close();
```

否则可能破坏原生模态生命周期，并且不会正常触发 close 事件。<Cite refs={["turn171841search25","turn171841search36"]}/>

## 4. Top Layer 与 z-index 的区别

这是原生 dialog 相对于传统自定义弹窗非常重要的优势。

假设页面存在以下结构：

```html
<div class="product-section">
  <div class="custom-modal">
    ...
  </div>
</div>

<header class="sticky-header">
  ...
</header>
```

```css
.product-section {
  position: relative;
  z-index: 1;
}

.custom-modal {
  position: fixed;
  z-index: 999999;
}

.sticky-header {
  position: sticky;
  top: 0;
  z-index: 100;
}
```

即使 `.custom-modal` 设置了非常大的 z-index，它仍然可能被 Header 遮挡。

因为它受到祖先 Stacking Context（层叠上下文）的限制。

    <text x="170" y="174" fontSize="12" fontWeight="600" textAnchor="middle" fill="currentColor">普通页面</text>
    <text x="170" y="192" fontSize="10" textAnchor="middle" fill="currentColor">Product section · z-index: 1</text>

    <text x="170" y="104" fontSize="12" fontWeight="600" textAnchor="middle" fill="currentColor">其他层叠上下文</text>
    <text x="170" y="122" fontSize="10" textAnchor="middle" fill="currentColor">Sticky Header · z-index: 100</text>
    <rect x="50" y="8" width="240" height="56" rx="7" fill="#39866B" fillOpacity=".12" stroke="#39866B" strokeWidth="1.5"/>
    <text x="170" y="30" fontSize="14" fontWeight="600" textAnchor="middle" fill="currentColor">Top Layer</text>
    <text x="170" y="48" fontSize="11" textAnchor="middle" fill="currentColor">Modal dialog / Popover / Fullscreen</text>
    <path d="M170 83 V65 M170 152 V138" stroke="currentColor" strokeOpacity=".35" strokeDasharray="3 3"/>
  </svg>
  <caption>Top Layer 是浏览器管理的独立顶层，不是简单地设置一个更大的 z-index。</caption>
</box>

当执行：

```javascript
dialog.showModal();
```

浏览器会将弹窗呈现在 Top Layer 中，因此不需要通过不断增大 z-index 来解决普通页面的层叠冲突。

需要注意，dialog 并没有因此被移动到 body 下，它在 DOM 中的真实父子关系仍然存在。

通过 Popover API 打开的元素也可以进入 Top Layer，但 Popover 本身是非模态的。<Cite refs={["turn171841search18","turn171841search1"]}/>

### 4.1 ::backdrop

原生模态 dialog 提供了专门的遮罩伪元素。

```css
dialog::backdrop {
  background: rgb(0 0 0 / 50%);
}
```

也可以实现背景模糊：

```css
dialog::backdrop {
  background: rgb(0 0 0 / 40%);
  backdrop-filter: blur(4px);
}
```

不再需要单独创建一个全屏遮罩 div。

不过，遮罩负责视觉表现，真正的背景交互隔离来自 showModal() 的原生模态行为。

### 5.4 浏览器替我们完成了什么？

这里并没有手动实现以下功能：

```javascript
trapFocus();
setBackgroundInert();
listenForEscape();
```

浏览器已经提供了基础的模态隔离、初始焦点选择、默认关闭请求和焦点恢复能力。

我们主要需要负责：

- 为弹窗提供正确的名称。
- 选择合适的初始焦点。
- 提供可见且可访问的关闭入口。
- 处理特殊的焦点恢复场景。
- 设计内部滚动、业务逻辑和动画。

对于新开发的 Theme 组件，原生 dialog 可以显著降低开发和维护成本。

## 6. cancel、close 事件与关闭机制

在复杂业务中，打开和关闭弹窗并不仅仅是修改显示状态。

例如，用户正在编辑收货地址，此时按下 Esc，我们可能需要判断是否存在尚未保存的数据。

### 6.1 cancel 与 close 的区别

| 事件 | 触发时机 | 可以阻止关闭 | 是否冒泡 |
|---|---|---|---|
| `cancel` | 收到关闭请求时 | 是 | 否 |
| `close` | 弹窗已经关闭后 | 否 | 否 |

这两个事件承担不同的生命周期职责。<Cite refs={["turn171841search9","turn171841search24"]}/>

### 6.2 close() 与 requestClose()

```javascript
dialog.close();
```

直接关闭弹窗，不经过可取消的 cancel 事件。

```javascript
dialog.requestClose();
```

先发出关闭请求，允许开发者通过 cancel 事件阻止关闭。

### 6.3 阻止关闭的业务示例

```javascript
let isSaving = false;

dialog.addEventListener('cancel', event => {
  if (isSaving) {
    event.preventDefault();

    status.textContent =
      'Saving your changes. Please wait.';
  }
});
```

这里的 status 应该是弹窗内部提前存在的 Live Region。

如果暂时阻止用户关闭弹窗，应明确告知原因，并确保操作失败或超时后能够恢复退出能力，不能让用户无限期地被困在弹窗中。

### 6.4 在 close 事件中统一清理资源

```javascript
dialog.addEventListener('close', () => {
  stopVideoPlayback();
  abortPendingRequests();
  clearTemporaryState();
});
```

相比只在关闭按钮的 click 事件中进行清理，这种方式更加合理。

因为弹窗可能通过 Esc、JavaScript、表单提交等不同方式关闭。

## 7. 点击遮罩关闭：Light Dismiss

对于 Size Guide、Quick Add、Cart Drawer 等弹窗，通常允许点击外部遮罩关闭。

但是对于支付确认、删除确认等重要操作，可能不希望用户误触遮罩导致弹窗关闭。

### 7.1 closedby 属性

现代 HTML 提供了一个专门控制关闭方式的属性。

```html
<dialog closedby="any">
  ...
</dialog>
```

| closedby | 点击外部关闭 | Esc 等关闭请求 | 开发者主动关闭 |
|---|---|---|---|
| `any` | 支持 | 支持 | 支持 |
| `closerequest` | 不支持 | 支持 | 支持 |
| `none` | 不支持 | 不支持 | 支持 |

原生 dialog 通过 showModal() 打开时，如果未指定该属性，默认行为相当于 closerequest。

截至目前，closedby 尚未达到广泛浏览器兼容的 Baseline 状态，因此仍然需要特性检测。<Cite ref="turn526085view1"/>

### 7.2 传统兼容方案

很多开发者会这样实现：

```javascript
dialog.addEventListener('click', event => {
  if (event.target === dialog) {
    dialog.close();
  }
});
```

这里有一个潜在问题：点击 dialog 内部的 padding 或空白区域时，event.target 也可能是 dialog 本身。

因此，可以进一步判断指针是否位于弹窗矩形之外。

```javascript
function isOutside(event, dialog) {
  const rect = dialog.getBoundingClientRect();

  return (
    event.clientX < rect.left ||
    event.clientX > rect.right ||
    event.clientY < rect.top ||
    event.clientY > rect.bottom
  );
}

let pressedOutside = false;

dialog.addEventListener('pointerdown', event => {
  pressedOutside =
    event.target === dialog &&
    isOutside(event, dialog);
});

dialog.addEventListener('pointerup', event => {
  const shouldClose =
    pressedOutside &&
    event.target === dialog &&
    isOutside(event, dialog);

  pressedOutside = false;

  if (shouldClose) {
    dialog.close();
  }
});

dialog.addEventListener('pointercancel', () => {
  pressedOutside = false;
});
```

同时判断 pointerdown 和 pointerup，是为了减少用户从弹窗内部拖动到外部时意外关闭弹窗的情况。

这个示例适用于普通矩形弹窗。对于复杂形状、多指触摸和具有关闭前校验的组件，还需要进一步处理。

**点击遮罩只是额外的关闭方式，不能替代可通过键盘操作的 Close 按钮。**

### 8.2 form method="dialog"

这是原生 dialog 非常实用的一个功能。

```html

```

这种表单提交方式不会像普通表单一样向服务器发送请求，而是关闭所在的 dialog，并将提交按钮的 value 作为弹窗返回值。

```javascript
function confirmRemoval() {
  dialog.returnValue = '';
  dialog.showModal();
}

dialog.addEventListener('close', () => {
  if (dialog.returnValue === 'confirm') {
    removeAddress();
  }
});
```

| 用户操作 | 业务结果 |
|---|---|
| 点击 Cancel | 不删除 |
| 点击 Remove | 执行删除逻辑 |
| 按 Esc | 不删除 |

每次打开前重置 returnValue，可以避免上一次弹窗的返回值影响本次判断。

如果删除操作需要等待服务器返回结果后才能关闭弹窗，则应该改为普通按钮配合异步请求，而不是使用自动关闭的 method="dialog"。

## 10. Scroll Lock：背景滚动锁定

这里要区分三个概念：

| 技术 | 职责 |
|---|---|
| `inert` | 禁止背景交互与无障碍访问 |
| Focus Trap | 限制页面内的焦点移动 |
| Scroll Lock | 禁止背景页面滚动 |

即使原生 dialog 已经处理了模态背景隔离，也不应该假设所有浏览器都会自动满足项目所需的背景滚动锁定效果。

### 10.1 基于 CSS 的方案

对于支持 `:has()` 和 `:modal` 的浏览器：

```css
html:has(dialog:modal) {
  overflow: hidden;
}

html {
  scrollbar-gutter: stable;
}
```

这种方案的优势是，滚动状态直接由当前是否存在原生模态弹窗决定。

当第二层 Modal 关闭，而第一层 Modal 仍然存在时，背景依然保持滚动锁定。

### 10.2 传统 JavaScript 方案的问题

```javascript
function openModal() {
  document.body.style.overflow = 'hidden';
}

function closeModal() {
  document.body.style.overflow = '';
}
```

对于只有一个 Modal 的简单页面可能没有问题。

但是对于多层 Modal：

```text
打开 Cart Drawer → 锁定滚动
打开 Size Guide → 锁定滚动
关闭 Size Guide → 解除滚动
```

此时 Cart Drawer 仍然打开，背景却已经恢复滚动。

可以使用 Set 维护当前持有滚动锁的组件。

```javascript
const scrollLocks = new Set();

function lockScroll(owner) {
  scrollLocks.add(owner);

  document.documentElement.classList.add(
    'modal-scroll-lock'
  );
}

function unlockScroll(owner) {
  scrollLocks.delete(owner);

  if (scrollLocks.size === 0) {
    document.documentElement.classList.remove(
      'modal-scroll-lock'
    );
  }
}
```

```css
html.modal-scroll-lock {
  overflow: hidden;
}
```

这里假设所有弹窗共同使用这一滚动锁管理器。

实际项目还需要在 iOS Safari、软键盘弹出、页面回弹以及滚动位置恢复等场景下测试。复杂情况下可以使用经过验证的滚动锁定库。

## 11. 弹窗动画与生命周期管理

这是第 9 课 CSS 动画知识在实际组件中的应用。

原生 dialog 的动画有一个特殊之处：关闭时，浏览器通常会将它从显示状态切换为隐藏状态，并移出 Top Layer。

因此，普通的 transition 不一定能够直接实现退出动画。

### 11.1 最简单可靠的方式：只实现进入动画

```css
@media (prefers-reduced-motion: no-preference) {
  .drawer[open] {
    animation: drawer-enter 250ms ease-out;
  }

  @keyframes drawer-enter {
    from {
      transform: translateX(100%);
    }

    to {
      transform: translateX(0);
    }
  }
}
```

这样：

- 调用 showModal() 后立即建立原生模态行为。
- CSS 负责 Drawer 的滑入效果。
- 调用 close() 后立即关闭。
- 减少运动模式下直接显示 Drawer。

对于十分关注稳定性和兼容性的项目，这种方式已经足够实用。

### 11.2 现代 CSS 实现进入和退出动画

现代 CSS 提供了几个相关能力。

| CSS 特性 | 职责 |
|---|---|
| `@starting-style` | 定义元素首次显示时的过渡起点 |
| `allow-discrete` | 允许适用的离散属性参与过渡 |
| `display` | 在退出动画期间延迟隐藏 |
| `overlay` | 在退出动画期间延迟移出 Top Layer |

这些特性可以配合实现原生 dialog 的进入和退出动画。<Cite refs={["turn526085search0","turn526085search2","turn526085search3"]}/>

```css
@media (prefers-reduced-motion: no-preference) {
  @supports (transition-behavior: allow-discrete)
    and (overlay: auto) {

    dialog.drawer {
      transform: translateX(100%);
      opacity: 0;

      transition:
        transform 250ms ease,
        opacity 250ms ease,
        display 250ms allow-discrete,
        overlay 250ms allow-discrete;
    }

    dialog.drawer[open] {
      transform: translateX(0);
      opacity: 1;
    }

    @starting-style {
      dialog.drawer[open] {
        transform: translateX(100%);
        opacity: 0;
      }
    }
  }
}
```

### 12.3 JavaScript 实现

使用第 11 课介绍的 `focus-trap` 库，避免自行重新实现复杂的浏览器焦点计算。

```bash
npm install focus-trap
```

```javascript
import { createFocusTrap } from 'focus-trap';

const storefront =
  document.querySelector('#storefront');

const modal =
  document.querySelector('#custom-modal');

const panel =
  document.querySelector('#modal-panel');

const trigger =
  document.querySelector('#open-modal');

const closeButton =
  document.querySelector('#close-modal');

let trap;
let previousFocus;
let previousInert;

function openModal(opener) {
  if (!modal.hidden) return;

  previousFocus = opener;
  previousInert = storefront.inert;

  modal.hidden = false;
  storefront.inert = true;

  lockScroll(modal);

  trap = createFocusTrap(panel, {
    initialFocus: '#modal-title',
    fallbackFocus: panel,
    escapeDeactivates: false,
    returnFocusOnDeactivate: false,
    clickOutsideDeactivates: false,
    allowOutsideClick: event =>
      event.target ===
        modal.querySelector('.modal-overlay')
  });

  trap.activate();
}

function closeModal() {
  if (modal.hidden) return;

  trap?.deactivate();
  trap = null;

  modal.hidden = true;
  storefront.inert = previousInert;

  unlockScroll(modal);

  if (previousFocus?.isConnected) {
    previousFocus.focus();
  }

  previousFocus = null;
}

trigger.addEventListener('click', event => {
  openModal(event.currentTarget);
});

closeButton.addEventListener('click', closeModal);

modal.querySelector('.modal-overlay')
  .addEventListener('click', closeModal);

modal.addEventListener('keydown', event => {
  if (
    event.key === 'Escape' &&
    !event.defaultPrevented
  ) {
    event.preventDefault();
    closeModal();
  }
});
```

这里复用了前面的滚动锁定函数。代码中的 npm import 需要通过构建工具打包，不能直接将裸模块名称放进未配置模块解析的 Shopify JS 文件中。

该实现针对单层、自定义模态弹窗。生产环境还需要处理备用焦点、嵌套弹窗栈、组件销毁和异常清理等情况。

### 12.4 与原生 dialog 的对比

| 能力 | 原生 dialog | 自定义 Modal |
|---|---|---|
| 基础 Role | 浏览器提供 | 手动添加 |
| 模态背景隔离 | 浏览器提供 | 手动实现 |
| Top Layer | 支持 | 通常不支持 |
| 焦点限制 | 浏览器提供 | 手动实现或使用库 |
| Esc 关闭 | 默认支持 | 手动实现 |
| 焦点恢复 | 浏览器提供基础能力 | 手动实现 |
| 遮罩 | `::backdrop` | 独立 DOM |
| 多层弹窗 | 原生模态叠加能力 | 自己维护 |
| 开发维护成本 | 相对较低 | 相对较高 |

因此，如果没有特殊的浏览器兼容性或现有架构约束，新项目优先使用原生 dialog。

## 13. Popover API 与 Dialog 的区别

Popover API 是另一项值得前端开发者掌握的原生 HTML 能力。

例如网站中的配送说明浮层：

```html

  type="button"
  popovertarget="shipping-info"
>
  Shipping information
</button>

<div id="shipping-info" popover="auto">
  <p>Free shipping on orders over $50.</p>

  <button
    type="button"
    popovertarget="shipping-info"
    popovertargetaction="hide"
  >
    Close
  </button>

```

上面的代码甚至不需要 JavaScript，就能够实现基础的显示与隐藏。

### 13.1 Popover API 提供的能力

```javascript
element.showPopover();

element.hidePopover();

element.togglePopover();
```

Popover 可以进入 Top Layer，`popover="auto"` 还支持原生 Light Dismiss。

但 Popover API 不会根据内容自动赋予菜单、列表框或对话框等具体业务语义，也不会将背景变成模态隔离状态。<Cite refs={["turn171841search17","turn171841search23"]}/>

因此：

| 业务需求 | 推荐技术 |
|---|---|
| 必须完成或关闭当前弹窗才能继续 | dialog.showModal() |
| 可同时操作其他页面内容的浮层 | Popover API |
| 普通 Accordion 内容展开 | details 或 Disclosure |
| 商品搜索建议列表 | Combobox + Listbox |
| 常驻侧栏 | 普通 HTML 区域 |
| 删除确认 | Modal + alertdialog |

下一课讲解 Dropdown、Menu 和 Combobox 时，还会继续应用 Popover API。

当前 Dawn 公开源码中的 ModalDialog 会在连接到文档后，将自身移动到 body 下，并保存原 Shopify Section 的标识。

### 14.2 为什么 Dawn 要将 Modal 移动到 body？

主要是为了让弹窗脱离原 Section 的布局和层叠上下文影响。

这与 React Portal 的设计思想有些类似：

```text
原始 DOM：

body
 └─ Shopify Section
     └─ modal-dialog

移动之后：

body
 ├─ Shopify Section
 └─ modal-dialog
```

这样可以减少 `overflow`、祖先 transform 和 Stacking Context 对弹窗显示的影响。

不过，移动 DOM 也可能影响依赖祖先结构的 CSS 选择器、Section 生命周期和局部重新渲染。因此，Theme Editor 中的 Section 卸载和重新加载也需要测试。

如果改用原生 dialog，Top Layer 能够解决许多这类布局问题，而无需实际移动 DOM。

### 15.2 accessible-modal.js

```javascript
class AccessibleModal extends HTMLElement {
  connectedCallback() {
    if (this.controller) return;

    this.dialog = this.querySelector('dialog');

    if (!this.dialog) return;

    this.controller = new AbortController();

    const signal = this.controller.signal;

    this.dialog.addEventListener(
      'close',
      () => this.handleClose(),
      { signal }
    );

    this.addEventListener('click', event => {
      const button = event.target.closest(
        '[data-modal-close]'
      );

      if (!button) return;

      // 避免父层组件处理子层 Modal 的按钮
      if (button.closest('accessible-modal') !== this) {
        return;
      }

      this.requestClose();
    }, { signal });
  }

  open(trigger = document.activeElement) {
    if (!this.dialog || this.dialog.open) {
      return;
    }

    this.opener = trigger;
    this.openerId = trigger?.id;

    this.dialog.returnValue = '';

    this.dialog.showModal();
  }

  close(value = '') {
    if (this.dialog?.open) {
      this.dialog.close(value);
    }
  }

  requestClose(value = '') {
    if (!this.dialog?.open) return;

    if (
      typeof this.dialog.requestClose === 'function'
    ) {
      this.dialog.requestClose(value);
      return;
    }

    // 旧浏览器的关闭前校验兼容方案
    const event = new Event('cancel', {
      cancelable: true
    });

    if (this.dialog.dispatchEvent(event)) {
      this.dialog.close(value);
    }
  }

  handleClose() {
    // 避免旧 close 事件干扰已经重新打开的弹窗
    if (this.dialog.open) return;

    const active = document.activeElement;

    // 原生浏览器已恢复合理焦点时，不主动抢夺
    const needsRestoration =
      !active ||
      active === document.body ||
      this.dialog.contains(active);

    if (needsRestoration) {
      this.restoreFocus();
    }

    this.opener = null;
    this.openerId = null;

    this.dispatchEvent(
      new CustomEvent('modal:closed', {
        bubbles: true,
        detail: {
          returnValue: this.dialog.returnValue
        }
      })
    );
  }

  restoreFocus() {
    const fallbackId =
      this.getAttribute('data-fallback-focus');

    const candidates = [
      this.opener,

      this.openerId
        ? document.getElementById(this.openerId)
        : null,

      fallbackId
        ? document.getElementById(fallbackId)
        : null
    ];

    for (const element of candidates) {
      if (!element?.isConnected) continue;
      if (element.matches(':disabled')) continue;

      if (
        element.closest(
          '[inert], [aria-hidden="true"]'
        )
      ) {
        continue;
      }

      element.focus();

      if (document.activeElement === element) {
        return;
      }
    }
  }

  disconnectedCallback() {
    this.controller?.abort();
    this.controller = null;

    if (this.dialog?.open) {
      this.dialog.close();
    }

    this.opener = null;
    this.openerId = null;
  }
}

if (!customElements.get('accessible-modal')) {
  customElements.define(
    'accessible-modal',
    AccessibleModal
  );
}
```

这里主要实现了：

| 能力 | 实现方式 |
|---|---|
| 原生模态行为 | `showModal()` |
| 关闭前校验 | `requestClose()` |
| 旧浏览器兼容 | 特性检测与 cancel 事件 |
| 焦点恢复 | 原触发元素及备用 ID |
| 生命周期管理 | connected/disconnectedCallback |
| 事件清理 | AbortController |
| 业务事件 | `modal:closed` |

### 15.3 通用触发机制

为了支持动态渲染的 Shopify 商品卡片，可以采用事件委托。

```javascript
document.addEventListener('click', event => {
  const trigger = event.target.closest(
    '[data-modal-open]'
  );

  if (!trigger) return;

  const modal = document.getElementById(
    trigger.dataset.modalOpen
  );

  if (!(modal instanceof AccessibleModal)) {
    return;
  }

  event.preventDefault();

  modal.open(trigger);
});
```

这样即使 Shopify Section Rendering 替换了触发按钮，新按钮也能够继续工作。

本节课最重要的开发思想是：

**Modal 并不是一个设置了 position: fixed 和高 z-index 的 div，而是一套完整的交互生命周期。**

在现代前端开发中，应该尽可能让浏览器承担底层通用能力，让应用层负责业务逻辑，而不是自己重复实现浏览器已经提供的机制。
