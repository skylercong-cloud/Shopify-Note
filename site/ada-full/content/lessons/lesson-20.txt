## 2. Header 的整体语义结构

一个合理的 Shopify Header，可以采用以下结构：

```liquid
<header class="site-header">

  <a href="{{ routes.root_url }}">
    {{ shop.name | escape }}
  </a>

  <nav aria-label="Main navigation">
    <!-- Main navigation links -->
  </nav>

  <div class="header-actions">

    <button type="button" aria-label="Search">
      <!-- Search icon -->
    </button>

    <a
      href="{{ routes.account_url }}"
      aria-label="My account"
    >
      <!-- Account icon -->
    </a>

    <a
      href="{{ routes.cart_url }}"
      aria-label="Shopping cart"
    >
      <!-- Cart icon -->
    </a>

  </div>

</header>
```

对应的 Accessibility Tree 大致如下：

<box border radius="lg" padding={3} gap={2}>
  **banner**
  <box padding={{left:3}} gap={2}>
    <text size="sm">link "STYLE STORE"</text>
    <box border radius="md" padding={2} gap={2}>
      **navigation "Main navigation"**
      <box padding={{left:3}} gap={1}>
        <text size="sm">list</text>
        <box padding={{left:3}} gap={1}>
          <text size="sm">link "Home"</text>
          <text size="sm">button "Clothing", collapsed</text>
          <text size="sm">link "Accessories"</text>
          <text size="sm">link "Sale"</text>
        </box>
      </box>
    </box>
    <text size="sm">button "Search"</text>
    <text size="sm">link "My account"</text>
    <text size="sm">link "Shopping cart"</text>
  </box>
</box>

这里需要特别注意，Shopify 的 `header-group` 是 Section Group，并不等同于 HTML 中的 header 语义。

浏览器不会因为某个 Section 属于 Header Group，就自动赋予它 banner 角色。

同样，Header 内部的 Logo、导航和工具按钮，也没有必要分别包裹在多个 header 元素中。

## 3. Skip to Content：跳过重复导航

这是 Shopify 网站中非常重要，但视觉设计稿通常不会体现的功能。

假设一个 Header 包含 60 个导航链接，键盘用户每访问一个新页面，都可能需要经过大量重复控件。

Skip Link 可以帮助用户直接进入主要内容。

<box border radius="lg" padding={3} gap={2}>
  <box border={{size:2,color:"#3978BC"}} radius="sm" padding={3} align="center">
    **Skip to content**
  </box>
  <box background="surface-tertiary" radius="md" padding={3} align="center">
    <title size="lg">STYLE STORE</title>
    <row justify="center" gap={3}>
      <text size="xs">Home</text>
      <text size="xs">Clothing</text>
      <text size="xs">Accessories</text>
      <text size="xs">Sale</text>
    </row>
  </box>
  <box align="center"><icon name="arrow-down" color="#3978BC"/><caption>跳过重复导航</caption></box>
  <box border={{size:2,color:"#3978BC"}} radius="md" padding={3}>
    <caption>main#MainContent</caption>
    <title size="xl">New arrivals</title>
    <text size="sm">Discover our latest products.</text>
  </box>
</box>

### 3.1 Liquid 实现

在 `layout/theme.liquid` 中：

```liquid
<body>

  <a class="skip-link" href="#MainContent">
    {{ 'accessibility.skip_to_text' | t }}
  </a>

  {% sections 'header-group' %}

  <main id="MainContent" tabindex="-1">
    {{ content_for_layout }}
  </main>

  {% sections 'footer-group' %}

</body>
```

### 3.2 CSS 实现

```css
.skip-link {
  position: fixed;
  inset-block-start: 12px;
  inset-inline-start: 12px;

  z-index: 10000;
  padding: 12px 20px;

  background: #fff;
  color: #111;

  transform: translateY(-200%);
}

.skip-link:focus {
  transform: translateY(0);
  outline: 2px solid currentColor;
  outline-offset: 3px;
}
```

这里不能使用 `display: none` 隐藏 Skip Link，否则键盘用户无法聚焦它。

`tabindex="-1"` 则允许 main 作为焦点跳转目标，同时不会让它额外进入普通 Tab 顺序。

这项功能对应 WCAG 2.4.1 Bypass Blocks（Level A）。Skip Link 是满足该要求的一种常见方法，并非唯一方法。<Cite ref="turn135853search10"/>

### 4.1 Logo 的 alt 应该怎么设置？

假设 Logo 图片本身包含品牌名称。

```liquid
<a
  href="{{ routes.root_url }}"
  aria-label="{{ shop.name | escape }} — Home"
>
  {{
    settings.logo
    | image_url: width: 400
    | image_tag: alt: ''
  }}
</a>
```

这里已经通过 aria-label 为链接提供了名称，所以内部 Logo 图片可以作为装饰图片处理。

另一种方案是不设置 aria-label，直接使用 Logo 图片的 alt 为链接提供名称。

不建议重复声明相同信息，也不建议使用没有实际意义的名称，例如 `Logo image`。

### 4.2 Search 应该是 button 还是 a？

取决于实际业务行为。

| 点击后的行为 | 推荐元素 |
|---|---|
| 跳转 `/search` 页面 | a |
| 打开 Search Modal | button |
| 展开当前页面的搜索区域 | button |
| 提交搜索表单 | button type="submit" |

打开 Search Modal：

```html
<button
  type="button"
  aria-label="Search"
  aria-haspopup="dialog"
  aria-controls="SearchDialog"
>
  <svg aria-hidden="true" focusable="false">
    <!-- Search icon -->
  </svg>
</button>
```

不要因为视觉上是图标，就使用 div 加 click 事件来实现。

### 4.3 Cart Icon 的动态名称

```liquid
<button
  type="button"
  id="HeaderCartButton"
  aria-haspopup="dialog"
  aria-label="Shopping cart, {{ cart.item_count }} items"
>
  <svg aria-hidden="true"></svg>

  <span
    class="cart-count"
    aria-hidden="true"

```

## 5. Mega Menu 的 Liquid 完整结构

第 16 课已经详细学习了 Disclosure Navigation。本节重点研究如何与 Shopify 的菜单数据结合。

假设商家在后台配置了这样的导航菜单：

<box border radius="lg" padding={3} gap={2}>
  <row><icon name="list-tree"/> **Main menu**</row>
  <box padding={{left:4}} gap={2}>
    <row><icon name="link" size="sm"/> Home</row>
    <row><icon name="folder" size="sm"/> Clothing</row>
    <box padding={{left:4}} gap={2}>
      <row><icon name="folder" size="sm"/> Men</row>
      <box padding={{left:4}} gap={1}>
        <text size="sm">T-shirts</text>
        <text size="sm">Jackets</text>
      </box>
      <row><icon name="folder" size="sm"/> Women</row>
      <box padding={{left:4}} gap={1}>
        <text size="sm">Dresses</text>
        <text size="sm">Tops</text>
      </box>
    </box>
    <row><icon name="link" size="sm"/> Accessories</row>
    <row><icon name="link" size="sm"/> Sale</row>
  </box>
</box>

Shopify Liquid 中可以通过以下属性获取菜单信息：

| 属性 | 含义 |
|---|---|
| `section.settings.menu.links` | 一级导航集合 |
| `link.title` | 导航名称 |
| `link.url` | 导航地址 |
| `link.links` | 子导航集合 |
| `link.current` | 当前链接是否匹配当前页面 |
| `link.active` | 当前链接是否处于活动路径 |
| `link.child_active` | 是否存在活动的子链接 |

### 5.1 使用 details / summary 实现 Mega Menu

```liquid
<nav aria-label="Main navigation" data-mega-nav>
  <ul class="main-menu" role="list">

    {% for link in section.settings.menu.links %}
      <li>

        {% if link.links != blank %}

          <details class="mega-menu">

            <summary>
              {{ link.title | escape }}

              <span aria-hidden="true">⌄</span>
            </summary>

            <div class="mega-menu__panel">

              <a href="{{ link.url }}"
                {% if link.current %}
                  aria-current="page"
                {% endif %}
              >
                View all {{ link.title | escape }}
              </a>

              <ul role="list">
                {% for child in link.links %}
                  <li>
                    <a href="{{ child.url }}"
                      {% if child.current %}
                        aria-current="page"
                      {% endif %}
                    >
                      {{ child.title | escape }}
                    </a>

                    {% if child.links != blank %}
                      <ul role="list">
                        {% for grandchild in child.links %}
                          <li>
                            <a href="{{ grandchild.url }}"
                              {% if grandchild.current %}
                                aria-current="page"
                              {% endif %}
                            >
                              {{ grandchild.title | escape }}
                            </a>
                          </li>
                        {% endfor %}
                      </ul>
                    {% endif %}
                  </li>
                {% endfor %}
              </ul>

            </div>

          </details>

        {% else %}

          <a href="{{ link.url }}"
            {% if link.current %}
              aria-current="page"
            {% endif %}
          >
            {{ link.title | escape }}
          </a>

        {% endif %}

      </li>
    {% endfor %}

  </ul>
</nav>
```

这套结构具有几个重要特征：保留原生导航与列表语义，使用 details 实现基础键盘交互，支持三级菜单，并且为一级分类额外提供 View all 链接。

即使 JavaScript 加载失败，基本的展开和导航依然可以正常工作。

普通网站导航通常不需要采用 ARIA Menu Pattern，这也符合 W3C APG 的导航示例。<Cite ref="turn135853search4"/>

### 5.2 aria-current 和 active class 的区别

假设当前页面是：

```text
/collections/t-shirts
```

导航层级为：

<box border radius="md" padding={3} gap={2}>
  <row>
    **Clothing**
    <spacer/><caption>child_active</caption>
  </row>
  <box padding={{left:4}} gap={2}>
    <row>
      **Men**
      <spacer/><caption>child_active</caption>
    </row>
    <box padding={{left:4}} gap={2}>
      <row>
        <text weight="bold" underline={true}>T-shirts</text>
        <spacer/>
        <text color="success" size="xs">aria-current="page"</text>
      </row>
      <text size="sm">Jackets</text>
    </box>
  </box>
</box>

Clothing 和 Men 可以具有视觉高亮，表示它们属于当前导航路径。

但是，不应该因此全部添加 `aria-current="page"`。

推荐：

```liquid
{% if link.current %}
  aria-current="page"
{% endif %}
```

而 active 或 child_active 主要用于实现导航路径的视觉样式。

## 6. Mega Menu 的键盘交互与关闭策略

一个桌面端 Mega Menu，推荐具有以下行为：

| 用户操作 | 预期行为 |
|---|---|
| Tab | 在导航按钮和链接之间移动 |
| Enter / Space | 展开或折叠 summary |
| Esc | 关闭当前 Mega Menu |
| 焦点进入子菜单 | 保持菜单展开 |
| 焦点离开当前菜单 | 可以自动关闭 |
| 点击其他一级菜单 | 关闭原菜单，打开新菜单 |
| 点击页面其他区域 | 关闭菜单 |

### 6.1 JavaScript 增强

在前面 Liquid 结构的基础上：

```javascript
const nav = document.querySelector('[data-mega-nav]');

const menus = [...nav.querySelectorAll(
  'details.mega-menu'
)];

function closeMenu(menu, restoreFocus = false) {
  const summary = menu.querySelector('summary');

  if (
    restoreFocus ||
    (menu.contains(document.activeElement) &&
     document.activeElement !== summary)
  ) {
    summary.focus();
  }

  menu.open = false;
}

menus.forEach(menu => {
  menu.addEventListener('toggle', () => {
    if (!menu.open) return;

    menus.forEach(other => {
      if (other !== menu && other.open) {
        closeMenu(other);
      }
    });
  });

  menu.addEventListener('keydown', event => {
    if (
      event.key === 'Escape' &&
      !event.defaultPrevented &&
      menu.open
    ) {
      event.preventDefault();
      event.stopPropagation();

      closeMenu(menu, true);
    }
  });

  menu.addEventListener('focusout', event => {
    if (
      event.relatedTarget &&
      !menu.contains(event.relatedTarget)
    ) {
      menu.open = false;
    }
  });
});

document.addEventListener('click', event => {
  menus.forEach(menu => {
    if (menu.open && !menu.contains(event.target)) {
      closeMenu(menu);
    }
  });
});
```

这个例子采用单实例、点击展开、同一时间最多展开一个 Mega Menu 的设计。

### 6.2 为什么 Mega Menu 不应该使用 Focus Trap？

{@body const [megaFocus,setMegaFocus]=DIL.useState(1)}

  {/each}
  <grid columns={2} gap={2}>
    <grid-item><button block variant="outline" color="secondary" onClick={()=>{const n=Math.max(0,megaFocus-1);setMegaFocus(n);if(n===0)setMegaOpen(false)}}>Shift + Tab</button></grid-item>
    <grid-item><button block variant="outline" color="secondary" onClick={()=>{if(megaOpen&&megaFocus===4){setMegaOpen(false);setMegaFocus(2)}else{setMegaFocus(Math.min(megaItems.length-1,megaFocus+1))}}}>Tab</button></grid-item>
    <grid-item><button block disabled={megaFocus!==1} onClick={()=>setMegaOpen(v=>!v)}>Enter / Space</button></grid-item>
    <grid-item><button block variant="outline" color="secondary" disabled={!megaOpen} onClick={()=>{setMegaOpen(false);setMegaFocus(1)}}>Esc</button></grid-item>
  </grid>
  <caption>模拟焦点：{megaItems[megaFocus]}。普通导航展开后仍然允许用户继续访问 Sale、Search 和购物车。</caption>
</card>

Mega Menu 属于非模态交互，不能把用户限制在菜单内部。

只有移动端菜单采用真正的模态 Drawer 时，才需要模态焦点隔离。

### 6.3 Hover Mega Menu 的特殊问题

很多设计要求鼠标经过一级菜单时自动展开。

如果需要支持这种功能，不能只写：

```css
.menu-item:hover .mega-menu {
  display: block;
}
```

因为这种实现可能缺少键盘展开能力，也可能导致 ARIA 状态与视觉状态不一致。

应该让 Hover、Click、Keyboard 共同调用统一的状态管理逻辑，并满足 WCAG 1.4.13 的可关闭、可悬停、持续显示要求。

尤其需要注意：用户按 Esc 关闭菜单之后，即使鼠标仍然悬停在触发元素上，也不应该立即重新打开。

## 9. 一个重要的实战问题：嵌套组件的 Esc 冲突

假设 Search Modal 已打开，并且搜索建议也已经展开。

此时按下 Esc，应该关闭谁？

{@body const [searchModalOpen,setSearchModalOpen]=DIL.useState(true)}
{@body const [suggestionsOpen,setSuggestionsOpen]=DIL.useState(true)}
<card gap={3}>
  <row align="center">
    **Search Modal**
    <spacer/>
    <caption>{searchModalOpen?"Open":"Closed"}</caption>
  </row>
  {#if searchModalOpen}
    <box border radius="md" padding={3} gap={2}>
      <row border radius="sm" padding={2}>
        <icon name="search" size="sm"/>
        cotton
      </row>
      {#if suggestionsOpen}
        <box background="surface-tertiary" radius="sm" padding={3} gap={2}>
          <text size="sm">Cotton T-shirt</text>
          <text size="sm">Cotton jacket</text>
          <text size="sm">Cotton sweatshirt</text>
        </box>
      {/if}
    </box>
  {/if}
  <button block variant="outline" color="secondary" disabled={!searchModalOpen} onClick={()=>{if(suggestionsOpen)setSuggestionsOpen(false);else setSearchModalOpen(false)}}>按下 Esc</button>
  <divider/>
  <row><caption>Search Modal</caption><spacer/>{String(searchModalOpen)}</row>
  <row><caption>Combobox expanded</caption><spacer/>{String(suggestionsOpen)}</row>
  <row><caption>模拟焦点</caption><spacer/><text size="sm">{searchModalOpen?"搜索输入框":"Header Search 按钮"}</text></row>
  <button block variant="ghost" color="secondary" onClick={()=>{setSearchModalOpen(true);setSuggestionsOpen(true)}}>重置实验</button>
</card>

第一次 Esc 关闭搜索建议，第二次 Esc 关闭 Search Modal。

错误的实现是两个组件都监听 document 上的 Esc，导致第一次按下时全部关闭。

可以在 Combobox 内部处理：

```javascript
input.addEventListener('keydown', event => {
  if (
    event.key === 'Escape' &&
    !listbox.hidden
  ) {
    event.preventDefault();
    event.stopPropagation();

    closeResults();
  }
});
```

自定义 Modal 的键盘处理器需要尊重事件状态：

```javascript
function onModalKeydown(event) {
  if (event.defaultPrevented) return;

  if (event.key === 'Escape') {
    closeModal();
  }
}
```

对于原生 dialog，通常应保留浏览器的关闭机制，通过内部按键处理及必要的 cancel 事件协调关闭行为，而不是另外实现一套全局 Esc 监听。

还需要在真实浏览器中测试原生 Search 输入框的 Esc 清空行为、输入法组合输入以及多个浮层同时存在的情况。

WCAG 2.2 的 2.4.11 Focus Not Obscured（AA）要求，键盘焦点所在组件不能被作者创建的内容完全遮挡。

固定 Header 和固定 Footer 都是典型的审计对象。<Cite refs={["turn135853search5","turn135853search8"]}/>

### 10.1 基础解决方案

```css
html {
  scroll-padding-block-start:
    calc(var(--sticky-header-height, 0px) + 16px);
}
```

### 10.2 动态计算 Header 高度

实际 Shopify Header 的高度往往不是固定值，因为存在商家配置、Announcement Bar、多语言及响应式布局。

```javascript
const header = document.querySelector(
  '[data-sticky-header]'
);

if (header) {
  const updateHeight = () => {
    const height = header.getBoundingClientRect().height;

    document.documentElement.style.setProperty(
      '--sticky-header-height',
      `${height}px`
    );
  };

  const observer = new ResizeObserver(updateHeight);

  observer.observe(header);

  updateHeight();
}
```

这里假设 `data-sticky-header` 对应的是整个实际遮挡内容的固定区域。

如果 Announcement Bar 和 Header 分别固定，则需要计算实际遮挡范围，而不仅是其中一个元素的高度。

### 10.3 自动隐藏 Header 的问题

很多 Shopify Theme 支持：

向下滚动时隐藏 Header，向上滚动时显示 Header。

但如果用户正在通过键盘访问 Header 内的控件，不能让 Header 突然滑出屏幕。

可以加入：

```css
.site-header:focus-within {
  transform: translateY(0);
}
```

同时在 JavaScript 的自动隐藏逻辑中考虑：

```javascript
if (
  header.contains(document.activeElement)
) {
  return;
}
```

`scroll-padding` 是解决遮挡问题的重要手段，但并不能保证所有焦点和滚动场景都正确，最终仍需要通过实际 Tab 导航验证。

## 13. Section Rendering 对 Header 的影响

这是 Shopify 项目中一个非常实际的问题。

假设用户加购商品后，我们通过 Section Rendering 获取新的 `cart-icon-bubble` HTML。

如果直接替换整个 Header：

```javascript
header.innerHTML = responseHTML;
```

可能造成以下问题：

| 问题 | 原因 |
|---|---|
| 焦点回到 body | 当前聚焦元素被删除 |
| Mega Menu 突然关闭 | 原有组件状态丢失 |
| Search Modal 状态丢失 | dialog 节点被替换 |
| 搜索请求仍然执行 | 旧组件未清理资源 |
| Live Region 无法正常通知 | 原消息节点被销毁 |
| 按钮事件失效 | 新节点未重新绑定事件 |

更推荐尽可能缩小更新范围。

例如保留 Cart 按钮本身：

```javascript
function updateCartIcon(count) {
  const button = document.querySelector(
    '#HeaderCartButton'
  );

  const badge = button.querySelector('.cart-count');

  badge.textContent = String(count);

  button.setAttribute(
    'aria-label',
    `Shopping cart, ${count} ${count === 1 ? 'item' : 'items'}`
  );
}
```

这样既能够更新视觉 UI，也能够保留 DOM 节点、原有事件以及当前焦点。

生产项目还需要使用翻译后的名称模板。

**Section Rendering 的无障碍优化，很多时候不是增加 ARIA，而是减少不必要的 DOM 销毁。**

```javascript
test('mega menu keyboard navigation', async ({ page }) => {
  await page.goto('/');

  const summary = page.locator(
    '.mega-menu > summary'
  ).filter({
    hasText: 'Clothing'
  });

  await summary.focus();
  await summary.press('Enter');

  const details = summary.locator('..');

  await expect(details).toHaveJSProperty(
    'open',
    true
  );

  await page.keyboard.press('Tab');

  const childLink = details.getByRole('link', {
    name: 'View all Clothing'
  });

  await expect(childLink).toBeFocused();

  await page.keyboard.press('Escape');

  await expect(details).toHaveJSProperty(
    'open',
    false
  );

  await expect(summary).toBeFocused();
});
```

### 14.3 测试 Search Modal

```javascript
test('search modal restores focus', async ({ page }) => {
  await page.goto('/');

  const trigger = page.getByRole('button', {
    name: 'Search',
    exact: true
  });

  await trigger.focus();
  await trigger.press('Enter');

  const dialog = page.getByRole('dialog', {
    name: 'Search products'
  });

  await expect(dialog).toBeVisible();

  const input = dialog.getByRole('combobox');

  await expect(input).toBeFocused();

  await page.keyboard.press('Escape');

  await expect(dialog).toBeHidden();

  await expect(trigger).toBeFocused();
});
```
