### 3.1 disabled 与 aria-disabled 应该如何选择？

| 对比项 | disabled | aria-disabled="true" |
|---|---|---|
| 浏览器阻止点击激活 | 是 | 否 |
| 阻止原生按钮提交 | 是 | 否 |
| 保留键盘焦点能力 | 通常否 | 是 |
| 表达不可操作状态 | 是 | 是 |
| 需要 JS 阻止操作 | 原生交互通常不需要 | 需要 |

在商品售罄时，可以使用原生 `disabled`。

但在用户已经点击 Add to cart、正在等待服务器响应时，可以使用 `aria-disabled="true"` 保留焦点，同时在提交处理器中阻止重复请求。

```javascript
if (isSubmitting) return;

isSubmitting = true;

button.setAttribute('aria-disabled', 'true');
```

注意，仅仅添加 aria-disabled 并不会阻止表单提交。

因此，真正的业务保护必须写在 submit 事件中，而不是只写在 button 的 click 事件中。

用户还可能通过 Enter 键提交表单。

### 3.2 Loading Spinner 是否需要被屏幕阅读器读取？

```html
<button type="submit">
  <span>Add to cart</span>

  <svg class="spinner" aria-hidden="true">
    <!-- Loading animation -->
  </svg>
</button>

<p role="status" class="visually-hidden"></p>
```

Spinner 只是视觉上的等待指示，不需要让屏幕阅读器读取 SVG 的路径或图形内容。

真正需要传递的是业务状态：

```javascript
status.textContent = 'Adding item to your cart.';
```

请求成功后，可以通知：

```javascript
status.textContent = 'Cotton T-shirt added to your cart.';
```

如果成功后直接打开 Cart Drawer，则可以通过弹窗的名称、初始焦点和内部通知传递结果，避免多处重复播报。

## 4. AJAX Cart API 与 Section Rendering

这是 Shopify 购物车前端开发的核心技术。

### 4.1 Cart API 的主要接口

| API | 职责 |
|---|---|
| `GET /cart.js` | 获取当前购物车数据 |
| `POST /cart/add.js` | 添加商品 |
| `POST /cart/change.js` | 修改单条已有购物车商品 |
| `POST /cart/update.js` | 更新购物车中的多个数量或其他属性 |
| `POST /cart/clear.js` | 清空购物车 |

这些都是 Shopify Storefront Ajax Cart API，不需要在 Theme 中暴露 Admin API Access Token。

请求地址应该使用当前语言区域对应的路径：

```javascript
const root = window.Shopify.routes.root;

fetch(`${root}cart.js`);
```

### 4.2 Bundled Section Rendering

传统加购需要分别执行：

<box border radius="md" padding={3} gap={1}>
  **传统方案**
  {#each ["POST cart/add.js","GET cart.js","请求 Cart Drawer HTML","请求 Header 购物车数量 HTML","更新 UI"] as t,i}
    <box background="surface-tertiary" radius="sm" padding={2}><text size="sm">{t}</text></box>
    {#if i<4}<box align="center"><icon name="arrow-down" size="xs" color="secondary"/></box>{/if}
  {/each}
  <divider/>
  **Bundled Section Rendering**
  <box border radius="sm" padding={3} gap={1}>
    <text size="sm">POST cart/add.js</text>
    <caption>同时传入 sections 与 sections_url</caption>
  </box>
  <box align="center"><icon name="arrow-down" color="secondary"/></box>
  <grid columns={2} gap={2}>
    <grid-item><box border radius="sm" padding={2}><text size="sm">加购结果 JSON</text></box></grid-item>
    <grid-item><box border radius="sm" padding={2}><text size="sm">Section HTML</text></box></grid-item>
  </grid>
</box>

例如：

```javascript
const response = await fetch(
  `${Shopify.routes.root}cart/add.js`,
  {
    method: 'POST',

    headers: {
      'Content-Type': 'application/json'
    },

    body: JSON.stringify({
      items: [
        {
          id: variantId,
          quantity: 1
        }
      ],

      sections: [
        'cart-drawer',
        'cart-icon-bubble'
      ],

      sections_url: window.location.pathname
    })
  }
);

const data = await response.json();
```

返回的数据结构可以简化理解为：

```javascript
{
  items: [
    {
      id: 123456789,
      quantity: 1
      // ...
    }
  ],

  sections: {
    "cart-drawer": "<div>...</div>",
    "cart-icon-bubble": "<div>...</div>"
  }
}
```

Shopify 支持在 Cart API 请求中同时获取最多五个 Section 的渲染结果。如果某个 Section 渲染失败，对应值可能为 null，而购物车操作本身仍然可能已经成功。<Cite refs={["turn769519search2","turn769519search14"]}/>

这意味着需要将两个结果分开处理：

- 商品是否成功加入购物车。
- 加购之后，购物车 UI 是否成功更新。

不能因为 Cart Drawer 渲染失败，就直接重新执行一次加购。

## 5. 实战：无障碍 AJAX 加购

### 5.1 HTML 与 Liquid

```liquid
{% form 'product', product, id: 'AccessibleProductForm' %}

  <input
    type="hidden"
    name="id"
    value="{{ variant.id }}"
  >

  <label for="ProductQuantity">Quantity</label>

  <input
    id="ProductQuantity"
    name="quantity"
    type="number"
    min="1"
    value="1"
    required
  >

  <button
    type="submit"
    data-add-button
    {% unless variant.available %}disabled{% endunless %}
  >
    Add to cart
  </button>

  <p data-cart-status role="status"></p>

  <p data-cart-error role="alert"></p>

{% endform %}
```

这里的两个 Live Region 提前存在于 DOM 中，并分别承担普通状态通知和错误通知。

### 5.2 JavaScript

以下示例采用加购成功后保留用户焦点、不自动打开 Drawer 的策略。

```javascript
const form = document.querySelector(
  '#AccessibleProductForm'
);

const button = form.querySelector('[data-add-button]');
const status = form.querySelector('[data-cart-status]');
const error = form.querySelector('[data-cart-error]');

let submitting = false;
let needsRefresh = false;

form.addEventListener('submit', async event => {
  event.preventDefault();

  if (submitting || needsRefresh || button.disabled) {
    return;
  }

  const body = new FormData(form);

  if (!body.get('id')) {
    error.textContent = 'Please select an available product.';
    return;
  }

  submitting = true;

  button.setAttribute('aria-disabled', 'true');
  button.classList.add('is-loading');

  error.textContent = '';
  status.textContent = 'Adding item to your cart.';

  body.set(
    'sections',
    'cart-drawer,cart-icon-bubble'
  );

  body.set('sections_url', location.pathname);

  try {
    const response = await fetch(
      `${Shopify.routes.root}cart/add.js`,
      {
        method: 'POST',
        body
      }
    );

    const data = await response.json();

    if (!response.ok || data.status) {
      throw new Error(
        data.description ||
        data.message ||
        'Unable to add item.'
      );
    }

    status.textContent = 'Item added to your cart.';

    // 单独处理 UI 渲染失败
    try {
      renderCartSections(data.sections);
    } catch {
      needsRefresh = true;

      error.textContent =
        'Item added, but the cart display could not be updated. Please view your cart.';
    }

  } catch (err) {
    // 加购请求异常时不能假定购物车未变化
    needsRefresh = true;

    status.textContent = '';

    error.textContent =
      `${err.message} Please check your cart before trying again.`;

  } finally {
    submitting = false;

    button.classList.remove('is-loading');

    if (!needsRefresh) {
      button.removeAttribute('aria-disabled');
    }
  }
});
```

其中 `renderCartSections()` 需要根据你的 Theme 中实际存在的 Section 和 DOM 结构实现。

生产环境中，应进一步提供重新读取购物车、刷新 Section 和恢复提交能力的入口。上面的教学代码采用了保守策略：出现不确定结果时暂时锁定加购，直到用户检查购物车。

### 5.4 为什么不能像商品筛选一样直接取消旧请求？

Collection 筛选通常是 GET 请求，旧请求取消后，可以直接使用最新请求结果。

但是加购属于服务器状态修改操作。

即使客户端调用：

```javascript
controller.abort();
```

也不能保证服务器没有完成加购。

如果网络中断，实际情况可能是：

```text
服务器已添加商品
        ↓
响应未成功到达浏览器
        ↓
前端认为请求失败
        ↓
再次执行加购
        ↓
商品数量重复增加
```

**读取操作可以采用最新请求优先，购物车写入操作则需要考虑服务器是否已经执行。**

这是 Collection Controller 与 Cart Controller 非常重要的架构区别。

### 6.1 HTML 结构

```html
<dialog

  aria-labelledby="CartDrawerTitle"
>

    <h2
      id="CartDrawerTitle"
      tabindex="-1"
      autofocus

    </h2>

      type="button"

    >
      ×
    </button>

    <!-- Cart item list -->
  </div>

    <!-- Total, discounts, shipping information -->
  </div>
```

特别注意三个区域的位置：

| 区域 | 更新策略 |

| Dialog 外壳 | 尽量保持稳定 |
| CartItems、CartTotals | 可以通过 Section Rendering 更新 |
| CartStatus、CartError | 尽量保留原 DOM 节点 |

如果每次修改商品数量都替换整个 dialog，会导致模态状态、初始焦点、关闭事件和 Live Region 全部受到影响。

## 7. 购物车数据模型：Variant ID、Line Item Key、Line Index

这一节非常重要。理解错误不仅会造成无障碍问题，还可能修改错误的购物车商品。

假设用户购买了同一个 Variant，但是分别填写了不同的定制文字。

| 商品 | Variant ID | Line Item Key | Line Index |
|---|---|---|---:|
| T-shirt，定制 Alice | 10001 | 10001:abc | 1 |
| T-shirt，定制 Bob | 10001 | 10001:def | 2 |
| Linen shirt | 10002 | 10002:xyz | 3 |

这里的两件 T-shirt 拥有相同的 Variant ID，却属于不同的购物车行。

### 7.1 三种标识的区别

| 标识 | 含义 | 局限 |
|---|---|---|
| Variant ID | 商品变体 ID | 购物车中可能重复 |
| Line Item Key | 当前购物车行的标识 | 某些属性或折扣变化后可能改变 |
| Line Index | 当前购物车行的位置，从 1 开始 | 删除或重新排序后可能变化 |

Shopify 官方明确说明，Line Item Key 并非永久不变的标识。修改指定购物车行时，应该结合当前购物车状态选择合适的标识。<Cite ref="turn769519search2"/>

因此：

- 不要仅凭 Variant ID 恢复某一行的焦点。
- 不要长期缓存 Line Index。
- 不要将 Line Item Key 当成永久业务 ID。

### 7.2 删除第一件商品后会发生什么？

<box border radius="lg" padding={3} gap={2}>
  <caption>删除之前</caption>
  {#each ["Cotton T-shirt · Alice","Cotton T-shirt · Bob","Linen shirt"] as p,i}
    <row border radius="sm" padding={2}><caption>Line {i+1}</caption><text size="sm">{p}</text></row>
  {/each}
  <box align="center"><icon name="arrow-down"/><caption>删除 Line 1</caption></box>
  {#each ["Cotton T-shirt · Bob","Linen shirt"] as p,i}
    <row border radius="sm" padding={2}><caption>Line {i+1}</caption><text size="sm">{p}</text></row>
  {/each}
  <caption>原来的 Line 2 变成 Line 1。之前记录的位置已经发生变化。</caption>
</box>

这也是购物车异步请求需要谨慎处理并发的原因。

## 9. 购物车数量更新与并发请求

修改购物车中已有商品数量，可以使用 `cart/change.js`。

```javascript
async function changeCartLine(key, quantity) {
  const response = await fetch(
    `${Shopify.routes.root}cart/change.js`,
    {
      method: 'POST',

      headers: {
        'Content-Type': 'application/json'
      },

      body: JSON.stringify({
        id: key,
        quantity,
        sections: [
          'cart-drawer',
          'cart-icon-bubble'
        ],
        sections_url: location.pathname
      })
    }
  );

  const cart = await response.json();

  if (!response.ok || cart.errors || cart.status) {
    throw new Error(
      cart.description || 'Unable to update cart.'
    );
  }

  return cart;
}
```

当 quantity 为 0 时，可以移除对应购物车行。

### 9.1 为什么不推荐多个写入请求随意并发？

例如当前数量为 1，用户连续点击三次加号。

<box border radius="lg" padding={3} gap={2}>
  <svg viewBox="0 0 340 152" width="100%">
    {#each [{t:"Request A",v:"quantity = 2",x:100,y:10,w:235,c:"#999999"},{t:"Request B",v:"quantity = 3",x:122,y:57,w:163,c:"#999999"},{t:"Request C",v:"quantity = 4",x:144,y:104,w:95,c:"#39866B"}] as p}
      <text x="2" y={p.y+15} fontSize="10" fill="currentColor">{p.t}</text>
      <text x="2" y={p.y+28} fontSize="9" fill="currentColor">{p.v}</text>
      <rect x={p.x} y={p.y} width={p.w} height="28" rx="4" stroke={p.c} fill={p.c} fillOpacity=".17"/>
    {/each}
  </svg>
  <caption>最新请求可能最先返回。更重要的是，客户端响应顺序并不能保证服务器状态修改顺序。</caption>
</box>

如果只使用 Request Version 忽略旧响应，可以避免部分 UI 覆盖问题，却不一定能保证服务器最终保存的是最新数量。

推荐采用以下策略：

| 策略 | 作用 |
|---|---|
| Debounce | 合并短时间连续修改 |
| Serialize | 按顺序执行购物车写入 |
| Coalesce | 合并尚未发送的重复数量修改 |
| Reconcile | 请求结束后与服务器真实购物车同步 |
| Checkout Guard | 等待购物车更新完成后再结账 |

### 9.2 简单的串行任务队列

```javascript
class CartMutationQueue {
  constructor() {
    this.tail = Promise.resolve();
    this.pending = 0;
  }

  enqueue(task) {
    this.pending++;

    const run = this.tail.then(task);

    const settled = run.finally(() => {
      this.pending--;
    });

    this.tail = settled.catch(() => {});

    return settled;
  }

  async idle() {
    while (this.pending > 0) {
      await this.tail;
    }
  }
}

const cartQueue = new CartMutationQueue();
```

使用方式：

```javascript
await cartQueue.enqueue(async () => {
  // 在真正执行任务时，获取最新的购物车行标识
  const line = resolveCurrentCartLine();

  const cart = await changeCartLine(
    line.key,
    desiredQuantity
  );

  applyCartState(cart);
});
```

这里的 `resolveCurrentCartLine()` 和 `applyCartState()` 是业务层需要实现的方法。

这个队列负责串行执行任务，但没有自行实现失败恢复、标识映射、合并任务或跨浏览器标签页同步。对于结果未知的网络错误，应在执行后续相关写入前重新核对购物车，而不是假设失败操作没有产生任何影响。

### 10.1 推荐焦点策略

| 删除场景 | 推荐焦点目标 |
|---|---|
| 删除中间商品 | 下一商品的同类操作控件 |

| 删除唯一商品 | Continue shopping 或空购物车标题 |
| 请求失败，商品未删除 | 保留原控件焦点，通知错误 |
| 请求期间用户已转移焦点 | 尽量尊重新的焦点位置 |

### 10.2 焦点恢复算法

在真正更新 DOM 之前记录当前操作位置：

```javascript
function captureCartFocus(container) {
  const active = document.activeElement;

  if (!container.contains(active)) {
    return null;
  }

  const row = active.closest('[data-cart-line]');

  if (!row) return null;

  const rows = [
    ...container.querySelectorAll('[data-cart-line]')
  ];

  return {
    key: row.dataset.lineKey,
    index: rows.indexOf(row),
    action: active.dataset.action
  };
}
```

更新购物车 HTML 后：

```javascript
function restoreCartFocus(container, snapshot) {
  if (!snapshot) return;

  const rows = [
    ...container.querySelectorAll('[data-cart-line]')
  ];

  const sameLine = rows.find(row =>
    row.dataset.lineKey === snapshot.key
  );

  const targetRow =
    sameLine ||
    rows[snapshot.index] ||
    rows[snapshot.index - 1];

  const control = targetRow
    ? [...targetRow.querySelectorAll('[data-action]')]
        .find(el => el.dataset.action === snapshot.action)
    : null;

  const candidates = [
    control,
    targetRow?.querySelector('a[href]'),
    container.querySelector('[data-empty-action]'),
    container.querySelector('[data-close]')
  ];

  for (const element of candidates) {
    if (!element?.isConnected) continue;
    if (element.matches(':disabled')) continue;
    if (element.closest('[hidden], [inert]')) continue;

    element.focus();

    if (document.activeElement === element) {
      break;
    }
  }
}
```

使用顺序：

```javascript
const snapshot = captureCartFocus(drawer);

renderUpdatedCartItems();

if (drawer.open) {
  restoreCartFocus(drawer, snapshot);
}
```

这里假设购物车行没有发生无法识别的合并或重排。若 Line Item Key 变化，还应结合商品属性和本次修改结果匹配对应商品。

同时，`drawer.open` 在这里指的是原生 dialog 的状态；如果使用 Dawn 自定义 Cart Drawer，则需要根据其实际打开状态判断。

### 10.3 为什么更新购物车后不能直接聚焦标题？

因为用户可能正在连续修改某一件商品的数量。

如果每次点击加号都将焦点移动到 Your cart 标题，那么键盘用户每次都必须重新找到原来的加号。

**打开购物车时可以移动焦点，购物车内部更新时则通常应该保留焦点。**

## 11. 购物车价格、折扣与总价

Shopify Cart 中有几个非常容易混淆的价格属性。

| Liquid 属性 | 含义 |
|---|---|
| `item.original_price` | 单件商品折扣前价格 |
| `item.final_price` | 单件商品应用行级折扣后的价格 |
| `item.original_line_price` | 当前商品行折扣前总价 |
| `item.final_line_price` | 当前商品行应用行级折扣后的总价 |
| `cart.original_total_price` | 购物车折扣前商品总价 |
| `cart.items_subtotal_price` | 商品行小计之和，不包含购物车级折扣 |
| `cart.total_price` | 应用折扣后的购物车商品总价 |
| `cart.total_discount` | 购物车总折扣金额 |

注意，Cart Total 不一定等于用户最终需要支付的金额，还可能涉及运费、税费等。

### 11.2 动态总价如何通知？

用户将商品数量从 1 修改为 2 后，可以通过统一 Live Region 通知：

```text

Cart total: $59.98.
```

不推荐同时让以下区域全部独立播报：

- 商品数量。
- 单件价格。
- 商品行总价。
- 购物车总价。
- Header 购物车数量。

否则一次简单的数量修改可能产生多次重复通知。

更合理的做法是由 Cart Controller 汇总必要信息，生成一条清晰的状态消息。

## 13. AJAX Cart API 错误处理

购物车中的错误通常比普通表单错误更复杂。

| 错误类型 | 推荐处理 |
|---|---|
| 商品库存不足 | 显示可购买数量或服务端限制 |
| Variant 已售罄 | 更新商品可购买状态 |
| 数量低于最小值 | 提示最低购买数量 |
| 不符合数量步长 | 提示允许的购买增量 |
| 网络请求失败 | 提示错误并核对实际购物车 |
| Section 渲染失败 | 保留已确认的购物车结果，重新获取 UI |
| 商品已经被删除 | 刷新购物车行及对应焦点 |

### 13.1 数量错误与输入框关联

```html

  type="number"
  value="10"
  aria-invalid="true"
  aria-describedby="QuantityError"
>

<p id="QuantityError">
  Only 3 items are available.
</p>

<p id="CartAlert" role="alert"></p>
```

JavaScript：

```javascript
function showQuantityError(input, message) {
  input.setAttribute('aria-invalid', 'true');

  document.querySelector(
    '#QuantityError'
  ).textContent = message;

  document.querySelector(
    '#CartAlert'
  ).textContent = message;
}
```

`aria-describedby` 负责让输入框与错误说明建立关系，`role="alert"` 则用于通知刚刚发生的重要错误。

真实项目中应根据播报效果避免重复通知，并在错误解决后清除 `aria-invalid` 和旧错误消息。

### 13.2 服务器修改了用户请求的数量怎么办？

例如用户希望购买 10 件，但 Shopify 只接受了 3 件。

- 配送方式变化后的选项名称是否易于理解。
- 不同地址及购物车条件下是否存在有效配送方式。
- 配送限制是否具有明确的用户反馈。
- 用户是否能够继续完成整个购买流程。

Shopify 托管结账不意味着商家安装的扩展、自定义业务规则和完整购买流程自动符合所有无障碍要求。

### 16.2 等待购物车更新

可以在表单的 submit 处理器中协调未完成的购物车操作。

下面是设计伪代码：

```javascript
async function handleCheckout(event) {
  if (checkoutResuming) return;

  flushDebouncedQuantityChanges();

  if (!cartHasPendingChanges()) return;

  event.preventDefault();

  if (checkoutWaiting) return;

  checkoutWaiting = true;

  announce('Updating your cart before checkout.');

  try {
    await waitForAllCartChanges();

    if (cartHasErrors()) {
      throw new Error('Cart update failed');
    }

    checkoutResuming = true;

    // 如果原按钮已被替换，需要获取最新节点
    const button = getCurrentCheckoutButton();

    button.form.requestSubmit(button);

  } catch {
    announceError(
      'Please resolve the cart errors before checking out.'
    );

  } finally {
    checkoutWaiting = false;
    checkoutResuming = false;
  }
}
```

这里还有几个工程细节：

- 需要先执行尚未触发的防抖任务。
- 需要检查所有保存是否真正成功，而不仅仅是 Promise 已完成。
- 重新提交时应避免无限递归。
- 如果 Section Rendering 替换了 Checkout 按钮，应获取新的 DOM 节点。
- 快捷支付入口也需要结合平台支持的方式进行协调。

这正好体现了 WCAG 3.3.4 Error Prevention（Level AA）的设计思想。对于涉及金融交易的提交过程，需要提供可撤销、错误检查或确认等至少一种适用机制，帮助用户避免严重错误。<Cite ref="turn769519search0"/>

等待购物车保存完成是重要的工程保护，但它本身不能代替完整的订单错误预防机制。
