上一课，我们学习了 Modal、Dialog、Drawer 和 Popover 的完整实现。

这一课，我们将研究另一类在前端开发中非常常见、却特别容易出现 ARIA 使用错误的组件：**下拉组件**。

尤其是在 Shopify Theme 开发中：

| 业务场景 | 对应组件模式 |
|---|---|
| Header Mega Menu | Disclosure Navigation |
| Collection 商品排序 | Select |

本课最重要的目标，是让你能够根据组件的真实业务用途，选择正确的无障碍语义、键盘交互和焦点管理方案，而不是看到下拉框就添加 `role="menu"`。

## 1. Dropdown 到底是什么？

Dropdown（下拉框）实际上只是一个 UI 设计概念，并不是一种明确的 HTML 元素或 ARIA Role。

视觉上非常相似的下拉组件，在无障碍体系中可能完全不同。

        </row>
      {/each}
      <divider/>
      **Select / Listbox**
      <caption>从多个选项中选择一个值。</caption>
    </box>
  </grid-item>
  <grid-item>
    <box border radius="lg" padding={3} gap={2}>

      **Editable Combobox**
      <caption>输入文字并选择搜索建议。</caption>
    </box>
  </grid-item>
</grid>

这四个组件虽然都有展开、收起的视觉表现，但是语义和操作模型完全不同。

| 组件 | 核心用途 | 主要键盘操作 |
|---|---|---|
| Disclosure | 显示或隐藏内容 | Tab、Enter、Space |
| Menu | 执行命令或菜单操作 | 方向键、Enter、Esc |
| Listbox | 选择一个或多个值 | 方向键、Space |
| Combobox | 输入或选择一个值 | 方向键、Enter、Esc |
| Native Select | 原生表单选项选择 | 浏览器自动处理 |
| Popover | 提供非模态浮层能力 | 取决于内部组件 |

**Popover 主要提供浮层显示机制，而 Menu、Listbox、Combobox 描述的是具体组件的语义及交互模式。**

一个 Combobox 可以使用 Popover API 实现建议列表的浮层显示，但使用 Popover API 并不会自动让它成为 Combobox。

## 2. Shopify Mega Menu：为什么不应该随意使用 role="menu"？

假设我们正在开发一个 Shopify Header。

<box border radius="lg" padding={3} gap={3}>
  <row align="center">
    <title size="lg">STYLE STORE</title>
    <spacer/>
    <icon name="search"/>
    <icon name="shopping-bag"/>
  </row>
  <divider/>
  <row justify="between" align="center">
    <text size="sm">Home</text>
    <row gap={1} align="center">
      <text size="sm" weight="medium" underline={true}>Clothing</text>
      <icon name="chevron-up" size="xs"/>
    </row>
    <text size="sm">Accessories</text>
    <text size="sm">Sale</text>
  </row>
  <box background="surface-tertiary" radius="md" padding={3}>
    <grid columns={2} gap={3}>
      <grid-item>
        <box gap={2}>
          **Men**
          <text size="sm">T-shirts</text>
          <text size="sm">Jackets</text>
          <text size="sm">Sweatshirts</text>
          <text size="sm">Pants</text>
        </box>
      </grid-item>
      <grid-item>
        <box gap={2}>
          **Women**
          <text size="sm">Dresses</text>
          <text size="sm">Tops</text>
          <text size="sm">Coats</text>
          <text size="sm">Accessories</text>
        </box>
      </grid-item>
    </grid>
  </box>
  <caption>典型电商 Mega Menu，本质上是一组可展开的网站导航链接。</caption>
</box>

很多开发者会这样实现：

```html
<nav role="menubar">

  <div role="menuitem">
    Clothing

    <div role="menu">
      <a role="menuitem" href="/collections/t-shirts">
        T-shirts
      </a>

      <a role="menuitem" href="/collections/jackets">
        Jackets
      </a>
    </div>

  </div>

</nav>
```

问题在于，ARIA Menu 和 Menubar 具有类似桌面软件命令菜单的交互约定。

使用这些角色后，辅助技术用户可能预期使用方向键在菜单项之间移动，而不是通过 Tab 遍历每一个链接。

W3C APG 专门提供了 Disclosure Navigation 示例，并解释了普通网站导航通常不需要完整的 ARIA Menu 交互模型。<Cite refs={["turn868794search1","turn868794search7"]}/>

### 2.1 更合理的 HTML 结构

```html
<nav aria-label="Main navigation">
  <ul>

    <li>
      <a href="/">Home</a>
    </li>

    <li>
      <button
        type="button"
        aria-expanded="false"
        aria-controls="clothing-menu"
      >
        Clothing
      </button>

      <ul id="clothing-menu" hidden>
        <li>
          <a href="/collections/t-shirts">
            T-shirts
          </a>
        </li>

        <li>
          <a href="/collections/jackets">
            Jackets
          </a>
        </li>
      </ul>
    </li>

    <li>
      <a href="/collections/sale">Sale</a>
    </li>

  </ul>
</nav>
```

这里不需要 `role="menu"`、`role="menuitem"`，甚至不需要为普通链接额外设置 tabindex。

原生 HTML 已经提供了 navigation、list、listitem、button 和 link 语义。

### 2.2 如果一级菜单本身也需要跳转呢？

例如 Clothing 本身是一个集合页链接，同时右侧箭头控制二级菜单。

推荐将两种操作拆分为两个控件。

<box border radius="md" padding={3} gap={2}>
  <row align="center" gap={1}>
    <box flex={1} border radius="sm" padding={3}>
      <text underline={true}>Clothing</text>
      <caption>跳转集合页</caption>
    </box>
    <box border radius="sm" padding={3} align="center">
      <icon name="chevron-down"/>
      <caption>展开子导航</caption>
    </box>
  </row>
</box>

```html
<li>
  <a href="/collections/clothing">
    Clothing
  </a>

  <button
    type="button"
    aria-label="Clothing submenu"
    aria-expanded="false"
    aria-controls="clothing-submenu"
  >
    <svg aria-hidden="true"></svg>
  </button>

  <ul id="clothing-submenu" hidden>
    <!-- Navigation links -->
  </ul>
</li>
```

不要让同一个控件同时承担含义不清晰的页面跳转和展开操作。

### 2.3 JavaScript 实现 Disclosure

```javascript
const button = document.querySelector(
  '[aria-controls="clothing-menu"]'
);

const panel = document.getElementById(
  'clothing-menu'
);

const container = button.closest('li');

function setOpen(open, restoreFocus = false) {
  button.setAttribute(
    'aria-expanded',
    String(open)
  );

  if (!open &&
      (restoreFocus ||
       panel.contains(document.activeElement))) {
    button.focus();
  }

  panel.hidden = !open;
}

button.addEventListener('click', () => {
  const open =
    button.getAttribute('aria-expanded') === 'true';

  setOpen(!open);
});

container.addEventListener('keydown', event => {
  if (
    event.key === 'Escape' &&
    !event.defaultPrevented &&
    button.getAttribute('aria-expanded') === 'true'
  ) {
    event.preventDefault();
    setOpen(false, true);
  }
});

container.addEventListener('focusout', event => {
  if (
    event.relatedTarget &&
    !container.contains(event.relatedTarget)
  ) {
    setOpen(false);
  }
});

document.addEventListener('click', event => {
  if (!container.contains(event.target)) {
    setOpen(false);
  }
});
```

这个实现具备基本的展开、折叠、Esc 关闭、焦点离开关闭和外部点击关闭能力。

它没有使用 Focus Trap，因为普通导航下拉菜单不是模态弹窗。

## 3. 原生 select：最容易被低估的组件

假设我们要开发 Collection 商品排序功能。

```liquid
<label for="SortBy">Sort by</label>

<select id="SortBy" name="sort_by">

  {% assign current_sort = collection.sort_by
    | default: collection.default_sort_by %}

  {% for option in collection.sort_options %}

    <option
      value="{{ option.value | escape }}"
      {% if option.value == current_sort %}
        selected
      {% endif %}
    >
      {{ option.name | escape }}
    </option>

  {% endfor %}

</select>
```

原生 select 已经提供了：

| 能力 | 是否需要自行实现 |
|---|---|
| Accessible Name | 通过 label 提供 |
| 选项角色与选中状态 | 否 |
| 键盘方向键选择 | 否 |
| 字符快速搜索 | 否 |
| 移动端原生选择界面 | 否 |
| disabled / required | 否 |
| 表单提交 | 否 |
| 值变化事件 | 监听 change 即可 |

{@body const [sort,setSort]=DIL.useState("best-selling")}
<card gap={3}>
  <label>Sort by</label>
  <select value={sort} onChange={setSort} options={[{label:"Featured",value:"manual"},{label:"Best selling",value:"best-selling"},{label:"Alphabetically, A–Z",value:"title-ascending"},{label:"Price, low to high",value:"price-ascending"},{label:"Price, high to low",value:"price-descending"},{label:"Date, new to old",value:"created-descending"}]}/>
  <divider/>
  <row><caption>Accessible Name</caption><spacer/>Sort by</row>
  <row><caption>当前表单值</caption><spacer/><text size="sm">{sort}</text></row>
  <box background="surface-tertiary" radius="sm" padding={2}>
    <text size="xs">{`?sort_by=${sort}`}</text>
  </box>
  <caption>常见 Shopify 排序选项示意，实际选项以 collection.sort_options 为准。</caption>
</card>

当选择发生变化时，只需要处理业务逻辑：

```javascript
select.addEventListener('change', event => {
  const sortBy = event.target.value;

  updateCollection({ sortBy });
});
```

如果使用 AJAX 更新商品列表，继续保留 select 的焦点，并通过 Live Region 通知结果即可。

### 3.1 原生 select 的无障碍 Role 是什么？

这取决于 select 的具体配置。

| HTML | 常见隐式角色 |
|---|---|
| `<select>` | combobox |
| `<select size="1">` | combobox |
| `<select size="5">` | listbox |
| `<select multiple>` | listbox |
| `<option>` | option |

所以不需要手动为 select 添加 `role="combobox"`。

### 3.2 什么时候才应该开发自定义 Select？

例如：

- 需要复杂的选项视觉样式。
- 需要在国家列表中展示国旗等辅助内容。
- 需要可搜索的选项列表。
- 需要特殊的虚拟滚动机制。
- 原生 select 无法满足业务交互需求。

但应当注意，自定义 Select 不是简单地使用 div 替换 select，而是需要重新承担键盘、焦点、状态、表单值及辅助技术兼容性等职责。

现代 CSS 还提供了 `appearance: base-select` 等原生 Select 自定义能力，可以作为渐进增强方案研究，不过需要检查目标浏览器的支持情况。<Cite ref="turn868794search20"/>

## 4. Menu Button：真正的 ARIA Menu 应该如何开发？

假设我们正在开发一个用户账户页面中的地址管理操作菜单。

它包含编辑、设为默认地址、删除地址等命令。

这种场景就比较适合 Menu Button Pattern。

### 4.1 HTML 结构

```html
<div id="address-actions">

  <button
    id="actions-button"
    type="button"
    aria-haspopup="menu"
    aria-expanded="false"
    aria-controls="actions-menu"
  >
    More actions
  </button>

  <ul
    id="actions-menu"
    role="menu"
    aria-labelledby="actions-button"
    hidden
  >
    <li role="none">
      <button role="menuitem" tabindex="-1"
        type="button" data-action="edit">
        Edit address
      </button>
    </li>

    <li role="none">
      <button role="menuitem" tabindex="-1"
        type="button" data-action="default">
        Set as default
      </button>
    </li>

    <li role="none">
      <button role="menuitem" tabindex="-1"
        type="button" data-action="delete">
        Delete address
      </button>
    </li>
  </ul>

</div>
```

注意几个关键点：

| 属性 | 职责 |
|---|---|
| `aria-haspopup="menu"` | 声明打开的是 ARIA Menu |
| `aria-expanded` | 表达当前展开状态 |
| `role="menu"` | 表达菜单容器 |
| `role="menuitem"` | 表达菜单命令 |
| `role="none"` | 移除中间 li 的列表项语义 |
| `tabindex="-1"` | 不让每个菜单项进入常规 Tab 顺序 |

### 4.2 键盘交互规范

| 按键 | 行为 |
|---|---|
| Enter / Space | 打开菜单并聚焦第一项，或执行当前命令 |
| ArrowDown | 移动到下一项 |
| ArrowUp | 移动到上一项 |
| Home | 移动到第一项 |
| End | 移动到最后一项 |
| Esc | 关闭菜单，返回触发按钮 |
| Tab / Shift + Tab | 离开菜单并关闭 |
| 字符键 | 可支持快速定位匹配的菜单项 |

这里最重要的区别是：**Menu 使用方向键访问内部选项，而普通导航 Disclosure 使用 Tab 访问内部链接。** <Cite refs={["turn868794search2","turn868794search9"]}/>

### 4.4 JavaScript 实现

```javascript
const root = document.querySelector('#address-actions');
const trigger = root.querySelector('#actions-button');
const menu = root.querySelector('[role="menu"]');

const items = [
  ...menu.querySelectorAll('[role="menuitem"]')
];

let activeIndex = 0;

function focusItem(index) {
  activeIndex =
    (index + items.length) % items.length;

  items[activeIndex].focus();
}

function openMenu(index = 0) {
  menu.hidden = false;

  trigger.setAttribute('aria-expanded', 'true');

  focusItem(index);
}

function closeMenu(restoreFocus = false) {
  trigger.setAttribute('aria-expanded', 'false');

  if (restoreFocus) {
    trigger.focus();
  }

  menu.hidden = true;
}

trigger.addEventListener('click', () => {
  menu.hidden
    ? openMenu()
    : closeMenu(true);
});

trigger.addEventListener('keydown', event => {
  if (event.key === 'ArrowDown') {
    event.preventDefault();
    openMenu(0);
  }

  if (event.key === 'ArrowUp') {
    event.preventDefault();
    openMenu(items.length - 1);
  }
});

menu.addEventListener('keydown', event => {
  switch (event.key) {
    case 'ArrowDown':
      event.preventDefault();
      focusItem(activeIndex + 1);
      break;

    case 'ArrowUp':
      event.preventDefault();
      focusItem(activeIndex - 1);
      break;

    case 'Home':
      event.preventDefault();
      focusItem(0);
      break;

    case 'End':
      event.preventDefault();
      focusItem(items.length - 1);
      break;

    case 'Escape':
      event.preventDefault();
      event.stopPropagation();
      closeMenu(true);
      break;

    case 'Tab':
      // 返回菜单入口，再让浏览器继续顺序导航
      closeMenu(true);
      break;
  }
});

menu.addEventListener('focusin', event => {
  const index = items.indexOf(event.target);

  if (index !== -1) {
    activeIndex = index;
  }
});

items.forEach(item => {
  item.addEventListener('click', () => {
    closeMenu(true);

    // 业务层函数
    executeAction(item.dataset.action);
  });
});

root.addEventListener('focusout', event => {
  if (
    event.relatedTarget &&
    !root.contains(event.relatedTarget)
  ) {
    closeMenu();
  }
});

document.addEventListener('click', event => {
  if (!root.contains(event.target)) {
    closeMenu(menu.contains(document.activeElement));
  }
});
```

这里使用真实 DOM 焦点在 menuitem 之间移动，但所有菜单项都保持 `tabindex="-1"`。

因为菜单打开时，由 JavaScript 主动设置内部焦点；菜单项不需要成为页面的常规 Tab 入口。

原生 button 已经支持 Enter 和 Space，因此不需要重复实现命令激活。

上述示例针对单层命令菜单；多级子菜单、动态菜单项以及不同浏览器中的 Tab 离开行为还需要进一步测试。

### 4.5 Typeahead 字符快速定位

例如用户打开一个国家选择菜单，然后按下 `c`，焦点移动到 Canada。

对于 Menu 和 Listbox，可以在相应模式中提供这种快捷导航。

```javascript
function findByCharacter(character) {
  const key = character.toLocaleLowerCase();

  for (let offset = 1; offset <= items.length; offset++) {
    const index =
      (activeIndex + offset) % items.length;

    const label = items[index].textContent
      .trim()
      .toLocaleLowerCase();

    if (label.startsWith(key)) {
      return index;
    }
  }

  return -1;
}

menu.addEventListener('keydown', event => {
  if (
    event.isComposing ||
    event.ctrlKey ||
    event.altKey ||
    event.metaKey ||
    event.key.length !== 1 ||
    event.key === ' '
  ) {
    return;
  }

  const index = findByCharacter(event.key);

  if (index >= 0) {
    event.preventDefault();
    focusItem(index);
  }
});
```

这是单字符匹配实现。更完整的 Typeahead 可以增加字符缓冲区、输入超时、多语言字符串匹配和重复字符循环。

特别注意，不要将这种字符拦截逻辑直接应用到可编辑 Combobox 的 input 上，否则会影响用户正常输入文字。

### 5.2 Listbox 内部能否放多个按钮？

例如：

```html
<div role="option">
  Cotton T-shirt

  <button>Add to cart</button>
  <button>Add to wishlist</button>
</div>
```

不应该这样设计。

Listbox 的选项主要表达可选择的值，并不适合承载多个独立的内部交互控件。

如果每条商品建议包含多个操作按钮，可以考虑普通商品列表、具有适当交互模型的 Grid，或者其他更符合业务需求的结构。

另外，Shopify Collection 多选筛选通常使用原生 Checkbox 就足够了，不必为了实现自定义样式将所有筛选项改造成多选 Listbox。

### 7.1 Combobox 所需要的 ARIA 属性

```html
<label for="search-input">Search products</label>

<input
  id="search-input"
  type="search"
  role="combobox"
  aria-expanded="true"
  aria-controls="search-results"
  aria-autocomplete="list"
  aria-activedescendant="option-2"
>

<ul id="search-results" role="listbox"
    aria-label="Search suggestions">

  <li id="option-1" role="option"
      aria-selected="false">
    Cotton T-shirt
  </li>

  <li id="option-2" role="option"
      aria-selected="true">
    Linen shirt
  </li>

</ul>
```

| 属性 | 职责 |
|---|---|
| `role="combobox"` | 声明组合输入控件 |
| `aria-expanded` | 建议列表是否展开 |
| `aria-controls` | 关联建议列表 |
| `aria-autocomplete` | 自动完成模式 |
| `aria-activedescendant` | 当前活动选项 |
| `role="listbox"` | 建议列表语义 |
| `role="option"` | 单条建议语义 |
| `aria-selected` | 建议列表中的选中状态 |

Combobox 隐式具有 `aria-haspopup="listbox"`，因此在使用 Listbox 弹出区域时，可以省略该属性。

如果弹出区域是 Grid、Tree 或 Dialog，则需要根据实际模式声明对应类型。

### 7.2 键盘交互设计

| 按键 | 行为 |
|---|---|
| 普通字符 | 正常输入关键词 |
| Backspace | 正常删除文字 |
| ArrowDown | 打开列表或移动到下一项 |
| ArrowUp | 移动到上一项 |
| Enter | 确认活动项，或提交原搜索词 |
| Escape | 关闭建议列表 |
| Tab | 离开组件 |
| ArrowLeft / Right | 保留输入框光标操作 |
| Home / End | 保留文本编辑行为 |

特别注意，Editable Combobox 不应该无条件拦截 Home、End、ArrowLeft、ArrowRight 等按键。

因为它首先是一个文本输入控件，其次才是一个具有建议列表的复合组件。

为什么这里不直接使用 `:focus` 高亮建议项？

因为 DOM 焦点始终在 input 上。

建议项的视觉高亮需要通过 `aria-selected` 或其他活动状态 class 来实现。

### 8.4 JavaScript：状态管理

```javascript
const form = document.querySelector('#ProductSearch');
const input = form.querySelector('#SearchInput');
const list = form.querySelector('#SearchResults');
const status = form.querySelector('#SearchStatus');

let results = [];
let activeIndex = -1;

let debounceTimer;
let controller;
let requestVersion = 0;

function setActive(index) {
  activeIndex = index;

  const options = [...list.children];

  options.forEach((option, i) => {
    option.setAttribute(
      'aria-selected',
      String(i === index)
    );
  });

  const active = options[index];

  if (!active) {
    input.removeAttribute('aria-activedescendant');
    return;
  }

  input.setAttribute(
    'aria-activedescendant',
    active.id
  );

  active.scrollIntoView({
    block: 'nearest',
    behavior: 'instant'
  });
}

function openResults() {
  if (!results.length) return;

  list.hidden = false;

  input.setAttribute('aria-expanded', 'true');
}

function hideResults() {
  setActive(-1);

  list.hidden = true;

  input.setAttribute('aria-expanded', 'false');
}
```

这里将展开状态、活动项、选中状态及视觉样式统一管理。

### 8.5 JavaScript：渲染建议列表

```javascript
function renderResults(items) {
  // 删除旧 DOM 前清理活动项引用
  setActive(-1);

  results = items;

  const fragment = document.createDocumentFragment();

  items.forEach((item, index) => {
    const option = document.createElement('li');

    option.id = `${list.id}-option-${index}`;

    option.setAttribute('role', 'option');
    option.setAttribute('aria-selected', 'false');

    option.dataset.index = index;

    option.textContent = item.title;

    fragment.appendChild(option);
  });

  list.replaceChildren(fragment);

  if (items.length) {
    openResults();
  } else {
    hideResults();
  }

  status.textContent =
    `${items.length} suggestions available.`;
}
```

注意，这里没有将整个 Listbox 设置为 Live Region。

根据第 14 课的知识，Live Region 只负责通知搜索结果数量，`aria-activedescendant` 则负责活动项变化。

### 8.6 JavaScript：接入 Shopify Predictive Search API

Shopify 提供两种主要的 Predictive Search 响应形式：

| API | 响应内容 |
|---|---|
| `/search/suggest.json` | JSON 数据 |
| `/search/suggest` + `section_id` | 服务端渲染的 Section HTML |

Dawn 主要采用第二种方式。本示例采用 JSON 方式，以便更清楚地展示组件内部的状态管理。<Cite ref="turn958684view1"/>

```javascript
function cancelPendingSearch() {
  requestVersion++;

  clearTimeout(debounceTimer);

  controller?.abort();

  list.setAttribute('aria-busy', 'false');
}

function dismissResults() {
  cancelPendingSearch();
  hideResults();

  status.textContent = '';
}

async function fetchSuggestions(query, version) {
  const request = new AbortController();

  controller = request;

  const params = new URLSearchParams({
    q: query,
    'resources[type]': 'product',
    'resources[limit]': '6'
  });

  const url =
    window.Shopify.routes.root +
    'search/suggest.json?' +
    params.toString();

  try {
    const response = await fetch(url, {
      signal: request.signal
    });

    if (!response.ok) {
      throw new Error(`HTTP ${response.status}`);
    }

    const data = await response.json();

    // 避免渲染已经过时的搜索结果
    if (version !== requestVersion) return;

    if (document.activeElement !== input) return;

    if (query !== input.value.trim()) return;

    const products =
      data.resources.results.products;

    // 将商品标题作为搜索建议，并去重
    const titles = [
      ...new Set(products.map(product => product.title))
    ];

    renderResults(
      titles.map(title => ({ title }))
    );

  } catch (error) {
    if (
      error.name === 'AbortError' ||
      version !== requestVersion
    ) {
      return;
    }

    hideResults();

    status.textContent =
      'Search suggestions are unavailable. ' +
      'You can still submit your search.';

  } finally {
    if (version === requestVersion) {
      list.setAttribute('aria-busy', 'false');
    }
  }
}
```

这里的请求 URL 使用 `window.Shopify.routes.root`，以支持 Shopify 的 locale-aware URL。

### 8.7 JavaScript：Debounce 与输入法处理

```javascript
function scheduleSearch() {
  cancelPendingSearch();

  hideResults();

  results = [];
  list.replaceChildren();

  status.textContent = '';

  const query = input.value.trim();

  if (!query) return;

  const version = requestVersion;

  list.setAttribute('aria-busy', 'true');

  debounceTimer = setTimeout(() => {
    fetchSuggestions(query, version);
  }, 250);
}

input.addEventListener('input', event => {
  if (event.isComposing) return;

  scheduleSearch();
});

input.addEventListener('compositionstart', () => {
  dismissResults();
});

input.addEventListener('compositionend', () => {
  scheduleSearch();
});
```

为什么需要处理输入法？

例如中文、日文等输入法在文字正式输入之前，会经历 Composition（组合输入）过程。

如果没有处理 `isComposing`，可能在用户尚未完成一个词语时就不断发起请求，甚至在用户按 Enter 确认输入法候选词时意外触发搜索提交。

## 9. 实现 Combobox 的完整键盘交互

继续编写上面的 JavaScript。

### 9.1 确认当前建议

```javascript
function selectOption(index) {
  const option = results[index];

  if (!option) return;

  input.value = option.title;

  dismissResults();

  input.focus();

  form.requestSubmit();
}
```

这里使用 `requestSubmit()`，而不是直接调用 `form.submit()`。

因为 `requestSubmit()` 更接近正常的表单提交行为，可以触发 submit 事件及适用的表单验证。

### 9.2 键盘导航

```javascript
input.addEventListener('keydown', event => {
  if (event.isComposing || event.keyCode === 229) {
    return;
  }

  switch (event.key) {
    case 'ArrowDown': {
      if (!results.length) return;

      event.preventDefault();

      openResults();

      setActive(
        (activeIndex + 1) % results.length
      );

      break;
    }

    case 'ArrowUp': {
      if (!results.length) return;

      event.preventDefault();

      openResults();

      setActive(
        activeIndex <= 0
          ? results.length - 1
          : activeIndex - 1
      );

      break;
    }

    case 'Enter': {
      if (!list.hidden && activeIndex >= 0) {
        event.preventDefault();

        selectOption(activeIndex);
      }

      // 没有活动项时，保留原生表单提交
      break;
    }

    case 'Escape': {
      if (!list.hidden ||
          list.getAttribute('aria-busy') === 'true') {
        event.preventDefault();
        event.stopPropagation();

        dismissResults();
      }

      break;
    }

    case 'Tab': {
      dismissResults();

      // 不调用 preventDefault()
      break;
    }
  }
});
```

这段代码中有三个非常值得关注的细节。

第一，只有存在活动建议项时，才拦截 Enter。否则用户可以直接搜索自己输入的关键词。

第二，Esc 优先关闭当前建议列表。如果建议列表已经关闭，则允许 Esc 继续传递给外层 Search Modal。

第三，Tab 只负责离开组件，不应该被 Focus Trap 限制在搜索框内部。

### 9.3 鼠标和触屏交互

```javascript
list.addEventListener('mousedown', event => {
  if (event.target.closest('[role="option"]')) {
    // 避免鼠标按下时 input 提前失去焦点
    event.preventDefault();
  }
});

list.addEventListener('click', event => {
  const option = event.target.closest('[role="option"]');

  if (!option) return;

  selectOption(
    Number(option.dataset.index)
  );
});

form.addEventListener('focusout', event => {
  if (
    event.relatedTarget &&
    event.relatedTarget !== input
  ) {
    dismissResults();
  }
});

document.addEventListener('click', event => {
  if (!form.contains(event.target)) {
    dismissResults();
  }
});

input.addEventListener('focus', () => {
  if (input.value.trim()) {
    scheduleSearch();
  }
});
```

一个搜索组件至少存在以下几种状态。

<box border radius="lg" padding={3} gap={1}>
  <box border radius="md" padding={2} align="center">Idle · 等待输入</box>
  <box align="center"><icon name="arrow-down" color="secondary"/></box>
  <box border radius="md" padding={2} align="center">Debouncing · 等待防抖</box>
  <box align="center"><icon name="arrow-down" color="secondary"/></box>
  <box border radius="md" padding={2} align="center">Loading · 请求中</box>
  <box align="center"><icon name="arrow-down" color="secondary"/></box>
  <grid columns={3} gap={1}>
    <grid-item><box border radius="sm" padding={2} align="center"><text size="sm">Success</text><caption>有建议</caption></box></grid-item>
    <grid-item><box border radius="sm" padding={2} align="center"><text size="sm">Empty</text><caption>无结果</caption></box></grid-item>
    <grid-item><box border radius="sm" padding={2} align="center"><text size="sm">Error</text><caption>请求失败</caption></box></grid-item>
  </grid>
  <box align="center"><icon name="arrow-down" color="secondary"/></box>
  <box border radius="md" padding={2} align="center">Dismissed · 用户关闭建议</box>
  <caption>用户可以在请求过程中随时关闭组件，因此关闭操作也必须使旧请求失效。</caption>
</box>

例如用户输入 shirt，发起 AJAX 请求。

请求还没有返回，用户就按下 Esc 关闭建议列表。

如果请求成功后仍然无条件执行：

```javascript
renderResults(data);
openResults();
```

已经关闭的建议列表就会重新出现。

这不仅是普通功能 Bug，还会导致屏幕阅读器收到用户已经不再需要的状态消息。

所以前面的实现同时使用了：

| 机制 | 解决的问题 |
|---|---|
| Debounce | 减少频繁网络请求 |
| AbortController | 取消旧请求 |
| Request Version | 防止过期响应更新页面 |
| Focus Check | 防止离开后重新打开列表 |
| Dismiss | 使关闭前的请求失效 |
| 清理活动项 | 防止引用已经删除的 DOM |
| Live Region | 通知有效结果 |

**无障碍组件并不是在普通组件完成之后再添加几个 ARIA 属性，而是从业务状态机设计阶段就需要考虑无障碍行为。**

## 13. Shopify Dawn：Mega Menu 源码解析

源码文件：[snippets/header-mega-menu.liquid](https://github.com/Shopify/dawn/blob/main/snippets/header-mega-menu.liquid)

Dawn 并没有为普通 Mega Menu 使用完整的 ARIA Menu 模式，而是基于原生 `details` 和 `summary` 实现。

简化后的结构：

```liquid
<nav class="header__inline-menu">

  <ul class="list-menu" role="list">

    {% for link in section.settings.menu.links %}

      <li>

        {% if link.links != blank %}

          <header-menu>

            <details class="mega-menu">

              <summary>
                {{ link.title | escape }}
              </summary>

              <div class="mega-menu__content">

                <ul role="list">

                  {% for childlink in link.links %}

                    <li>
                      <a href="{{ childlink.url }}"
                        {% if childlink.current %}
                          aria-current="page"
                        {% endif %}
                      >
                        {{ childlink.title | escape }}
                      </a>
                    </li>

                  {% endfor %}

                </ul>

              </div>

            </details>

          </header-menu>

        {% else %}

          <a href="{{ link.url }}">
            {{ link.title | escape }}
          </a>

        {% endif %}

      </li>

    {% endfor %}

  </ul>

</nav>
```

以上是根据 Dawn 公开源码简化的教学结构，省略了三级导航、样式及部分属性。<Cite ref="turn144170view3"/>

这个实现有几个值得学习的地方：

| Dawn 的设计 | 目的 |
|---|---|
| `nav` | 保留导航 Landmark |
| `ul`、`li` | 保留列表结构 |
| `details`、`summary` | 提供原生展开能力 |
| `header-menu` | 扩展组件交互 |
| `a[href]` | 保留真实导航链接 |
| `aria-current="page"` | 表达当前页面 |

也就是说，Dawn 的 Mega Menu 本质上也是一种 Disclosure Navigation。

对于你自己开发的 Theme，如果需求比较简单，甚至可以优先使用 `details` 和 `summary`，减少 JavaScript 状态同步工作。

### 14.3 switchOption() 的核心思想

Dawn 使用的是虚拟焦点机制，而不是真实 DOM 焦点移动。

下面是根据其源码逻辑编写的简化示例：

```javascript
function updateActiveOption(previous, next, input) {
  previous?.setAttribute('aria-selected', 'false');

  next.setAttribute('aria-selected', 'true');

  input.setAttribute(
    'aria-activedescendant',
    next.id
  );
}
```

实际源码还负责查询可见选项、计算当前索引和处理方向键循环。

这里不会对搜索建议执行 `.focus()`，因此搜索框仍然可以接收用户输入。

阅读实际源码时，可以重点验证：

| 实现细节 | 需要检查的问题 |
|---|---|
| 使用 `offsetParent` 判断可见性 | 是否能准确处理当前布局中的隐藏选项 |
| 使用 `event.code` 判断按键 | 输入法及特殊键盘环境是否正常 |

### 15.1 Playwright 测试 Combobox

以下测试假设测试店铺中存在与 `shirt` 匹配的商品。

```javascript
import { test, expect } from '@playwright/test';

test('predictive search keyboard navigation',
  async ({ page }) => {

    await page.goto('/');

    const input = page.getByRole('combobox', {
      name: 'Search products'
    });

    await input.fill('shirt');

    await expect(input).toHaveAttribute(
      'aria-expanded',
      'true'
    );

    await page.keyboard.press('ArrowDown');

    // DOM 焦点应该始终位于输入框
    await expect(input).toBeFocused();

    const activeId = await input.getAttribute(
      'aria-activedescendant'
    );

    expect(activeId).toBeTruthy();

    await expect(
      page.getByRole('option', {
        selected: true
      })
    ).toHaveAttribute('id', activeId);

    await page.keyboard.press('Escape');

    await expect(input).toHaveAttribute(
      'aria-expanded',
      'false'
    );

    await expect(input).not.toHaveAttribute(
      'aria-activedescendant',
      /.+/
    );

    await expect(input).toBeFocused();
  }
);
```

### 15.2 检查活动项引用是否有效

在 Chrome DevTools Console 中执行：

```javascript
console.table(
  [...document.querySelectorAll('[role="combobox"]')]
    .map(element => {
      const id = element.getAttribute(
        'aria-activedescendant'
      );

      const controls = element.getAttribute(
        'aria-controls'
      );

      const target = id
        ? document.getElementById(id)
        : null;

      const popup = controls
        ? document.getElementById(controls)
        : null;

      return {
        element,
        expanded: element.getAttribute('aria-expanded'),
        activeId: id,
        targetExists: Boolean(target),
        popupExists: Boolean(popup),
        activeInsidePopup: Boolean(
          target && popup?.contains(target)
        ),
        domFocused: document.activeElement === element
      };
    })
);
```

这个脚本适合检查普通 DOM 中使用 Listbox Popup 的 Combobox。它只能帮助排查引用关系，不能替代完整的 ARIA 结构及屏幕阅读器测试。

## 6.3 Combobox 的核心 ARIA 属性

一个典型的可编辑 Combobox 结构如下：

```html
<label for="search-input">
  Search products
</label>

<input
  id="search-input"
  type="search"
  role="combobox"
  aria-autocomplete="list"
  aria-expanded="true"
  aria-controls="search-results"
  aria-activedescendant="result-2"
>

<ul
  id="search-results"
  role="listbox"
  aria-label="Product suggestions"
>
  <li
    id="result-1"
    role="option"
    aria-selected="false"
  >
    Cotton T-shirt
  </li>

  <li
    id="result-2"
    role="option"
    aria-selected="true"
  >
    Linen shirt
  </li>
</ul>
```

各个属性的作用如下：

| 属性 | 职责 |
|---|---|
| `role="combobox"` | 表达组合输入控件 |
| `aria-autocomplete="list"` | 提供列表式输入建议 |
| `aria-expanded` | 表达建议列表是否展开 |
| `aria-controls` | 关联弹出列表 |
| `aria-activedescendant` | 指向当前活动选项 |
| `role="listbox"` | 表达选项列表 |
| `role="option"` | 表达单个建议选项 |
| `aria-selected` | 表达列表中的选中状态 |

Combobox 隐式具有 `aria-haspopup="listbox"`，所以当弹出区域为 listbox 时，可以省略 aria-haspopup。

如果弹出区域采用 grid、tree 或 dialog，则需要声明对应的类型。<Cite ref="turn868794search0"/>

### 6.4 Combobox 的四种状态

在开发 Combobox 时，应该明确区分四个变量。

```javascript
const state = {
  inputValue: 'shirt',
  isOpen: true,
  activeIndex: 1,
  committedValue: null
};
```

| 状态 | 含义 |
|---|---|
| inputValue | 用户当前输入的文字 |
| isOpen | 建议列表是否展开 |
| activeIndex | 方向键当前指向的选项 |
| committedValue | 用户最终确认的值 |

例如用户输入 `shirt`，然后按两次 ArrowDown，高亮 Linen shirt。

此时输入框的值仍然可以是 `shirt`，用户尚未确认 Linen shirt。

  </row>

### 6.5 Editable Combobox 键盘交互

以下是适合手动确认模式的电商搜索交互设计。

| 按键 | 行为 |
|---|---|
| 普通字符 | 编辑输入内容并获取建议 |
| ArrowDown | 展开列表或移动到下一项 |
| ArrowUp | 移动到上一项 |
| Enter（有活动项） | 确认当前建议 |
| Enter（无活动项） | 提交原始搜索关键词 |
| Escape | 关闭建议列表，保留输入内容 |
| Tab | 离开组件，不强制选择建议 |
| ArrowLeft / Right | 保留原生文本编辑行为 |
| Home / End | 保留原生光标移动行为 |
| Backspace / Delete | 保留原生编辑行为 |

特别注意，不能为了实现下拉框导航，破坏输入框本身的文字编辑能力。

例如下面的写法是不合理的：

```javascript
input.addEventListener('keydown', event => {
  event.preventDefault();
});
```

应该仅在实际处理特定导航按键时阻止默认行为。

### 8.5 活动选项管理

```javascript
function setActiveOption(index) {
  const options = [
    ...listbox.querySelectorAll('[role="option"]')
  ];

  activeIndex =
    index >= 0 && index < options.length
      ? index
      : -1;

  options.forEach((option, i) => {
    option.setAttribute(
      'aria-selected',
      String(i === activeIndex)
    );
  });

  if (activeIndex === -1) {
    input.removeAttribute('aria-activedescendant');
    return;
  }

  const option = options[activeIndex];

  input.setAttribute(
    'aria-activedescendant',
    option.id
  );

  option.scrollIntoView({
    block: 'nearest',
    inline: 'nearest'
  });
}
```

这里有三个同步更新的状态：活动选项索引、ARIA 属性以及视觉高亮。

特别是 `scrollIntoView()`，这是开发自定义 Listbox 时容易遗漏的一步。

因为 option 没有真实获得 DOM 焦点，浏览器不会像普通 focus() 一样自动保证活动项可见。

### 8.6 展开、关闭与清理请求

```javascript
function hideResults() {
  setActiveOption(-1);

  listbox.hidden = true;

  input.setAttribute('aria-expanded', 'false');
}

function openResults() {
  if (!results.length) return;

  listbox.hidden = false;

  input.setAttribute('aria-expanded', 'true');
}

function cancelPendingSearch() {
  clearTimeout(debounceTimer);

  controller?.abort();

  requestVersion++;

  listbox.setAttribute('aria-busy', 'false');
}

function closeResults() {
  cancelPendingSearch();

  hideResults();

  status.textContent = '';
}
```

为什么关闭列表时还需要取消请求？

假设用户输入 `shirt`，AJAX 请求尚未返回，此时按下 Esc。

如果只是关闭视觉浮层，却没有取消请求，服务器响应返回后可能再次打开列表。

这就违背了用户刚刚执行的关闭操作。

### 8.7 请求 Shopify 搜索 API

```javascript
async function fetchSuggestions(query) {
  const version = ++requestVersion;

  controller?.abort();
  controller = new AbortController();

  const params = new URLSearchParams({
    q: query,
    'resources[type]': 'product',
    'resources[limit]': '8'
  });

  const url =
    window.Shopify.routes.root +
    'search/suggest.json?' +
    params.toString();

  listbox.setAttribute('aria-busy', 'true');

  status.textContent = 'Searching products...';

  try {
    const response = await fetch(url, {
      signal: controller.signal
    });

    if (!response.ok) {
      throw new Error('Search request failed');
    }

    const data = await response.json();

    // 忽略已经过期的请求
    if (version !== requestVersion) return;

    // 防止输入框内容已发生变化
    if (input.value.trim() !== query) return;

    // 用户离开搜索框后不重新打开浮层
    if (document.activeElement !== input) return;

    results =
      data.resources.results.products || [];

    renderResults(results);

  } catch (error) {
    if (
      error.name === 'AbortError' ||
      version !== requestVersion
    ) {
      return;
    }

    results = [];
    hideResults();

    status.textContent =
      'Suggestions unavailable. You can still search.';

  } finally {
    if (version === requestVersion) {
      listbox.setAttribute('aria-busy', 'false');
    }
  }
}
```

注意 URL 使用了 `window.Shopify.routes.root`，这是为了兼容 Shopify 的多语言路径，而不是直接将请求地址硬编码为 `/search/suggest.json`。

Shopify 官方也建议 Ajax API 使用与当前语言区域一致的 URL。<Cite ref="turn868794search3"/>

### 8.8 渲染建议列表

```javascript
function renderResults(products) {
  // 清理对旧 DOM 节点的引用
  setActiveOption(-1);

  const fragment = document.createDocumentFragment();

  products.forEach((product, index) => {
    const option = document.createElement('li');

    option.id = `SearchOption-${index}`;

    option.setAttribute('role', 'option');

    option.setAttribute('aria-selected', 'false');

    option.dataset.index = String(index);

    option.textContent = product.title;

    fragment.appendChild(option);
  });

  listbox.replaceChildren(fragment);

  if (products.length) {
    openResults();

    status.textContent =
      `${products.length} product suggestions found.`;
  } else {
    hideResults();

    status.textContent = 'No product suggestions found.';
  }
}
```

这里故意使用 `textContent` 而不是通过字符串拼接 `innerHTML`，避免将商品标题错误地解释为 HTML。

同时，在替换选项之前清理 aria-activedescendant，避免它指向已经被删除的旧节点。

本示例的 result ID 只适用于单个搜索组件；多个搜索实例应加入唯一前缀。

### 8.9 输入防抖与中文输入法处理

```javascript
function scheduleSearch() {
  cancelPendingSearch();
  hideResults();

  results = [];
  status.textContent = '';

  const query = input.value.trim();

  if (!query) {
    listbox.replaceChildren();
    return;
  }

  debounceTimer = setTimeout(() => {
    fetchSuggestions(query);
  }, 250);
}

input.addEventListener('input', event => {
  if (event.isComposing || composing) return;

  scheduleSearch();
});

input.addEventListener('compositionstart', () => {
  composing = true;

  closeResults();
});

input.addEventListener('compositionend', () => {
  composing = false;

  scheduleSearch();
});
```

为什么需要处理 compositionstart 和 compositionend？

例如用户使用中文输入法输入“衬衫”，中间可能经历：

```text
c
ch
chen
chenshan
衬衫
```

不应该把所有尚未确认的拼音都发送到 Predictive Search API，也不应该在用户通过 Enter 确认中文候选字时，错误地跳转到商品详情页。

这不仅是性能问题，也是国际化和键盘无障碍问题。

### 8.10 完整键盘交互

```javascript
function commitOption(index) {
  const product = results[index];

  if (!product) return;

  closeResults();

  window.location.assign(product.url);
}

input.addEventListener('keydown', event => {
  if (
    composing ||
    event.isComposing ||
    event.keyCode === 229
  ) {
    return;
  }

  switch (event.key) {
    case 'ArrowDown':
      if (results.length) {
        event.preventDefault();

        openResults();

        setActiveOption(
          (activeIndex + 1) % results.length
        );
      }
      break;

    case 'ArrowUp':
      if (results.length) {
        event.preventDefault();

        openResults();

        setActiveOption(
          activeIndex <= 0
            ? results.length - 1
            : activeIndex - 1
        );
      }
      break;

    case 'Enter':
      if (!listbox.hidden && activeIndex >= 0) {
        event.preventDefault();

        commitOption(activeIndex);
      }

      // 没有活动项时，保留原生表单提交
      break;

    case 'Escape':
      if (
        !listbox.hidden ||
        listbox.getAttribute('aria-busy') === 'true'
      ) {
        event.preventDefault();
        event.stopPropagation();

        closeResults();
      } else {
        cancelPendingSearch();
      }
      break;

    case 'Tab':
      closeResults();

      // 不阻止 Tab 的原生行为
      break;
  }
});
```

这里没有拦截 ArrowLeft、ArrowRight、Home、End 等文本编辑按键。

另外，Predictive Search 如果位于 Search Modal 内部，Esc 应当优先关闭当前搜索建议列表，而不是立即关闭整个 Search Modal。

父级 Modal 的 Esc 处理器也应该尊重已经处理过的事件。

### 8.11 鼠标、触屏与外部关闭

```javascript
listbox.addEventListener('mousedown', event => {
  if (event.target.closest('[role="option"]')) {
    // 避免鼠标按下时输入框提前失去焦点
    event.preventDefault();
  }
});

listbox.addEventListener('click', event => {
  const option = event.target.closest('[role="option"]');

  if (!option) return;

  commitOption(Number(option.dataset.index));
});

document.addEventListener('pointerdown', event => {
  if (!form.contains(event.target)) {
    closeResults();
  }
});

document.addEventListener('focusin', event => {
  if (event.target !== input) {
    closeResults();
  }
});

input.addEventListener('focus', () => {
  if (input.value.trim() && !composing) {
    scheduleSearch();
  }
});
```

至此，我们已经将前面学习的六项核心能力整合到了一个组件中：

| 知识 | 实际应用 |
|---|---|
| HTML 语义 | form、label、input |
| ARIA | combobox、listbox、option |
| Focus Management | DOM 焦点保留在 input |
| Keyboard | 方向键、Enter、Esc |
| AccName | 搜索框及列表名称 |
| Live Region | 搜索结果数量通知 |

该代码采用的是**商品建议确认后直接导航到商品页**的电商搜索模式，而非仅将选项文字填入 input 的通用 Combobox。它覆盖主要交互流程，但仍属于教学版本：尚未加入多实例管理、组件卸载、完整本地化、结果缓存、图片价格渲染及全部触屏辅助技术兼容性处理。

## 9. Select-only Combobox：自定义 Select 应该怎么实现？

上一节的 Predictive Search 允许用户自由输入。

但如果我们开发的是商品尺寸选择器、国家选择器或者自定义排序下拉框，用户只能从已有选项中选择，就可以采用 Select-only Combobox。

### 9.1 HTML 结构

```html
<span id="sort-label">Sort by</span>

<div
  id="sort-combobox"
  role="combobox"
  tabindex="0"
  aria-labelledby="sort-label"
  aria-expanded="false"
  aria-controls="sort-options"
>
  Best selling
</div>

<ul
  id="sort-options"
  role="listbox"
  aria-labelledby="sort-label"
  hidden
>
  <li
    id="sort-option-1"
    role="option"
    aria-selected="true"
    data-value="best-selling"
  >
    Best selling
  </li>

  <li
    id="sort-option-2"
    role="option"
    aria-selected="false"
    data-value="price-ascending"
  >
    Price, low to high
  </li>

  <li
    id="sort-option-3"
    role="option"
    aria-selected="false"
    data-value="price-descending"
  >
    Price, high to low
  </li>
</ul>

<input
  type="hidden"
  name="sort_by"
  value="best-selling"
>
```

它与 Editable Combobox 最大的区别在于：

- 不提供自由文字输入。
- 方向键和字符键可以用于选项导航。
- 不需要 `aria-autocomplete`。
- 需要自行维护用于表单提交的实际值。

### 9.2 焦点与已确认值

{@body const sortOptions=[{label:"Best selling",value:"best-selling"},{label:"Price, low to high",value:"price-ascending"},{label:"Price, high to low",value:"price-descending"},{label:"Date, new to old",value:"created-descending"}]}
{@body const [selectOpen,setSelectOpen]=DIL.useState(false)}
{@body const [selectedIndex,setSelectedIndex]=DIL.useState(0)}
{@body const [highlightIndex,setHighlightIndex]=DIL.useState(0)}
<card gap={3}>
  **Select-only Combobox 实验室**
  <label>Sort by</label>
  <pressable border radius="md" padding={3} onClick={()=>{setHighlightIndex(selectedIndex);setSelectOpen(!selectOpen)}}>
    <row align="center">
      {sortOptions[selectedIndex].label}
      <spacer/>
      <icon name={selectOpen?"chevron-up":"chevron-down"}/>
    </row>
  </pressable>
  {#if selectOpen}
    <box border radius="md" padding={2} gap={1}>
      {#each sortOptions as o,i}
        <pressable border={{size:highlightIndex===i?2:1,color:highlightIndex===i?"#3978BC":"transparent"}} background={highlightIndex===i?"#3978BC12":"surface"} radius="sm" padding={3} onClick={()=>{setSelectedIndex(i);setHighlightIndex(i);setSelectOpen(false)}}>
          <row align="center">
            <text size="sm">{o.label}</text>
            <spacer/>
            {#if selectedIndex===i}<icon name="check" color="success" size="sm"/>{/if}
          </row>
        </pressable>
      {/each}
    </box>
  {/if}
  <grid columns={4} gap={1}>
    <grid-item><button block variant="outline" color="secondary" onClick={()=>{setHighlightIndex(selectOpen?Math.max(0,highlightIndex-1):selectedIndex);setSelectOpen(true)}}><icon name="arrow-up"/></button></grid-item>
    <grid-item><button block variant="outline" color="secondary" onClick={()=>{setHighlightIndex(selectOpen?Math.min(sortOptions.length-1,highlightIndex+1):selectedIndex);setSelectOpen(true)}}><icon name="arrow-down"/></button></grid-item>
    <grid-item><button block variant="outline" color="secondary" onClick={()=>{if(selectOpen){setSelectedIndex(highlightIndex);setSelectOpen(false)}else{setHighlightIndex(selectedIndex);setSelectOpen(true)}}}>Enter</button></grid-item>
    <grid-item><button block variant="outline" color="secondary" onClick={()=>{setSelectOpen(false);setHighlightIndex(selectedIndex)}}>Esc</button></grid-item>
  </grid>
  <divider/>
  <caption>当前活动项</caption>
  <text size="sm">{selectOpen?sortOptions[highlightIndex].label:"未展开"}</text>
  <caption>当前已确认的值</caption>
  **{sortOptions[selectedIndex].label}**
  <box background="surface-tertiary" radius="sm" padding={3}>
    <text size="xs">{`<input name="sort_by"\n  type="hidden"\n  value="${sortOptions[selectedIndex].value}">`}</text>
  </box>
  <caption>使用方向键高亮其他选项，再按 Esc，观察原来的排序值是否被保留。</caption>
</card>

这里最值得学习的是，方向键高亮选项时，不立即触发 Collection 排序请求。

只有用户确认选择后，才修改最终值并执行排序。

否则，用户每按一次方向键，就可能产生一次 AJAX 请求。

### 9.3 需要补充的键盘机制

Select-only Combobox 通常还需要支持 Home、End、Typeahead，以及适当的 Tab 确认与离开行为。

W3C APG 的 Select-only Combobox 示例在 Tab 离开时会确认当前活动选项，并继续正常焦点导航；Esc 则允许取消当前选择。<Cite ref="turn868794search2"/>

可以直接研究官方提供的完整实现：

[W3C Select-Only Combobox Example](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/examples/combobox-select-only/)

不过，对于 Shopify 商品排序这种相对简单的业务，我仍然优先推荐原生 select。

自定义组件应该解决真实业务需求，而不是单纯为了替换原生控件。

## 10. Popover API 与下拉组件定位

传统下拉组件经常面临一个 CSS 问题：浮层被祖先元素裁切。

```css
.header-container {
  overflow: hidden;
}

.dropdown {
  position: absolute;
  z-index: 99999;
}
```

即使 z-index 很大，Dropdown 仍然可能被 overflow 裁切。

现代浏览器可以使用上一课学习的 Popover API 来解决这一类问题。

### 10.1 原生 Popover

```html
<button
  type="button"
  popovertarget="category-dropdown"
>
  Categories
</button>

<div id="category-dropdown" popover="auto">
  <ul>
    <li><a href="/collections/shirts">Shirts</a></li>
    <li><a href="/collections/pants">Pants</a></li>
    <li><a href="/collections/jackets">Jackets</a></li>
  </ul>
</div>
```

使用 `popovertarget` 建立关联后，浏览器能够提供基础的展开状态语义、焦点导航顺序处理、Esc 和点击外部关闭机制。<Cite ref="turn144170search0"/>

### 10.2 CSS Anchor Positioning

可以进一步使用 CSS Anchor Positioning，让浮层定位在触发按钮附近。

```css
#category-dropdown {
  position: fixed;
  position-area: bottom;
  margin: 8px 0 0;

  min-width: 180px;
  max-width: calc(100vw - 32px);

  border: 1px solid #888;
  border-radius: 8px;
  padding: 16px;

  position-try-fallbacks: flip-block;
}
```

这里可以看到，Dawn 同时使用了 aria-owns 和 aria-controls。<Cite ref="turn144170view1"/>

### 11.4 switchOption() 的核心思想

Dawn 没有直接将真实 DOM 焦点移动到商品链接上，而是通过 `aria-selected` 和 `aria-activedescendant` 表达活动项。

简化后的教学伪代码：

```javascript
function switchOption(direction) {
  const options = getVisibleOptions();

  const previous = getSelectedOption();

  const next = getNextOption(
    options,
    previous,
    direction
  );

  previous?.setAttribute(
    'aria-selected',
    'false'
  );

  next.setAttribute(
    'aria-selected',
    'true'
  );

  input.setAttribute(
    'aria-activedescendant',
    next.id
  );
}
```

它的实际源码会计算可见候选项、寻找当前选项、处理首尾循环，并更新 input 的活动项引用。<Cite ref="turn958684view0"/>

这与我们前面自己实现的虚拟焦点机制，本质上是一样的。

|---|---|

## 12. 下拉组件的统一关闭策略

在实际组件库中，下拉框可能通过多种方式关闭。

不同关闭原因，应该对应不同的焦点处理策略。

| 关闭原因 | 焦点策略 |
|---|---|
| 用户按 Esc | Menu 返回触发按钮；Combobox 保留输入框焦点 |
| 用户按 Tab | 允许继续正常导航 |
| 点击外部控件 | 尊重用户新的操作目标 |
| 选择 Menu 命令 | 根据命令结果决定焦点位置 |
| 选择商品建议 | 导航到商品详情页 |
| 搜索结果为空 | 保留搜索框焦点 |
| 父级 Modal 关闭 | 清理下拉状态与未完成请求 |
| AJAX 替换组件 | 必要时恢复对应控件焦点 |

因此，可以在自己的组件库中将关闭原因作为参数传入。

```javascript
close({
  reason: 'escape'
});
```

```javascript
close({
  reason: 'outside-click'
});
```

而不是所有关闭操作都直接执行：

```javascript
trigger.focus();
```

例如用户已经点击了页面上的另一个输入框，下拉组件关闭时就不应该强制把焦点抢回原触发按钮。

这与第 11 课所强调的原则一致：**焦点管理应该服务于用户的操作上下文。**

## 13. 如何测试 Dropdown 与 Combobox？

### 13.1 Chrome DevTools 调试

在 Console 中执行：

```javascript
const input = document.querySelector(
  '[role="combobox"]'
);

const activeId = input.getAttribute(
  'aria-activedescendant'
);

const activeOption = activeId
  ? document.getElementById(activeId)
  : null;

console.table({
  inputValue: input.value,

  expanded: input.getAttribute('aria-expanded'),

  activeId,

  activeOption: activeOption?.textContent,

  selected: activeOption?.getAttribute(
    'aria-selected'
  ),

  domFocus: document.activeElement === input
});
```

当按下方向键时，重点观察：

```text
DOM Focus: true
activeId: SearchOption-1
selected: true
```

如果 DOM Focus 已经离开输入框，或者 activeId 对应的元素不存在，就说明焦点管理或动态更新逻辑存在问题。

### 13.2 Playwright 自动化测试

下面测试 Shopify Predictive Search 的主要无障碍交互。

```javascript
import { test, expect } from '@playwright/test';

test('predictive search keyboard navigation',
  async ({ page }) => {

    await page.goto('/');

    const input = page.getByRole('combobox', {
      name: 'Search products'
    });

    await input.fill('shirt');

    await expect(input).toHaveAttribute(
      'aria-expanded',
      'true'
    );

    await input.press('ArrowDown');

    await expect(input).toBeFocused();

    const activeId = await input.getAttribute(
      'aria-activedescendant'
    );

    expect(activeId).toBeTruthy();

    const activeOption = page
      .getByRole('option')
      .and(page.locator(`[id="${activeId}"]`));

    await expect(activeOption).toHaveAttribute(
      'aria-selected',
      'true'
    );

    await input.press('Escape');

    await expect(input).toHaveAttribute(
      'aria-expanded',
      'false'
    );

    await expect(input).not.toHaveAttribute(
      'aria-activedescendant',
      /.+/
    );

    await expect(input).toBeFocused();

    await expect(input).toHaveValue('shirt');
  }
);
```

这个测试假设测试页面已经展示搜索组件，且测试店铺中存在与 shirt 匹配的商品。正式测试可以通过固定测试数据或 API Mock 减少不稳定因素。

### 13.3 需要重点测试的边缘场景

| 测试场景 | 预期结果 |
|---|---|
| 快速输入多个关键词 | 只展示最新结果 |
| 请求过程中按 Esc | 不意外重新展开 |
| 请求过程中按 Tab | 不抢夺焦点 |
| 搜索结果为空 | 明确通知用户 |
| 网络请求失败 | 保留普通搜索能力 |
| 中文输入法按 Enter | 不误触发建议选择 |
| 连续按方向键 | 活动项保持可见 |
| 用户放大页面 | 建议列表不会被裁切 |
| 多个搜索组件共存 | 不存在重复 ID |
| 搜索组件位于 Modal 内 | Esc 优先处理适当的内层组件 |
| 触屏屏幕阅读器操作 | 能够正常探索和激活建议 |
