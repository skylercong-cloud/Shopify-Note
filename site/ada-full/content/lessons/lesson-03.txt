上一课我们学习了屏幕阅读器、浏览模式、焦点模式以及虚拟光标。

我们知道，屏幕阅读器通常并不是直接读取 HTML 源代码，而是通过浏览器和操作系统提供的无障碍接口获取网页信息。

那么，浏览器究竟是如何将 HTML 转换成辅助技术能够理解的信息的？

这就是本节课的核心内容：**Accessibility Tree（无障碍树，简称 AX Tree）。**

这一课偏向浏览器底层原理。理解之后，你再学习 ARIA、HTML 语义化和焦点管理，就不需要单纯依靠记忆规范了。

## 1. 浏览器中的四种树

作为前端开发工程师，你应该已经比较熟悉 DOM Tree、CSSOM 和 Render Tree。但在无障碍开发中，我们还需要关注第四种树。

| 树结构 | 主要描述的信息 | 主要用途 |
|---|---|---|
| DOM Tree | HTML 节点与文档结构 | 文档操作 |
| CSSOM | CSS 样式规则 | 样式计算 |
| Render Tree | 渲染所需的结构 | 页面布局和绘制 |
| Accessibility Tree | 元素语义、名称、状态、关系等 | 辅助技术访问 |

这里有一个非常重要的知识点：

**DOM Tree、Render Tree 和 Accessibility Tree 中的节点并不是一一对应的。**

一个元素可以存在于 DOM Tree 中，却不存在于 Accessibility Tree 中；也可以在视觉上完全透明，却依然能够被屏幕阅读器读取。

下面我们通过具体案例理解。

## 2. DOM Tree 是如何映射到 Accessibility Tree 的？

假设我们有一个简化的商品详情页：

```html
<main>
  <div class="product">
    <h1>Cotton T-shirt</h1>

    <img src="shirt.jpg" alt="Black cotton T-shirt">

    <p>Price: $29.99</p>

    <div class="actions">
      <button type="button">
        <svg aria-hidden="true">
          <!-- Cart icon -->
        </svg>
        Add to cart
      </button>
    </div>
  </div>
</main>
```

浏览器生成的 DOM Tree 和 Accessibility Tree 可以简化为下面的结构。

观察右边的无障碍树，你会发现：

- 用于布局的 `div.product` 和 `div.actions` 可能被省略。
- `h1` 被映射为 heading，并具有 level 1 属性。
- `img` 被映射为 image，并通过 alt 获得名称。
- `button` 被映射为 button，并通过内部文字获得名称。
- 设置了 `aria-hidden="true"` 的装饰性 SVG 不会作为独立内容暴露给辅助技术。

也就是说，浏览器会对 DOM 结构进行语义映射和简化。

### 2.1 浏览器是根据什么规则进行映射的？

W3C 有几份专门定义这类映射规则的规范。

| 规范 | 作用 |
|---|---|
| HTML-AAM | 定义 HTML 元素如何映射到无障碍 API |
| Core-AAM | 定义 ARIA 角色、状态和属性的映射 |
| SVG-AAM | 定义 SVG 元素的无障碍映射 |
| AccName | 定义可访问名称和描述的计算规则 |

例如 HTML-AAM 定义了原生 HTML 元素在不同平台上的无障碍语义映射。<Cite refs={["turn281887search20","turn281887search3"]}/>

我们不需要背诵这些规范，但要理解浏览器的映射行为是有标准依据的，并非简单地把标签名称直接复制到无障碍树中。

## 3. Accessibility Node 包含哪些信息？

可以将无障碍树中的一个节点理解为一个 Accessibility Object（无障碍对象）。

例如：

```html
<label for="quantity">Quantity</label>

<input
  id="quantity"
  type="number"
  min="1"
  max="10"
  value="2"
  aria-describedby="quantity-help"
  required
>

<p id="quantity-help">
  Maximum 10 items per order.
</p>
```

页面的视觉表现：

<box border radius="lg" padding={4} gap={2}>
  **Quantity** <text color="danger" inline>*</text>
  <box border radius="md" padding={2} width="145px">
    <row align="center">
      2
      <spacer/>
      <box gap=0>
        <icon name="chevron-up" size="xs"/>
        <icon name="chevron-down" size="xs"/>
      </box>
    </row>
  </box>
  <caption>Maximum 10 items per order.</caption>
</box>

对应的无障碍节点可以抽象为：

```javascript
// 用于理解的伪代码，并非真实浏览器 JS API
{
  role: "spinbutton",
  name: "Quantity",
  description: "Maximum 10 items per order.",
  value: 2,
  valueMin: 1,
  valueMax: 10,
  required: true,
  disabled: false,
  focusable: true,
  focused: false
}
```

> Quantity, spin button, required, 2. Maximum 10 items per order.

### 3.1 Role：角色是如何产生的？

Role 有两个常见来源：隐式角色（Implicit Role）和显式角色（Explicit Role）。

**隐式角色**来自 HTML 元素本身。

| HTML 元素 | Implicit Role |
|---|---|
| `button` | button |
| `a href="..."` | link |
| `h1` ～ `h6` | heading |
| `input type="checkbox"` | checkbox |
| `input type="radio"` | radio |
| `input type="number"` | spinbutton |
| `input type="range"` | slider |
| `textarea` | textbox |
| `nav` | navigation |
| `main` | main |
| `ul` | list |
| `li` | listitem |
| `dialog` | dialog |

**显式角色**则是通过 `role` 属性指定的。

```html
<div role="button">Add to cart</div>

<div role="dialog">Shopping cart</div>

<div role="alert">Something went wrong</div>
```

在规范允许的情况下，显式 Role 可以改变元素原有的无障碍角色。

但 Role 改变的是无障碍语义，不会自动改变 DOM 类型和原生交互行为。

例如：

```html
<div role="button" id="cart">Add to cart</div>
```

```javascript
const cart = document.querySelector('#cart');

console.log(cart.tagName); // DIV

console.log(cart instanceof HTMLButtonElement);
// false
```

它在 Accessibility Tree 中可能是 button，但在 DOM Tree 中仍然是一个 div。

这两个体系是相互关联的，但并不等价。

### 3.2 Name：可访问名称是如何产生的？

Accessible Name 是辅助技术用于识别元素的名称。

例如：

```html
<button>Add to cart</button>
```

Name 是 `Add to cart`。

```html
<button aria-label="Open shopping cart">
  <svg aria-hidden="true"></svg>
</button>
```

Name 是 `Open shopping cart`。

```html
<label for="email">Email address</label>
<input id="email" type="email">
```

输入框的 Name 是 `Email address`。

常见的名称来源包括：

| 来源 | 典型用途 |
|---|---|
| `aria-labelledby` | 引用其他元素的文字 |
| `aria-label` | 直接指定名称 |
| `label` | 为表单控件提供名称 |
| `alt` | 为图片提供替代文本 |
| 元素内部文字 | 按钮、链接、标题等 |
| `title` | 部分情况下作为后备名称 |

这些来源存在一定的计算优先级，并且不同角色支持的名称来源并不完全相同。

例如：

```html
<button aria-label="Buy now">
  Add to cart
</button>
```

视觉用户看到的是 `Add to cart`，而计算出的 Accessible Name 是 `Buy now`。

这不仅造成信息不一致，还可能影响语音控制用户通过可见文字定位按钮。

所以不能为了添加 ARIA 而随意覆盖原本正确的名称。

第 13 课会专门学习完整的 Accessible Name 计算规则。

### 3.3 State：元素状态是如何产生的？

原生 HTML 属性与 ARIA 属性都可能影响无障碍状态。

```html
<input type="checkbox" checked>

<button disabled>Sold out</button>

<button aria-expanded="false">Menu</button>

<button aria-pressed="true">Favorite</button>
```

<box border radius="lg" padding={3} gap={2}>
  {#each [{html:"checked",ax:"checked: true"},{html:"disabled",ax:"disabled: true"},{html:'aria-expanded="false"',ax:"expanded: false"},{html:'aria-pressed="true"',ax:"pressed: true"}] as p}
    <row align="center">
      <box flex={1} background="surface-tertiary" radius="sm" padding={2}><text size="xs">{p.html}</text></box>
      <icon name="arrow-right" size="sm" color="secondary"/>
      <box flex={1} padding={2}><text size="sm" color="success">{p.ax}</text></box>

  {/each}
</box>

需要注意的是，原生 HTML 属性一般还会影响浏览器的实际行为，而 ARIA 状态主要影响辅助技术获取的信息。

例如，`disabled` 会禁用原生按钮，但 `aria-disabled="true"` 不会自动阻止按钮点击。

## 4. 哪些 DOM 节点不会出现在无障碍树中？

这是实际工作中非常重要的一部分。

常见情况包括没有独立语义的布局容器被省略、不需要向用户传递信息的装饰性图片被忽略、隐藏元素被排除，以及某些子元素的语义被合并。

### 4.1 没有独立语义的布局元素

```html
<div class="container">
  <div class="wrapper">
    <div class="inner">
      <h1>Products</h1>
    </div>
  </div>
</div>
```

在 DOM Tree 中有多个层级，但在简化的 Accessibility Tree 中，可能只保留有意义的标题节点。

```text
heading "Products" level=1
```

并不是所有 div 都必然被移除。有些 div 会因为角色、焦点能力、关系或其他条件成为有意义的无障碍对象。

### 4.2 装饰性图片

```html
<img src="decoration.png" alt="">
```

空的 `alt` 表示该图片不需要提供独立的替代文本。对于普通非交互的装饰性图片，浏览器通常会忽略其图片语义。

而：

```html
<img src="product.jpg" alt="Black cotton T-shirt">
```

会提供有意义的图片信息。

注意，`alt=""` 和完全不写 `alt` 并不是一回事。缺少 alt 时，辅助技术可能使用文件名等后备信息，导致用户听到无意义的内容。

### 4.3 role="presentation" 与 role="none"

这两个 Role 是同义的，主要用于移除元素原有的语义。

```html
<h2 role="presentation">
  Product description
</h2>
```

原本的无障碍语义：

```text
heading "Product description" level=2
```

移除标题语义之后，可能变为：

```text
StaticText "Product description"
```

文字仍然能够被读取，但是用户不能再将它作为二级标题快速导航。

`role="presentation"` 与 `aria-hidden="true"` 的区别在于：前者主要移除角色语义，后者主要将内容排除出无障碍树。

此外，浏览器在元素可聚焦或具有某些全局 ARIA 属性时，可能忽略 presentation 角色。<Cite refs={["turn281887search0","turn281887search3"]}/>

所以不要随意对具有实际意义的标题、表格、列表或交互控件添加这个 Role。

## 5. CSS 隐藏与 Accessibility Tree 的关系

这是本节课最重要的实战知识点之一。

在 Shopify Theme 开发过程中，我们经常需要隐藏元素，例如购物车弹窗、移动端导航菜单、商品轮播、下拉菜单、搜索建议框等。

但是，不同的隐藏方式对无障碍树的影响完全不同。

### 5.1 不同隐藏方式的对比

假设我们有一个普通按钮：

```html
<button>Add to cart</button>
```

下面分别对它应用不同的隐藏方式。

| 隐藏方式 | DOM 中存在 | 占据布局空间 | 视觉可见 | AX Tree 中可访问 | Tab 可聚焦 |
|---|---|---|---|---|---|
| `display: none` | 是 | 否 | 否 | 否 | 否 |
| `visibility: hidden` | 是 | 是 | 否 | 否 | 否 |
| `opacity: 0` | 是 | 是 | 否 | 是 | 是 |
| `hidden` | 是 | 否 | 否 | 否 | 否 |
| `aria-hidden="true"` | 是 | 是 | 是 | 应排除 | 是 |
| `inert` | 是 | 是 | 是 | 否 | 否 |
| `transform` 移出屏幕 | 是 | 是 | 否 | 是 | 是 |
| `pointer-events: none` | 是 | 是 | 是 | 是 | 是 |
| `visually-hidden` | 是 | 通常否 | 否 | 是 | 是 |
| `disabled` | 是 | 是 | 是 | 是 | 否 |
| `element.remove()` | 否 | 否 | 否 | 否 | 否 |

以上以普通按钮和常规样式为例，不考虑特殊样式覆盖及浏览器兼容性差异。

其中尤其需要注意 `opacity: 0`、`aria-hidden` 和 `inert`。<Cite refs={["turn233622search2","turn233622search11","turn233622search32","turn233622search33"]}/>

下面我们重点分析几种容易出问题的方式。

### 5.3 opacity: 0

```css
.drawer {
  opacity: 0;
}
```

很多开发人员使用 opacity 实现弹窗显示与隐藏的动画。

但是 `opacity: 0` 只会使元素透明，不会移除其无障碍语义，也不会阻止其获得焦点。

假设购物车弹窗中有以下内容：

```html
<div class="drawer" style="opacity: 0">
  <button>Close</button>
  <button>Remove product</button>
  <button>Checkout</button>
</div>
```

即使弹窗没有显示，用户仍然可能通过 Tab 键访问其中的按钮。

这是一种典型的无障碍问题：Invisible Focus（不可见焦点）。

### 5.4 aria-hidden="true"

```html
<div aria-hidden="true">
  Some content
</div>
```

这个属性主要影响无障碍树，不会改变视觉表现，也不会阻止元素交互。

比较适合以下场景：

```html
<button>
  <svg aria-hidden="true">
    <!-- 装饰性的购物车图标 -->
  </svg>
  Add to cart
</button>
```

因为 SVG 只是装饰性的，按钮文字已经能够完整表达它的用途。

但是下面的写法是错误的：

```html
<div aria-hidden="true">
  <button>Checkout</button>
</div>
```

按钮仍然可能进入键盘焦点顺序，但辅助技术可能无法正确获取它的信息。

另外还有一个非常容易踩坑的地方：

```html
<div aria-hidden="true">
  <div aria-hidden="false">
    Product description
  </div>
</div>
```

子元素上的 `aria-hidden="false"` 无法抵消祖先元素上的 `aria-hidden="true"`。

父级区域被排除后，不能单纯通过给子元素设置 false 来重新暴露其语义。<Cite ref="turn233622search2"/>

### 5.5 inert

`inert` 是一个原生 HTML 全局属性，非常适合处理暂时不允许交互的区域。

```html
<div inert>
  <a href="/products/shirt">View product</a>
  <button>Add to cart</button>
  <input type="text">
</div>
```

设置 inert 后，这个区域及其通常受影响的后代元素：

- 不再进入正常的键盘焦点顺序。
- 不再响应普通用户点击和编辑操作。
- 不再暴露给辅助技术。
- 不会因为 inert 而自动隐藏或改变视觉样式。

JavaScript 也可以直接操作它：

```javascript
const element = document.querySelector('#main');

element.inert = true;

// 恢复交互
element.inert = false;
```

它与 `aria-hidden` 最大的区别在于，inert 同时影响交互能力和无障碍树。<Cite ref="turn233622search11"/>

### 5.6 visually-hidden

如果你阅读过 Dawn 主题源码，应该对 `visually-hidden` 这个类名有印象。

这个类的作用恰好与 `aria-hidden` 有所不同。

  <grid-item>
    <box border radius="lg" padding={3} gap={2}>
      **aria-hidden**
      <divider/>
      <row><icon name="eye" color="success"/><text size="sm">视觉用户可见</text></row>
      <row><icon name="volume-x" color="secondary"/><text size="sm">辅助技术不可见</text></row>
      <caption>适用于装饰性图标等内容。</caption>
    </box>
  </grid-item>
  <grid-item>
    <box border radius="lg" padding={3} gap={2}>
      **visually-hidden**
      <divider/>
      <row><icon name="eye-off" color="secondary"/><text size="sm">视觉用户不可见</text></row>
      <row><icon name="volume-2" color="success"/><text size="sm">辅助技术可访问</text></row>

一个常见的 CSS 实现如下：

```css
.visually-hidden {
  position: absolute !important;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip: rect(0, 0, 0, 0);
  clip-path: inset(50%);
  white-space: nowrap;
  border: 0;
}
```

注意，`visually-hidden` 并不是浏览器原生提供的类，而是开发人员定义的一种 CSS 工具类。

例如购物车按钮：

```html
<button type="button">
  <svg aria-hidden="true">
    <!-- Cart icon -->
  </svg>

  <span class="visually-hidden">
    Open shopping cart
  </span>
</button>
```

最终视觉用户只会看到购物车图标，但按钮仍然具有 `Open shopping cart` 这个可访问名称。

如果把 `visually-hidden` 替换成 `display: none`，普通情况下这段文字就不会参与按钮的名称计算。

不过，这里存在一个需要了解的例外。

### 5.7 隐藏元素也可以参与名称计算吗？

可以，在特定条件下。

```html
<button aria-labelledby="cart-label">
  <svg aria-hidden="true"></svg>
</button>

<span id="cart-label" hidden>
  Open shopping cart
</span>
```

虽然 `cart-label` 本身不会作为普通内容暴露给辅助技术，但由于它被 `aria-labelledby` 直接引用，其文字仍然可以参与按钮的 Accessible Name 计算。

`aria-describedby` 也存在类似机制。<Cite ref="turn233622search25"/>

所以要区分两个概念：

**不作为独立节点暴露在无障碍树中，不代表其文本在所有情况下都无法被用于无障碍名称或描述计算。**

## 6. Accessibility Tree 是动态变化的

Accessibility Tree 并不是浏览器加载页面时构建一次之后就不再改变。

当 JavaScript 修改 DOM、CSS 或 ARIA 状态时，浏览器会相应更新无障碍信息，并在适当情况下通过平台接口通知辅助技术。

### 6.1 修改元素状态

例如一个收藏按钮：

```html
<button id="favorite" aria-pressed="false">
  Favorite
</button>
```

```javascript
const button = document.querySelector('#favorite');

button.addEventListener('click', () => {
  const pressed =
    button.getAttribute('aria-pressed') === 'true';

  button.setAttribute('aria-pressed', String(!pressed));
});
```

### 6.2 添加或删除 DOM 节点

```javascript
const button = document.createElement('button');

button.textContent = 'Checkout';

document.body.appendChild(button);
```

当按钮插入 DOM 后，浏览器也会将对应的无障碍信息加入相关结构中。

当执行：

```javascript
button.remove();
```

对应的无障碍对象也会被移除。

### 6.3 Accessibility Tree 更新不等于屏幕阅读器自动播报

这两个概念一定要区分。

假设有：

```html
<span id="price">$29.99</span>
```

切换商品变体之后：

```javascript
document.querySelector('#price').textContent = '$39.99';
```

无障碍树中的文字信息会相应发生变化，但屏幕阅读器不一定会立即主动播报新的价格。

## 7. 能否通过 JavaScript 直接获取 Accessibility Tree？

相信作为前端开发人员，你可能会想到这样的问题。

我们可以通过以下方式获取 DOM Tree：

```javascript
document.documentElement
```

也可以获取元素计算后的 CSS：

```javascript
window.getComputedStyle(element)
```

那么有没有类似这样的 API？

```javascript
// 假设的 API，实际不存在
document.accessibilityTree
```

目前，普通网页 JavaScript 没有一个通用、跨浏览器的标准 API，可以直接获取完整的浏览器 Accessibility Tree。

但是可以通过浏览器调试协议来获取相关信息。

### 7.1 Chrome DevTools Protocol

Chrome DevTools Protocol（CDP）提供了 Accessibility Domain。

部分常用方法包括：

| CDP 方法 | 作用 |
|---|---|
| `Accessibility.enable` | 启用 Accessibility Domain |
| `Accessibility.getFullAXTree` | 获取指定文档的无障碍树 |
| `Accessibility.getPartialAXTree` | 获取指定节点相关的无障碍树 |
| `Accessibility.queryAXTree` | 按名称、角色等条件查询 |
| `Accessibility.getChildAXNodes` | 获取无障碍节点的子节点 |

例如使用 Puppeteer：

```javascript
import puppeteer from 'puppeteer';

const browser = await puppeteer.launch({
  headless: true
});

const page = await browser.newPage();

await page.goto('https://example.com');

const client = await page.createCDPSession();

await client.send('Accessibility.enable');

const { nodes } = await client.send(
  'Accessibility.getFullAXTree'
);

console.log(nodes);

await browser.close();
```

返回的数据大致类似：

```javascript
{
  nodeId: "15",
  ignored: false,
  role: {
    type: "role",
    value: "button"
  },
  name: {
    type: "computedString",
    value: "Add to cart"
  },
  properties: [
    {
      name: "focusable",
      value: {
        type: "booleanOrUndefined",
        value: true
      }
    }
  ],
  childIds: []
}
```

这也是开发无障碍检测工具、浏览器插件、自动化测试工具时可以考虑的技术方向。

相关文档：[Chrome DevTools Protocol — Accessibility Domain](https://chromedevtools.github.io/devtools-protocol/tot/Accessibility/)。

需要注意，CDP 返回的是 Chromium 的无障碍信息，不代表所有浏览器和屏幕阅读器最终暴露或播报的内容完全相同。

### 9.2 使用 inert 改善交互隔离

可以在 Drawer 关闭时使其处于 inert 状态。

```html
<main id="main-content">
  <!-- 页面内容 -->
</main>

<aside id="cart-drawer" inert>
  <!-- 购物车内容 -->
</aside>
```

打开 Drawer 时：

```javascript
function openCart() {
  drawer.inert = false;
  drawer.classList.add('is-open');

  mainContent.inert = true;

  closeButton.focus();
}
```

关闭 Drawer 时：

```javascript
function closeCart() {
  mainContent.inert = false;

  triggerButton.focus();

  drawer.inert = true;
  drawer.classList.remove('is-open');
}
```

这里只展示 inert 和焦点恢复的基本原理。真实项目还需要处理 Header、Footer 等其他背景区域、Esc 关闭、弹窗角色及名称等问题。

如果使用原生 `<dialog>` 配合 `showModal()`，浏览器还能够提供原生的模态交互隔离能力，这会是我们第 15 课的重要内容。

本节课最重要的不是记住所有属性，而是建立一种新的前端开发思维：

**开发网页时，你实际上同时在构建视觉界面和无障碍语义界面。**

CSS 负责控制用户看到什么，HTML 和 ARIA 等机制共同决定辅助技术能够理解什么，JavaScript 则负责使视觉状态、交互状态和无障碍状态保持一致。
