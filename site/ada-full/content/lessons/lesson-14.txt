上一课，我们深入学习了 Accessible Name 和 Accessible Description 的计算机制。

但是，正确的名称、描述和角色，只能保证用户在访问元素时获得正确的信息。

如果用户没有访问某个元素，而这个元素的内容突然发生变化，屏幕阅读器应该如何知道？

例如，在 Shopify 网站中：

| 业务场景 | 需要通知用户的信息 |
|---|---|
| AJAX 加购 | 商品已成功加入购物车 |
| 商品变体切换 | 最新价格、库存状态 |
| Collection 筛选 | 当前有多少个匹配商品 |
| Predictive Search | 找到多少条搜索建议 |
| 购物车数量修改 | 数量及金额更新结果 |
| 删除购物车商品 | 商品已经移除 |
| 优惠码验证 | 优惠码是否有效 |
| Newsletter 提交 | 订阅成功或失败 |
| 异步请求 | 加载中、加载完成或请求失败 |

这些场景都涉及本节课的核心技术：**Live Region（实时区域）**。

这也是第三阶段的最后一课。学完之后，我们将正式进入复杂 UI 组件的无障碍实战。

## 1. 为什么需要 Live Region？

假设有一个普通的 Shopify 商品加购按钮：

```html
<button id="add-to-cart" type="button">
  Add to cart
</button>

<p id="message"></p>
```

AJAX 请求成功后，JavaScript 更新页面：

```javascript
document.querySelector('#message').textContent =
  'Product added to your cart.';
```

对于视觉用户，可以直接看到页面上出现了成功提示。

但是，对于屏幕阅读器用户，即使 DOM 和 Accessibility Tree 已经发生变化，也不意味着屏幕阅读器会立即主动播报这段文字。

<box border radius="lg" padding={3} gap={3}>
  <grid columns={2} gap={3}>
    <grid-item>
      <box border radius="md" padding={3} gap={2}>
        **普通 DOM 更新**
        <box background="#333333" theme="dark" padding={2} radius="sm" align="center">
          <text color="#FFFFFF" size="sm">Add to cart</text>
        </box>
        <text color="success" size="sm">Product added to your cart.</text>
        <divider/>
        <row align="center">
          <icon name="volume-x"/>
          <caption>不保证主动播报</caption>
        </row>
      </box>
    </grid-item>
    <grid-item>
      <box border radius="md" padding={3} gap={2}>
        **Live Region 更新**
        <box background="#333333" theme="dark" padding={2} radius="sm" align="center">
          <text color="#FFFFFF" size="sm">Add to cart</text>
        </box>
        <text color="success" size="sm">Product added to your cart.</text>
        <divider/>
        <row align="center">
          <icon name="volume-2"/>
          <caption>可以主动通知用户</caption>
        </row>
      </box>
    </grid-item>
  </grid>
  <caption>两种实现的视觉效果相同，但动态信息通知机制不同。</caption>
</box>

只需要修改 HTML：

```html
<p id="message" aria-live="polite"></p>
```

JavaScript 保持不变：

```javascript
document.querySelector('#message').textContent =
  'Product added to your cart.';
```

浏览器就能够将这个区域的内容变化作为适当的无障碍通知传递给辅助技术。

而且，整个过程中不需要调用：

```javascript
message.focus();
```

**Live Region 的核心价值，是在不改变用户当前焦点的情况下，让辅助技术感知重要的动态内容变化。**

这里特别需要注意：

Live Region 并不是 JavaScript 的语音合成 API。

它与以下代码完全不同：

```javascript
speechSynthesis.speak(
  new SpeechSynthesisUtterance('Added to cart')
);
```

| 对比项 | Live Region | Speech Synthesis |
|---|---|---|
| 使用者 | 辅助技术用户 | 一般网站用户也可以听到 |
| 播报控制 | 辅助技术 | 网站 JavaScript |
| 遵循屏幕阅读器设置 | 是 | 不一定 |
| 与无障碍树关联 | 是 | 否 |
| 适合无障碍状态通知 | 是 | 不应作为替代方案 |

开发者负责提供正确的动态语义，而具体播报行为由屏幕阅读器控制。

不存在一个通用的 JavaScript API，可以保证某句话立即被所有屏幕阅读器完整播报。

## 3. aria-live 的三种取值

`aria-live` 用于告诉辅助技术，应该以什么优先级处理这个区域的动态变化。

```html
<div aria-live="off"></div>

<div aria-live="polite"></div>

<div aria-live="assertive"></div>
```

| 取值 | 含义 | 适用场景 |
|---|---|---|
| `off` | 通常不主动通知，焦点位于区域内时仍可能通知 | 普通动态内容 |
| `polite` | 在适当时机通知，通常不打断当前播报 | 加购成功、搜索结果、价格更新 |
| `assertive` | 高优先级通知，可能打断当前播报 | 重要且需要及时感知的错误 |

### 3.2 aria-live="off" 不等于 aria-hidden="true"

```html
<div aria-live="off">
  Current price: $29.99
</div>
```

屏幕阅读器仍然可以正常访问其中的内容，只是通常不会在用户没有访问该区域时主动播报变化。

而：

```html
<div aria-hidden="true">
  Current price: $29.99
</div>
```

会将该区域从无障碍访问中排除。

两者分别控制通知机制和无障碍暴露机制，不能互相替代。

### 3.3 如何选择消息优先级？

在电商网站中，绝大多数动态业务消息使用 polite 即可。

| 消息 | 建议 |
|---|---|
| Product added to your cart. | polite |
| 24 products found. | polite |
| Price updated to $39.99. | polite |
| Loading products. | polite，必要时才播报 |
| 优惠码无效 | 根据错误严重程度选择 |
| 订单提交失败且需要处理 | 可考虑 assertive |
| 每秒变化的促销倒计时 | 通常 off |

不要因为希望某条消息一定被读出来，就将所有 Live Region 都设置为 assertive。

这可能造成更糟糕的阅读体验。

## 4. role="status"、role="alert" 与 role="log"

除了直接设置 aria-live，ARIA 还提供了一些自带 Live Region 语义的 Role。

| Role | 隐式 aria-live | 隐式 aria-atomic |
|---|---|---|
| `status` | polite | true |
| `alert` | assertive | true |
| `log` | polite | false |
| `timer` | off | false（默认） |
| `marquee` | off | false（默认） |

这些隐式属性来自 WAI-ARIA 的角色定义。<Cite refs={["turn952928search5","turn952928search19"]}/>

### 4.1 role="status"

适合普通业务状态反馈。

```html
<p id="cart-status" role="status"></p>
```

```javascript
cartStatus.textContent =
  'Cotton T-shirt added to your cart.';
```

它隐含：

```html
aria-live="polite"
aria-atomic="true"
```

所以，对于普通业务状态消息，不一定需要再重复添加这些属性。考虑到不同辅助技术的支持差异，有时也可以显式声明 `aria-atomic="true"`。

### 4.2 role="alert"

适合重要的动态错误消息。

```html
<p id="cart-error" role="alert"></p>
```

```javascript
cartError.textContent =
  'Unable to update your cart. Please try again.';
```

注意，alert 本身不是弹窗。

| Role | 是否为弹窗 | 是否需要用户响应 |
|---|---|---|
| alert | 否 | 不一定 |
| alertdialog | 是 | 通常需要 |
| status | 否 | 不需要 |

如果用户必须确认删除操作，就应该考虑 alertdialog，而不是简单使用 alert。

另外，给 `role="alert"` 再添加 `aria-live="assertive"` 通常没有必要，在某些 VoiceOver 环境中还可能造成重复播报。

### 4.3 role="log"

适合按顺序追加的消息，例如客服聊天、订单处理日志。

```html
<div role="log" aria-label="Customer support messages">

  <p>Support: How can I help you?</p>

</div>
```

接收到新消息后：

```javascript
const message = document.createElement('p');

message.textContent =
  'Support: Your order has been shipped.';

log.appendChild(message);
```

辅助技术通常只需要通知新追加的消息，而不需要重新播报所有历史记录。

### 4.4 role="timer"

例如限时促销：

```html
<div role="timer" aria-label="Offer ends in">
  00:29:59
</div>
```

timer 默认不会持续主动播报每一秒的变化。

如果确实存在需要通知的关键时间节点，可以通过独立的 status 区域提供适度提醒。

但减少播报频率并不代表限时购物流程已经满足 WCAG 的时间限制要求，相关时间控制仍需单独评估。

## 5. aria-atomic：播报整个区域还是变化的部分？

这是 Live Region 中非常重要的属性。

假设我们有一个购物车商品数量：

```html
<p aria-live="polite">
  Cart contains
  <span id="count">2</span>
  items.
</p>
```

JavaScript 更新：

```javascript
count.textContent = '3';
```

辅助技术可能只播报：

```text
3
```

但是用户听到一个孤立的数字 3，并不知道它代表什么。

可以使用：

```html
<p
  aria-live="polite"
  aria-atomic="true"
>
  Cart contains
  <span id="count">2</span>
  items.
</p>
```

此时，辅助技术可以获得完整的上下文：

```text
Cart contains 3 items.
```

### 5.2 atomic 并不是越大越好

例如：

```html
<main
  aria-live="polite"
  aria-atomic="true"
>
  <!-- Entire storefront -->
</main>
```

当其中一个价格发生变化时，可能产生非常冗长的通知。

正确的做法是控制 Live Region 的范围，使区域本身只包含需要播报的业务信息。

对于购物车状态、筛选数量等简短消息，`aria-atomic="true"` 通常是不错的选择。<Cite ref="turn952928search2"/>

## 6. aria-relevant：哪些变化值得通知？

Live Region 内部的 DOM 变化主要可以分为增加、删除和文字变化。

| 取值 | 关注的变化 |
|---|---|
| `additions` | 新增节点 |
| `removals` | 移除节点 |
| `text` | 文本及文本替代变化 |
| `all` | 以上所有类型 |
| `additions text` | 默认值 |

例如一个动态列表：

```html
<div
  aria-live="polite"
  aria-relevant="additions text"
>
  <p>Cotton T-shirt</p>
  <p>Linen shirt</p>
</div>
```

默认情况下，增加内容和文字变化属于相关通知，而删除节点本身通常不在默认通知范围内。<Cite ref="turn952928search10"/>

这也解释了购物车删除商品的一个常见问题：

```javascript
cartItem.remove();
```

不能指望屏幕阅读器因此自动播报：

```text
Cotton T-shirt removed from your cart.
```

虽然可以使用 `aria-relevant="removals"`，但辅助技术对删除变化的支持和表达方式存在差异。

更可靠的业务设计，是在删除成功后主动生成一条具有完整含义的消息。

```javascript
cartItem.remove();

cartStatus.textContent =
  'Cotton T-shirt removed from your cart.';
```

## 7. aria-busy：控制更新的完整性

假设用户切换商品变体后，页面需要更新：

- 商品价格。
- 库存状态。
- 商品 SKU。
- 加购按钮状态。
- 商品图片。

如果每个变化都独立产生通知，用户可能会连续听到多条零散消息。

可以在区域更新期间使用：

```html
<div
  id="variant-status"
  role="status"
  aria-busy="false"
></div>
```

```javascript
variantStatus.setAttribute('aria-busy', 'true');

variantStatus.textContent = 'Price: $39.99.';

variantStatus.append(' In stock.');

variantStatus.setAttribute('aria-busy', 'false');
```

`aria-busy="true"` 提示辅助技术当前更新尚未完成，可以等待该区域恢复非忙碌状态，再处理变化。<Cite ref="turn952928search28"/>

不过，实际开发中，如果可以提前组合完整的消息，下面的代码往往更加简单：

```javascript
variantStatus.textContent =
  'Price: $39.99. In stock.';
```

## 8. WCAG 4.1.3：Status Messages 状态消息

Live Region 最直接对应的 WCAG 准则，就是 **4.1.3 Status Messages（Level AA）**。

它要求适用的状态消息能够通过角色或属性被辅助技术识别，从而让用户不必移动焦点就能感知这些消息。<Cite ref="turn952928search7"/>

但是，并不是所有动态内容都属于 Status Message。

### 8.1 哪些内容属于状态消息？

| 动态变化 | 是否属于典型状态消息 |
|---|---|
| 加购成功提示 | 是 |
| 搜索结果数量 | 是 |
| 请求加载进度 | 是 |
| 表单提交成功 | 是 |
| 请求失败提示 | 是 |
| 搜索结果商品列表本身 | 通常不是 |
| 展开 Accordion 后的正文 | 通常不是 |
| 打开 Modal 后的内部内容 | 通常不是 |
| 点击 Tab 后展示的面板 | 通常不是 |

例如用户筛选 Collection 商品后：

```html
<p role="status">
  24 products found.
</p>

<ul class="product-grid">
  <!-- 24 products -->
</ul>
```

应该将商品数量作为状态消息，而不是将整个商品列表设置为 Live Region。

这样屏幕阅读器用户可以先了解筛选结果，再自行决定是否访问商品列表。

### 8.2 Live Region 与 Focus Management 的区别

这是第 11 课和本节课之间最重要的联系。

| 业务变化 | 焦点管理 | Live Region |
|---|---|---|
| 打开 Cart Drawer | 移入 Drawer | 视需要补充加购结果 |
| AJAX 加购但不打开 Drawer | 保留焦点 | 通知加购成功 |
| 展开 Accordion | 保留焦点 | 通常不需要 |
| Collection 筛选 | 保留筛选控件焦点 | 通知商品数量 |
| 删除当前聚焦的商品 | 恢复合理的焦点 | 通知删除结果 |
| 表单验证失败 | 可聚焦错误摘要 | 根据设计决定是否补充 |
| 变体价格更新 | 保留变体控件焦点 | 通知新价格 |

可以将这两个机制理解为：

<grid columns={2} gap={3}>
  <grid-item>
    <box border radius="lg" padding={3} gap={2}>
      <icon name="focus" size="2xl"/>
      **Focus Management**

## 9. 为什么 Live Region 设置正确，却没有播报？

这是实际项目中非常常见的兼容性问题。

很多开发者第一次使用 Live Region，会编写如下代码：

```javascript
const message = document.createElement('div');

message.setAttribute('role', 'status');

message.textContent =
  'Product added to your cart.';

document.body.appendChild(message);
```

从 HTML 语义来看似乎没有问题，但是部分屏幕阅读器可能不会播报。

### 9.1 Live Region 应该提前存在

更可靠的方式是在初始 HTML 中建立一个空的 Live Region：

```html
<div
  id="announcer"
  class="visually-hidden"
  role="status"
></div>
```

等到业务事件发生后，再更新其内容：

```javascript
document.querySelector('#announcer').textContent =
  'Product added to your cart.';
```

<box border radius="lg" padding={3} gap={3}>
  <grid columns={2}>
    <grid-item>
      **不够可靠的方式**
      {#each ["创建 DOM 元素","设置 role=status","立即添加消息","插入页面"] as item,i}
        <box border radius="sm" padding={2} align="center"><text size="xs">{item}</text></box>
        {#if i<3}<box align="center"><icon name="arrow-down" size="sm" color="secondary"/></box>{/if}
      {/each}
      <text size="sm" color="danger">可能被视为新区域的初始内容</text>
    </grid-item>
    <grid-item>
      **推荐的方式**
      {#each ["页面初始化","建立空 Live Region","用户触发业务操作","更新区域内的消息"] as item,i}
        <box border radius="sm" padding={2} align="center"><text size="xs">{item}</text></box>
        {#if i<3}<box align="center"><icon name="arrow-down" size="sm" color="secondary"/></box>{/if}
      {/each}
      <text size="sm" color="success">已有区域发生内容变化</text>
    </grid-item>
  </grid>
</box>

普通 Live Region 通常需要先被浏览器和辅助技术识别，再通过后续内容变化触发通知。

`role="alert"` 存在特殊情况：许多浏览器和辅助技术会主动播报新插入的 alert 初始内容，但仍不建议将这种行为当作所有 Live Region 的通用规则。<Cite refs={["turn952928search9","turn952928search6"]}/>

### 9.2 Live Region 不能真正隐藏

错误写法：

```html
<div
  id="announcer"
  role="status"
  style="display: none"
></div>
```

同样需要注意：

```html
<div role="status" hidden></div>

<div role="status" aria-hidden="true"></div>
```

这些隐藏方式会影响区域在无障碍树中的暴露。

即使 JavaScript 更新了内部文字，也可能无法正常通知辅助技术。

如果希望消息只供辅助技术用户访问，应该使用第 9 课学习的 visually-hidden。

```css
.visually-hidden {
  position: absolute !important;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip: rect(0, 0, 0, 0);
  clip-path: inset(50%);
  white-space: nowrap;
  border: 0;
}
```

如果页面已经有适合的可见状态提示，优先直接将该提示设置为 Live Region，而不是额外复制一份隐藏文字。

### 9.3 Section Rendering 替换了整个 Live Region

假设有以下结构：

```html
<div id="cart-section">

  <div id="cart-items">
    <!-- Cart items -->
  </div>

  <p id="cart-status" role="status"></p>

</div>
```

AJAX 更新时：

```javascript
cartSection.innerHTML = responseHTML;
```

原来的 `cart-status` 节点也被删除了。

即使新的 HTML 中仍然存在同样 ID 的 Live Region，它也是一个全新的 DOM 节点，可能需要重新建立无障碍通知关系。

推荐调整结构：

```html
<div id="cart-section">

  <div id="cart-items">
    <!-- Only this area is replaced -->
  </div>

</div>

<p
  id="cart-status"
  role="status"
  class="visually-hidden"
></p>
```

这样只更新 cart-items，Live Region 本身始终存在。

这对于 Shopify Section Rendering 尤其重要。

### 9.4 模态弹窗中的特殊情况

假设页面使用原生 dialog：

```html
<body>

  <div id="global-announcer" role="status"></div>

  <dialog id="cart-dialog">
    ...
  </dialog>

</body>
```

当调用：

```javascript
cartDialog.showModal();
```

弹窗之外的背景内容会进入原生模态隔离状态。

此时，位于弹窗外部的 global-announcer 可能无法正常承担弹窗内部业务的通知工作。

比较合理的设计是：

```html
<dialog id="cart-dialog">

  <!-- Cart content -->

  <p role="status" data-cart-status></p>

  <p role="alert" data-cart-error></p>

</dialog>
```

因此，全局 Announcer 并不意味着所有场景只需要一个 Live Region。模态弹窗内部也可以拥有自己的消息区域。

## 10. 重复消息与连续消息

### 10.1 相同的消息为什么可能只播报一次？

假设用户连续两次加购同一个商品。

第一次：

```javascript
status.textContent =
  'Product added to your cart.';
```

第二次：

```javascript
status.textContent =
  'Product added to your cart.';
```

因为最终文字相同，浏览器或辅助技术可能认为没有值得通知的新变化。

一种更有业务价值的方式是加入真实变化的信息：

```javascript
status.textContent =
  'Cotton T-shirt added. 2 items in your cart.';
```

再次加购：

```javascript
status.textContent =
  'Cotton T-shirt added. 3 items in your cart.';
```

这样不仅能够区分两次操作，还能帮助用户理解购物车最新状态。

### 10.2 清空后重新写入

如果确实需要重复通知相同文字，常见的兼容性处理方式是先清空，再延迟写入。

```javascript
function announce(message) {
  status.textContent = '';

  setTimeout(() => {
    status.textContent = message;
  }, 100);
}
```

但是需要注意：

- 100ms 不是 W3C 规定的标准延迟。
- 同一个 JavaScript 任务中先清空再立即写入，仍可能被浏览器合并处理。
- setTimeout 或 requestAnimationFrame 都不能保证屏幕阅读器一定播报。
- 多次调用时需要处理旧定时器，否则可能播报已经过期的消息。

这是兼容性策略，而不是可靠的语音控制协议。

### 10.3 连续更新造成消息堆积

假设用户快速修改购物车数量：

<box border radius="lg" padding={3} gap={3}>
  **逐次通知**
  {#each ["Quantity updated to 2.","Quantity updated to 3.","Quantity updated to 4.","Quantity updated to 5."] as m,i}
    <row align="center">
      <caption>{i*100}ms</caption>
      <box flex={1} background="surface-tertiary" radius="sm" padding={2}><text size="sm">{m}</text></box>
    </row>
  {/each}
  <divider/>
  **合并最新状态**
  <row align="center">
    <icon name="volume-2"/>
    <box flex={1} border radius="md" padding={3}>
      <text size="sm">Quantity updated to 5. Cart total: $149.95.</text>
    </box>
  </row>
  <caption>对于快速连续的同类状态更新，最终有效结果通常比所有中间结果更有价值。</caption>
</box>

这里可以采用前端开发中非常熟悉的 Debounce 思想。

```javascript
let announceTimer;

function announceQuantity(quantity) {
  clearTimeout(announceTimer);

  announceTimer = setTimeout(() => {
    status.textContent =
      `Quantity updated to ${quantity}.`;
  }, 300);
}
```

但是，合并消息只适用于可被最新状态替代的业务信息。

例如搜索结果、滑块数值、快速变化的数量等。

对于多个独立商品的加购成功、不同的请求错误等消息，不能简单地丢弃之前的结果。可以根据实际业务进行汇总。

### 11.3 JavaScript 工具类

创建 `assets/accessibility-announcer.js`：

```javascript
class AccessibilityAnnouncer {
  constructor(container) {
    this.regions = {
      polite: container.querySelector(
        '[data-announcer="polite"]'
      ),

      assertive: container.querySelector(
        '[data-announcer="assertive"]'
      )
    };

    this.timers = {
      polite: null,
      assertive: null
    };
  }

  announce(message, {
    priority = 'polite',
    delay = 100
  } = {}) {
    const region = this.regions[priority];

    if (!region || !message?.trim()) {
      return;
    }

    clearTimeout(this.timers[priority]);

    region.textContent = '';

    this.timers[priority] = setTimeout(() => {
      if (region.isConnected) {
        region.textContent = message;
      }

      this.timers[priority] = null;
    }, delay);
  }

  success(message) {
    this.announce(message);
  }

  error(message) {
    this.announce(message, {
      priority: 'assertive'
    });
  }

  clear(priority) {
    const region = this.regions[priority];

    if (!region) return;

    clearTimeout(this.timers[priority]);

    this.timers[priority] = null;

    region.textContent = '';
  }

  destroy() {
    this.clear('polite');
    this.clear('assertive');
  }
}
```

初始化：

```javascript
const announcer = new AccessibilityAnnouncer(
  document.querySelector('#a11y-announcer')
);
```

业务组件中使用：

```javascript
announcer.success(
  'Product added to your cart.'
);
```

```javascript
announcer.error(
  'Unable to update your cart.'
);
```

### 11.5 这个工具类的局限

这是一种 Latest Message Wins（最新消息优先）的教学实现。

同一优先级的新消息会取消尚未写入 DOM 的旧消息。

所以，它适合价格变化、数量变化、筛选结果等可以被最新状态替代的信息，但不适合未经处理地传递多个不可丢失的独立业务事件。

生产环境可以根据不同业务增加消息合并、事件去重、组件作用域管理，以及本地化能力。

### 12.2 JavaScript 实现

```javascript
const form = document.querySelector(
  '#AccessibleProductForm'
);

const button = form.querySelector(
  'button[type="submit"]'
);

const status = form.querySelector(
  '[data-product-status]'
);

const error = form.querySelector(
  '[data-product-error]'
);

let pending = false;

form.addEventListener('submit', async event => {
  event.preventDefault();

  if (pending) return;

  pending = true;

  button.setAttribute('aria-disabled', 'true');

  status.textContent = '';
  error.textContent = '';

  // 防止快速请求产生不必要的加载播报
  const loadingTimer = setTimeout(() => {
    status.textContent =
      'Adding product to your cart.';
  }, 700);

  try {
    const response = await fetch(
      window.Shopify.routes.root + 'cart/add.js',
      {
        method: 'POST',
        headers: {
          Accept: 'application/json'
        },
        body: new FormData(form)
      }
    );

    const result = await response.json();

    if (!response.ok || result.status >= 400) {
      throw new Error(
        result.description ||
        'Unable to add this product.'
      );
    }

    clearTimeout(loadingTimer);

    status.textContent =
      `${result.product_title} added to your cart.`;

  } catch (err) {
    clearTimeout(loadingTimer);

    status.textContent = '';

    error.textContent =
      'Unable to confirm the cart update. ' +
      'Please check your cart.';

    console.error(err);

  } finally {
    clearTimeout(loadingTimer);

    pending = false;

    button.removeAttribute('aria-disabled');
  }
});
```

### 12.3 为什么这里使用 aria-disabled？

如果直接设置：

```javascript
button.disabled = true;
```

获得焦点的按钮在一些浏览器中可能会失去焦点。

使用：

```javascript
button.setAttribute('aria-disabled', 'true');
```

可以在保留焦点能力的同时，向辅助技术表达控件暂时不可用。

但正如第 12 课所学，aria-disabled 不会自动禁止提交，因此还必须使用：

```javascript
if (pending) return;
```

防止重复请求。

另外，上面的代码仅演示单商品 AJAX 加购与消息通知。实际项目仍需结合库存状态、购物车 UI 刷新、多语言翻译和服务端错误分类进行完善。如果网络响应丢失，也不能直接认定加购一定失败，应该核实购物车实际状态。

### 13.1 方案一：独立 Live Region

```html
<div id="product-price" role="status">
  $29.99
</div>

<p id="product-inventory" role="status">
  In stock
</p>
```

切换变体时：

```javascript
price.textContent = variant.formattedPrice;

inventory.textContent = variant.available
  ? 'In stock'
  : 'Sold out';
```

这种方式的优点是简单，并且可见 UI 自身就是状态消息区域。

缺点是多个区域同时变化时，播报顺序和完整性不容易预测。

### 13.2 方案二：统一 Announcer

```javascript
function renderVariant(variant) {
  price.textContent = variant.formattedPrice;

  inventory.textContent = variant.available
    ? 'In stock'
    : 'Sold out';

  addButton.disabled = !variant.available;

  announcer.announce(
    `Price: ${variant.formattedPrice}. ` +
    `${variant.available ? 'In stock.' : 'Sold out.'}`
  );
}
```

这里假设 `formattedPrice` 是业务层已经根据当前币种格式化好的价格字符串，而不是 Shopify 原生 Variant 对象必然具有的属性。

采用这个方案时，就不应该再让价格、库存和 Announcer 同时播报相同的信息。

### 13.3 是否应该播报变体名称？

例如用户选择 L：

```text
Large, radio button, checked.
```

原生 radio 本身已经能够表达当前选择。

此时 Live Region 可以专注于补充选择所引发的变化：

```text
Price: $39.99. In stock.
```

没有必要把 radio 的名称、角色、选中状态全部重复一遍。

### 14.2 处理 AJAX 请求竞争

假设用户连续选择三个筛选条件，产生三个请求。

<box border radius="lg" padding={3} gap={2}>
  <svg viewBox="0 0 340 185" width="100%">
    {#each [{n:"Request A",x:65,w:251,y:20,c:"#888888",v:"旧结果：32"},{n:"Request B",x:115,w:145,y:73,c:"#888888",v:"旧结果：16"},{n:"Request C",x:160,w:57,y:126,c:"#39866B",v:"新结果：8"}] as r}

      <rect x={r.x} y={r.y} width={r.w} height="27" rx="4" fill={r.c} fillOpacity=".18" stroke={r.c} strokeOpacity=".7"/>
      <text x={r.x+r.w/2} y={r.y+17} fontSize="10" textAnchor="middle" fill="currentColor">请求中</text>
      <text x={r.x+r.w} y={r.y+41} fontSize="10" textAnchor="end" fill={r.c}>{r.v}</text>
    {/each}
  </svg>
  <caption>最新发出的 C 请求可能最先返回。如果随后继续使用 A、B 的结果，就会覆盖正确页面并播报过时的数量。</caption>
</box>

因此，Live Region 不仅需要正确的 ARIA 属性，还需要正确的异步请求管理。

```javascript
let requestVersion = 0;
let controller;

async function updateCollection(url) {
  const version = ++requestVersion;

  controller?.abort();

  controller = new AbortController();

  const grid = document.querySelector(
    '#ProductGridContainer'
  );

  const count = document.querySelector(
    '#ProductCount'
  );

  grid.setAttribute('aria-busy', 'true');

  try {
    const response = await fetch(url, {
      signal: controller.signal
    });

    if (!response.ok) {
      throw new Error('Request failed');
    }

    const html = new DOMParser().parseFromString(
      await response.text(),
      'text/html'
    );

    if (version !== requestVersion) return;

    const newGrid = html.querySelector(
      '#ProductGridContainer'
    );

    const newCount = html.querySelector(
      '#ProductCount'
    );

    if (!newGrid || !newCount) {
      throw new Error('Invalid section response');
    }

    grid.innerHTML = newGrid.innerHTML;

    // 保留原来的 Live Region 节点
    count.textContent = newCount.textContent.trim();

  } catch (error) {
    if (
      error.name !== 'AbortError' &&
      version === requestVersion
    ) {
      announcer.error(
        'Unable to update products.'
      );
    }

  } finally {
    if (version === requestVersion) {
      grid.setAttribute('aria-busy', 'false');
    }
  }
}
```

这个例子假设传入的 URL 返回包含对应商品区域和数量区域的 HTML。

它展示了三个重要的工程机制：取消旧请求、校验最新请求版本、保留 Live Region 节点。

实际开发中还需要接入上一课的 Focus Preservation，尤其是在筛选操作同时替换筛选控件 DOM 的情况下。

Predictive Search 同时涉及我们第三阶段学习的多种技术。

| 技术 | 职责 |

### 15.1 不要重复通知活动项

用户按下 ArrowDown 时，可以执行：

```javascript
input.setAttribute(
  'aria-activedescendant',
  option.id
);
```

不需要每次再执行：

```javascript
announcer.announce(option.textContent);
```

因为 aria-activedescendant 本身就能够向辅助技术表达活动项变化。

重复通过 Live Region 通知，可能产生两次相同播报。

### 15.2 不要将整个搜索列表设置为 Live Region

错误思路：

```html
<ul role="listbox" aria-live="polite">
  <!-- Search results -->
</ul>
```

每次输入都可能产生大量无关通知。

推荐：

```html
<p
  id="search-status"
  role="status"
  class="visually-hidden"
></p>

<ul id="search-results" role="listbox">
  <!-- Search results -->
</ul>
```

请求完成后：

```javascript
searchStatus.textContent =
  `${results.length} results found.`;
```

活动项的导航则继续通过第 10 课学习的虚拟焦点机制处理。

### 16.2 Cart Drawer

文件：`snippets/cart-drawer.liquid`

Dawn 在购物车抽屉中设置了多种通知区域。

| 元素 ID | Role | 职责 |
|---|---|---|
| `CartDrawer-LiveRegionText` | status | 购物车状态区域 |
| `CartDrawer-LineItemStatus` | status | 商品行加载状态 |
| `CartDrawer-LineItemError-*` | alert | 商品行相关错误 |
| `CartDrawer-CartErrors` | alert | 购物车整体错误 |

其中加载状态区域包含本地化 Loading 文案，初始时设置 `aria-hidden="true"`。<Cite ref="turn652062view2"/>

### 16.3 cart.js 中的 updateLiveRegions()

Dawn 的 `assets/cart.js` 提供了以下方法：

```javascript
updateLiveRegions(line, message)
```

其主要处理逻辑是更新对应商品行的错误文字、隐藏加载状态区域、临时暴露购物车状态区域，并在约一秒后再次隐藏它。<Cite ref="turn745528view0"/>

值得注意的是，这里的实现与我们前面推荐的「长期存在且始终暴露的空 Live Region」有所不同。

Dawn 使用了切换 aria-hidden 的兼容性处理方式。

但是，这种方式并不能保证所有浏览器和屏幕阅读器都会正常播报。特别是快速连续更新时，旧定时器可能影响新消息。

因此，不应该直接把 Dawn 的一秒延迟视为规范要求，也不能仅凭源码存在 role=status，就认为所有购物车变化一定能够正确通知用户。

### 16.4 Predictive Search

文件：`assets/predictive-search.js`

Dawn 提供了以下几个相关方法：

| 方法 | 职责 |
|---|---|
| `setLiveRegionLoadingState()` | 设置搜索加载通知 |
| `setLiveRegionText(statusText)` | 更新状态区域文字 |
| `setLiveRegionResults()` | 通知搜索结果信息 |
| `renderSearchResults()` | 渲染搜索建议并触发结果通知 |

它从服务端返回的搜索结果 HTML 中获取 `data-predictive-search-live-region-count-value` 对应文字，并将其写入状态区域。

同时，状态区域也采用临时切换 aria-hidden 的策略。<Cite ref="turn652062view1"/>

这说明，在 Shopify Theme 中，Liquid 不仅可以负责生成视觉 HTML，也可以负责生成已经过翻译的无障碍消息。

## 17. Live Region 与 Shopify 多语言体系

对于跨境电商网站，不能只翻译视觉界面，而忽略无障碍专用消息。

例如：

```javascript
announcer.announce(
  `${product.title} added to your cart.`
);
```

这段代码将英语硬编码在 JavaScript 中。

更推荐使用 Shopify locales 文件维护消息模板。

例如 `locales/en.default.json` 中的自定义配置：

```json
{
  "custom_accessibility": {
    "cart": {
      "added": "{{ product }} added to your cart.",
      "removed": "{{ product }} removed from your cart."
    },
    "collection": {
      "results": {
        "one": "{{ count }} product found.",
        "other": "{{ count }} products found."
      }
    }
  }
}
```

上述配置需要合并到已有 locale 文件，而不是覆盖整个文件。

Liquid 可以提前生成业务消息：

```liquid
<script type="application/json" id="A11yMessages">
{
  "cartAdded": {{ 'custom_accessibility.cart.added'
    | t: product: '[product]'
    | json
  }},
  "cartRemoved": {{ 'custom_accessibility.cart.removed'
    | t: product: '[product]'
    | json
  }}
}
</script>
```

JavaScript：

```javascript
const messages = JSON.parse(
  document.querySelector('#A11yMessages').textContent
);

announcer.success(
  messages.cartAdded.replace(
    '[product]',
    () => productTitle
  )
);
```

Collection 商品数量则可以由 Liquid 使用 `t` filter 传入实际 count，让 Shopify 处理对应语言的复数规则。

需要统一管理的内容包括：

| 内容 | 本地化需求 |
|---|---|
| Accessible Name | 控件名称 |
| Accessible Description | 控件说明 |
| Live Region | 动态通知 |
| Error Message | 业务错误 |
| Loading Message | 加载反馈 |
| Currency | 金额及币种格式 |
| Pluralization | 单复数规则 |

无障碍文案本质上也是产品文案的一部分。

## 18. 如何调试 Live Region？

### 18.1 查询页面中所有 Live Region

在 Chrome DevTools Console 中运行：

```javascript
const selector = [
  '[aria-live]',
  '[role="status"]',
  '[role="alert"]',
  '[role="log"]',
  '[role="timer"]',
  '[role="marquee"]'
].join(',');

console.table(
  [...document.querySelectorAll(selector)]
    .map(el => ({
      element: el,

      id: el.id,

      role: el.getAttribute('role'),

      live: el.getAttribute('aria-live'),

      atomic: el.getAttribute('aria-atomic'),

      busy: el.getAttribute('aria-busy'),

      relevant: el.getAttribute('aria-relevant'),

      ariaHidden: el.getAttribute('aria-hidden'),

      text: el.textContent.trim()
    }))
);
```

这可以帮助你发现页面中有哪些显式 Live Region 声明。

但如果 `role="status"` 对应的 live 属性返回 null，不代表它没有 polite 语义，因为浏览器还需要计算该 Role 的隐式属性。

### 18.2 使用 MutationObserver 监听消息变化

```javascript
const observer = new MutationObserver(records => {
  const regions = new Set();

  for (const record of records) {
    const target =
      record.target.nodeType === Node.ELEMENT_NODE
        ? record.target
        : record.target.parentElement;

    const region = target?.closest(`
      [aria-live],
      [role="status"],
      [role="alert"],
      [role="log"]
    `);

    if (region) {
      regions.add(region);
    }
  }

  regions.forEach(region => {
    console.log('[Live Region Updated]', {
      time: performance.now(),

      element: region,

      message: region.textContent.trim(),

      busy: region.getAttribute('aria-busy')
    });
  });
});

observer.observe(document.body, {
  subtree: true,
  childList: true,
  characterData: true,

  attributes: true,

  attributeFilter: [
    'aria-live',
    'aria-busy',
    'aria-hidden',
    'role'
  ]
});
```

测试结束后：

```javascript
observer.disconnect();
```

这个工具能够帮助你了解现有消息区域何时发生 DOM 更新，但它无法证明浏览器真正产生了相应的无障碍事件，也无法读取屏幕阅读器实际播报的内容。

## 19. Live Region 常见错误汇总

| 错误 | 推荐修复 |
|---|---|
| 所有消息都使用 assertive | 普通消息使用 polite |
| 整个商品列表使用 aria-live | 仅通知商品数量或摘要 |
| Live Region 使用 display:none | 使用 visually-hidden 或可见消息 |
| 创建区域时立即填入消息 | 提前建立空区域 |
| Section Rendering 替换消息节点 | 保留稳定的 Live Region |
| 消息只有孤立数字 | 提供完整业务上下文 |
| 每秒播报促销倒计时 | 降低或取消自动通知 |
| 快速请求返回旧消息 | 请求取消与版本校验 |
| aria-busy 一直为 true | 在完成及失败时正确恢复 |
| 使用 focus() 强制读取状态 | 优先考虑 Live Region |
| 活动选项重复进行手动播报 | 优先依赖正确的控件状态 |
| 模态弹窗使用背景消息区域 | 使用当前模态范围内的通知区域 |
| 只检查 DOM，不测试屏幕阅读器 | 使用真实辅助技术验证 |
