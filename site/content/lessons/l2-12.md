# L2-12 Predictive Search：防抖与竞态

> **本课目标：** 解释 debounce、AbortController 与键盘体验。

官方参考：

- [Predictive Search API](https://shopify.dev/docs/api/ajax/reference/predictive-search)
- [Predictive search UX](https://shopify.dev/docs/storefronts/themes/navigation-search/search/predictive-search-ux)

## Predictive Search 和 Search Page 不一样

```text
Full Search
→ 用户正式提交
→ /search?q=shirt
→ 完整结果页
```

```text
Predictive Search
→ 用户还在输入
→ sh
→ shi
→ shirt
→ 下拉建议
```

Predictive Search 是：

> 搜索前的实时辅助体验。

---

## 最小请求

```js
async function predictiveSearch(query) {
  const url = new URL(
    window.Shopify.routes.root + 'search/suggest.json',
    window.location.origin
  );

  url.searchParams.set('q', query);

  const response = await fetch(url);
  return response.json();
}
```

---

## 为什么要 debounce？

如果用户输入：

```text
s
sh
shi
shir
shirt
```

每敲一个字符都请求：

```text
5 次请求
```

实际用户可能在 200ms 内就继续输入。

所以可以等待：

```text
停止输入 200–300ms
```

再请求。

---

## 但是 debounce 不能解决 Race Condition

假设：

```text
请求 A: sh
请求 B: shirt
```

网络时序可能：

```text
B 先返回
→ UI 显示 shirt

A 后返回
→ UI 又被旧的 sh 覆盖
```

这就是 Race Condition。

---

## AbortController 解决的是“旧请求已经没有价值”

```js
let controller;

async function search(query) {
  controller?.abort();
  controller = new AbortController();

  const url = new URL(
    window.Shopify.routes.root + 'search/suggest.json',
    window.location.origin
  );

  url.searchParams.set('q', query);

  const response = await fetch(url, {
    signal: controller.signal
  });

  return response.json();
}
```

状态：

```text
输入 sh
→ Request A

输入 shirt
→ abort A
→ Request B
```

---

## Predictive Search 还要考虑键盘体验

真实功能不是：

```text
fetch + innerHTML
```

还包括：

```text
↑ / ↓ 切换建议
Enter 打开
Esc 关闭
输入框和 popup ARIA 关系
没有结果时怎么办
移动端如何表现
```

这就是为什么 Shopify 官方有专门的 Predictive Search UX 指南。

## 练习与验收

在慢网下快速输入并清空，确认旧结果不会覆盖最新状态。

验收时记录：操作步骤、预期结果、实际结果，以及出现问题时检查的数据和文件。不要只以“页面看起来正常”作为通过依据。
