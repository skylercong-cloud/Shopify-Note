# L1-03 主题编辑器、组件生命周期与调试

> **本课目标：** 理解局部重渲染为何导致重复绑定或组件失效。

## 为什么普通页面正常，编辑器里却失效

普通页面通常加载一次，你的脚本在初次加载时查询 DOM 并绑定监听。

Theme Editor 会在商家修改设置、添加或删除模块时局部替换 Section HTML，不一定刷新整个页面。旧节点被移除，新节点出现，初次绑定不会自动迁移。

因此需要同时考虑：首次初始化、模块重新加载、模块卸载、重复初始化。

## 两种常见组织方式

1. 使用自定义元素，把初始化放在 `connectedCallback`，把事件、计时器和外部观察器的清理放在 `disconnectedCallback`。
2. 使用显式 `init(root)` / `destroy(root)`，在首次加载及编辑器的 section 事件中调用。

自定义元素是一种浏览器组件机制，不是 React，也不等于某一套 Shopify 官方 Web Components。选择方式应与已有主题保持一致。

下面是可独立理解的浏览器组件例子，创建一个按钮计数器。将其放进主题现有的全局 JS 资源加载流程；不要在每次 Section 重渲染时重复执行全局注册。

```javascript
class LessonCounter extends HTMLElement {
  connectedCallback() {
    // 某些 DOM 移动会重新触发连接；初始化要可重复执行。
    this.controller?.abort();
    this.controller = new AbortController();
    this.button = this.querySelector('button');
    if (!this.button) return;
    this.count = 0;
    this.button.textContent = '点击次数：0';
    this.button.addEventListener('click', () => {
      this.count += 1;
      this.button.textContent = `点击次数：${this.count}`;
    }, { signal: this.controller.signal });
  }

  disconnectedCallback() {
    this.controller?.abort();
  }
}

if (!customElements.get('lesson-counter')) {
  customElements.define('lesson-counter', LessonCounter);
}
```

对应 HTML：

```html
<lesson-counter>
  <button type="button">点击次数：0</button>
</lesson-counter>
```

这里用 `AbortController` 释放事件监听；它不自动清理你创建的 `setInterval`、Swiper 或 `ResizeObserver`。对应资源仍需调用清理方法。例子在重新连接时重置计数，这是明确选择的行为；真实商品选择状态应按 URL 或服务端 HTML 重新同步。

## 编辑器事件什么时候需要用

Shopify 提供 `shopify:section:load`、`shopify:section:unload` 等事件。普通函数组织的组件可以从事件目标中查找组件并初始化或销毁。

```javascript
document.addEventListener('shopify:section:load', event => {
  // initComponents(event.target);
});

document.addEventListener('shopify:section:unload', event => {
  // destroyComponents(event.target);
});
```

这里的注释是接入位置，不是已经实现的初始化函数。若自定义元素已负责生命周期，不要再让事件处理器重复绑定同一组监听。

## 作用域为什么重要

同一个 Section 可能出现多次。用 `document.querySelector` 查按钮，可能拿到另一实例的节点。组件应尽量从自己的根节点查询，ID 应包含实例身份。

同理，Section Rendering 返回 HTML 后，必须按真实包装结构替换节点，才能触发正确的生命周期并避免嵌套重复容器。

## 调试顺序

1. 在 Elements 中确认操作的节点属于哪个 Section 实例。
2. 在 Network 中确认是否发起了重复请求、是否返回预期 section HTML。
3. 记录初始化与销毁次数，检查一次点击是否触发多个 handler。
4. 在编辑器里连续改变设置，再测试功能。
5. 最后验证普通页面及同一模块的多个实例。

官方参考：[与主题编辑器集成](https://shopify.dev/docs/storefronts/themes/best-practices/editor/integrate-sections-and-blocks)、[Section Rendering API](https://shopify.dev/docs/api/ajax/section-rendering)。

## 练习与验收

在编辑器中连续添加、修改和删除同一个 Section 三次，检查是否出现重复监听、遗留定时器或重复请求。

验收时记录：操作步骤、预期结果、实际结果，以及出现问题时检查的数据和文件。不要只以“页面看起来正常”作为通过依据。
