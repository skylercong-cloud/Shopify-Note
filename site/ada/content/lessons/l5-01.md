# L5-01 收到一个无障碍缺陷，第一步查哪里？

> **本课目标：** 从复现步骤和用户任务定位 HTML、CSS、交互或媒体问题。

## 从缺陷还原用户任务

Dreame 德国站的大图弹窗原始清单里有三个现象：读屏只报「图形」，弹窗打开时仍可浏览背景，正向 Tab 可以留在图片区域而反向 Shift+Tab 会跳出。

把反馈写成可复现步骤。例如，「用键盘打开大图，焦点到达第一个控件，按 Shift+Tab 后落到背景商品页」。写明页面、系统、浏览器、读屏或 WebView 版本和起始状态。验收时按原路径重走。

## 根据现象找检查位置

| 现象 | 先查哪里 |
| --- | --- |
| 读屏只说「图形」 | Elements 中的实际大图、`alt`、无障碍树计算出的名称。缩略图和弹窗节点可能分别渲染。 |
| Tab 跑到底层 | 用 `document.activeElement` 看落点。分别检查末尾 Tab 和开头 Shift+Tab，以及组件的边界处理。 |
| Tab 在弹窗内，读屏仍到背景 | 查模态隔离与读屏实际浏览，验证背景的可访问性。 |
| 焦点在按钮上，但眼睛看不到 | CSS 描边、容器裁剪、叠层或悬浮元素。 |
| 有字幕选项，播放却看不到字幕 | 当前视频的实际字幕轨、加载结果、语言和显示状态。 |

DevTools 适合定位浏览器提供的角色、名称和状态。键盘和读屏分别重走，记录真实落点或播报。[Chrome DevTools](https://developer.chrome.com/docs/devtools/accessibility/reference/) · [W3C 初步检查](https://www.w3.org/WAI/test-evaluate/preliminary/)

## 练习与验收

受影响的同一个商品任务应能完整走完：打开大图、读出关键信息、正反导航、Escape 或点按关闭、回到入口继续看商品。每个结果对应一个动作和环境。

手机竖屏正常，横屏后看不到关闭按钮，用外接键盘有时还能关闭。先确认按钮是否仍能聚焦，再检查短视口导致的裁剪和遮挡。
