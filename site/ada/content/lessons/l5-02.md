# L5-02 自动扫描通过了，商品页还要怎么验收？

> **本课目标：** 组合自动扫描、交互断言、键盘、桌面读屏和手机真机。

## 先选择一条购买路径

选择规格，打开配件详情，修改数量，关闭弹窗，加购并确认结果。对这条路径，不同的检查回答不同问题。

| 方法 | 验证什么 |
| --- | --- |
| 自动扫描 | 初始页和弹窗打开后是否有空名称、无效 ARIA 或缺少标签。 |
| 纯键盘 | 焦点是否可见、数量能否改、正反 Tab 与关闭恢复是否正确。 |
| 桌面读屏 | 是否听得懂名称、选中状态、数量和加购结果。 |
| 真机 App/Mall | TalkBack 或 VoiceOver 能否逐项浏览配件控件、屏蔽背景并恢复到入口。 |
| 缩放与窄屏 | 价格、关闭和加购在各布局状态下是否可视且可用。 |

「Tab 留在配件弹窗内」与「TalkBack 滑不到底层」是两条测试结果，分别用实际输入方式验证。[W3C 评估方法](https://www.w3.org/WAI/test-evaluate/tools/) · [模态弹窗模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)

## 把焦点回归写成自动断言

```js
const trigger = page.getByRole('button', { name: '查看配件', exact: true });
const dialog = page.getByRole('dialog', { name: '配件详情', exact: true });

await trigger.focus();
await page.keyboard.press('Enter');
await expect(dialog.getByRole('button', { name: '关闭配件详情' }))
  .toBeFocused();

await page.keyboard.press('Escape');
await expect(dialog).toBeHidden();
await expect(trigger).toBeFocused();
```

这段测试从入口已获得焦点开始。入口能否通过自然 Tab 到达，要从前一个控件继续测。状态消息的 DOM 文本可写断言，实际播报用读屏确认。[Playwright 无障碍测试](https://playwright.dev/docs/accessibility-testing) · [断言](https://playwright.dev/docs/test-assertions)

## 练习与验收

写下环境、动作和结果。例如「Windows Chrome，用 Tab 打开配件。Shift+Tab 从关闭按钮回到弹窗最后一项。Escape 后回到入口，继续 Tab 去下一项」。正常加购和库存不足分别走一次。

自动扫描和焦点断言都通过，只有十分钟真机时间。优先挑两条桌面检查无法体现的任务，例如独立操作加减按钮和验证弹窗背景隔离，写出实际观察结果。
