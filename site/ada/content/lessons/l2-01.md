# L2-01 键盘按 Tab 时，焦点到底去哪了？

> **本课目标：** 分别检查键盘可达性、焦点可见性和实际激活结果。

## 把「键盘没反应」拆成三个问题

A2 的「加入购物车」和「立即购买」曾能获得键盘焦点，用户却看不出目前在哪个按钮上。先区分故障是哪一层。

| 问题 | 检查方式 |
| --- | --- |
| 焦点到得了？ | 从前一个控件按 Tab，再走 Shift+Tab。确认元素、禁用与隐藏状态。 |
| 焦点看得见？ | 到达后观察实际指示，检查样式、裁剪或浮层。 |
| 按键能操作？ | 按符合控件习惯的键，核对用户实际看到的结果。 |

在 DevTools 中，`document.activeElement` 可以辅助确认当前元素。原生按钮默认可通过 Tab 到达，`disabled` 和 `tabindex="-1"` 会影响这条路径。链接通常用 Enter，按钮支持 Enter 和 Space。[WCAG 键盘操作](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html) · [W3C 按钮模式](https://www.w3.org/WAI/ARIA/apg/patterns/button/)

## 焦点到了，怎么找样式问题

如果主题重置了 `outline`，可以保留浏览器默认指示，或为购买按钮定义清楚的轮廓：

```css
.purchase-button:focus-visible {
  outline: 3px solid #155eef;
  outline-offset: 3px;
}
```

用真实背景看轮廓。轮播容器的 `overflow: hidden` 可能裁掉外侧轮廓。固定导航或底部浮层可能盖住整个按钮。这两个场景分别查裁剪和滚动位置。[WCAG 焦点可见](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html) · [焦点无遮挡](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)

焦点看得见却没有执行动作时，检查现有事件是否只绑了 `mousedown` 或触摸事件。普通按钮的操作可以从 `click` 统一处理鼠标和键盘激活。验证是否真的打开弹窗，或是否加入了正确的商品和数量。

## 练习与验收

「立即购买」能触发，焦点框却被商品栏裁掉。「查看配件」焦点清楚，鼠标可以打开，Enter 和 Space 却不行。分别检查父容器的裁剪和按钮的事件入口，再用键盘重走「规格、数量、查看配件」。
