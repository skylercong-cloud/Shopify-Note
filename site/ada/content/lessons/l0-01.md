# L0-01 同一个商品页，用户是怎么用的？

> **本课目标：** 区分 ADA、WCAG、ARIA，并用商品页理解键盘、视觉和无障碍树。

## 从一次普通的购物操作开始

假设你写了一个 Shopify 商品页。用鼠标打开配件详情，把数量改成 2，关掉弹窗，再加入购物车。现在用三种方式重走这条路径。

| 用户怎么用 | 需要页面提供什么 |
| --- | --- |
| 只用键盘 | Tab 找到控件，看见焦点，用按键完成操作。 |
| 使用读屏 | 听懂哪个控件能增加数量、当前数量是多少、弹窗是否打开。 |
| 放大页面 | 读完整段说明，并确保加购按钮没有被固定浮层遮住。 |

无障碍优化的对象是这条用户任务。Dreame 德国站 A2 的购买按钮曾经能获得焦点，但用户看不见焦点指示。定位到这种情况，就先查 CSS 的焦点状态。

## ADA、WCAG 和 ARIA 的分工

| 名称 | 开发时怎么理解 |
| --- | --- |
| ADA | 美国《残疾人法》。项目里常把网站无障碍整改叫「ADA 优化」。欧洲站点的具体适用要求按当地市场判断。 |
| WCAG | W3C 的 Web 内容无障碍指南，把障碍变成可测试的准则，如 2.1.1 键盘和 2.4.7 焦点可见。WCAG 2.2 AA 中，2.2 是版本，AA 要考虑适用的 A 和 AA 条目。 |
| ARIA | 向辅助技术表达角色、名称、状态和关系。比如 `aria-expanded="true"` 表示已展开。开合和键盘操作由组件实现。 |

[美国司法部 ADA 指引](https://www.ada.gov/resources/web-guidance/) · [W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/)

## 浏览器是怎样把页面交给用户的？

```text
HTML、CSS、组件状态
        ↓
      浏览器
        ├─ 视觉呈现 → 样式、位置、可见焦点
        ├─ 键盘行为 → Tab 到达、按键激活
        └─ 无障碍树 → 读屏获取角色、名称和状态
```

`<button type="button">查看配件</button>` 自带按钮角色，可以由 Tab 到达，并用 Enter 或 Space 激活。组件负责打开详情。把一个 `div` 用 CSS 画成按钮、用鼠标事件打开详情时，默认的按钮语义和键盘行为还需要补齐。优先选能表达动作的 HTML 元素。[W3C 按钮模式](https://www.w3.org/WAI/ARIA/apg/patterns/button/)

## 练习与验收

下面三条反馈分别从哪一层查起？

1. Enter 能加购，屏幕上看不出焦点。
2. 鼠标能打开配件，Tab 一直跳不到入口。
3. 读屏找到关闭按钮，却只说「按钮」。

参考思路：第一条查样式，第二条从元素与可聚焦状态查，第三条看浏览器计算出的名称。验收时各重走一次原操作。
