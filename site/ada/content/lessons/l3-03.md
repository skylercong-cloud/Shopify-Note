# L3-03 加购成功了，读屏用户怎么知道？

> **本课目标：** 用状态消息报告操作结果，并在适当位置保留焦点。

## 让用户知道发生了什么

假设加购后继续停留在商品页，角标从 0 变 1。读屏用户的焦点仍在触发按钮，可能错过角标变化。一条完整反馈可以是「已将 Dreame A2 加入购物车，购物车内共 1 件商品」。

区分本次加购数量和购物车总数。原本 3 件，本次加了 2 件，结果可以是「已加入 2 件，购物车内共 5 件」。[WCAG 状态消息](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)

## 保留一个可以更新的状态区

```html
<p id="cart-status" role="status" aria-atomic="true"></p>
```

```js
const cartStatus = document.querySelector('#cart-status');

function announceAddToCart(productName, cartCount) {
  cartStatus.textContent =
    `已将 ${productName} 加入购物车。购物车内共 ${cartCount} 件商品。`;
}
```

页面初始时保留这个空节点。实际请求成功之后，用真实数据更新文字。`role="status"` 默认是 `polite`，通常等适当时机播报。`aria-atomic="true"` 让消息以整句呈现。用户无需聚焦状态区。[W3C role=status](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA22)

如果主题会动态替换 Cart Drawer 的 HTML，可以把消息节点放在替换范围之外。若页面实际打开了一个模态抽屉，焦点按弹窗模式进入和恢复。[Shopify Section Rendering](https://shopify.dev/docs/api/ajax/section-rendering) · [W3C 模态弹窗](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)

## 练习与验收

分别验证成功加购、连续加购同一商品、库存不足。失败提示说明下一步，例如「当前仅剩 1 件，请修改数量后重试」。把字段相关错误放在能找回的位置。普通反馈可用 `status`，确实需要立即关注的重要消息可考虑 `alert`。[W3C 表单通知](https://www.w3.org/WAI/tutorials/forms/notifications/)
