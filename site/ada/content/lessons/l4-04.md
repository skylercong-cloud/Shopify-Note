# L4-04 图片对比能拖了，为什么还要提供点击操作？

> **本课目标：** 为拖动和触屏手势提供可用替代，并验证各条输入路径。

## 拖、按键和单点是三条路径

德国站图片对比分隔条曾经只能拖动。给它补上键盘焦点与方向键后，再想一种操作：用户能点击或轻触，却很难一直按住并移动鼠标或手指。

| 操作 | 检查方式 |
| --- | --- |
| 拖动 | 拖分隔线，看画面变化。 |
| 键盘 | Tab 到滑块，用方向键改变比例。 |
| 无需拖动的单指针 | 点轨道或点加减按钮，也能调整到需要的值。 |

单指针可以连续点几次，每次都能松开。要从 50% 到 65%，每次增加 5% 的按钮点三次即可。[WCAG 拖动操作](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)

## 让几条路径共用一个数值

```html
<label for="compare-range">左侧画面占比（百分比）</label>
<input id="compare-range" type="range" min="0" max="100" step="5" value="50">
<button type="button" id="compare-less">减少左侧画面占比</button>
<button type="button" id="compare-more">增加左侧画面占比</button>
```

```js
const range = document.querySelector('#compare-range');

function updateComparison() {
  // renderComparison 接入组件已有的图片裁剪和分隔条定位逻辑。
  renderComparison(range.valueAsNumber);
}

range.addEventListener('input', updateComparison);

document.querySelector('#compare-less').addEventListener('click', () => {
  range.stepDown();
  updateComparison();
});

document.querySelector('#compare-more').addEventListener('click', () => {
  range.stepUp();
  updateComparison();
});

updateComparison();
```

原生控件提供范围和键盘行为。按钮改变相同的滑块值，再调用同一更新逻辑。测试 0%、50%、100%，核对画面、分隔条和读屏值。[HTML 范围输入](https://html.spec.whatwg.org/multipage/input.html#range-state-(type=range)) · [W3C 滑块模式](https://www.w3.org/WAI/ARIA/apg/patterns/slider/)

## 练习与验收

iOS Mall 曾只有边缘右滑返回。加上具名返回按钮后，在实际 WebView 里复测它能否被 VoiceOver 找到、激活，以及是否回到预期页面。再想想只有左右滑动的图库，该为触屏用户补怎样的上一张、下一张入口。[WCAG 指针手势](https://www.w3.org/WAI/WCAG22/Understanding/pointer-gestures.html)
