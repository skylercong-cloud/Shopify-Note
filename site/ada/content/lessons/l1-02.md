# L1-02 为什么读屏知道数值，却不知道是哪款商品？

> **本课目标：** 用语义表格关联商品、参数和数据，验证读屏表格导航。

## 表格为什么需要两个方向的表头

德国站商品对比页曾经只靠视觉布局呈现参数。读屏能遇到一串内容，却无法用表格导航确认每个数值属于哪款产品。看下面的教学数据：

| 参数 | 产品 A | 产品 B |
| --- | --- | --- |
| 续航时间 | 80 分钟 | 100 分钟 |
| 充电时间 | 120 分钟 | 90 分钟 |

你看到 100 分钟，向上一扫是「产品 B」，向左一扫是「续航时间」。HTML 要把这两个关系交给浏览器。[WCAG 1.3.1 信息和关系](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html)

```html
<table>
  <caption>电池参数对比</caption>
  <thead>
    <tr>
      <th scope="col">参数</th>
      <th scope="col">产品 A</th>
      <th scope="col">产品 B</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">续航时间</th>
      <td>80 分钟</td>
      <td>100 分钟</td>
    </tr>
    <tr>
      <th scope="row">充电时间</th>
      <td>120 分钟</td>
      <td>90 分钟</td>
    </tr>
  </tbody>
</table>
```

`caption` 说清整张表的用途。`thead` 和 `tbody` 分别组织头部行和正文行，每个 `tr` 是一行。`th` 和 `td` 都占一个单元格的位置。在这个没有合并单元格的例子里，每行的第 1、2、3 个单元格分别落在第 1、2、3 列。

- 「100 分钟」是这一行的第 3 个单元格。同一列上方的 `<th scope="col">产品 B</th>` 提供列标题。
- 这一行的第一个单元格是 `<th scope="row">续航时间</th>`，为同行的数据提供行标题。

浏览器把表格坐标和表头关联交给辅助技术。这里 `tbody` 里的「续航时间」同样是表头，所以要用 `th`。[W3C 行列双表头教程](https://www.w3.org/WAI/tutorials/tables/two-headers/) · [HTML 表格关联规则](https://html.spec.whatwg.org/multipage/tables.html#attr-th-scope)

## Tab 到不了普通数据格，读屏怎么读它？

示例中的普通 `<td>100 分钟</td>` 默认不参与 Tab。用 NVDA 浏览模式的 **Ctrl + Alt + 方向键**可以在格子之间移动。可能听到「产品 B，续航时间，100 分钟」，也可能只重复这次变化的表头。比如从「80 分钟」向右移动，同一行没变，可能主要听到「产品 B，100 分钟」。设置允许时，NVDA 也会播报单元格坐标。验收时关注用户能否确定商品与参数，具体播报随工具与设置而异。[NVDA 浏览模式和表格命令](https://download.nvaccess.org/documentation/userGuide.html#BrowseMode)

## Dreame 德国站为什么可以直接 Tab 到数值格？

德国站扫拖机器人对比页使用原生表格，列标题是视觉隐藏的 `<th scope="col">`，行标题用 `<th scope="row">`。数值格另外设置了 `tabindex="0"`，所以 Tab 可以直接停在它上面。浏览器从实际表格结构获得行列位置，页面不需要手写 `aria-rowindex` 或 `aria-colindex`。最左边还有一列参数名，所以第一款商品在表格里是第 2 列。[德国站扫拖机器人对比页](https://de.dreametech.com/pages/robot-vacuum-and-mop-comparison)

这个案例还有两个值得复测的细节。核对时，线上数值格的 `headers` 引用了行标题和列标题，只有行标题的 ID 能找到对应元素。列标题本身仍有 `scope="col"`，测试者用的浏览器与读屏组合可以从表格结构获取列名。本地换商品逻辑更新了可见商品名和数值，但没有在同一逻辑更新隐藏的 `thead`。因此，**首次进入能读出列名**和**换完商品后仍能读出正确列名**要分别验证。

普通对比表可以用表格导航读取静态参数，保留 Tab 给链接、按钮和表单控件。项目特意加了 `tabindex="0"` 时，也要用 Tab 检查实际停靠和播报。

## 练习与验收

换成「产品 C」后，页面显示的新数值正确，读屏却仍把它归到「产品 B」下面。先检查列标题如何更新，再确认同一列的商品属性跟随新的数据。

用 NVDA 浏览模式进入表格，按 Ctrl+Alt+左右方向键在同一行比较商品，再按 Ctrl+Alt+上下方向键看同一商品的不同参数。切换产品后，再走这两步。移动端重排后如果还采用表格，要复查真实页面的结构和表头。[NVDA 表格导航](https://download.nvaccess.org/documentation/userGuide.html)
