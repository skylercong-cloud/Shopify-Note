# L2-02 为什么每个按钮都能 Tab 到，顺序还是不对？

> **本课目标：** 区分视觉、Tab 和读屏阅读顺序，用 DOM 表达用户任务。

## 视觉顺序、Tab 顺序和阅读顺序各指什么

商品页上看见「颜色、数量、加入购物车」。但按 Tab 时，可能先到加购，再折返选颜色。虽然每个控件都能操作，顺序已经打乱了购买步骤。

| 顺序 | 看什么 |
| --- | --- |
| 视觉顺序 | CSS 排版后的位置。 |
| Tab 顺序 | 普通页面默认按 DOM 中可聚焦元素的顺序。 |
| 读屏阅读顺序 | 浏览时遇到标题、静态说明和控件的顺序。 |

静态说明可以由读屏访问，通常无需单独成为 Tab 停靠点。德国站 A2 商品页曾记录移动端连续读屏浏览顺序异常。排查这类问题，要用实际的滑动浏览验证。[WCAG 有意义的顺序](https://www.w3.org/WAI/WCAG22/Understanding/meaningful-sequence.html) · [焦点顺序](https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html)

## 让 DOM 表达任务的顺序

假设 Liquid 先输出加购按钮，CSS 用 `order` 把它移到底部。通常只是画面变了，默认 Tab 仍先到按钮。可以先在模板里排好「选颜色、改数量、提交」，再用 CSS 排版。

```html
<label for="color">颜色</label>
<select id="color" name="color">
  <option>白色</option>
  <option>黑色</option>
</select>

<label for="quantity">数量</label>
<input id="quantity" name="quantity" type="number" min="1" value="1">

<button type="submit">加入购物车</button>
```

## 原生控件的「默认顺序」相当于 tabindex="0" 吗？

普通的 `button`、`input`、`select`、`textarea` 和带 `href` 的链接在可用时通常能直接用 Tab 到达。在上面的表单里，默认顺序就是「颜色 → 数量 → 加入购物车」。省略 `tabindex` 时浏览器按元素自己的规则处理焦点。给普通可用按钮显式写 `tabindex="0"`，Tab 的效果通常一样。给原本无默认焦点行为的元素加这个属性，则会多一个 Tab 停靠点。

| 写法 | 正常 Tab 会停吗？ | 调用 `.focus()` 能聚焦吗？ |
| --- | --- | --- |
| 可用的原生 `<button>` | 会 | 能 |
| 普通 `<h2>` | 不会 | 不能 |
| `<h2 tabindex="0">` | 会 | 能 |
| `<h2 tabindex="-1">` | 通常跳过 | 能 |
| 可聚焦元素的 `tabindex="1"` 等正数 | 会，通常排在默认和 `0` 之前。多个正数由小到大 | 能 |

`tabindex` 规定元素能否接收焦点、如何参与 Tab 顺序。它本身不移动焦点。`.focus()` 是代码执行时尝试移动焦点的动作，目标需要先能接收焦点。通常直接对普通 `h2` 调用 `.focus()`，焦点会留在原处。在现有页面用正数给控件排队，可能让新增控件落到意外位置，优先调整 DOM。

## 为什么弹窗标题常用 -1 再调用 focus()？

假设弹窗顶部是「配件说明」，下面有多段内容，末尾才是「关闭」。打开时希望用户从顶部开始阅读，所以给标题加 `tabindex="-1"`，再在打开后调用 `.focus()`。这里说的是**内容长的弹窗**，标题本身可以很短。

```html
<h2 id="accessory-title" tabindex="-1">配件说明</h2>
```

```js
// 在弹窗显示后，把焦点放到阅读起点。
document.querySelector('#accessory-title').focus();
```

若改成 `tabindex="0"` 再调用 `.focus()`，标题同样能先获得焦点。区别出现在接下来的导航：从标题 Tab 到「关闭」后，`0` 会让 Shift+Tab 回到标题，`-1` 会让正常 Tab 路径跳过标题。标题始终保留 `h2` 语义，读屏仍可按标题浏览。

[HTML tabindex 规则](https://html.spec.whatwg.org/multipage/interaction.html#the-tabindex-attribute) · [W3C DOM 与视觉顺序](https://www.w3.org/WAI/WCAG22/Techniques/css/C27) · [常用属性速查](?lesson=ref-02)

## 练习与验收

手机版用 CSS 挪动了「查看配件」，Tab 仍先到它，再跳到画面上方的数量控件。先比对 DOM、CSS 和实际焦点路径。改完测手机和桌面。普通价格用读屏阅读验证，Tab 主要核对交互控件。
