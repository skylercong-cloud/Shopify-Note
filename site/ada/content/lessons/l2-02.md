# L2-02 为什么每个按钮都能 Tab 到，顺序还是不对？

> **本课目标：** 区分视觉、Tab 和读屏阅读顺序，用 DOM 表达用户任务。

## 视觉顺序、Tab 顺序和阅读顺序各指什么

商品页上看见「颜色、数量、加入购物车」。但按 Tab 时，可能先到加购，再折返选颜色。虽然每个控件都能操作，顺序已经打乱了购买步骤。

| 顺序 | 看什么 |
| --- | --- |
| 视觉顺序 | CSS 排版后的位置。 |
| Tab 顺序 | 普通页面默认按 DOM 中可聚焦元素的顺序。 |
| 读屏阅读顺序 | 浏览时遇到标题、静态说明和控件的顺序。 |

静态说明可以由读屏访问，通常无需单独成为 Tab 停靠点。德国站 A2 商品页曾记录移动端连续读屏浏览顺序异常。排查这类问题，要用实际的滑动浏览验证。[WCAG 有意义的顺序](https://www.w3.org/WAI/WCAG22/Understanding/meaningful-sequence.html) · [焦点顺序](https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html)

## 让 DOM 表达任务的顺序

假设 Liquid 先输出加购按钮，CSS 用 `order` 把它移到底部。通常只是画面变了，默认 Tab 仍先到按钮。可以先在模板里排好「选颜色、改数量、提交」，再用 CSS 排版。

```html
<label for="color">颜色</label>
<select id="color" name="color">
  <option>白色</option>
  <option>黑色</option>
</select>

<label for="quantity">数量</label>
<input id="quantity" name="quantity" type="number" min="1" value="1">

<button type="submit">加入购物车</button>
```

原生控件一般保留默认顺序。`tabindex="0"` 让元素进入正常 Tab 顺序，`tabindex="-1"` 常用于程序化聚焦，例如弹窗长标题。正数会给元素额外优先级，页面后来插入控件时容易打乱路径。[HTML tabindex 规则](https://html.spec.whatwg.org/multipage/interaction.html#the-tabindex-attribute) · [W3C DOM 与视觉顺序](https://www.w3.org/WAI/WCAG22/Techniques/css/C27)

## 练习与验收

手机版用 CSS 挪动了「查看配件」，Tab 仍先到它，再跳到画面上方的数量控件。先比对 DOM、CSS 和实际焦点路径。改完测手机和桌面。普通价格用读屏阅读验证，Tab 主要核对交互控件。
