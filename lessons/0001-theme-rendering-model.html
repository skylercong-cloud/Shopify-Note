Lesson 01 · 约 15 分钟

Shopify 主题不是一张网页，而是一套可配置的页面系统

这一课只解决一个问题：当顾客打开商品页时，Shopify 如何从主题文件拼出最终 HTML？掌握它，后面学 Liquid、Section 和 JSON 才不会变成背目录。

先建立类比

普通前端项目

路由决定页面，组件负责 UI，数据由接口或状态管理提供。

Shopify 主题

页面类型匹配模板，Section 是商家可配置的组件，Liquid 读取 Shopify 提供的数据并输出 HTML。

1. 一次请求经过什么

以 /products/mug 为例：

URL /products/mug
  ↓
页面类型：product
  ↓
templates/product.json
  ↓
sections/main-product.liquid
sections/related-products.liquid
  ↓
blocks + snippets + Shopify 数据
  ↓
HTML + CSS + JavaScript

模板更像“编排文件”，Section 才是“实现文件”。JSON 模板保存要渲染哪些 Section、它们的顺序和设置值；Section 的 Liquid 负责真正输出标记。

2. 主题目录只记职责

目录你可以把它理解为典型问题
layout/全站 HTML 外壳全站 head、全局资源在哪里加载？
templates/页面编排商品页有哪些模块、顺序是什么？
sections/可配置组件商家能否添加、删除、排序和修改模块？
snippets/可复用函数片段价格、图片、按钮是否重复实现？
assets/静态资源CSS、JS、图片如何加载？
config/ + locales/设置与翻译全局主题设置和多语言在哪里维护？

3. JSON 模板 vs Liquid 模板

优先选择 JSON 模板：它让商家在 Theme Editor 中添加、删除和排序 Section。

Liquid 模板：HTML/Liquid 直接写在模板中，适合少数不能使用 Section 的场景；它本身没有 JSON 的固定 schema。

一个关键规则：如果你希望页面使用可拖拽的 Section 组合，就使用 JSON 模板，把 HTML/Liquid 放进被引用的 Section 文件中。

4. Section 为什么是 Shopify 的核心

Section 是一个 Liquid 文件，通常包含 HTML/Liquid 和一个 {% schema %} 配置块。Schema 告诉 Theme Editor：这个模块叫什么、有哪些设置、允许哪些 blocks、默认添加时长什么样。

{% schema %}
{
  "name": "Promo banner",
  "settings": [
    {"type": "text", "id": "title", "label": "标题"}
  ],
  "presets": [{"name": "Promo banner"}]
}
{% endschema %}

注意：schema 是给编辑器和主题配置使用的元数据，不会直接输出到页面 HTML。
